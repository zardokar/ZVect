บทสรุปย่อ

คลิปนี้อธิบาย Reciprocal Rank Fusion (RRF) ด้วยตัวอย่างที่คิดมือได้ทุกช่อง: คำถามเรื่องรายได้ของ Tesla สองสำนวนให้รายการ chunk คนละ 5 อันดับ ผู้สอนให้คะแนนแต่ละตำแหน่งด้วย 1 ÷ (k + อันดับ) แล้วบวกคะแนนของ chunk เดียวกันข้ามรายการ เริ่มจาก k = 0 (X และ Y ได้ 1.5 เท่ากัน, Z ได้ 0.53) แล้วชี้ว่า k = 0 ลงโทษอันดับ 2 ถึง 50% จึงเปลี่ยนเป็น k = 60 (X และ Y ได้ 0.0325, Z ได้ 0.0313) ช่วงท้ายรันโค้ด Python ที่รวมผลจาก 3 คำถาม 15 chunk เหลือ 7 chunk ที่ไม่ซ้ำ รายงานนี้แสดงทุกสูตรเป็นสมการจริง แทนค่าทุกแถวของตารางทั้ง k = 0 และ k = 60 ถอดผลรันของโค้ดกลับเป็นอันดับในแต่ละรายการ และเสริม RRF แบบถ่วงน้ำหนัก (ไม่มีในคลิป) ที่มาของเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ (license มาตรฐานของ YouTube) สมการ ตัวเลขบนสไลด์ และโค้ดถอดตามภาพ

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ แบบวิเคราะห์เชิงลึก (license มาตรฐานของ YouTube) สมการ ตัวเลขบนสไลด์ และโค้ดสั้น ๆ ถอดตรงตามภาพ ทุกค่าในตัวอย่างผู้จัดทำคำนวณซ้ำด้วย python (recompute.py)

สรุปเชิงลึก

ปัญหาที่ RRF แก้: เมื่อถามคำถามเดียวกันหลายสำนวน (multi-query) แต่ละสำนวนได้รายการ chunk ของตัวเอง chunk เดียวกันจึงซ้ำกันข้ามรายการ ผู้สอนบอกว่าจะรวมรายการแบบไม่คิดแล้วส่งให้ LLM ไม่ได้เพราะสิ้นเปลือง RRF ให้คะแนนแต่ละ chunk จาก ตำแหน่ง ของมันในทุกรายการ: สูตรบนสไลด์คือ RRF_score = Σ (1 / (k + rank_position)) โดย rank_position คือตำแหน่งในผลค้น ผลรวมทำ "ข้ามทุกคำถามที่ chunk นั้นปรากฏ" และ k เป็นค่าคงที่ที่ผู้สอนบอกว่าในผลิตภัณฑ์จำนวนมาก "ถือว่าเป็น 60 เสมอ"

ตัวอย่าง: Retrieval A ("What are the revenue streams for Tesla?") ได้ X, Y, Z, W, V และ Retrieval B ("In what ways does Tesla generate income?") ได้ Y, X, A, B, Z ที่ k = 0 คะแนนตำแหน่งคือ 1, 0.5, 0.33, 0.25, 0.2 ผลรวม: X = 1 + 0.5 = 1.5, Y = 0.5 + 1 = 1.5 (เสมอ), Z = 0.33 + 0.2 = 0.53, A = 0.33, W = 0.25, B = 0.25 (เสมอ), V = 0.2 chunk ที่ไม่อยู่ในรายการใดนับ 0 จากรายการนั้น ถ้าส่งได้แค่ 3 chunk ก็เลือก X, Y, Z

ทำไม k = 0 ไม่ดี: อันดับ 2 ได้ 0.5 (โดนลด 50%) อันดับ 3 ได้ 0.33 (ลด 67%) ผู้สอนยกกรณีที่ X กับ Y มี similarity ใกล้กันมาก (0.95 กับ 0.94) แต่ RRF แปลงความต่าง 0.01 นั้นเป็นคะแนนต่างกัน 2 เท่า (1.0 กับ 0.5) จึงเปลี่ยนเป็น k = 60: คะแนนตำแหน่งกลายเป็น 0.0164, 0.0161, 0.0159, 0.0156, 0.0154 และผลรวม X = Y = 0.0325, Z = 0.0313, A = 0.0159, W = B = 0.0156, V = 0.0154 ผู้สอนพูดว่าระยะห่าง X กับ Z "เป็น 0.003" ซึ่งคลาดไป ค่าจากสไลด์เองคือ 0.0325 − 0.0313 = 0.0012 (ค่าไม่ปัด 0.00126) ข้อสรุปห้าข้อบนสไลด์: RRF ดัน chunk ที่ปรากฏหลายรายการ (consensus), k = 0 แรงเกินไป, k = 60 สมดุลและใช้กันแพร่หลาย, chunk ที่มีเฉพาะในคำถามเดียวยังได้คะแนน (diversity), และ RRF "มักชนะ" วิธีรวมที่ซับซ้อนกว่า

โค้ด: ฟังก์ชัน reciprocal_rank_fusion(chunk_lists, k=60, verbose=True) วนทุกรายการ ใช้ page_content เป็นตัวระบุ chunk คิด position_score = 1 / (k + position) โดยตำแหน่งเริ่มที่ 1 บวกสะสม แล้วเรียงจากมากไปน้อย การรันจริงรวม 3 คำถาม × 5 chunk = 15 เหลือ 7 chunk คะแนนอันดับ 1–5 คือ 0.0487, 0.0476, 0.0474, 0.0315, 0.0310

ผลตรวจของผู้จัดทำ: ตัวเลขบนสไลด์ทุกตัวคำนวณซ้ำได้ตรง (recompute.py) ลำดับที่ k = 0 และ k = 60 เหมือนกันทุกตำแหน่ง ต่างกันแค่ขนาดช่องว่าง (X − Z: 0.967 เทียบ 0.00126) การตัด 5 chunk ตามเชิงอรรถของสไลด์ตกกลางคู่เสมอ W/B ทั้งสองค่า k จึงต้องมีกติกาตัดสินเสมอซึ่งคลิปไม่ได้บอก ผู้จัดทำถอด log ของโค้ดกลับได้ว่า chunk อันดับ 1 อยู่ในทั้ง 3 รายการ (อันดับ 2, 1, 2) ส่วนคะแนนสูงสุดที่เป็นไปได้กับ 3 รายการคือ 3/61 = 0.0492 ข้อตรวจ 7 ข้อ: ยืนยัน 4 · ยืนยันบางส่วน 2 · ขัดแย้ง 1

จะเอาไปใช้อย่างไร (ข้อเสนอของผู้จัดทำ): ใช้ตัวอย่างนี้เป็นบทเรียนคิดมือของ RRF (ตารางเจ็ดแถว ทั้ง k = 0 และ k = 60) เป็นชุดทดสอบของไลบรารี และกำหนดกติกาที่คลิปไม่ได้ระบุให้ชัดก่อนเขียนโค้ด: อันดับเริ่มที่ 1, ไม่อยู่ในรายการนับ 0, กติกาตัดสินเสมอแบบกำหนดแน่นอน, ความยาวรายการที่นำมารวม และน้ำหนักต่อรายการถ้าต้องการ (หัวข้อ 13)

ในตัวอย่างนี้ลำดับที่ k = 0 และ k = 60 เหมือนกันทุกตำแหน่ง (X = Y, Z, A, W = B, V) สิ่งที่เปลี่ยนคือระยะห่าง: X − Z หดจาก 0.967 เหลือ 0.00126 ค่า k จะพลิกลำดับได้เมื่อ chunk หนึ่งชนะอันดับ 1 ในรายการเดียว แต่อีก chunk อยู่กลาง ๆ ในหลายรายการ ดูตัวอย่าง P กับ Q ในหัวข้อ 13

9. สิ่งที่ควรจำ 5 ข้อ (~8:50–9:50)

  1. RRF ดัน chunk ที่ปรากฏในผลของหลายคำถามขึ้นมา ผู้สอนเรียกว่าผล consensus
  2. k = 0 แรงเกินไป เน้นอันดับต้นเกินจริงและให้ค่าอันดับล่างน้อยเกินไป
  3. k = 60 ให้ความสมดุล อันดับต้นยังสำคัญแต่ความต่างสมเหตุสมผลกว่า และสไลด์บอกว่าใช้กันแพร่หลายในโปรเจกต์ยอดนิยม
  4. RRF รักษาความหลากหลาย (diversity): chunk ที่มีเฉพาะในคำถามเดียวยังได้คะแนนและยังอยู่ในการจัดอันดับรวม
  5. เรียบง่ายแต่ได้ผล: แม้จะง่าย สไลด์บอกว่า RRF "often outperforms" วิธีรวมที่ซับซ้อนกว่า (ผลตรวจในตาราง: ยืนยันบางส่วน)
เสริมจากผู้จัดทำ: บทถอดเสียงช่วงนี้

บทถอดเสียงอัตโนมัติเขียนข้อ 3 เป็น "K equals0 provides balance" และ "K equals0 is widely used" ซึ่งขัดกับสไลด์ที่เขียน k=60 ชัดเจน รายงานนี้ยึดสไลด์

12. ฟังก์ชัน reciprocal_rank_fusion ทีละส่วน และปิดท้าย (~11:57–12:59)

ผู้สอนไล่โค้ด: วนผ่านทุกรายการ chunk ในผลของแต่ละคำถาม ใช้เนื้อหา chunk เป็นตัวระบุที่ไม่ซ้ำ ให้รหัสสั้น ๆ เก็บ object ของ chunk ไว้ คิดคะแนนตำแหน่งด้วยสูตร แล้วเรียงทุก chunk ตามคะแนน RRF

def reciprocal_rank_fusion(chunk_lists, k=60, verbose=True):
    rrf_scores = defaultdict(float)  # Will store: {chunk_content: rrf_score}
    all_unique_chunks = {}  # Will store: {chunk_content: actual_chunk_object}
    for query_idx, chunks in enumerate(chunk_lists, 1):
        for position, chunk in enumerate(chunks, 1):  # position is 1-indexed
            chunk_content = chunk.page_content   # Use chunk content as unique identifier
            all_unique_chunks[chunk_content] = chunk
            position_score = 1 / (k + position)  # Calculate position score: 1/(k + position)
            rrf_scores[chunk_content] += position_score
    sorted_chunks = sorted(
        [(all_unique_chunks[chunk_content], score) for chunk_content, score in rrf_scores.items()],
        key=lambda x: x[1],  # Sort by RRF score
        reverse=True  # Highest scores first
    )
    return sorted_chunks

Key Takeaways

1.RRF ให้คะแนน chunk ด้วย Σ 1/(k + อันดับ) ข้ามทุกรายการที่ chunk ปรากฏ รายการที่ไม่มี chunk นั้นนับ 0 และใช้แค่อันดับ ไม่ใช้คะแนน similarity
2.ตัวอย่างในคลิปคิดมือได้ทุกช่อง: k = 0 ได้ X = Y = 1.5, Z = 0.53 ส่วน k = 60 ได้ X = Y = 0.0325, Z = 0.0313 (ผู้จัดทำคำนวณซ้ำตรงทุกค่า)
3.ผู้สอนเลือก k = 60 เพราะ k = 0 ลงโทษอันดับ 2 ถึง 50% ทำให้ความต่าง similarity ราว 1% กลายเป็นคะแนนต่าง 2 เท่า
4.ในตัวอย่างนี้ k ไม่เปลี่ยนลำดับ แต่ทำให้ช่องว่างแคบลงมาก (X − Z: 0.967 → 0.00126) และคลิปไม่ได้บอกวิธีตัดสินคะแนนเสมอ (ผู้จัดทำ)
5.โค้ดจริงรวม 3 คำถาม × 5 = 15 chunk เหลือ 7 ใช้ page_content เป็นคีย์ตัดซ้ำ และอันดับเริ่มที่ 1 ตรงกับสูตร
