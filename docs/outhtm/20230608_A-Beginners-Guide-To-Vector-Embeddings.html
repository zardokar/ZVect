📋 บทสรุปย่อ

บทสรุปย่อ: คลิปปูพื้นสามเรื่องตามลำดับ: vector embedding คือการแปลงข้อความ ภาพ วิดีโอ ให้เป็นตัวเลขที่คอมพิวเตอร์เข้าใจ โดยของที่คล้ายกันจะอยู่ใกล้กัน, วิธีสร้าง (จาก feature engineering โดยผู้เชี่ยวชาญ ไปสู่โมเดลอย่าง Word2Vec, GloVe, BERT และ CNN อย่าง VGG, Inception), และ การเก็บและค้น ด้วย vector index / vector database (เช่น Pinecone, Weaviate) พร้อมตัวอย่างบอตถามตอบบนฐานความรู้ภายในบริษัท ปิดท้ายด้วยการใช้งาน: แนะนำสินค้า ค้นข้อความและภาพ แชตบอต และตรวจจับการโกง

โหมดของเนื้อหา: แปลแบบตีความ ครบทุกรายละเอียด (license มาตรฐานของ YouTube, ตรวจ 2026-10-10) ทุกประเด็นอยู่ครบตามลำดับ เรียบเรียงด้วยคำของผู้จัดทำโดยไม่เปลี่ยนความหมาย ชื่อเฉพาะจาก caption auto ตรวจกับภาพในคลิป ส่วนที่ผู้จัดทำเพิ่มเองอยู่ในส่วนที่ 7 และ 8

🧭 สรุปเชิงลึก

ทำไมต้องมี embedding: ผู้พูดเริ่มจากกระแส generative AI ปีนั้น และบอกว่าระบบ AI ใช้งานได้หลากหลายขึ้นอีกเมื่อดึงข้อมูลภายนอกเข้ามา ซึ่งเป็นจุดที่ vector store และ embedding เข้ามามีบทบาท อัลกอริทึม machine learning ทำงานกับตัวเลข และ vector embedding คือวิธีแปลงข้อความ ภาพ วิดีโอ ฯลฯ ให้เป็นตัวเลข: ส่งสิ่งของเข้า embedding model แล้วได้ เวกเตอร์ ออกมา ซึ่งให้มองเหมือนรายการพิกัด ผู้พูดชอบนึกถึงพิกัดในอวกาศ 3 มิติ ยิ่ง embedding อยู่ใกล้กัน ยิ่งคล้ายกัน และวัดความคล้ายด้วยระยะห่าง เช่น KNN (k-nearest neighbors) ใช้ทำระบบแนะนำ: ชอบรายการนี้ก็อาจชอบรายการที่ใกล้กัน

สร้างอย่างไร: แต่ก่อนใช้ feature engineering ที่ผู้เชี่ยวชาญในสาขากำหนดตัวเลขเองจากลักษณะ เช่น รูปร่าง สี บริเวณ ซึ่งจับความหมายได้แต่ขยายขนาดได้ไม่ดีนัก เพราะใช้แรงและเวลามาก ช่วงหลังจึงใช้โมเดลที่ฝึกมาเพื่อสร้าง embedding: ข้อความใช้ Word2Vec, GloVe, BERT (แปลงคำ ประโยค ย่อหน้า) ภาพใช้ CNN เช่น VGG และ Inception และขยายไปถึงเสียงได้

เห็นเป็นภาพ: เดโม Colorful Vectors วางชื่อสีลงในพื้นที่ 3 มิติตามค่า R, G, B สีที่ใกล้กันอยู่เป็นกลุ่ม เช่น Payne's gray กับ cadet อยู่ติดกันมาก light slate gray อยู่ห่างออกไปหน่อย และเมื่อซูมออกจะเห็นกลุ่มเรียงกัน: เหลือง น้ำเงิน แดงกับ magenta ม่วง เขียว

เก็บและค้น: embedding ที่โมเดลสร้างต้องเก็บไว้ให้ค้นได้ จึงมี vector index และ vector database ที่ค้นข้อมูลได้เร็วผ่านการ query vector database อย่าง Pinecone และ Weaviate ออกแบบมาเพื่อข้อมูลแบบนี้โดยเฉพาะ ให้ performance, scalability และ flexibility ตัวอย่างบอตถามตอบ: สร้าง embedding ของความรู้ทั้งหมดในบริษัทไว้ก่อน ผู้ใช้ถาม "how do I open a support ticket?" ระบบใช้ โมเดลเดียวกัน สร้าง embedding ของคำถาม แล้วให้ฐานข้อมูลหา embedding ที่ใกล้ (เรื่อง support) ส่งกลับ ส่วนต่างของ index กับ database ที่ผู้พูดสรุปคือ database รองรับ create/read/update/delete และเชื่อมกับแหล่งข้อมูลอื่น BI และ ETL ได้ดีกว่า

ใช้ทำอะไร: ระบบแนะนำ, ค้นข้อความ, ค้นภาพ (เช่น หาหนังที่โทนสีคล้ายหนังของ Wes Anderson), ค้นสินค้า, แชตบอตและระบบตอบคำถาม (ลดเวลาแก้ case โดยค้น case เก่าที่ใกล้กัน) และตรวจจับการโกง: ธุรกรรมปกติอยู่เป็นกลุ่ม จุดที่อยู่ห่างกลุ่มคือสิ่งที่น่าสงสัย ผู้พูดปิดว่าสาขานี้ยังค่อนข้างอยู่ในช่วงต้นและเปลี่ยนเร็ว

ตรวจทาน (เสริมจากผู้จัดทำ): ไม่พบข้อผิดใหญ่ มีสามจุดที่ควรเข้าใจให้ตรง: (1) embedding จริงมีหลายร้อยถึงหลายพันมิติ ภาพ 2–3 มิติเป็นการเปรียบเทียบ (2) ตัวเลขใน embedding คือคุณลักษณะที่โมเดลเรียนมา ส่วน metadata มักเก็บแยกไว้คู่กันในฐานข้อมูล (3) เดโมสีใช้ค่า RGB ที่กำหนดตรง ๆ จึงใกล้กับ feature engineering มากกว่า embedding ที่โมเดลเรียนเอง

1. vector embedding คืออะไร: ตัวเลขที่ใกล้กันแปลว่าคล้ายกัน

~0:00–1:54 (บท "Introduction to Vector Embeddings")

ผู้พูดบอกว่าอยากทำคลิปสั้น ๆ แนะนำแนวคิด vector embedding ซึ่งน่าสนใจและเรียบง่ายมากเมื่อแยกออกมาดูทีละส่วน และว่าเว้นแต่จะอยู่บนเกาะห่างไกล ปีนี้คงได้ยินเรื่อง generative AI มาเยอะ ระบบ AI เหล่านี้ทรงพลังอยู่แล้ว แต่ จะใช้งานได้หลากหลายขึ้นอีกเมื่อนำข้อมูลภายนอกเข้ามาร่วม และนั่นคือจุดที่ vector store กับ embedding เข้ามามีบทบาท

embedding คือการแปลงสิ่งของเป็นตัวเลข

อัลกอริทึม machine learning ทำงานกับตัวเลข และแก่นของ vector embedding คือวิธีแปลงสิ่งต่าง ๆ เช่น ข้อความ ภาพ วิดีโอ ให้เป็นตัวเลขที่คอมพิวเตอร์เข้าใจได้ ในแผนภาพที่ผู้พูดเปิด สิ่งของ (object) วิ่งเข้า embedding model ซึ่งเป็นตัวแปลงสิ่งของเป็น embedding แล้วออกมาเป็น vector embedding ที่ให้มองเหมือน รายการพิกัด

ใกล้กัน = คล้ายกัน

ขยายจากเรื่องพิกัด ผู้พูดชอบคิดว่า vector embedding คือพิกัดในพื้นที่ 3 มิติ โดย ยิ่ง embedding อยู่ใกล้กันเท่าไร ยิ่งคล้ายกันเท่านั้น เขาเปิดตัวอย่างแบบ 2 มิติก่อน (บอกว่าจะไปดูแบบ 3 มิติในอีกสักครู่): ประโยค "a sad boy is walking", "a little boy is walking" และ "a little boy is running" อยู่ใกล้กันพอสมควร เวลาวัดระยะห่างของเวกเตอร์ด้วยวิธีอย่าง KNN (k-nearest neighbors) นั่นคือการวัดความคล้าย

ตัวอย่างการใช้ที่เห็นชัด: ระบบแนะนำ

การใช้งานที่ชัดเจนคือ recommendation engine: ถ้าชอบรายการนี้ ก็อาจชอบอีกรายการที่ใกล้เคียงกัน หรือในการแนะนำสินค้า ถ้าชอบสินค้านี้ก็อาจชอบสินค้านั้นด้วย หรือ podcast นี้คู่กับ podcast นั้น เป็นต้น

2. สร้าง embedding อย่างไร

~1:54–3:00 (บท "How Vector Embeddings are Created")

ผู้พูดบอกว่ามีอยู่สองสามวิธีในการสร้าง vector embedding

วิธีเดิม: feature engineering

ในอดีตวิธีหนึ่งคือ feature engineering: ผู้เชี่ยวชาญในสาขานั้นจะวัดลักษณะต่าง ๆ ของสิ่งของออกมาเป็นตัวเลข เช่น รูปร่าง สี บริเวณ ฯลฯ ซึ่งจับความหมาย (semantics) ของสิ่งของนั้นได้ แต่เป็นกระบวนการที่ขยายขนาดไม่ได้จริง เพราะใช้แรงงานมากและกินเวลามาก

วิธีใหม่: โมเดลที่ฝึกมาเพื่อสร้าง embedding

ในช่วงหลังมีความก้าวหน้าของโมเดล machine learning ที่เชี่ยวชาญการสร้าง vector embedding เราฝึกโมเดลเหล่านี้ให้แปลงสิ่งของหลายประเภท ไม่ว่าจะเป็นข้อความ ภาพ หรืออย่างอื่น ให้เป็น vector embedding ตัวอย่างที่เปิดให้ดู:

  • ข้อความ: Word2Vec, GloVe และ BERT แปลงคำ ประโยค และย่อหน้าให้เป็น vector embedding
  • ภาพ: convolutional neural network (CNN) เช่นโมเดล VGG และ Inception รับภาพแล้วแปลงเป็น embedding
  • และขยายแนวคิดนี้ไปถึง เสียง และอื่น ๆ ได้

ภาพในช่วงนี้เป็นย่อหน้าของบทความ Pinecone ทั้งหน้า จึงไม่ได้นำภาพมาใส่ เนื้อหาที่ผู้พูดอ่านอยู่ครบในรายการข้างบน

3. เห็นเป็นภาพ: เดโมสีในพื้นที่ RGB

~3:00–4:27 (บท "Vector Embeddings Visualized")

ผู้พูดกลับมาที่เรื่องเวกเตอร์และการแทนในพื้นที่ 3 มิติ ด้วยเดโม Colorful Vectors (Hugging Face) ที่ใช้ สีแดง เขียว น้ำเงิน (RGB) เป็นพิกัด ให้มอง RGB เป็นจุดพิกัดที่ใช้วางของลงในพื้นที่ เช่น สี blue มีพิกัดเป็นค่า RGB ของมัน และ Han purple (caption auto เขียนว่า "hand purple") ก็มีพิกัด RGB เหมือนกัน

เมื่อซูมเข้าไปจะเจอกลุ่มของที่อยู่ใกล้กัน ถ้าดูจุดที่ชิดกัน เช่น Payne's gray กับ cadet (กล่องที่เด้งขึ้นแสดงสีด้วย) สองสีนี้ใกล้เคียงกันมาก และผู้พูดบอกว่าเป็นอย่างที่คาดไว้ เพราะอยู่ชิดกันมากใน embedding นี้ ถ้าขยับออกมาอีกหน่อยจะเจอ light slate gray (caption auto เขียนว่า "light slight gray")

เมื่อซูมออกจะเห็นว่ากลุ่มเรียงกันเป็นระเบียบ: สีเหลือง อยู่ราว ๆ มุมขวาล่าง แล้วมี สีน้ำเงิน, สีแดงกับ magenta, สีม่วง และ สีเขียว ผู้พูดสรุปว่านี่เป็นวิธีที่ดีในการนึกภาพ vector embedding

4. การเก็บ: vector index, vector database และบอตถามตอบ

~4:14–6:30 (บท "Vector Databases")

เมื่อมีแนวคิดว่า vector embedding คืออะไรแล้ว ผู้พูดอยากพูดเรื่อง การเก็บ และ กรณีใช้งาน

ทำไมต้องมีที่เก็บ

เมื่อมีเวกเตอร์ (ซึ่งย้ำว่าให้มองเป็นพิกัด) ก็ต้องมีวิธีเก็บ ผู้พูดบอกว่า embedding ที่ AI model สร้างขึ้น "มี metadata จำนวนมากเกี่ยวกับคุณลักษณะหรือ feature บางอย่างของสิ่งของ" จึงต้องเก็บไว้ในแบบที่ค้นหาผ่านได้ ตรงนี้จึงมี vector index และ vector database ซึ่งเหมือน index และ database ทั่วไป คือให้หาข้อมูลที่ต้องการได้เร็วและง่าย โดยทั่วไปผ่านความสามารถในการ query

vector database

vector database อย่าง Pinecone และ Weaviate ช่วยเพิ่มประสิทธิภาพของฟังก์ชันที่หลายธุรกิจต้องใช้ในการทำงานกับระบบแบบนี้ และถูกออกแบบมาโดยตั้งใจให้รองรับข้อมูล embedding แบบนี้โดยเฉพาะ เพื่อให้ได้ performance, scalability และ flexibility

ตัวอย่าง: บอตถามตอบบนฐานความรู้ภายในบริษัท

ผู้พูดเปิดตัวอย่างว่าคนอาจใช้ระบบเวกเตอร์อย่างไร: มีแอปพลิเคชันที่ผู้ใช้เข้ามาถาม อาจเป็นบอตถามตอบที่ค้นในฐานความรู้ส่วนตัวของบริษัท ลำดับคือ

  1. สร้าง vector embedding ของข้อมูลความรู้ทั้งหมดของบริษัทไว้ก่อน
  2. ผู้ใช้พิมพ์ query เข้ามา เช่น "how do I open a support ticket?"
  3. ใช้ embedding model ตัวเดียวกัน สร้าง embedding ของ query นั้น
  4. ใช้ vector database ค้นหา vector embedding ที่คล้ายกัน ระบบจะเจอสิ่งที่ใกล้เคียงกันมาก ในตัวอย่างนี้คือ embedding ที่เกี่ยวกับ support หรือวิธีขอ support
  5. ส่งผลเหล่านั้นกลับไป

5. ความต่างของ index กับ database

~6:30–6:55

ผู้พูดบอกว่าระหว่าง index กับ vector database มีความต่างอยู่บ้าง แต่จะไม่ลงลึก สรุปแค่ว่า database ให้ทางออกที่แข็งแรงกว่ามาก สำหรับเรื่องต่อไปนี้:

  • การ create, read, update และ delete ข้อมูล
  • การ เชื่อมต่อกับแหล่งข้อมูลอื่น หลายแบบ
  • การทำงานร่วมกับเครื่องมือประเภท business intelligence และ ETL และอื่น ๆ ทำนองนี้

ภาพบนจอช่วงนี้เป็นรายการข้อดีของ vector database จากบทความ Pinecone (เช่น การจัดการข้อมูล การเก็บ metadata และการกรอง การขยายขนาด การอัปเดตแบบ real-time การสำรองข้อมูล และการเชื่อมกับระบบอื่น) ผู้พูดไม่ได้อ่านรายการนั้นทีละข้อ รายงานนี้จึงบันทึกเฉพาะสิ่งที่ผู้พูดพูด และระบุสิ่งที่อยู่บนจอแยกไว้ตรงนี้

6. ใช้ทำอะไรได้บ้าง

~6:55–8:29 (บท "Example Use Cases")

สุดท้าย vector embedding ใช้ทำอะไรได้จริง ผู้พูดไล่ไว้ดังนี้

  • ระบบแนะนำ (recommendation): อย่างที่พูดไปแล้ว ถ้าชอบสิ่งหนึ่งก็อาจชอบอีกสิ่งที่ใกล้เคียงกัน
  • การค้นหา (search):
    • ค้นข้อความ ซึ่งผู้พูดบอกว่าเป็นการหาแบบ keyword และความเกี่ยวข้อง (relevance)
    • ค้นภาพ ที่ผู้พูดว่าเจ๋งมาก เพราะใส่ภาพเข้าไปแล้วหาสิ่งที่ใกล้เคียงกันมากได้ และเมื่อเทคโนโลยีพัฒนาไป อาจนึกถึงหนังได้ด้วย เช่น "ชอบหนังของ Wes Anderson เรื่องนี้ โดยเฉพาะโทนสี หาหนังอื่นที่ใกล้เคียงให้หน่อย"
    • สินค้าและการค้นสินค้า ก็ทำแบบนี้ได้เช่นกัน
  • แชตบอตและระบบตอบคำถาม: เช่น ระบบจัดการ case ที่ลด mean time to resolution ของ support case ได้ด้วยการค้นใน vector store หา case เก่าที่ใกล้เคียงกับ case ปัจจุบัน
  • ตรวจจับการโกง (fraud detection) ที่ผู้พูดบอกว่าเจ๋งมาก: กลับไปที่ภาพกลุ่มจุด สมมติมีกลุ่มที่การจ่ายเงินทั้งหมดควรอยู่ เรารู้ว่าการจ่ายเงินทั้งหมดใกล้เคียงกันมาก และควรอยู่ในกลุ่มนี้ กรณีนี้เรามองหา outlier: ถ้าจุดไหนอยู่ห่างออกไปจาก embedding อื่นของเรา ก็อาจเป็นการโกง

ผู้พูดปิดว่ายังมีอีกหลายอย่างที่ทำได้ สาขานี้ยังค่อนข้างอยู่ในช่วงต้นและเปลี่ยนแปลงเร็ว แล้วขอบคุณผู้ชม

7. ตรวจทานและข้อมูลเสริม (จากผู้จัดทำ)

เสริมจากผู้จัดทำ ทั้งส่วนนี้ไม่ได้อยู่ในคลิป

ข้อความในคลิปที่ควรเข้าใจให้ตรง

ในคลิปข้อสังเกต
นึกถึง embedding เป็นพิกัดในพื้นที่ 3 มิติ (~0:58)ผู้พูดใช้เป็นวิธีคิด embedding จริงมักมีหลายร้อยถึงหลายพันมิติ ภาพ 2–3 มิติเป็นการเปรียบเทียบ (เรื่องมิติสูงดูบท 8 ของ ZVect)
embedding "มี metadata จำนวนมาก" (~4:39)ตัวเลขใน embedding คือคุณลักษณะที่โมเดลเรียนมา ส่วน metadata (เช่น ชื่อเอกสาร วันที่) มักเก็บแยกไว้คู่กับเวกเตอร์ในฐานข้อมูล ซึ่งตรงกับรายการ "metadata storage and filtering" ที่อยู่บนจอ
ค้นข้อความแบบ keyword และ relevance (~7:08)การค้นด้วย embedding หาความหมายที่ใกล้ แม้ไม่มีคำตรงกัน ส่วนการค้นแบบ keyword เทียบคำตรงตัว ระบบจริงหลายระบบใช้ทั้งสองแบบร่วมกัน
เดโมสีในพื้นที่ RGB (~3:01)ตำแหน่งของสีคือค่า R, G, B ที่กำหนดตรง ๆ ไม่ได้มาจากโมเดลที่เรียนเอง จึงคล้าย feature engineering มากกว่า แต่ยังเป็นภาพที่ดีของแนวคิด "ใกล้ = คล้าย"

ลองคำนวณด้วยค่าสีที่อยู่บนจอ (lib ของ ZVect)

Key Takeaways

  1. embedding คือการแปลงสิ่งของ (ข้อความ ภาพ วิดีโอ) เป็นรายการตัวเลข ด้วย embedding model
  2. ยิ่งใกล้กันยิ่งคล้ายกัน และวัดความคล้ายด้วยระยะห่าง เช่น KNN
  3. feature engineering ด้วยมือขยายขนาดได้ไม่ดีนัก ช่วงหลังมีโมเดลอย่าง Word2Vec, GloVe, BERT และ CNN มาช่วย
  4. ต้องเก็บ embedding ไว้ให้ค้นได้ ด้วย vector index หรือ vector database (Pinecone, Weaviate)
  5. ในตัวอย่างบอตถามตอบ คำถามผ่านโมเดลเดียวกับที่ใช้กับเอกสาร แล้วจึงหา embedding ที่ใกล้ส่งกลับ
