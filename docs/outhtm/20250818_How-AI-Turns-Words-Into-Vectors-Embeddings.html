1. คอมพิวเตอร์รู้ความหมายของคำได้อย่างไร

~0:00–0:33

สวัสดีและยินดีต้อนรับสู่ Blackboard AI วันนี้เราจะไขความลับของแนวคิดพื้นฐานที่สุดเรื่องหนึ่งในปัญญาประดิษฐ์สมัยใหม่ นั่นคือ vector embedding

คอมพิวเตอร์ซึ่งเข้าใจได้แค่ตัวเลข เรียนรู้ความหมายของคำอย่าง king ได้อย่างไร มันรู้ได้อย่างไรว่า king เกี่ยวข้องกับ queen มากกว่า apple

คำตอบอยู่ที่เทคนิคอันชาญฉลาด คือ การแปลงคำเป็นลิสต์ตัวเลขพิเศษที่เรียกว่า vector แต่คำแต่ละคำได้ vector ประจำตัวมาอย่างไรกันแน่ มาวาดให้ดูกัน

ผู้จัดทำคำนวณจากตัวเลขในภาพ: cosine(king, queen) = 0.996, cosine(king, apple) = −0.446, ระยะ king ถึง queen = 0.105 แต่ king ถึง apple = 1.688 ตัวเลขชุดนี้จึงแสดงสิ่งที่คลิปพูดได้ตรง: king ใกล้ queen มากกว่า apple มาก

2. ปัญหาของ one-hot encoding

~0:33–1:21

ก่อนจะดูวิธีสมัยใหม่ มาเข้าใจปัญหาก่อน วิธีที่ง่ายที่สุดในการแทนคำด้วยตัวเลขคือเทคนิคที่เรียกว่า one-hot encoding

ลองนึกว่าพจนานุกรมทั้งหมดของเรามีแค่ 4 คำ เราให้แต่ละคำมี index ไม่ซ้ำกัน

ถ้าจะแทนคำว่า cat เราสร้าง vector ที่ยาวเท่าขนาดคำศัพท์ ในที่นี้คือ 4 ในทำนองเดียวกัน vector ของ dog จะมีเลข 1 อยู่ตำแหน่งที่สี่

แต่วิธีนี้มีปัญหาใหญ่สองข้อ

  1. เปลืองมาก คำศัพท์จริงมี 50,000 คำหรือมากกว่า vector ของทุกคำจึงยาว 50,000 ช่อง
  2. ไม่มีความหมาย ข้อนี้สำคัญกว่า vector เหล่านี้ไม่บอกอะไรเลยเรื่องความหมาย เพราะทุกคำต่างกันเท่า ๆ กันหมด
ข้อสังเกต: ตาราง Vocabulary Mapping ในคลิปใช้คำ King, Queen, Man, Woman แต่ตัวอย่าง one-hot ถัดมาใช้ cat กับ dog ซึ่งไม่อยู่ในตาราง เป็นตัวอย่างคนละชุดกัน แนวคิดยังถูกต้อง

3. Embedding matrix: ตาราง lookup

~1:21–2:03

นี่พาเรามาถึงหัวใจของการทำงานของโมเดลสมัยใหม่ คือสิ่งที่เรียกว่า embedding matrix

ขั้นแรก เรากำหนดขนาดคำศัพท์ และ embedding dimension ที่เล็กกว่ามาก เช่น 300 ตาราง lookup ของเราจึงมี 50,000 แถว แถวละหนึ่งคำ และ 300 คอลัมน์

ตอนเริ่ม train โมเดล เราเติมตารางขนาดใหญ่นี้ด้วยตัวเลขสุ่มค่าเล็ก ๆ

แล้ว token ได้ vector ของมันมาอย่างไร ง่ายจนน่าแปลกใจ มันก็แค่การ lookup โมเดลหา ID ของคำ ไปที่ matrix แล้วหยิบทั้งแถวที่ตรงกันออกมา

โอเค เรากำลังหยิบแถวของตัวเลขสุ่มอยู่ แล้วมันจะช่วยให้เข้าใจความหมายได้อย่างไร

4. ทำให้ vector ฉลาดขึ้นด้วยการ train

~2:03–2:42

กุญแจคือตัวเลขเหล่านี้ไม่ได้สุ่มตลอดไป มันถูกเรียนรู้ผ่านการ train

สมมติว่าจากตัวเลขสุ่ม โมเดลทายว่าคำถัดไปคือ "shoe" ซึ่งผิด (คำที่ถูกในภาพคือ crown) โมเดลคำนวณความผิดพลาด (error) แล้วย้อนกลับไปปรับตัวเลขใน vector ของ queen ทีละนิด

ทีนี้ทำซ้ำแบบนี้หลายล้านครั้ง กับข้อความปริมาณมหาศาลจากอินเทอร์เน็ต

คำที่ปรากฏในบริบทคล้ายกัน เช่น king กับ queen จะถูกดัน vector ไปในทิศทางคล้ายกัน ในที่สุด vector ของคำที่เกี่ยวข้องกันจะอยู่ใกล้กัน ตัวเลขจึงเต็มไปด้วยความหมาย

คำว่า "shoe" มาจาก transcript อัตโนมัติที่เขียนว่า "shu" ผู้จัดทำตีความว่าเป็น shoe ไม่ได้ยืนยันจากภาพ ส่วนคำที่ถูก (crown) อ่านจากภาพโดยตรง

5. สรุป: จาก token ไปเป็น vector

~2:42–3:32

มาสรุปสั้น ๆ ว่า embedding model กำหนด vector ให้ token อย่างไร

  1. ทุกคำได้ ID ไม่ซ้ำกัน และสร้าง embedding matrix ขนาดใหญ่ที่เต็มไปด้วยตัวเลขสุ่ม
  2. การกำหนด vector คือการ lookup ธรรมดา โมเดลเอา ID ของคำไปดึงแถวที่ตรงกันจาก matrix
  3. ผ่านการ train โมเดลปรับตัวเลขไปเรื่อย ๆ ทำให้ vector ของคำที่คล้ายกันอยู่ใกล้กันในทางคณิตศาสตร์
แค่นั้นเอง มันคือตาราง lookup ที่เริ่มจากค่าสุ่ม แล้วฉลาดขึ้นด้วยประสบการณ์

6. ตรวจทานและข้อมูลเสริม (จากผู้จัดทำ)

ส่วนนี้ไม่ได้อยู่ในคลิป ตัวเลขคำนวณด้วย Python เมื่อ 2026-10-10

6.1 ทำไม one-hot "ไม่มีความหมาย" ในเชิงตัวเลข

one-hot ของสองคำที่ต่างกันมี dot product = 0 เสมอ จึงได้ cosine = 0 และระยะ = √2 ≈ 1.414 ทุกคู่ ไม่ว่าจะเป็น cat กับ kitten หรือ cat กับ rocket ไม่มีทางบอกได้ว่าคู่ไหนใกล้กว่า

6.2 lookup คือการคูณ matrix แบบทางลัด

ถ้าเอา one-hot ของคำที่ ID = 2 ไปคูณกับ embedding matrix จะได้แถวที่ 2 พอดี (ทดสอบด้วย matrix ขนาด 4 × 2 ได้ [0.5, 0.6] เท่ากับแถวที่ 2) ระบบจริงจึงข้ามการคูณแล้วหยิบแถวตรง ๆ

6.3 ตัวเลขในภาพ Model Feedback เห็นแค่ 3 มิติแรก

ภาพ ~2:18 แสดง king [0.91, −0.15, 0.42, …], queen [0.83, 0.74, 0.51, …], man [0.88, −0.21, −0.35, …], woman [0.79, 0.68, −0.41, …] ถ้าคิด cosine จากแค่ 3 ตัวแรกได้ราว 0.64–0.70 ทุกคู่ แยกความหมายไม่ออก เพราะเป็นแค่ส่วนเล็ก ๆ ของ vector ไม่ใช่ข้อผิดพลาดของคลิป

6.4 สิ่งที่คลิปทำให้ง่ายลง

  • โมเดลภาษาสมัยใหม่ไม่ได้ตัดเป็น "คำ" แต่ตัดเป็น token ซึ่งมักเป็นชิ้นส่วนของคำ (subword) หลักการ lookup ยังเหมือนเดิม
  • การ "ทายคำถัดไป" เป็นหนึ่งในหลายวิธี train embedding งานบางแบบให้ทายคำรอบ ๆ แทน แต่ผลลัพธ์เหมือนกัน คือคำที่อยู่ในบริบทคล้ายกันจะได้ vector คล้ายกัน
  • คลิปพูดถึงการปรับเฉพาะแถวของ queen ในการ train จริง ส่วนอื่นของโมเดลก็ถูกปรับไปพร้อมกัน

Key Takeaways

1
one-hot ใช้ไม่ได้ในงานจริง เพราะยาวเท่าจำนวนคำศัพท์ และทุกคำห่างกันเท่ากันจนไม่บอกความหมาย
2

3
ตัวเลขในตารางเริ่มจากค่าสุ่ม และมีความหมายขึ้นมาเพราะการ train ที่ปรับตัวเลขตาม error ซ้ำหลายล้านครั้ง
4
คำที่อยู่ในบริบทคล้ายกันจะได้ vector คล้ายกัน ความหมายจึงกลายเป็น "ความใกล้" ใน vector space
