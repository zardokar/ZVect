📋 บทสรุปย่อ

บทสรุปย่อ: คลิปนี้เป็นตอนต่อจาก tokenization ในซีรีส์สร้าง LLM เอง ผู้สอนชี้ว่าเลข token ไม่มีความหมายของคำ แล้วสร้าง vector embedding ด้วยการให้ "น้ำหนัก" กับคุณลักษณะหลายมิติ (เป็นสัตว์ไหม เป็นสัตว์เลี้ยงไหม กินได้ไหม) โดยคำที่น้ำหนักต่างกันน้อยคือคำที่คล้ายกัน เล่าขนาดของ GPT-1 ถึง GPT-3 (768 ถึง 12,288 มิติ) และวิธีหาน้ำหนัก (เริ่มสุ่ม → ทำนาย → วัด error → ปรับ) แล้วทดลองกับ Word2Vec ของ Google (3 ล้านคำ 300 มิติ): yen − Japan + India ได้ rupee, ชื่อที่ไม่มีในคลังคำทำให้ error, และ king กับ queen คล้ายกัน 0.65 (65%) มากกว่า king กับ man 0.229 (ผู้สอนพูดว่าราว 22%)

โหมดของเนื้อหา: แปลแบบตีความ ครบทุกรายละเอียด (license มาตรฐานของ YouTube, ตรวจ 2026-10-10) ทุกประเด็นอยู่ครบตามลำดับ เรียบเรียงด้วยคำของผู้จัดทำโดยไม่เปลี่ยนความหมาย ตัวเลขบนสไลด์และใน notebook ระบุว่าเป็น "บนจอ" ส่วนที่ผู้จัดทำเพิ่มเองอยู่ในส่วนที่ 8 และ 9

🧭 สรุปเชิงลึก

ปัญหาของเลข token: ตอนก่อนแปลง token เป็นตัวเลขแล้ว (เพราะเครื่องเข้าใจแค่ตัวเลข) แต่ตัวเลขไม่ได้พกความหมาย ในตัวอย่าง "cat is a pet, lion is a pet?, dog is a pet" ผู้สอนพูดเลขเช่น cat 23, a 1, lion 50, dog 150 ซึ่งไม่ได้บอกเลยว่า cat ใกล้ pet หรือ dog ใกล้ pet และ lion ไม่ใช่สัตว์เลี้ยง ความหมายและบริบทของคำหายไป (บริบทของประโยคเรียกว่า contextual embedding ซึ่งพูดทีหลัง)

ใช้คุณลักษณะหลายมิติ: วิธีง่ายสุดคือเขียนคุณลักษณะของคำ เช่น เป็นสัตว์ไหม เป็นคนไหม เป็นสัตว์เลี้ยงไหม เป็นสีไหม กินได้ไหม มีสี่ขาไหม และเขียนได้ไม่จำกัด แต่ตอบแค่ใช่/ไม่ใช่ไม่พอ: lion เป็นสัตว์เลี้ยงไหม (ผู้สอนยก Dubai ว่ามีคนเลี้ยง แต่น้อยมาก) และ "กินได้" ขึ้นกับว่าถามจากมุมของใคร จึงใช้ น้ำหนัก แทน เช่น เป็นสัตว์: cat, lion, dog 0.90; เป็นสัตว์เลี้ยง: dog 0.99, cat 0.89, lion ต่ำลง; กินได้: sandwich สูงสุด, blue ต่ำมาก คำที่น้ำหนักต่างกันน้อยในทุกมิติคือคำที่คล้ายกัน และนี่คือ vector embedding (word ไม่เท่ากับ token ตามที่เรียนเรื่อง byte pair encoding)

ขนาดในโมเดลจริง: GPT-1 คลังคำราว 40,000 และ 768 มิติ, GPT-2 คลังคำ 50,257 และ 768 ถึง 1,600 มิติ, GPT-3 คลังคำเท่าเดิมแต่ 12,288 มิติต่อ token วิธีหาน้ำหนัก: เริ่มสุ่ม ทำนาย วัด error หา loss/gradient ปรับน้ำหนัก ทำซ้ำจนได้ค่าดีที่สุด ใน GPT น้ำหนักเหล่านี้ถูกปรับระหว่าง pre-training ลำดับคือ tokenization → vector embedding → positional embedding → contextual embedding → self-attention และจะใช้ embedding ที่ฝึกไว้แล้วก่อนเข้า self-attention ก็ได้

ทดลองกับ Word2Vec: library ของ Google ขนาด 3 ล้านคำ (ผู้สอนบอกว่าคือ 30 lakh) 300 มิติ ดูเวกเตอร์ 300 ค่าของ cat และ dog ได้และใช้ฝึก LLM ได้ yen − Japan + India ได้ rupee ที่ 61.9% ตามด้วย Rupee, Rupees, Indian Rupee แล้วผู้สอนบอกว่าเริ่ม "hallucinate" แต่ใช้ไม่ได้ทุกครั้ง: Bill Gates ไม่มีในคลังคำจึง error ดังนั้นต้องสร้าง embedding ของตัวเองตามข้อมูลที่ใช้ฝึก (เช่น ข้อมูลการเงิน) ความคล้าย king กับ queen 65% สูงกว่า king กับ man 22% ผู้สอนปิดว่า 300 มิติอาจไม่พอ (อาจต้องหลักหมื่น มิติยิ่งสูงยิ่งดีแต่มีข้อแม้) และถ้าจะปรับ LLM ของตัวเองต้องพัฒนา embedding เอง

ตรวจทาน (เสริมจากผู้จัดทำ): ตัวเลข GPT และ Word2Vec ตรงกับที่ทราบกันทั่วไป และตรงกับ notebook บนจอ (0.6192, 0.6511, 0.2294) ข้อที่ควรเข้าใจให้ตรง: มิติในโมเดลจริงไม่ได้มีคนเขียนเป็นคำถามแบบ "เป็นสัตว์เลี้ยงไหม" แต่เป็นค่าที่เรียนมาและมักตีความตรง ๆ ไม่ได้ ตารางคุณลักษณะในคลิปเป็นตัวอย่างเพื่อให้เข้าใจ และ "65%" คือค่า cosine similarity 0.65 ไม่ใช่ความน่าจะเป็น

1. เลข token ไม่พกความหมาย

~0:00–1:58

ผู้สอนต้อนรับเข้าสู่ซีรีส์สร้าง LLM เอง และบอกว่าวันนี้ว่าด้วย vector embedding ตอนก่อนพูดเรื่อง tokenization ซึ่งสำคัญมาก เพราะอัลกอริทึมหรือเครื่องเข้าใจแค่ตัวเลข เราจึงเอา token มาแปลงเป็นตัวเลข แต่คำถามคือ ตัวเลขนั้นพกความหมายของคำไปด้วยไหม หรือเป็นแค่การแปลงคำเป็นตัวเลข

ตัวอย่าง: ถ้าพูดว่า cat เป็นสัตว์เลี้ยง lion เป็นสัตว์เลี้ยงไหมเป็นคำถาม แต่ dog เป็นสัตว์เลี้ยง เมื่อแปลงเป็น token ID ก็ได้ตัวเลขชุดหนึ่ง (บนสไลด์คือ 23, 1, 120, 50, 1, 120) และการจับคู่ token กับ ID คือ vocabulary แต่ใช้ตัวเลขพวกนี้บอกความหมายให้อัลกอริทึม neural network attention mechanism หรือโค้ด Python ได้ไหม และมันจะทำงานได้ถูกไหม

ผู้สอนชี้ว่า เมื่อบอกว่า cat คือ 23, a คือ 1, lion คือ 50 และ dog คือ 150 ตัวเลขเหล่านี้ไม่ได้บอกว่า cat ใกล้กับ pet หรือ pet ใกล้กับ dog และ lion ไม่ใกล้ pet หรือเป็นสัตว์ เราไม่ได้จับข้อมูลอะไรเกี่ยวกับความหมายของคำเลย ความหมายหายไป เราแปลงคำเป็นตัวเลขได้แล้ว แต่ความหมายและบริบทของคำล่ะ (ผู้สอนย้ำว่าหมายถึงบริบทของ คำ ไม่ใช่ของประโยค ซึ่งคือ contextual embedding ที่จะพูดทีหลัง)

2. ให้คำมีคุณลักษณะหลายมิติ และปัญหาของใช่/ไม่ใช่

~1:58–3:44

วิธีที่ง่ายที่สุดคือ ให้แต่ละคำมี feature หรือคุณลักษณะต่าง ๆ ตัวอย่างคำ: cat, lion, dog, blue, sandwich และอยากรู้ว่าจะจับความหมายหรือความใกล้ของคำได้อย่างไร เช่น cat ใกล้ dog มากกว่าใกล้ lion

ทำได้ด้วยการเขียนคุณลักษณะทั้งหมดที่คำหนึ่งมีได้ โดยตั้งคำถาม เช่น เป็นสัตว์ไหม เป็นคนไหม เป็นสัตว์เลี้ยงไหม เป็นสีไหม กินได้ไหม มีสี่ขาไหม มีสองขาไหม มีขาเดียวไหม และเขียนต่อได้เรื่อย ๆ ไม่ว่าจะเรียกว่าคุณลักษณะ feature หรือ มิติ (dimension) ผู้สอนบอกว่าแบ่งคำทั้งหมดในจักรวาลออกเป็นมิติต่าง ๆ ได้ไม่จำกัด ตอนนี้เขียนไว้บางมิติ: cat เป็นสัตว์ไหม ใช่ lion ใช่ dog ใช่ blue ไม่ใช่ sandwich ไม่ใช่ ไปเรื่อย ๆ

ใช่/ไม่ใช่ไม่พอ

  • สัตว์เลี้ยง: ช่องของ lion ถูกติ๊กไว้ แต่น่าจะเป็นกากบาท แล้วถ้าเป็นที่ Dubai ล่ะ โอกาสที่ lion ถูกเลี้ยงเป็นสัตว์เลี้ยงน้อยมาก แต่ก็มีคนเลี้ยงอยู่บ้าง จะตอบใช่หรือไม่ใช่ ถูกหรือผิด 1 หรือ 0 ผู้สอนตั้งคำถามว่าทุกอย่างเป็นขาวกับดำแบบนี้หรือ และตอบว่าไม่
  • กินได้: cat, lion, dog กินได้ไหม ถามจากมุมของใคร ถ้าถามจากมุมของ lion ว่า cat หรือ dog กินได้ไหม คำตอบก็ต่างไป

3. ใช้น้ำหนัก: นี่คือ vector embedding และสิ่งที่ต้องสร้าง

~3:44–6:12

ผู้สอนจึงเสนอให้ใช้ น้ำหนัก (weights) แทน: โอกาสที่ cat ถูกมองว่าเป็นสัตว์สูงที่สุด ให้น้ำหนัก 90 lion ก็เป็นสัตว์ ให้ 90 dog ให้ 90 ส่วน blue เป็นสัตว์ไม่ได้ ให้น้ำหนักน้อยมาก

  • สัตว์เลี้ยง: dog สูงมาก 99, cat ก็สูง 89, lion ลดลงเป็นราว 30, 20 หรือ 50 เปอร์เซ็นต์ (บนสไลด์ใช้ 0.50)
  • กินได้: สิ่งที่มีโอกาสกินได้สูงที่สุดคือ sandwich ส่วน blue เป็นสีจึงกินไม่ได้ ให้น้ำหนักต่ำมาก แล้วให้น้ำหนักกับ cat, lion, dog ตามลำดับ

น้ำหนักเหล่านี้ช่วยจับความหมายและความใกล้ของคำ ยิ่งความต่างของน้ำหนักในทุกคุณลักษณะน้อยเท่าไร ยิ่งคล้ายหรือใกล้กันเท่านั้น และนี่คือ vector embedding จะเรียกว่าคุณลักษณะหรือมิติก็ได้ คือมิติที่เราใช้กำหนดน้ำหนักของ token หรือคำหนึ่งคำ

ผู้สอนย้ำว่า word ไม่เท่ากับ token ตามที่เรียนในเรื่อง byte pair encoding แต่ตรรกะทั้งหมดคือเหตุผลที่ต้องมีเวกเตอร์และ vector embedding คือการนิยามคำหนึ่งคำด้วยมิติสี่ห้ามิติ เท่านั้นเอง

สิ่งที่ต้องสร้าง: token ID, มิติ, น้ำหนัก (~5:34–6:12)

ผู้สอนสรุปสิ่งที่ต้องสร้างในท้ายที่สุด:

  1. vocabulary คือการแปลง token หรือคำเป็นตัวเลข (token ID)
  2. สำหรับแต่ละตัวเลขหรือ token ต้องมี มิติหรือคุณลักษณะ หลายตัว
  3. แล้ว กำหนดน้ำหนัก ให้แต่ละมิติ

คือต้องมี token ID, มิติหรือคุณลักษณะ และน้ำหนัก ส่วนคำถามสำคัญถัดไปคือทำอย่างไร และโมเดลที่ฝึกมาดีแล้วใช้ขนาดเท่าไร

4. ขนาดในโมเดล GPT

~6:12–7:00

ผู้สอนเล่าขนาดของโมเดลที่ฝึกแล้ว:

  • GPT-1: คลังคำ 40,000 คำ และแต่ละคำหรือ token มี 768 มิติ ไม่ใช่สี่ห้ามิติ ผู้สอนพูดว่ามีการเขียนคุณลักษณะ 768 อย่าง เช่น เป็นสัตว์เลี้ยงไหม เป็นสัตว์ไหม เป็นคนไหม มีสี่ขาไหม มีสองขาไหม
  • GPT-2: คลังคำ 50,257 และจำนวนมิติจากโมเดลเล็กสุดถึงใหญ่สุดคือ 768 ถึง 1,600
  • GPT-3: จำนวนคำเท่าเดิม แต่มิติราว 12,000 คือทุก token มีคุณลักษณะประมาณนั้น และต้องกำหนดน้ำหนัก 12,288 ค่าต่อคำหรือ token

5. หาน้ำหนักอย่างไร และอยู่ตรงไหนใน GPT

~7:00–8:29

วิธีที่ง่ายที่สุดในการสร้าง vector embedding: เอา token หรือ token ID กับมิติมา แล้ว กำหนดน้ำหนักแบบสุ่ม จากนั้นลองทำนายด้วยน้ำหนักนั้น เพราะน้ำหนักสุ่ม จึงมี error ระหว่างผลทำนายกับพฤติกรรมจริงแน่นอน คำนวณ error หา loss function หรือ gradient แล้วปรับน้ำหนัก และทำซ้ำไปเรื่อย ๆ จนได้น้ำหนักที่ดีที่สุด

ใน GPT สิ่งนี้ทำ "ที่ระดับ attention" คือเมื่อเริ่มฝึกโมเดลก็กำหนดน้ำหนัก ขั้นตอนตามที่ผู้สอนไล่:

  1. tokenization
  2. vector embedding
  3. positional embedding
  4. contextual embedding
  5. self-attention ซึ่งเป็นที่ที่ฝึกโมเดล

เมื่อเริ่มฝึกโมเดล น้ำหนักเหล่านี้ถูกปรับ ดังนั้นใน GPT vector embedding ถูกสร้างตอน pre-training ของโมเดล แต่ก็มี น้ำหนักที่ฝึกไว้แล้ว สำหรับ vector embedding ใช้ก่อนเข้าขั้น self-attention ได้เช่นกัน ผู้สอนบอกว่าเราจะลองพัฒนาวิธีทำ vector embedding ของเราเอง แต่ก่อนนั้นขอดูสิ่งที่มีอยู่แล้วก่อน คือมี library ดี ๆ ที่ดึงมิติหรือน้ำหนักของคำออกมาเล่นได้ไหม หาความคล้ายได้ไหม หรือหาว่าการรวมคำทำให้ได้คำอื่นได้ไหม

6. ทดลองกับ Word2Vec ของ Google

~8:29–11:40

ผู้สอนใช้ Word2Vec library ที่ Google พัฒนา ซึ่งมี 300 มิติ คำที่ฝึกไว้มีราว 3 ล้านคำ (caption เขียนว่า "three words"; ผู้สอนพูดว่า 30 lakh ซึ่งคือ 3 ล้าน) และทุกคำมีเวกเตอร์หรือน้ำหนักกำหนดไว้ เขาตรวจใน notebook ว่าฝึกกับกี่คำและมิติเท่าไร (300 คุณลักษณะต่อคำ) แล้วดู 10–11 คำแรกในคลัง

จากนั้นดูเวกเตอร์ของ cat ซึ่งมีน้ำหนัก 300 ค่าสำหรับมิติต่าง ๆ รูปร่างคือ 300 มิติ ดูของ dog ด้วย และผู้สอนบอกว่าใช้เวกเตอร์เหล่านี้ฝึก LLM ได้

yen − Japan + India

ต่อมาลองหาความคล้ายจากการรวมคำ: เอา yen ลบ Japan แล้วบวก India ผู้สอนบอกว่าทุกคนคงเดาคำตอบได้แล้ว ระหว่างคำนวณ ระบบหาความต่างของน้ำหนักในทุกเวกเตอร์ ผลคือ rupee ที่ 61.9% ตามด้วย rupee อีกแบบ, rupees, Indian rupee แล้ว "เริ่ม hallucinate" แต่ผู้สอนบอกว่ามันพยายามให้คำตอบที่ใกล้ที่สุดกับคำถาม

ใช้ไม่ได้ทุกครั้ง

แต่จะได้ทุกครั้งไหม ขึ้นกับว่าโมเดลเคยฝึกกับทุกคำหรือเปล่า ในตัวอย่างถัดไปเกิด error เพราะ โมเดลไม่ได้ฝึกกับคำว่า Bill Gates จึงขึ้นว่า key "Bill Gates" ไม่อยู่ในคลังคำ ผู้สอนจึงบอกว่า จำเป็นต้องสร้าง vector embedding ของตัวเองตามสิ่งที่จะฝึก เช่น เป็นข้อมูลการเงิน หรือคำทั่วไปแบบ GPT และนี่คือเหตุผลที่ต้องเข้าใจอัลกอริทึม: สร้างน้ำหนักสุ่ม ทำนาย หา error ทำ loss function แล้วปรับน้ำหนัก

7. ความคล้าย king/queen กับ king/man และข้อสรุป

~11:40–13:56

ผู้สอนบอกว่าจะลองหาค่าความคล้ายระหว่างสองคำด้วย: ความคล้ายของ king กับ queen ได้ 65% แล้วถ้าเปลี่ยนเป็น king กับ man (ต้อง restart kernel ก่อน) ได้ราว 22% ผู้สอนบอกว่าไม่มีความคล้ายระหว่าง king กับ "mango man" ซึ่งเขาขยายต่อว่าคือคนธรรมดา (common man) (หมายเหตุผู้จัดทำ: น่าจะมาจากคำฮินดี aam aadmi ที่ aam แปลว่ามะม่วงด้วย) สรุปคือความคล้ายของ king กับ queen สูงกว่า king กับ man

ข้อสรุปของผู้สอน

Word2Vec ของ Google ที่ใช้ไปเป็น vector embedding แบบหนึ่งที่มีอยู่แล้ว ซึ่งมีแค่ 300 มิติ เราอาจต้องใช้ถึงราว 10,000 มิติ เพราะ ยิ่งมิติสูง โมเดลยิ่งทำนายได้ดีขึ้น ผู้สอนบอกเองว่าประโยคนี้มีข้อแม้ แต่พูดแบบง่าย ๆ เพื่อเน้นว่า ในท้ายที่สุดเราต้องพัฒนา vector embedding มิติ และน้ำหนักของเราเอง

ตอนนี้ผู้สอนแค่อยากให้เห็นภาพว่า vector embedding คืออะไร และใช้ library ที่มีอยู่แล้วได้ไหม คำตอบคือได้ แต่ถ้าจะปรับ LLM ของตัวเอง ต้องพัฒนา vector embedding มิติของ embedding และน้ำหนักของ embedding เอง แล้วปิดคลิปด้วยการขอบคุณผู้ชม

โค้ดเทียบเท่า (ผู้จัดทำเขียนเอง, Python + gensim)

Python
import gensim.downloader as api
w2v = api.load("word2vec-google-news-300")
print(len(w2v.key_to_index), w2v.vector_size) # 3000000 300
print(w2v.most_similar(positive=["Yen", "India"], negative=["Japan"], topn=5))
print(w2v.similarity("king", "queen"), w2v.similarity("king", "man"))

Key Takeaways

  1. เลข token ไม่บอกความหมาย ตัวเลขของ cat, lion, dog ไม่ได้บอกว่าคำไหนใกล้กัน
  2. vector embedding คือน้ำหนักในหลายมิติ คำที่น้ำหนักต่างกันน้อยคือคำที่คล้ายกัน และใช้น้ำหนักแทนใช่/ไม่ใช่เพราะความจริงไม่ใช่ขาวกับดำ
  3. โมเดลจริงใช้หลายร้อยถึงหนึ่งหมื่นกว่ามิติ: GPT-1 768, GPT-2 768–1,600, GPT-3 12,288
  4. หาน้ำหนักด้วยการเริ่มสุ่มแล้วปรับจาก error ซ้ำไปเรื่อย ๆ ใน GPT ทำระหว่าง pre-training
  5. embedding ที่ฝึกไว้แล้ว (Word2Vec) ใช้ได้แต่มีข้อจำกัด คำที่ไม่มีในคลังคำใช้ไม่ได้ ผู้สอนจึงแนะนำให้สร้าง embedding เองสำหรับ LLM ของตัวเอง
