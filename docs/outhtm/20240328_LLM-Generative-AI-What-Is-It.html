บทสรุปย่อ

คลิปยาวประมาณ 1 ชั่วโมงนี้ (เผยแพร่ 28 มีนาคม 2024) พาเดินจากคำถาม "AI อย่าง ChatGPT, Claude, Gemini ทำงานเบื้องหลังอย่างไร" ไปทีละขั้น: Generative AI คือสิ่งที่ AI สร้างขึ้น → ทวน Neural Network ด้วยตัวอย่างอาหารโปรด → Transformer (เปลี่ยนข้อความเป็นเวกเตอร์ แล้วใช้ Attention หาความสัมพันธ์) → LLM คือ Transformer ที่มีพารามิเตอร์จำนวนมหาศาล → Prompt / In-Context Learning → Pretrained เทียบกับ Instruct Model → Reinforcement Learning (RLHF) → Multimodal → เครื่องมือที่ผู้พูดใช้ ผู้พูดเล่าแบบไม่ลงลึกเกินไปและบอกตรง ๆ ว่าบางเรื่องเขาเองก็ยังศึกษาอยู่ รายงานนี้เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ตัวเลขและข้ออ้างที่ตรวจได้ถูกตรวจแล้วในตาราง "ตรวจข้อเท็จจริง" และมีหัวข้อที่ 13 ที่แกะ flow การเล่าให้เข้าใจง่าย ของคลิปนี้เป็นแม่แบบ (วิเคราะห์โดยผู้จัดทำ ตามที่เจ้าของโปรเจกต์ขอ)

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ แบบวิเคราะห์เชิงลึก (license มาตรฐานของ YouTube) ตรวจข้อเท็จจริงกับแหล่งภายนอกแล้ว ส่วนวิเคราะห์ flow การเล่าเป็นของผู้จัดทำ

สรุปเชิงลึก

ข้อโต้แย้งหลักของคลิป ผู้พูดอยากให้ผู้ชมเห็นว่า AI ที่ "ทำงานราวกับมนุษย์" ไม่ใช่เวทมนตร์ แต่เป็นลำดับขั้นของการเรียนรู้ที่ต่อกันเป็นชั้น ๆ: โมเดลภาษาขนาดใหญ่ที่เรียนความสัมพันธ์ในข้อมูลก่อน (Pretrained) → มนุษย์สอนว่าคำตอบแบบไหนถูกผิด (Instruct / Supervised Fine-tune) → ให้รางวัลจากผลลัพธ์เพื่อจูนต่อเนื่อง (Reinforcement Learning from Human Feedback) และผู้ใช้อย่างเราก็เป็นส่วนหนึ่งของวงจรนี้

ลำดับความคิดตั้งแต่ต้น (1) Generative AI คืออะไรก็ตามที่ AI สร้างขึ้น ไม่ได้มีต้นฉบับจากคน (2) เบื้องหลังคือ Neural Network ซึ่งผู้พูดเปรียบง่าย ๆ ว่าเป็นการเปลี่ยนเงื่อนไข if-else ให้กลายเป็นความน่าจะเป็นที่ซ้อนกันหลายชั้น (3) ข้อมูลทุกอย่างต้องเป็นตัวเลขก่อนคำนวณ จึงต้องมี Encoder ที่แปลงข้อความเป็นเวกเตอร์ และ Decoder ที่แปลงกลับ; ตัว "weight vector" ที่ได้จากการเทรนทำหน้าที่เหมือนพจนานุกรมความสัมพันธ์ ผลคูณให้คะแนนกับแต่ละคำ (ตัวอย่างสมมติ 0.1, 0.4, 0.5 แล้วเลือกคำที่ได้มากที่สุดคือ "แมว") และ Attention คือส่วนที่คำนวณความสัมพันธ์ ทำให้ข้อความยาว ๆ ไม่หลงต้นประโยคเหมือน RNN (4) LLM คือ Transformer ที่พารามิเตอร์มากพอจะจับความสัมพันธ์ได้ละเอียด (GPT-2 ราว 1.5 พันล้าน, GPT-3 175 พันล้าน, GPT-4 ผู้พูดพูดว่าราว 1.4 ล้านล้านแต่บอกว่าไม่ได้เปิดเผย) และมันสร้างคำตอบทีละคำวนจนจบ (5) ใช้งานจริงต้อง "กรอบ" ด้วย Prompt (Zero-shot, Few-shot, Chain of Thought) ซึ่งเรียกรวมว่า In-Context Learning แต่ผู้พูดเตือนว่าได้ผลบ้างไม่ได้บ้าง จึงมีขั้น Instruct และ RL ต่อ (6) ความสามารถเดียวกันขยายไปภาพ เสียง วิดีโอ (Multimodal) โดยแปลงทุกอย่างเป็นเวกเตอร์เหมือนข้อความ

สิ่งที่ถูกและสิ่งที่ผู้จัดทำตรวจพบ ผลตรวจข้อเท็จจริง 12 รายการ: ยืนยัน 5, ยืนยันบางส่วน 6, ไม่พบ 1 และมีข้อที่ควรแก้ความเข้าใจ: (ก) ผังเดียว Encoder → weight vector → Decoder ที่ผู้พูดใช้อธิบาย LLM เป็นภาพประกอบที่ง่ายเกินไป เพราะ GPT-3 เป็น decoder-only ตามที่ Wikipedia ระบุ ส่วน Transformer ในงานวิจัยต้นฉบับเป็นแบบ encoder-decoder; (ข) ตัวเลข Bard 300 กว่าล้าน ผู้จัดทำไม่พบในแหล่งที่อ่าน (Google บอกว่า Bard เริ่มด้วย LaMDA รุ่น lightweight โดยไม่ระบุขนาด; รุ่นเล็กสุดในงานวิจัย LaMDA คือ 2 พันล้าน) จึงตัดสินไม่ได้; (ค) ผู้พูดเรียกขั้น Pretrained ว่า Unsupervised แต่ภาพประกอบที่เขาเปิดดูเองใช้คำว่า Self-supervised; (ง) การกด "bad response" ผู้พูดอธิบายเหมือนให้รางวัลแล้วโมเดลปรับทันที ซึ่งในเอกสาร InstructGPT ขั้นตอนจริงคือเก็บการจัดอันดับคำตอบไปฝึก reward model แล้วค่อยใช้ RL

ที่คลิปไม่ได้พูดถึง ไม่มีสูตรของ Attention, ไม่มีรายละเอียดของ PPO หรือ reward model, ไม่มีเรื่อง context window / การถอดรหัส (sampling) / การประเมินผลโมเดล, RAG พูดเพียงแนวคิดและผู้พูดยอมรับว่ายังไม่ลึก

ควรนำไปทำอะไรต่อ คลิปนี้เป็นภาพรวมภาษาไทยของ G1 (pre-training) และ G2 (post-training) ที่ใช้เป็นสะพานของคู่มือ LLM ใน ZVect ได้ และที่มีค่ามากกว่าเนื้อหาคือ flow การเล่า (หัวข้อที่ 13) ซึ่งสรุปเป็นแม่แบบได้ 15 ขั้นตอน

Quick Reference

รายการค่า / ข้อความตามคลิป
Generative AIอะไรก็ตามที่สร้างขึ้นโดย AI ไม่ได้มีต้นฉบับจากคน (ตัวอย่าง: ก ไก่ที่ AI สร้าง)
Neural Network (ตามคลิป)รับ input → คำนวณตรงกลาง (มี Hidden Layer) → ได้ prediction; มองเป็น if-else ที่ใส่ความน่าจะเป็น
ตัวอย่างสมมติของผู้พูดเสื้อสีน้ำเงิน 0.6 กะเพรา / สีส้ม 0.4 ผักคะน้า; นนทบุรี 0.56 กะเพรา / กรุงเทพ 0.44 ผักคะน้า
ทำไมต้องเป็นเวกเตอร์ข้อมูลต้องเป็นตัวเลขจึงคำนวณใน Neural Network ได้; feature ที่ซ่อนในข้อความ (ไวยากรณ์ ลำดับ ชนิดประโยค) เก็บในเวกเตอร์
Encoder / DecoderEncoder แปลงข้อมูลต้นฉบับเป็นเวกเตอร์ที่คำนวณได้; Decoder แปลงผลลัพธ์กลับเป็นข้อความ
Weight Vectorผลของการเทรน เปรียบเป็นพจนานุกรมที่เก็บความสัมพันธ์; เวกเตอร์คูณกับมันได้คะแนน (ตัวอย่าง 0.1 0.4 0.5) แล้วเลือกคำที่คะแนนสูงสุด
Attentionส่วนคำนวณความสัมพันธ์ระหว่างข้อมูลที่ใส่เข้ามากับสิ่งที่เรียนรู้ไว้
ปัญหาของ RNN (ตามคลิป)ข้อความยาวแล้วข้อมูลตอนต้นเริ่มหาย; Transformer คำนวณทั้งชุดจึงไม่หาย
วิธีเทรน 2 แบบที่ยกมาmasked (ปิดคำให้ทายคำที่หาย) และ next sequence (ทายคำถัดไป)
ที่มาของ Transformerงานวิจัยของทีม Google Brain ชื่อ Attention Is All You Need (หน้าจอแสดงปี 2017)
ขนาดพารามิเตอร์ที่พูดถึงGPT-2 1.5 พันล้าน; GPT-3 175 พันล้าน; GPT-4 ราว 1.4 ล้านล้าน (ผู้พูดบอกว่าไม่ได้เปิดเผย); "Bard ตัวแรก 300 กว่าล้าน"
LLM ภาษาชาวบ้านโมเดลทำนายข้อความ; สร้างทีละคำ วิเคราะห์ใหม่ทั้งชุดทุกครั้งจนถึงจุดสิ้นสุด
โมเดลที่ลองโหลดมารันได้หาที่ Hugging Face (ผู้พูดยังไม่เคยลอง); ตัวอย่างไทย: Typhoon ของ SCB 10X; ตระกูลอื่นที่พูดถึง: Gemini (Google), Llama (Meta)
Prompt techniques ที่ยกมาZero-shot, Few-shot, Chain of Thought (จาก Prompting Guide)
In-Context Learningสอนโมเดลผ่าน prompt โดยไม่ปรับโมเดล
Pretrainedโมเดลที่เทรนเสร็จแล้ว มี weight พร้อมใช้ เรียนรู้ความสัมพันธ์ในข้อมูลเท่านั้น (ผู้พูดเรียก Unsupervised)
Instruct ModelPretrained + มนุษย์ label ถูก/ผิด (Supervised) แล้ว Fine-tune; ตัวอย่างที่พูดถึง GPT-3.5
Reinforcement Learningstate + action + reward; Deep RL เปลี่ยนตารางเป็น Neural Network; RLHF คือกระบวนการที่ผู้พูดบอกว่า GPT-4 ใช้
Multimodalแปลงภาพ เสียง วิดีโอเป็นเวกเตอร์ด้วย Encoder แล้วหาความสัมพันธ์เหมือนข้อความ (ตัวอย่าง Sora)
เครื่องมือที่ผู้พูดใช้GPT-4, Gemini (Advanced), Claude (Opus เมื่อจ่ายเงิน), Perplexity (ค้นข้อมูล + LLM, เกี่ยวกับแนวคิด RAG)
คีย์เวิร์ดแนะนำให้ศึกษาPretrained, Fine-tune, Prompting (และ Prompt Engineer)

เปรียบเทียบ

ขั้นเรียนจากอะไรมนุษย์เกี่ยวข้องอย่างไรผลที่ได้ (ตามคลิป)
Pretrainedข้อมูลปริมาณมหาศาล (ตัวอย่าง Wikipedia, หนังสือ, เว็บบอร์ด, Reddit)ไม่ได้บอกว่าความสัมพันธ์ไหนถูกผิด (ผู้พูดเรียก Unsupervised)โมเดลทำนายข้อความที่ "รู้เยอะ" แต่ไม่รู้ว่าอะไรถูกไม่ถูก ต้องใช้ Prompt กรอบเอง
Instruct Modelผลลัพธ์ของ Pretrained + ตัวอย่าง input/output ที่ต้องการมนุษย์ label ว่าตอบแบบนี้ถูก แบบนี้ผิด (Supervised, Fine-tune)โมเดลที่ตอบคำถามตรงประเด็นขึ้น
RL Fine-tunedผลลัพธ์ของ Instruct + reward จาก feedbackมนุษย์ให้ feedback แล้วสะสมเป็นรางวัลเพื่อจูนต่อเนื่องโมเดลระดับ ChatGPT / Claude; ผู้พูดบอกว่าแต่ละเจ้าให้ผลต่างกันเพราะ Instruct และ reward ต่างกัน แม้ใช้โมเดลฐานเดียวกัน
เสริมจากผู้จัดทำ: วิธีเลือกขั้น (ตัดสินด้วยเกณฑ์ ผู้จัดทำสรุปจากคลิป)

ถ้าต้องการเข้าใจว่าโมเดล "เรียนอะไรมา" ให้ดูที่ Pretrained; ถ้าต้องการให้ตอบตามรูปแบบที่คนอยากได้ ให้ดูที่ Instruct; ถ้าสงสัยว่าทำไมเจ้าเดียวกันตอบต่างกัน ให้ดูที่ขั้น reward ตัวเลือกเหล่านี้เป็นคำอธิบายแนวคิดจากคลิป ไม่ใช่คู่มือเลือกโมเดลจริง

1. แนะนำหัวข้อและกรอบการเล่า (~0:00–2:38)

ผู้พูดเปิดด้วยชื่อที่ผู้ชมรู้จักอยู่แล้ว (ChatGPT, Claude) แล้วบอกว่า LLM คือสิ่งที่อยู่เบื้องหลังสมองของ AI เหล่านั้น เขาจะเล่าในมุมที่ค่อนข้าง technical เพื่อให้เห็นว่าเบื้องหลังเป็นอย่างไร โดยตั้งใจ "ไม่ให้หนักหน่วงเกินไป" เท่าที่ตัวเขาเล่าได้ และยอมรับตรง ๆ ว่ามีหลายส่วนที่เขายังอยู่ระหว่างศึกษา

เขาวางตำแหน่ง Generative AI ว่ามีมาหลายปีแล้ว แต่การมาถึงของ ChatGPT, DALL-E และ Gemini ทำให้จากของเฉพาะกลุ่ม กลายเป็นสิ่งที่ทุกคนจับต้องได้ ปี 2024 จึงเป็นปีที่คนพูดถึงการใช้ AI มาก และเขาคิดว่าอีกสิบปีข้างหน้า AI อาจ กลมกลืนกับชีวิตประจำวันจนไม่ต้องเรียนรู้วิธีใช้ AI อีก

เรื่องความสัมพันธ์ของคำ: AI กว้างกว่า LLM; Neural Network คือการจำลองสมองในคอมพิวเตอร์ เป็นเบื้องหลังของ Deep Learning ซึ่ง LLM เป็นหนึ่งในประเภทของมัน ผู้พูดแนะนำให้คนที่อยากเข้าใจลึกไปฟังหัวข้อ Neural Network ที่เขาเคยทำไว้ก่อน เป้าหมายของคลิปคือให้ผู้ชมลองคิดไปด้วยกันว่าของที่ใช้ทุกวันซึ่งทำงานราวกับเป็นมนุษย์คนหนึ่ง จริง ๆ แล้วมีรูปแบบการทำงานเบื้องหลังอย่างไร

2. Generative AI คืออะไร และทวน Neural Network (~2:38–8:42)

นิยาม ผู้พูดเริ่มจากรากศัพท์ generate: อะไรก็ตามที่ถูกสร้างขึ้นมาจากโมเดล AI ถือว่าอยู่ภายใต้ Generative AI เขาวาดภาพให้เห็นว่า ถ้าเขาเขียน ก ไก่เอง ภาพนั้นเป็นของเขา แต่ถ้าส่งคำสั่งไปให้กล่อง AI แล้วได้ ก ไก่ออกมา (อาจสวยแบบฉบับ AI) สิ่งนั้นคือสิ่งที่ AI สร้าง ไม่ได้เกิดเป็น original จากคน เบื้องหลังเป็นโมเดลชนิดหนึ่งที่ใช้ Neural Network

ทวน Neural Network เขาบอกว่าไม่ลงลึก (มีคลิปแยกแล้ว) ใช้การเปรียบเทียบกับสมอง: รับ input หลายอย่าง (ตัวอย่าง: ขยับมือ สัมผัสคอมพิวเตอร์ พยายามงอจอ รวมเป็นสาม input) สมองประมวลผล แล้วได้ผลลัพธ์ (เช่น ตัดสินใจจะปิดคอม) ใน Neural Network ข้อมูลถูกเปลี่ยนเป็นตัวเลขแล้วเข้าสมการ ตัวอย่างพยากรณ์: ใส่เพศ ที่อยู่ การแต่งตัวเป็น x1, x2, x3 ผลที่ออกมาคือเดาว่าคนนี้ชอบกะเพราหรือข้าวไข่ต้ม

จาก condition เป็นความน่าจะเป็น แทนที่จะเขียนเงื่อนไขว่าถ้าเสื้อสีน้ำเงินก็กะเพรา ถ้าสีส้มก็ผักคะน้า ให้เปลี่ยนเป็นความน่าจะเป็น (ตัวเลขสมมติ: น้ำเงิน 0.6 กะเพรา, ส้ม 0.4 ผักคะน้า) แล้วเพิ่มข้อมูลที่สอง (นนทบุรี/กรุงเทพ) ผ่านชั้นพิเศษที่เรียกว่า Hidden Layer (ตัวเลขสมมติ นนทบุรี 0.56 กะเพรา, กรุงเทพ 0.44 ผักคะน้า) ชั้นถัดไปคูณความน่าจะเป็นต่อกัน แล้วดูว่าผลสุดท้ายยังเป็นกะเพราหรือผักคะน้า

ข้อสรุปของผู้พูด: จริง ๆ คือการใส่ความน่าจะเป็นเข้าไป จนตอบไม่ได้ทันทีว่าเสื้อสีน้ำเงินกับอยู่กรุงเทพจะชอบอะไรมากกว่า และเมื่อตัวแปรเพิ่มขึ้นเรื่อย ๆ ก็ยิ่งหนาแน่น ซึ่งเป็นเบื้องหลังของ LLM

3. Transformer: จากข้อความเป็นเวกเตอร์ Encoder Decoder และ Attention (~8:42–17:52)

ผู้พูดเรียก Transformer ว่าเป็นสิ่งที่เปลี่ยนโลก (เล่นมุกว่าไม่ใช่หุ่นยนต์แปลงร่าง) และบอกว่าถ้าไม่มีมัน เราคงไม่เห็น LLM แบบปัจจุบัน

ทำไมต้องเป็นตัวเลข ท้ายที่สุดข้อมูลใน Neural Network ต้องเป็นตัวเลขเพราะข้างในเป็นสมการ (Activation, การคูณ weight) ผู้พูดยกตัวอย่างแปลงเสื้อสีน้ำเงินเป็น 0 สีส้มเป็น 1 นนทบุรีเป็น 0.5 กรุงเทพเป็น 0.4 (ตัวเลขสมมติ ~9:21) แต่ข้อมูลส่วนใหญ่ในโลกเป็นข้อความ ก่อนหน้านี้มีวิธีของสาย NLP ที่แปลงสตริงเป็นตัวเลข เขาจะโฟกัส Transformer

คำถามตั้งต้นที่ผู้ชมรู้สึกได้ เราจะรู้ได้อย่างไรว่าข้อความสองข้อความสัมพันธ์กัน ตัวอย่าง: ถ้าถามว่าสัตว์อะไรน่ารัก แล้วคนส่วนใหญ่ตอบว่าแมว ความสัมพันธ์ของแมวกับสัตว์น่ารักในคอมพิวเตอร์ต้องอธิบายได้

ตัวละครทีละตัว Encoder คือตัวแปลงข้อมูลต้นฉบับให้เป็นข้อมูลชุดที่คำนวณได้; Decoder คือตัวแปลงผลลัพธ์ที่คำนวณแล้วกลับเป็นข้อความ ข้อความมี feature ซ่อนอยู่มาก (ไวยากรณ์ ลำดับก่อนหลัง เป็นประโยคคำถามหรือบอกเล่า) ข้อมูลที่เปรียบเทียบกันได้จึงเป็น เวกเตอร์ ผู้พูดบอกว่าจะอธิบายวิธีแปลงภายหลัง

ตัวอย่างต่อเนื่อง (ทายคำที่หายไป) สมมติให้ทายคำที่เว้นไว้ 3 คำ ขั้นแรกข้อมูลถูกแปลงเป็นเวกเตอร์ แล้วทำ operation กับ Weight Vector ซึ่งเป็นผลของกระบวนการเรียนรู้ (เทรน) ผู้พูดเปรียบว่าเป็น Dictionary นำทางที่ฉลาดกว่า เพราะเก็บความสัมพันธ์ไว้ ผลคูณให้ค่าต่าง ๆ (ในภาพ 0.1, 0.4, 0.5) แล้วดูว่าค่าไหนมากสุด ไปเทียบตำแหน่งในพจนานุกรม ได้คำว่าแมว นี่คือภาพอย่างง่าย

Attention และ Position กระบวนการด้านซ้ายคือ Encoder ด้านขวาคือ Decoder ส่วนตรงกลางคือ Attention ซึ่งเป็นตัวคำนวณความสัมพันธ์ระหว่างข้อมูลที่ใส่เข้ามากับสิ่งที่เรียนรู้ไว้ ในของจริงไม่ได้แค่เทียบทีละคำกับพจนานุกรม มี Position (ตำแหน่งของข้อมูล) เข้ามาด้วย เช่นในประโยคสัตว์อะไรน่ารักและน่ากลัวในเวลาเดียวกัน Attention ช่วยไม่ให้คำว่าน่ารักกับสัตว์หายไปเมื่ออ่านถึงท้ายประโยค

เทียบกับ RNN ผู้พูดอธิบายว่า RNN (Recurrent Neural Network) ส่งข้อมูลจากขั้นก่อนต่อกันไปเรื่อย ๆ พอข้อความยาว (ตัวที่ 10 ตัวที่ 20) input ต้น ๆ จะเริ่มหาย ส่วน Transformer สร้างเวกเตอร์แล้วคำนวณทั้งชุด ความสัมพันธ์ของข้อมูลต้น ๆ จึงไม่หาย

ผังจริงของ Transformer (~16:35–17:28) ผู้พูดเปิด diagram จริงโดยบอกว่า "ไม่ลงรายละเอียดเพราะแน่นมาก": input text → tokenize (แยกข้อความเป็น token ก่อน) → embedding (แปลงเป็นเวกเตอร์) + position encoding → โมดูล Attention คำนวณความสัมพันธ์ภายใน → ส่งความหมายไป Decoder → เทียบกับ Dictionary หาข้อความที่เข้าเค้าที่สุดแล้วหยิบมาแสดง

ผู้พูดสรุปไอเดียของ Transformer สั้นลงว่า คือการสร้างของบางอย่างโดยใช้ความสัมพันธ์ภายในระบบ ทั้งความสัมพันธ์ในข้อมูลที่ส่งเข้าไป และความสัมพันธ์ในฐานข้อมูลที่ได้จากการเรียนรู้ มาเทียบกันเพื่อสร้างข้อมูลชุดใหม่

ข้อที่ควรเข้าใจให้ตรง

ผู้จัดทำตรวจ: ผังเดียว Encoder → weight vector → Decoder ในคลิปเป็นภาพประกอบเพื่อให้เห็นแนวคิดอย่างง่าย เพราะ Transformer ในงานวิจัยต้นฉบับเป็นแบบ encoder-decoder (ออกแบบสำหรับงานแปล) ส่วนตระกูล GPT (GPT-3 และ GPT-3.5 ที่ ChatGPT รุ่นแรกใช้) เป็นโมเดลแบบ decoder-only ตามที่ Wikipedia ระบุ (ดูตารางตรวจข้อเท็จจริง) ผู้ชมที่จะเขียนโค้ดตามไม่ควรยึดผังนี้เป็นสถาปัตยกรรมจริงของ LLM

4. Transformer ทำงานทีละคำ การเทรน และที่มา (~17:52–21:37)

ทำไมข้อความของ ChatGPT ค่อย ๆ ทยอยมา ผู้พูดชี้ให้ผู้ชมนึกถึงความรู้สึกนี้ และบอกว่าไม่ได้ช้าเพราะเครื่องช้า แต่เพราะมัน ค่อย ๆ คำนวณ: ได้คำว่า "แมว" แล้วเอา "แมว" ไปคำนวณใหม่ทั้งชุดเพื่อหาคำถัดไป แล้วเอาคำใหม่ไปคำนวณทั้งชุดอีกครั้ง วนจนสร้างข้อความทั้งหมดได้

เทคนิคเทรนที่ยกมา (ผู้พูดบอกว่ามีหลายเทคนิค) (1) masking ปิดบางคำให้ทายว่าคำที่หายไปคืออะไร (ตัวอย่างสมมติ: ประโยคที่ลงท้ายว่า "…น่ารัก" เมื่อเทียบกับการสุ่มตัวอย่างพบว่าคำที่หายไปคือ "หน้า") (2) next sequence ให้ทายว่าคำถัดไปมีความน่าจะเป็นแบบไหน ผลลัพธ์ของทั้งสองวิธีคือตารางของ Weight Vector ที่นำไปคำนวณต่อได้

ที่มาและบริบท ผู้พูดบอกว่า Transformer เกิดจากงานวิจัยของทีม Google Brain ชื่อ "Attention [Is All You Need]" (ปี 2017 บนหน้าจอ) ซึ่งจุดประกายให้วิเคราะห์ข้อความทั้งชุดรวมกันได้ จากเดิมที่ RNN จดจำทีละก้าว สิ่งนี้เติมเต็มความเป็น Generative AI อย่างไรก็ตาม Generative AI ไม่จำเป็นต้องเป็น Transformer ก็ได้ เช่นก่อนหน้านี้มี GAN ซึ่งผู้พูดบอกว่าใช้ RNN ด้วย (ตามที่ผู้พูดพูด; ผู้จัดทำสังเกตว่า GAN สร้างภาพส่วนใหญ่ใช้ CNN ไม่ใช่ RNN และไม่ได้ตรวจประเด็นนี้ต่อ) และเจอปัญหาจำข้อมูลต้นทางไม่ได้เมื่อข้อมูลใหญ่ ผู้พูดว่างานสร้างภาพ GAN "อาจยังพอไหว" แต่เมื่อต้องสร้างข้อความที่ยาวขึ้นอาจเริ่มเสียบริบทไประหว่างทาง

เสริมจากผู้จัดทำ: ผู้พูดวนกลับไปที่นิยามตอนต้น

ตอน ~20:47–20:56 ผู้พูดย้อนไปที่ประโยคแรกของหัวข้อ ("Generative AI คือสิ่งที่ AI สร้าง") เพื่อบอกว่า Transformer ไม่ใช่ทางเดียวแต่เป็นทางที่ทำให้ข้อความยาว ๆ สร้างได้ดี เป็นเทคนิคการเล่าแบบ "วนกลับไปหาคำตอบแรก" ที่ใช้ซ้ำในหัวข้อที่ 13

5. LLM แท้จริงคืออะไร (~21:37–26:57)

นิยาม ผู้พูดอธิบายว่า LLM ใช้สถาปัตยกรรม Transformer โดยเพิ่ม พารามิเตอร์ขนาดใหญ่ Transformer ก็เป็น Neural Network เช่นกัน LLM จึงคือ Transformer ที่มีพารามิเตอร์มหาศาล หมายถึงมี feature ภายใน context มากพอจะจับความสัมพันธ์ได้ละเอียด

ตัวอย่างของเล่นอธิบาย feature สมมติมีตัวอักษร a b c d e: โมเดลเล็กอาจเรียนรู้ได้ว่า b มักตามหลัง a; ถ้ามี c อาจต้องอยู่หลัง b; แต่ถ้าเจอข้อมูลใหม่ c a d ก็ต้องถามว่าทำไม a อยู่หลัง c (เพราะตามด้วย d หรือเปล่า) คำว่าอยู่หลังอยู่ก่อนนี่แหละคือ feature ที่อยู่ในตัวข้อความ ยิ่งพารามิเตอร์มาก ยิ่งวิเคราะห์ text ได้มาก LLM = Large Language Model คือ Neural Network ที่มีพารามิเตอร์จำนวนมากและวิเคราะห์ context ได้

ขนาดที่ผู้พูดยกมา ไม่ใช่สิบ ร้อย พัน แต่เป็นพันล้านกว่าตัว: Bard ตัวแรกสุดของ Google 300 กว่าล้าน (ตามที่ผู้พูดพูด ดูตารางตรวจข้อเท็จจริง), GPT-2 1.5 พันล้าน, GPT-3 175 พันล้าน, GPT-4 ราว ๆ 1.4 ล้านล้าน ซึ่งผู้พูดบอกว่าไม่ได้เปิดเผย ยิ่งเยอะยิ่งรับ token ได้ปริมาณมาก และต้องรันบนคอมพิวเตอร์ที่มีพลังประมวลผลมาก

มุมมองโปรแกรมเมอร์และภาษาชาวบ้าน ผู้พูดให้นึกภาพ Neural Network เป็น if-else ที่มีความน่าจะเป็น จากเดิมสามสี่ตัวเป็นหลายพันล้านตัว LLM จึงคือก้อน Language Model ที่เป็น Neural Network ภายใน; เวลาตอบมันค่อย ๆ พ่นข้อความทีละข้อความ วิเคราะห์ใหม่ทั้งชุดทุกครั้งจนถึงจุดสิ้นสุด ภาษาชาวบ้านที่เขาเลือกใช้ (ย้ำว่าไม่ใช่ศัพท์ทางการ) คือ "โมเดลทำนายข้อความ" ที่ไปเรียนรู้ว่าอะไรสัมพันธ์กับอะไร แล้วเมื่อส่งข้อความเข้าไปก็ได้คำตอบจากรูปแบบความน่าจะเป็นภายใน

ข้อมูลที่ใช้เรียนกำหนดพฤติกรรม ถ้าเรียนจาก Wikipedia ก็เป็น LLM แบบ Wikipedia หลายเจ้าจึงใช้หลายช่องทาง ทั้งเว็บไซต์ หนังสือ เว็บบอร์ด Reddit เพื่อลด bias ถ้าถามผู้สร้างว่าทำไมตอบแบบนี้ ก็ขึ้นกับว่าเอาอะไรไปเรียนรู้และเรียนรู้อย่างไร กระบวนการเรียนรู้จึงสำคัญมาก

6. LLM ที่ลองโหลดไปรันเองได้ (~26:57–30:12)

ผู้พูดบอกว่าใครสนใจก็รัน LLM เองที่บ้านได้ เพราะเป็น base model และชี้ไปที่ Hugging Face ซึ่งเป็นที่รวมโมเดล (หน้าโมเดลบอกขนาด data set เช่น 300 GB และสัดส่วนข้อมูลเช่น Literature กี่เปอร์เซ็นต์ ข่าวกี่เปอร์เซ็นต์ ทำให้ประเมินได้ว่าโมเดลน่าจะเก่งด้านไหน) แต่บางโมเดลต้องใช้กำลังประมวลผลไม่ธรรมดา และตัวผู้พูดเองยังไม่เคยรัน

ตัวอย่างไทยที่เขาหยิบมา: ไต้ฝุ่น (Typhoon) ของ SCB 10X เป็นโมเดลภาษาไทยที่อยู่บน Hugging Face ซึ่งทุกคนลองใช้ Pretrained ตัวนี้ได้ ผู้พูดบอกว่ามีโค้ดตัวอย่างและมีการเปรียบเทียบกับ GPT-3.5 ตระกูลอื่นที่พูดถึง: GPT-2, GPT-3, Gemini ของ Google (เป็น base ของ LLM ฝั่ง Google) และ Llama ของ Meta

เสริมจากผู้จัดทำ: ข้อสังเกตเรื่อง "GPT-3 ให้ลองรัน"

ตอน ~27:02 ผู้พูดพูดถึงการลองรัน GPT-3 แล้วไป search ที่ Hugging Face ต่อทันที Wikipedia ระบุว่า GPT-3 เข้าถึงได้ผ่าน API เป็นหลัก ผู้จัดทำจึงตีความว่าผู้พูดหมายถึงการดูโมเดลตระกูล LLM บน Hugging Face ทั่วไป ไม่ได้หมายถึงน้ำหนักของ GPT-3 เอง (เป็นการตีความ ไม่ใช่คำพูดตรง ๆ)

ปมที่ผู้พูดทิ้งไว้ ตอน ~29:05 ผู้พูดชี้ว่าคนส่วนใหญ่ไม่ได้โหลดโมเดลมาใช้เอง แต่ชินกับการใช้ LLM ผ่าน interface อย่าง ChatGPT ซึ่งเป็นตัวที่ทำให้คนพูดถึง Generative AI อย่างกว้างขวาง แล้วที่ ~29:28–30:04 เขาตั้งคำถามว่าถ้ามีโมเดลแล้ว ทำไมไม่ปล่อยให้คนใช้เลย พร้อมตอบล่วงหน้าสั้น ๆ ว่ายังมีกระบวนการอีกขั้นคือ Instruction Tuned Model เพื่อให้ LLM ตอบโจทย์ของแอปพลิเคชันได้ ซึ่งเป็นเนื้อหาของหัวข้อที่ 8

7. Prompt และ In-Context Learning (~30:12–34:12)

โจทย์ที่ตั้งก่อน LLM คือโมเดลที่ทำนายคำจากข้อมูลก่อนหน้า ถ้าอยากได้คำตอบที่ต้องการต้องทำอย่างไร? คำตอบของผู้พูดคือการใส่กรอบข้อความ: ยิ่งมีข้อมูลก่อนหน้าที่ดี LLM ยิ่งตอบตรงประเด็น ซึ่งเรียกว่า Prompt (scope ว่าอยากได้อะไร ถ้า scope ถูกก็ตอบตรง)

เทคนิคจาก Prompting Guide ผู้พูดเปิดเว็บ Prompting Guide ซึ่งมีศาสตร์ Prompt Engineer (Formatting, basic prompt ฯลฯ) และยกสามแบบ: Zero-shot พิมพ์ถามแล้วตอบทันที, Few-shot (ผู้พูดอธิบายสั้น ๆ ว่าเล่าเรื่องให้แล้วโมเดลสรุปออกมา; ช่วงที่ยกตัวอย่างเสียงไม่ชัด [ฟังไม่ชัด]; ตามนิยามทั่วไป ผู้จัดทำเสริม: คือการให้ตัวอย่างก่อนแล้วโมเดลทำตาม), Chain of Thought ให้ตอบเป็นเรื่องเป็นราวทีละขั้น ตัวอย่างโจทย์ที่ Roger มีลูกเทนนิส 5 ลูก ซื้อเพิ่ม 2 ลูกแล้วมีเท่าไร และโจทย์ cafeteria ที่มีแอปเปิล 23 ลูก

ข้อควรระวัง (ผู้พูดเตือนเอง) ตัวอย่าง Chain of Thought "ทำได้บ้างทำไม่ได้บ้าง ขึ้นกับโมเดลและความยากของโจทย์" ถ้าการคำนวณหรือข้อความยาว จะกิน token มาก ผลลัพธ์อาจผิดได้ จึงเป็นไอเดียที่ใช้ได้แต่ต้องใช้อย่างระมัดระวัง เพราะ LLM คือโมเดลทางภาษาที่ทำนาย

In-Context Learning เป้าหมายของ Prompt คือใส่ข้อมูลให้ LLM กรอบสิ่งที่ต้องการให้ได้มากที่สุด เรียกว่า In-Context Learning (ผู้พูดให้เป็นคีย์เวิร์ดไว้ ไม่ขยายยาว) คือการสอนผ่าน Prompt โดยไม่ปรับโมเดล การปรับโมเดลคือส่งไปเรียนใหม่ (เหมือนส่งเข้าสถาบัน แล้วจูนใหม่ได้ LLM ตัวใหม่) ส่วนการใส่ Prompt จะเอาข้อความทั้งหมดไปคำนวณความน่าจะเป็นรวมกัน แล้วหาคำตอบที่ใกล้เคียงที่สุดจากโมเดลทำนายตัวเดิม

ความเห็นส่วนตัวของผู้พูดที่แทรกมา (~32:58–33:32)

ผู้พูดบอกว่าเขาไม่ได้ทำงานสายนี้ เป็นแค่ผู้สนใจ และเชื่อว่าเราจะใช้ชีวิตร่วมกับ AI ในฐานะเครื่องมือที่ช่วยส่งเสริมการทำงาน ส่วนเรื่องแทนงานได้หรือไม่ ทุกคนต้องติดตามเอง เพราะ ณ ตอนนี้เขายังไม่เห็นภาพว่าจะแทนเราทั้งหมดได้อย่างไร แต่ที่เห็นแน่ชัดคือมันช่วยงานได้มาก

8. Pretrained, Instruct Model และการ Fine-tune (~34:12–40:31)

Pretrained คืออะไร LLM ที่เราหยิบมาใช้คือโมเดลที่ผ่านการเทรนแล้ว ถ้ายังไม่มี ต้องสร้าง Transformer เอง ตั้งพารามิเตอร์ จูน และเทรนซึ่งผู้พูดบอกว่าใช้เวลาประมาณสักปี ในมุมของผู้พูด บริษัทใหญ่ที่มีพลังประมวลผลมากกว่าไปเรียนรู้ไว้ให้ แล้วส่งกล่องที่ผ่านการเรียนรู้แล้ว (Weight Vector) มาให้ใช้ได้เลย

เรียนรู้อะไร ขั้น Pretrained เรียนรู้ความสัมพันธ์ภายในข้อมูลเท่านั้น ซึ่งอธิบายไม่ได้ จึงต้องสร้างความสัมพันธ์จำนวนมาก (พารามิเตอร์พันล้านกว่า) ผู้พูดเรียกการเรียนแบบนี้ว่า Unsupervised Learning เหมือนโมเดล NLP ทั่วไปที่หา pattern แต่เมื่อไปใช้กับงานเฉพาะทาง ผู้พูดมองว่าการให้ผู้ใช้ใส่ Prompt กรอบเองก็ใช้ได้ แต่ต้องพึ่งโชคมากเกินไป จึงต้องสอนโมเดลเพิ่ม

การเปรียบเทียบของผู้พูด LLM เหมือนคนที่ "รู้เยอะ" (เรียนข้อมูลมาเป็นพันล้านตัว; โมเดลที่เปิดดูเรียนมา 200–300 GB) แต่ไม่รู้ว่าอะไรถูกอะไรผิด คนที่รู้คือมนุษย์ เราจึงต้อง เสี้ยมสอน เช่น ถ้าถามว่าน้ำสีอะไรแล้วโมเดลตอบสีม่วง ถือว่าผิด นี่คือ Supervised Learning คือการ label ข้อมูลที่ได้ผลลัพธ์จาก LLM แล้ว Fine-tune ได้โมเดลใหม่ที่เรียกว่า Instruct Model (ตัวอย่างที่ผู้พูดชี้: GPT-3.5)

ข้อที่ควรเข้าใจให้ตรง

ผู้จัดทำตรวจ: ผู้พูดเรียกขั้นแรกว่า Unsupervised Learning แต่ภาพจากบทความที่ผู้พูดเปิดดูในตอน ~48:20 เขียนว่า "Self-supervised learning" ในขั้น Pre-training และ "Human-feedback learning" ในขั้นถัดมา ภาพนั้นสื่อความหมายเดียวกับที่ผู้พูดต้องการสื่อ คือขั้นนี้ไม่มีมนุษย์บอกถูกผิด จึงไม่ได้เปลี่ยนใจความ เพียงเลือกใช้คำให้ตรงกับภาพ

ภาพที่ผู้พูดเตรียมไว้ LLM หนึ่งตัวสร้างข้อความได้หลายแบบ มนุษย์คัดกรองว่าถ้าเป็น Prompt แบบนี้ Desired Input/Output ควรเป็นอย่างไร ผู้พูดบอกว่าประโยชน์ของ LLM ยังอยู่ที่การหาความใกล้เคียงของข้อมูล เพราะท้ายสุดทุกอย่างถูกแปลงเป็นเวกเตอร์ ยกตัวอย่าง: เมื่อต้องตอบสวัสดีแล้วกลับเป็นบองชู้ หากไม่ผ่านการสอน LLM อาจต่อบทไปแบบแปลก ๆ หรือเป็นภาษาเก๋ไก๋ขึ้นตามข้อมูลที่เรียนมา (เช่นเรียนจากงานวิจัยก็อาจตอบเป็นทางการมากขึ้น) Instruct Model จึงคือการสอนว่าเมื่อมีคนถามควร action อย่างไร ตัวอย่างที่ผู้พูดยกคือ Falcon Instruct และอีกตัวที่ถอดเสียงได้ว่า DALL-E 2 (น่าจะหมายถึง Dolly 2) และเป็นขั้นแรกที่ต้องทำ แต่ยังไม่ใช่ขั้นสุดท้าย

9. Reinforcement Learning กับ LLM และภาพรวมการเรียนรู้ (~40:31–50:17)

ปมของหัวข้อ ผู้พูดบอกว่า Instruct ยังไม่ใช่ process สุดท้าย ของที่เราเห็นในระดับ ChatGPT, Claude ผ่านขั้น Reinforcement Learning Fine-tuned LLM เพื่อไม่ต้องนั่งสอนว่าถูกผิดจากการรวบรวมข้อมูลแล้วเทรนใหม่อย่างเดียว

แนวคิด RL ด้วยสองตัวอย่างในชีวิต ทารกร้องไห้ได้นม (agent ทำ action → ได้ reward) และ หนูในเขาวงกตที่เจอชีส (ตอนแรกเดินมั่ว พอเจอทางออกได้ชีส ครั้งหน้าจะกระตือรือร้นขึ้น) RL คือ AI รูปแบบหนึ่งที่ map state, action, reward เอาไว้ (Q-Learning เป็นตาราง state-action) ตัวอย่างหุ่นยนต์ในตาราง: ช่องที่ใกล้ทางออกได้ reward มากกว่า ช่องที่โดนระเบิดได้ 0

Deep Reinforcement Learning → LLM จากตาราง state-action เปลี่ยนเป็น Neural Network ให้เรียนรู้ reward เอง แล้ว feed กลับไปปรับ weight ให้ได้ reward ดีขึ้น ผู้พูดมอง Neural Network ตัวนี้เป็น LLM: ใส่ prompt แล้วให้ reward ว่าตอบถูกหรือผิด จะได้ไม่ต้อง fine-tune ตลอดเวลา (ตัวอย่างเดิม: ตอบน้ำสีม่วงได้คะแนนติดลบ รอบหน้าความน่าจะเป็นของคำว่าม่วงลดลง ส่วนน้ำเงินเพิ่มขึ้น)

ตัวอย่างใน ChatGPT ผู้พูดลองถาม ChatGPT ว่า Who is Michael J. Fox (เขาคาดว่าโมเดลรุ่นนั้นน่าจะตอบไม่ได้เพราะข้อมูลสิ้นสุดที่ปีหนึ่ง [ฟังไม่ชัด] แต่ก็ได้คำตอบ) แล้วชี้ปุ่ม bad response และ Regenerate: การกด bad response เปรียบเหมือนการให้ reward ว่าคำตอบนี้ไม่ work รอบหน้าอาจไม่หยิบคำตอบนี้ เขาอธิบายว่าได้ a b c d แล้วให้คะแนนว่าควรตอบ c มากกว่า b จนได้ Neural Network ที่จูนด้วย reward model ผู้ใช้ที่ใช้ฟีเจอร์นี้จึงเป็นส่วนหนึ่งของการจูนโมเดล และการจูนต้องมีกระบวนการถ่วงน้ำหนักเพื่อไม่ให้ bias เกินไป (เขายกตัวอย่าง SimSimi แชตบอตเก่าที่หลายคนเคยเล่น ซึ่งถูกสอนจนกลายเป็นหยาบคาย; ถอดเสียงได้ว่า บิซิมิ) กระบวนการนี้มีชื่อว่า Reinforcement Learning from Human Feedback และผู้พูดบอกว่า GPT-4 ใช้

ข้อที่ควรเข้าใจให้ตรง

ผู้จัดทำตรวจ: ตามเอกสาร InstructGPT ขั้นตอนจริงคือ labeler จัดอันดับคำตอบหลายแบบ เพื่อฝึก reward model แล้วจึงใช้ RL กับโมเดล (ดูตารางตรวจข้อเท็จจริง) ผู้จัดทำไม่พบแหล่งที่อ่านซึ่งบอกว่าการกดปุ่ม bad response หนึ่งครั้งปรับน้ำหนักโมเดลทันที จึงควรอ่านที่ผู้พูดอธิบายว่าเป็นภาพแทนแนวคิดว่า feedback คือ reward ไม่ใช่กลไกแบบทันที

ข้อสรุปเชิงความหมาย (~46:38–48:11) LLM / AI ที่เห็น คือโมเดลภาษาที่มนุษย์คอยจูนจนได้โมเดลที่ตอบโจทย์มนุษย์ ผู้พูดบอกว่ามัน "ไม่ใช่ magic" ถ้าในอนาคตนิยามจิตวิญญาณของ AI และความต้องการของมันได้ชัดเจน AI น่าจะแทนมนุษย์ได้ แต่ ณ ปัจจุบันมนุษย์ยังเป็นคนกรอบผลลัพธ์ผ่าน Instruct, Supervised และ feedback

สรุปภาพรวมและทำไมแต่ละเจ้าต่างกัน (~48:11–50:17) โมเดลฐาน → Fine-tune เป็น Instruct Model → feedback learning จนได้ Augmented Model ที่ใช้ในแอป (นี่คือลำดับที่ผู้พูดอ่านจากภาพ; ในภาพจริง Augmented model มาจากขั้น Prompting) ใน UI ทั้งหมดอยู่ในระดับ Instruct Model แต่ละเจ้า fine-tune และให้ reward ไม่เหมือนกัน จึงได้ผลต่างกันแม้ใช้ GPT-3 เหมือนกัน คีย์เวิร์ดที่ผู้พูดแนะนำให้ศึกษา: Pretrained, Fine-tune, Prompting และเขาแนะนำศาสตร์ Prompting (รวม Chain of Thought) เป็นพิเศษ เพราะผลลัพธ์ขึ้นกับว่าสั่งดีหรือไม่ดี (ที่ ~49:54 เขาบอกว่าถ้ามีโอกาสอาจกลับมาเล่าเรื่อง Prompt Engineer เพิ่ม แต่ยังไม่หยิบมาตอนนี้เพราะมีเนื้อหามาก)

10. Multimodal: ภาพ เสียง วิดีโอ (~50:17–53:42)

ผู้พูดบอกว่าเนื้อหาที่เล่ามาหยุดอยู่ราวปี 2023 และประเด็นสร้าง AI มาแทนที่อุตสาหกรรมเพิ่งถูกพูดถึงในครึ่งปีหลังของปีก่อน (~50:29) แต่ Generative AI ไม่ได้สร้างแค่ข้อความ สิ่งใดที่ AI สร้างก็เป็น Generative หมด ข้อมูลดิจิทัลไม่ได้มีแค่ text ภาพเป็นตัวอย่างที่ใกล้ตัว

แนวคิด แปลงให้เป็น pattern เดียวกับ text คือเวกเตอร์: เพิ่ม Encoder เพื่อเปลี่ยนภาพ เสียง วิดีโอเป็นเวกเตอร์ แล้วสร้างความสัมพันธ์ระหว่างข้อมูลต่างชนิด จะได้ LLM ที่ support ข้อมูลเหล่านี้ ซึ่งผู้พูดบอกว่าโมเดลแบบนี้ใหญ่กว่ารุ่นข้อความอย่างมาก (ข้อมูลพื้นฐานเป็น binary; วิดีโอ "เละเทะ") ตัวใหม่ล่าสุดตอนที่พูดคือ Sora ที่สร้างวิดีโอจากข้อความ ไอเดียคือใส่ prompt พร้อม instruction ว่าต้องการวิดีโอ แล้วจากเดิมที่จับคู่ text กับ text ก็เป็นจับคู่ text กับ video แทน ผู้พูดบอกว่าต่อไปเราอาจไม่รู้ด้วยซ้ำว่าอะไรคนสร้างหรือ AI สร้าง แต่เบื้องหลังยังคือ Transformer และ LLM

ผู้พูดสรุปว่า ข้อมูลทั้งหมดจะถูกแปลงเป็นรูปแบบเดียวกัน (เวกเตอร์) เพื่อคำนวณ Attention และทำความเข้าใจร่วมกัน แล้วได้ผลออกมาเป็นภาพหรือวิดีโอ เรียกอย่างเป็นทางการว่า Multimodal (ผู้พูดบอกให้ไป search คำนี้) ตอนนั้นยังมีโมเดลที่รองรับไม่มาก ส่วนใหญ่เป็นโมเดลแบบ API อย่าง GPT-4 ที่รองรับแล้ว ส่วน Gemini ผู้พูดคิดว่าคงมีรุ่นที่รองรับภาพและเสียงออกมาแน่นอน

11. เครื่องมือที่ผู้พูดใช้ และ RAG (~53:42–59:05)

ส่วนนี้เป็นการเล่าประสบการณ์ ณ วันที่บันทึก (ผู้พูดบอกว่าบันทึกวันที่ 27 ของปี 2024 โดยไม่ระบุเดือน; คลิปเผยแพร่ 28 มี.ค. 2024) ว่าตอนนี้โลกปล่อย GPT-4 แล้ว ทุกอย่างในหัวข้อนี้เป็นความเห็นส่วนตัวของเขา ไม่ใช่ผลทดสอบ

  • GPT-4 ถ้าถามผู้พูด ยังเป็นโมเดลที่คนชอบในแง่ความคิดสร้างสรรค์; look and feel ฟุ้ง ๆ แต่ฟุ้งแล้วได้ไอเดียใหม่
  • Gemini เปลี่ยนชื่อมาจาก Bard ใช้ชื่อเดียวกันทั้งส่วนที่เป็น LLM และ Instruct จุดแข็งคือเชื่อมต่อบริการของ Google ได้เมื่อใช้ Gemini Advanced และสร้างภาพได้ (ตัวอย่างสั่งสร้างภาพแมวที่กำลังเขียนโค้ด) ซึ่งใช้ความสามารถ Multimodal
  • Claude สิ่งที่ผู้พูดชอบที่สุดคือภาษาไทยอยู่ในเกณฑ์ดีมาก เขาทดสอบถาม "LLM คืออะไร": Claude ตอบเป็นภาษาไทยได้อย่างลื่นไหล ส่วน GPT-3.5 เมื่อถามว่า LLM คืออะไร ตอบเป็น Master of Law (ผู้พูดว่าไม่น่าใช่) พอเขาถามใหม่ด้วยชื่อเต็ม Large Language Model ก็ตอบได้ แต่ผู้พูดมองว่าสำนวนภาษาไทยแข็งกว่า; ผู้พูดว่าโจทย์คณิตศาสตร์หลายอย่างที่ลอง Claude ทำได้ดีกว่า ChatGPT ค่อนข้างมาก (ตามประสบการณ์เขา)
  • Perplexity ตัวที่เขาใช้เป็นหลัก เป็น LLM ที่ใช้แหล่งข้อมูลภายนอก ค้นข้อมูลจากอินเทอร์เน็ตเหมือน Google แล้วนำผลมาผสมและสรุป ซึ่งเกี่ยวกับ (บางส่วน) แนวคิด RAG

RAG ตามที่ผู้พูดอธิบาย (เขายอมรับว่ายังไม่ลึก และอาจทำเพิ่มภายหลัง) จุดอ่อนของ LLM คือถูกจำกัดที่ข้อมูลตอนเทรน: ถ้าส่งข้อมูลเข้าถึงปี 2023 ก็ตอบ "ปัจจุบัน" ไม่ได้ RAG คือการนำ source ภายนอกมาผสม รวมถึงงานเฉพาะทาง (เช่น AI ทางการแพทย์ ที่ข้อมูลของ base model อาจไม่พอ) เพื่อใช้ความเก่งทางภาษาของ LLM วิเคราะห์ข้อมูลนั้น ตัวอย่างที่เขายกคือ ChatGPT แบบที่เกี่ยวกับงาน research ซึ่งไปดึงงานวิจัยมาใส่ให้ LLM ใหม่ (~58:05)

เรื่องจ่ายเงิน เหตุผลที่ผู้พูดชอบ Perplexity คือเลือกโมเดลได้ (เมื่อจ่าย) เช่นบางจังหวะอยากได้ GPT-4 เพราะฟุ้งกว่า บางจังหวะอยากได้ Claude (~58:26–58:38) และ AI ทุกเจ้าเมื่อจ่ายเงินจะได้ base model ที่เก่งที่สุดของแต่ละเจ้า: Gemini Advanced, ChatGPT 4, Claude 3 Opus

12. สรุปทั้งหมดและส่งท้าย (~59:05–62:23)

ผู้พูดทวนตามลำดับเดิมของคลิป: Generative AI คือของที่ AI สร้างออกมา → จุดเริ่มคือ Transformer และ Neural Network (Neural Network เป็น base know-how ของ Deep Learning ที่ใช้สร้างทุกอย่าง ต่างกันที่การเรียบเรียง) → Transformer แปลงข้อมูลชุดหนึ่งเป็นสิ่งที่คำนวณใน Neural Network ได้ เช่นเวกเตอร์ → เมื่อพารามิเตอร์มาก ๆ ได้ Large Language Model → LLM ยังไม่ตอบโจทย์เพราะต้องมี prompt มาก จึงมี Instruct (มนุษย์เสี้ยมสอน) → ปรับอีกเวอร์ชันให้รับ feedback จากผู้เชี่ยวชาญและผู้ใช้ทั่วไป คือเพิ่ม Reinforcement Learning เข้าไปใน fine-tune → ต่อยอดไปสู่ข้อมูลแต่ละประเภท (text, image) ด้วย concept เดียวกัน

ส่งท้าย ผู้พูดบอกว่าเรื่องนี้โลกยังพัฒนาต่ออย่างต่อเนื่อง สิ่งที่เล่าอยู่อาจเป็นเรื่องเก่าเมื่อผู้ชมมาดูในอนาคต เพราะ LLM "แทบจะเกิดมาใหม่ทุก ๆ วัน" (ดูได้จาก Hugging Face ที่เป็น AI Community) ชวนติดตามว่าจะมีบทบาทต่ออุตสาหกรรมแค่ไหน จะแทนคนได้หรือไม่ และจะนำไปสู่ LLM ที่เรียนรู้กันเองได้หรือไม่ เขาย้ำว่าเรื่องนี้ใหม่สำหรับเขาเช่นกัน ชวนคอมเมนต์ถ้ามีรายละเอียดที่ตกหล่น และบอกว่าจะกลับมาในสัปดาห์ถัดไป

13. Flow การเล่าให้เข้าใจง่ายของคลิปนี้ — แม่แบบ (วิเคราะห์โดยผู้จัดทำ) (~0:00–62:23)

Key Takeaways

1.Generative AI คือสิ่งที่ AI สร้างขึ้น ไม่ใช่ของที่มีต้นฉบับจากคน และเบื้องหลังเป็น Neural Network ที่เปลี่ยน condition ให้เป็นความน่าจะเป็นซ้อนกันหลายชั้น
2.Transformer เปลี่ยนข้อความเป็นเวกเตอร์ แล้วใช้ Attention คำนวณความสัมพันธ์ทั้งชุด (จึงไม่ลืมต้นประโยคแบบ RNN); LLM คือ Transformer ที่พารามิเตอร์มากพอ และสร้างคำตอบทีละคำวนจนจบ
3.Prompt / In-Context Learning คือการสอนผ่านข้อความโดยไม่ปรับโมเดล แต่ผู้พูดเตือนว่าได้ผลบ้างไม่ได้บ้าง จึงมี Instruct (มนุษย์สอนถูก/ผิด) และ RL (feedback เป็น reward) ต่อ
4.แต่ละเจ้าได้ผลต่างกันเพราะ Instruct และ reward ต่างกัน แม้ใช้โมเดลฐานเดียวกัน; ข้อที่ต้องแก้ความเข้าใจ: ผัง Encoder-Decoder เป็นภาพประกอบง่าย ๆ (GPT เป็น decoder-only), ตัวเลข Bard 300 กว่าล้านไม่พบในแหล่งที่อ่าน, กด bad response ไม่ได้ปรับโมเดลทันที
5.Flow การเล่าที่ทำให้เข้าใจง่าย: ชื่อที่คุ้น → สัญญาขอบเขต → ฉากง่าย → คำถามที่รู้สึกได้ → ตัวอย่างเดียวเพิ่มทีละตัว → ชื่อมาหลังภาพ → ประโยคเดียว → ขั้นบันไดพร้อมอุปมาและสรุปซ้ำ
