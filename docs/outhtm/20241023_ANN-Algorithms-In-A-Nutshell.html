เดโมโดยผู้จัดทำ (ไม่ได้มาจากต้นฉบับ)

เดโมนี้วาดพื้นตารางและกล่องแบบเดียวกับภาพในคลิป (~0:28–0:39) แต่ให้ผู้อ่านลงมือเอง กล่องสีน้ำเงินคือข้อมูลที่เก็บไว้ เส้นที่โยงกล่องคือกราฟที่บอกว่ากล่องไหนเป็นเพื่อนบ้านกัน (ผู้จัดทำต่อแต่ละกล่องกับ 3 กล่องที่ใกล้ที่สุด) และกล่องสีชมพูคือคำถาม

สิ่งที่ลองได้:

  • กด ทีละขั้น หรือ เล่น เพื่อดูการค้นเริ่มจากจุดเริ่ม (entry point) แล้ววัดระยะเพื่อนบ้าน เก็บ ef จุดที่ใกล้คำถามที่สุด และย้ายศูนย์กลางไปจุดที่ดีที่สุด เหมือนข้อความ "calculate 3 closest to query" และ "recenter on best candidate" บนจอ
  • แตะช่องว่างบนพื้นเพื่อย้ายคำถาม เลื่อน ef จาก 1 ถึง 6 หรือกด สุ่มจุดเริ่ม แล้วดูว่าคำตอบยังตรงกับจุดที่ใกล้ที่สุดจริงไหม
  • สลับเป็น kNN: วัดทุกจุด เพื่อเทียบจำนวนครั้งที่ต้องวัดระยะ
  • กด ทดสอบ 300 คำถามสุ่ม เพื่อดูตารางว่า ef แต่ละค่าได้คำตอบถูกกี่เปอร์เซ็นต์ และวัดระยะเฉลี่ยกี่ครั้ง ซึ่งคือการแลกระหว่างความแม่นกับความเร็วที่คลิปพูดถึง

บทสรุปย่อ

คลิปสั้น 1 นาทีจาก Weaviate อธิบายว่า ANN (Approximate Nearest Neighbor อัลกอริทึมหาเพื่อนบ้านที่ใกล้ที่สุดแบบประมาณ) คือวิธีที่ระบบค้นหาใช้ดึงข้อมูลให้ search engine, ระบบแนะนำ และงานจดจำภาพ ต่างจาก kNN ที่วัดระยะจากคำถามไปทุกเอกสาร ANN ตั้งใจแลกระหว่างความแม่นกับความเร็ว โดยยอมเสียความแม่นแบบเป๊ะ และไม่รับประกันว่าจะได้ตัวที่ใกล้ที่สุดจริง แต่ผู้ใช้ดึงเวกเตอร์ชุดบน ๆ ได้ภายในไม่กี่มิลลิวินาทีแม้จาก object หนึ่งพันล้านชิ้น ระหว่างนั้นจอแสดงภาพการค้นบนกราฟด้วย ef = 3 และปิดท้ายว่า ANN มีมากมายหลายแบบ แต่ละแบบมีจุดแข็งและข้อเสีย และสำคัญมากต่อแอปที่ต้องรับข้อมูลจำนวนมาก

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ครบทุกประเด็นและตัวเลข (คลิปใช้ YouTube standard license)

ผังภาพรวม

ในภาพนี้:

  1. กล่องแรกคือคำถามที่ผู้ใช้ส่งเข้ามา ซึ่งอาจเป็นข้อความหรือภาพ ตามงานที่คลิปยกมา
  2. กล่องที่เน้นสีคือ ANN algorithm ซึ่งใช้เทคนิคต่าง ๆ เร่งการดึงข้อมูล ต่างจาก kNN ที่คำนวณระยะไปทุกเอกสาร
  3. ลูกศรที่เขียนว่า "เสียความแม่นแบบเป๊ะ" บอกว่า ANN ใช้เทคนิคต่าง ๆ เพื่อให้เร็ว และยอมเสียความแม่นแบบเป๊ะไประหว่างทาง
  4. ผลคือเวกเตอร์ชุดบน ๆ (ข้อมูลกลุ่มแรกที่ใกล้คำถามที่สุด) ที่ผู้ใช้ดึงได้ภายในไม่กี่มิลลิวินาที แล้วถูกส่งกลับถึงผู้ใช้

ภาพนี้บอกว่า ทั้งคลิปเล่าเส้นทางเดียว คือคำถามเข้า ANN แล้วได้ผลที่เร็วพอสำหรับข้อมูลจำนวนมาก โดยยอมเสียความแม่นแบบเป๊ะ

1. ANN คืออะไร และถูกใช้ในงานไหน (~0:00–0:11)

หัวข้อนี้จะพาดูอะไร: ชื่อเต็มของ ANN และงานสามแบบที่คลิปบอกว่าระบบค้นหาใช้ ANN ช่วย

ใจความ: คลิปนี้มาจากช่อง Weaviate vector database (ผู้จัดทำ: Weaviate เป็นบริษัทที่ทำฐานข้อมูลเวกเตอร์ ตามชื่อช่อง) ผู้พูดเปิดคลิปด้วยชื่อเต็ม Approximate Nearest Neighbor หรือ ANN แปลตรงตัวว่า "เพื่อนบ้านที่ใกล้ที่สุดแบบประมาณ" (ผู้จัดทำ: คำว่าเพื่อนบ้านในที่นี้หมายถึงข้อมูลที่เก็บไว้ซึ่งอยู่ใกล้สิ่งที่ผู้ใช้ถาม ส่วนคำว่าประมาณบอกว่าคำตอบอาจไม่ใช่ตัวที่ใกล้ที่สุดเป๊ะ) ผู้พูดบอกว่าอัลกอริทึมกลุ่มนี้ถูกใช้โดยระบบค้นหา (search system) เพื่อช่วยการดึงข้อมูล (information retrieval) ให้กับงานสามแบบ (ผู้จัดทำ: ทั้งสามงานต้องตอบคำถามว่า "ของชิ้นไหนในคลังคล้ายกับสิ่งที่ถามมากที่สุด")

ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (ผู้จัดทำยกขึ้นเอง ไม่ได้มาจากคลิป)

ผู้ใช้พิมพ์คำว่า "รองเท้าวิ่ง" ลงในร้านออนไลน์ ระบบค้นหาต้องหาสินค้าที่ใกล้คำนี้ที่สุดจากคลังสินค้าทั้งหมด แล้วส่งรายการกลับมาให้ผู้ใช้

เสริมจากผู้จัดทำ: "ใกล้" วัดกันอย่างไร

ผู้จัดทำ: คลิปไม่ได้อธิบายส่วนนี้ ระบบแบบนี้มักแปลงข้อมูลแต่ละชิ้น ทั้งข้อความ สินค้า และภาพ เป็นชุดตัวเลขที่เรียกว่าเวกเตอร์ (vector) โดยให้ของที่ความหมายคล้ายกันได้ชุดตัวเลขที่ใกล้กัน ความใกล้จึงวัดเป็นระยะระหว่างเวกเตอร์สองชุดได้ คำว่า "เวกเตอร์ชุดบน ๆ" ในหัวข้อ 3 จึงหมายถึงข้อมูลกลุ่มแรกที่อยู่ใกล้คำถามที่สุด

งานสามแบบที่คลิปยกมา (คำอธิบายของแต่ละงานเป็นของผู้จัดทำ):

  • search engine ใช้ ANN หาเอกสารหรือหน้าเว็บที่เกี่ยวข้องกับคำค้นของผู้ใช้ เช่นหาสินค้าที่ใกล้คำว่า "รองเท้าวิ่ง"
  • ระบบแนะนำ (recommendation system) ใช้ ANN หาสินค้าหรือเนื้อหาที่คล้ายกับสิ่งที่ผู้ใช้สนใจ เพื่อแนะนำของชิ้นถัดไป
  • งานจดจำภาพ (image recognition) ใช้ ANN หาภาพในคลังที่คล้ายกับภาพที่ส่งเข้ามา

ในภาพนี้:

  1. ชั้นบนสุดคืองานสามแบบที่คลิปยกมา ได้แก่ search engine, ระบบแนะนำ และงานจดจำภาพ ซึ่งเป็นงานที่ผู้ใช้เห็นผลโดยตรง
  2. ชั้นกลางคือระบบค้นหาที่ทำหน้าที่ดึงข้อมูล (information retrieval) ให้กับงานชั้นบน
  3. ชั้นล่างที่เน้นสีคือ ANN algorithm ซึ่งเป็นเครื่องมือที่ระบบค้นหาใช้หาของที่ใกล้คำถาม

ภาพนี้บอกว่า ANN ไม่ใช่แอปที่ผู้ใช้เห็นเอง แต่เป็นชิ้นส่วนด้านล่างที่ระบบค้นหาใช้ดึงข้อมูลให้งานทั้งสามแบบ

เอาไปใช้ทำอะไร: เมื่อเห็นงานที่ต้องหา "ของที่คล้ายที่สุด" จากคลังใหญ่ ทั้งการค้น การแนะนำ หรือการเทียบภาพ ให้นึกว่าระบบค้นหาตัวนั้นมักมี ANN อยู่ข้างใน

2. kNN วัดทุกเอกสาร ส่วน ANN ตั้งใจแลกความแม่นกับความเร็ว (~0:11–0:28)

หัวข้อนี้จะพาดูอะไร: ความต่างระหว่าง kNN กับ ANN และสิ่งที่ ANN ยอมเสียไปเพื่อให้ค้นเร็วขึ้น

ใจความ: ผู้พูดเทียบ ANN กับ kNN หรือ k Nearest Neighbors (หา k ตัวที่ใกล้ที่สุด) kNN คำนวณระยะจริงระหว่างคำถามกับเอกสารทุกชิ้นในคลัง ทีละชิ้นจนครบ ส่วนอัลกอริทึม ANN เลือกแลกระหว่างความแม่นกับความเร็วในการดึงข้อมูลอย่างตั้งใจ อัลกอริทึม ANN ใช้เทคนิคต่าง ๆ เพื่อเร่งเวลาดึงข้อมูล และในกระบวนการนั้นก็ยอมเสียความแม่นแบบเป๊ะไป คลิปไม่ได้บอกว่าเทคนิคเหล่านั้นคืออะไร แต่หัวข้อถัดไปมีภาพบนจอที่แสดงหนึ่งในวิธีให้ดู

ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (ผู้จัดทำยกขึ้นเอง ไม่ได้มาจากคลิป)

คลังมีเอกสาร 1,000 ชิ้น kNN ต้องวัดระยะจากคำถามไปครบทั้ง 1,000 ชิ้นก่อนจะตอบ ส่วน ANN อาจวัดเพียงบางส่วน แล้วตอบจากชิ้นที่ได้วัด

ในภาพนี้:

  1. ฝั่งซ้ายคือ kNN ซึ่งคำนวณระยะจริงระหว่างคำถามกับเอกสาร และทำแบบนี้กับเอกสารทุกชิ้น ในตัวอย่างจึงต้องวัดครบ 1,000 ครั้ง
  2. ฝั่งขวาคือ ANN และแถวบนที่เน้นสีคือหัวใจของมัน คือใช้เทคนิคต่าง ๆ เพื่อเร่งเวลาดึงข้อมูล และยอมเสียความแม่นแบบเป๊ะไประหว่างทาง
  3. ลูกศรตรงกลางเขียนว่า "แลกความแม่นกับความเร็ว" ซึ่งคือคำที่ผู้พูดใช้อธิบายสิ่งที่ ANN เลือกทำอย่างตั้งใจ
  4. บรรทัดตัวอย่างในฝั่ง ANN มีป้าย (ผู้จัดทำ) เพราะคลิปไม่ได้บอกว่า ANN วัดกี่ชิ้น

ภาพนี้บอกว่า kNN คำนวณระยะจริงกับทุกชิ้น ส่วน ANN ใช้เทคนิคเร่งความเร็วและยอมเสียความแม่นแบบเป๊ะ (ผู้จัดทำ: จึงอาจวัดเพียงบางส่วน)

เสริมจากผู้จัดทำ: ความแม่นที่เสียไปหน้าตาเป็นอย่างไร

ผู้จัดทำ: "เสียความแม่น" ในที่นี้ไม่ได้แปลว่าคำตอบผิดไปไกล แต่แปลว่าบางครั้งตัวที่ได้อาจไม่ใช่ตัวที่ใกล้ที่สุดอันดับหนึ่งจริง ปุ่ม "ทดสอบ 300 คำถามสุ่ม" ในเดโม "ลองเล่น" ที่ต้นหน้านี้แสดงเรื่องนี้เป็นตัวเลข เมื่อให้การค้นเก็บตัวเลือกไว้มากขึ้นในแต่ละขั้น (ค่าที่หัวข้อ 3 เรียกว่า ef) อัตราที่ได้ตัวใกล้ที่สุดจริงสูงขึ้น แต่จำนวนครั้งที่ต้องวัดระยะก็เพิ่มตาม ตัวเลขในตารางนั้นมาจากข้อมูลจำลองของเดโม ไม่ได้มาจากคลิป

เอาไปใช้ทำอะไร: เวลาเลือกระหว่างค้นทุกชิ้นกับค้นแบบ ANN ให้ถามว่างานนั้นยอมรับคำตอบที่ "ใกล้มากแต่อาจไม่ใช่อันดับหนึ่งเป๊ะ" ได้ไหม ถ้าได้ ANN แลกส่วนนั้นเป็นความเร็ว

3. ไม่รับประกันตัวที่ใกล้ที่สุดจริง แต่ได้ผลในไม่กี่มิลลิวินาที และภาพการค้นบนกราฟ (~0:28–0:39)

หัวข้อนี้จะพาดูอะไร: ข้อจำกัดและข้อดีของ ANN ที่ผู้พูดสรุปไว้ พร้อมภาพเคลื่อนไหวบนจอที่แสดงการค้นบนกราฟทีละขั้น

ใจความ: ผู้พูดบอกตรง ๆ ว่า ANN ไม่รับประกันว่าจะได้เพื่อนบ้านที่ใกล้ที่สุดจริง แต่ด้วย ANN ผู้ใช้ดึงเวกเตอร์ชุดบน ๆ (top vectors หรือข้อมูลที่ใกล้คำถามที่สุดกลุ่มแรก) ได้ภายในไม่กี่มิลลิวินาที แม้จะค้นจาก object หนึ่งพันล้านชิ้น ระหว่างที่พูดประโยคนี้ จอแสดงภาพเคลื่อนไหวของการค้นบนกราฟ ภาพนั้นวางข้อมูลเป็นกล่องบนพื้นตาราง โยงกล่องที่เป็นเพื่อนบ้านกันด้วยเส้น แล้วเดินจากจุดเริ่มเข้าหาคำถามทีละขั้น ผู้พูดไม่ได้อธิบายภาพนี้ด้วยคำพูด คำอธิบายภาพด้านล่างจึงมาจากข้อความบนจอและสิ่งที่เห็นในภาพ และส่วนที่ผู้จัดทำอ่านเพิ่มมีป้ายกำกับ

ในภาพนี้:

  1. กล่องสีน้ำเงินแต่ละกล่องคือข้อมูลหนึ่งชิ้นที่เก็บไว้ (ผู้จัดทำ: ตำแหน่งบนพื้นแทนเวกเตอร์ของข้อมูลชิ้นนั้นแบบย่อเหลือสองมิติ กล่องที่อยู่ใกล้กันจึงหมายถึงข้อมูลที่คล้ายกัน)
  2. เส้นสีน้ำเงินเข้มโยงกล่องที่เป็นเพื่อนบ้านกัน (ผู้จัดทำ: การค้นในภาพต่อ ๆ ไปเดินไปตามเส้นเหล่านี้ บนจอไม่ได้บอกว่าเส้นถูกโยงอย่างไร ดัชนีแบบกราฟโดยทั่วไปโยงแต่ละจุดกับจุดที่อยู่ใกล้มันตั้งแต่ตอนสร้างดัชนี)
  3. กล่องสีชมพูที่มีป้าย query คือคำถาม ซึ่งเป็นตำแหน่งที่อยากหาข้อมูลที่อยู่ใกล้ที่สุด
  4. ข้อความใต้ภาพ querying the top_k=1 results แปลว่าขอผลลัพธ์เพียงตัวเดียวที่ใกล้ที่สุด

ภาพนี้บอกว่า ก่อนเริ่มค้น ข้อมูลถูกจัดเป็นกราฟไว้แล้ว และงานคือหากล่องหนึ่งกล่องที่ใกล้กล่องสีชมพูที่สุด

ในภาพนี้:

  1. ข้อความมุมซ้ายบน ef = 3 คือค่าที่บนจอใช้ และข้อความใต้ภาพ calculate 3 closest to query บอกว่าทุกขั้นจะหา 3 ตัวที่ใกล้คำถามที่สุด
  2. กล่องด้านบนที่มีป้าย entry point คือจุดเริ่ม การค้นเริ่มจากกล่องนี้ ไม่ได้เริ่มจากทุกกล่องพร้อมกัน (บนจอไม่ได้บอกว่าเลือกกล่องนี้อย่างไร)
  3. กล่องสีเขียวสองกล่องกับกล่องสีเหลืองหนึ่งกล่องรวมเป็น 3 ตัวที่ใกล้คำถามที่สุดในขั้นนี้ และกล่องสีเหลืองน่าจะเป็นตัวที่ดีที่สุด (best candidate) (ผู้จัดทำอ่านจากภาพถัดไป ในภาพนี้ข้อความยังขึ้นแค่ recenter on)
  4. กล่องสีฟ้าซีดรอบจุดเริ่มคือกล่องที่การค้นผ่านมาแล้ว (ผู้จัดทำอ่านความหมายของสีจากภาพ บนจอไม่มีคำอธิบายสี)

ภาพนี้บอกว่า ขั้นแรกของการค้นเริ่มจากจุดเดียวบนสุด แล้วเลือก 3 ตัวที่ใกล้คำถามที่สุดจากกล่องรอบ ๆ จุดนั้นเท่านั้น

ในภาพนี้:

  1. ข้อความใต้ภาพตอนนี้ครบประโยคว่า recenter on best candidate หมายความว่าศูนย์กลางของการค้นถูกย้ายไปที่กล่องสีเหลืองของขั้นก่อน
  2. กล่องที่เคยเป็นสีเหลืองกลายเป็นสีเขียว และสีเหลืองย้ายไปอยู่ที่กล่องซึ่งใกล้กล่อง query สีชมพูมากขึ้น เพราะ 3 ตัวที่ดีที่สุดถูกเลือกใหม่จากเพื่อนบ้านของศูนย์กลางใหม่ (กล่องไม่ได้ขยับ สีต่างหากที่ย้าย)
  3. กล่องสีฟ้าซีดเพิ่มขึ้นตามทางที่เดินผ่านมา ส่วนกล่องสีน้ำเงินด้านซ้ายยังไม่ถูกแตะ

ภาพนี้บอกว่า การค้นซ้ำวงเดิม คือย้ายศูนย์กลางไปตัวที่ดีที่สุดแล้วเลือก 3 ตัวใหม่ จึงเข้าใกล้คำถามทีละขั้น

ในภาพนี้:

  1. กล่องสีเหลืองซึ่งเป็นตัวที่ดีที่สุดตอนนี้อยู่ติดกับกล่อง query สีชมพูแล้ว
  2. กล่องสีเขียวสองกล่องที่เหลืออยู่ด้านบนของกล่องสีเหลือง และรวมกับมันเป็น 3 ตัวที่ใกล้ที่สุดของขั้นนี้
  3. กล่องสีฟ้าซีดเรียงเป็นทางจากจุดเริ่มลงมาถึงกล่องสีเขียวและสีเหลืองที่อยู่ใกล้คำถาม ส่วนกล่องสีน้ำเงินด้านซ้ายไม่ถูกแตะเลยตลอดทาง

ภาพนี้บอกว่า เมื่อดูทั้งสามภาพต่อกัน การค้นบนจอไม่ได้วัดทุกกล่อง แต่เดินจากจุดเริ่มไปตามเส้น ย้ายศูนย์กลางไปตัวที่ดีที่สุดทีละขั้นจนถึงข้างคำถาม กล่องที่ไม่อยู่บนทางจึงไม่ต้องวัดเลย (ผู้จัดทำอ่านจากสีของกล่อง บนจอไม่ได้บอกจำนวนครั้งที่วัด)

ในภาพนี้: ผังงานอ่านจากบนลงล่าง ทุกกล่องตรงกับภาพจากคลิป ยกเว้นกล่องเงื่อนไขหยุดที่ผู้จัดทำเติม

  1. เริ่มที่จุดเริ่ม (entry point) ซึ่งคือกล่องบนสุดในภาพจากคลิป
  2. วัดระยะจากเพื่อนบ้านของศูนย์กลางไปถึงคำถาม (ผู้จัดทำ: เพราะในภาพการค้นเดินตามเส้นที่โยงไว้)
  3. เก็บไว้ 3 ตัวที่ใกล้คำถามที่สุด ตามค่า ef = 3 บนจอ ซึ่งก็คือกล่องสีเขียวสองกล่องกับสีเหลืองหนึ่งกล่อง
  4. ย้ายศูนย์กลางไปตัวที่ดีที่สุด (กล่องสีเหลือง) ตามข้อความ recenter on best candidate
  5. ถามว่ายังมีตัวที่ใกล้คำถามกว่าเดิมให้ไปต่อไหม ถ้ามีจึงกลับไปข้อ 2 (วัดระยะเพื่อนบ้าน) ถ้าไม่มีก็หยุด (ข้อนี้ผู้จัดทำเติม เพราะบนจอไม่ได้แสดงว่าหยุดเมื่อไร)
  6. ตอบตัวที่ใกล้ที่สุดหนึ่งตัว ตาม top_k = 1 ที่ขอไว้ตั้งแต่ภาพแรก

ภาพนี้บอกว่า สิ่งที่บนจอทำซ้ำคือวงเดียว "วัดเพื่อนบ้าน เก็บ 3 ตัว ย้ายไปตัวที่ดีที่สุด" และวงนี้ทำให้วัดเพียงกล่องที่อยู่ใกล้ทางเดิน ไม่ใช่ทุกกล่อง (ผู้จัดทำอ่านจากสีของกล่อง บนจอไม่ได้บอกจำนวนครั้งที่วัด)

เสริมจากผู้จัดทำ: ภาพนี้คือวิธีแบบไหน

ผู้จัดทำ: ผู้พูดไม่ได้เอ่ยชื่อวิธีในภาพนี้ แต่คำอธิบายใต้คลิปชี้ไปที่หน้าเอกสาร HNSW (Hierarchical Navigable Small World) ของ Weaviate และคำว่า ef, entry point กับการย้ายศูนย์กลางไปตัวที่ดีที่สุด ก็เป็นคำที่ใช้กับการค้นในชั้นหนึ่งของกราฟ HNSW ภาพบนจอแสดงกราฟชั้นเดียว ส่วน HNSW จริงมีกราฟหลายชั้นซ้อนกัน ชั้นบนมีจุดน้อยไว้กระโดดไกลเข้าหาย่านของคำถาม แล้วจึงลงไปค้นละเอียดในชั้นล่างที่มีจุดครบ

เสริมจากผู้จัดทำ: ทำไมการเดินแบบนี้จึง "ไม่รับประกัน"

ผู้จัดทำ: ในภาพของคลิป การเดินไปจบข้างคำถามพอดี แต่ไม่ได้เป็นแบบนั้นเสมอ การค้นหยุดเมื่อเพื่อนบ้านของตัวเลือกที่เก็บไว้ไม่มีตัวไหนใกล้คำถามกว่าเดิม ถ้าตัวที่ใกล้ที่สุดจริงไม่ได้โยงเส้นมาถึงทางที่เดิน การค้นก็หยุดก่อนและตอบตัวที่ใกล้น้อยกว่า นี่คือเหตุผลที่การค้นบนกราฟแบบนี้ไม่รับประกันตัวที่ใกล้ที่สุดจริง (ANN แบบอื่นใช้เทคนิคต่างกัน จึงอาจพลาดด้วยเหตุผลอื่น) ในเดโม "ลองเล่น" ที่ต้นหน้านี้ ลองตั้ง ef = 1 แล้วกด "สุ่มคำถาม" หลาย ๆ ครั้ง จะเห็นช่อง "ตรงกับจุดที่ใกล้ที่สุดจริงไหม" ขึ้นว่าไม่ตรงเป็นบางครั้ง

เอาไปใช้ทำอะไร: (ผู้จัดทำ) ภาพนี้แสดงอย่างน้อยหนึ่งแบบว่า ANN เร็วได้อย่างไร คือเดินเข้าหาคำถามตามเส้นในกราฟแทนการวัดทุกชิ้น และ ef = 3 บนจอคู่กับข้อความ calculate 3 closest to query จึงบอกว่าแต่ละขั้นเก็บตัวเลือกไว้กี่ตัว ลองปรับค่านี้ได้ในเดโม "ลองเล่น" ที่ต้นหน้านี้

4. ANN มีหลายแบบ และสำคัญต่อแอปที่มีข้อมูลมาก (~0:39–0:58)

หัวข้อนี้จะพาดูอะไร: ประโยคปิดท้ายของคลิปว่า ANN มีหลายชนิด และทำไมผู้พูดจึงบอกว่ามันสำคัญมาก พร้อมตัวอย่างแอปสองตัวบนจอ

ใจความ: ผู้พูดบอกว่า ANN มีอยู่มากมายหลายแบบ และทุกแบบมีจุดแข็งและข้อเสียของตัวเอง คลิปไม่ได้ระบุชื่อหรือเทียบแบบต่าง ๆ จากนั้นผู้พูดสรุปว่า ไม่ว่าจะใช้ขับ search engine ให้ดึงข้อมูลที่เกี่ยวข้อง ใช้แนะนำเนื้อหาที่เหมาะกับแต่ละคน หรือใช้ช่วยงานจดจำภาพ อัลกอริทึม ANN ก็สำคัญมากในการช่วยให้แอปรับมือกับข้อมูลจำนวนมาก แล้วส่งผลลัพธ์ที่เร็วและเกี่ยวข้องกลับไปถึงผู้ใช้ งานทั้งสามแบบนี้คืองานชุดเดียวกับที่เปิดคลิปในหัวข้อแรก ระหว่างนั้นจอแสดงตัวอย่างแอปสองตัวประกอบ

ในภาพนี้:

  1. หัวหน้าต่างมีโลโก้และชื่อ Verba พร้อมข้อความ Weaviate Chatbot ซึ่งบอกว่าเป็นแอปแชตตัวอย่างของ Weaviate
  2. ฝั่งซ้ายเป็นช่องแชต ข้อความต้อนรับบอกว่าแอปนี้เก็บเอกสาร บล็อก และวิดีโอของ Weaviate ไว้ และผู้ใช้ถามว่า What is hybrid search?
  3. ฝั่งขวาแสดงเอกสารที่แอปดึงมาได้ ชื่อ Blog Hybrid-search-explained และป้ายมุมล่างบอกว่ากำลังส่งคำถามไปค้นเอกสาร

ภาพนี้บอกว่า ขณะผู้พูดพูดถึง search engine ที่ดึงข้อมูลที่เกี่ยวข้อง จอแสดงแอปที่รับคำถามแล้วค้นเอกสารที่เกี่ยวข้องมาแสดง (ผู้จัดทำ: คลิปไม่ได้บอกว่าแอปนี้ใช้ ANN แบบไหน ภาพนี้จึงเป็นภาพประกอบของงานค้นเอกสาร)

ในภาพนี้:

  1. ข้อความด้านบนบอกว่าจะลองส่งคำถามเพื่อดูว่าสุนัขตัวไหนในคลังคล้ายลูกสุนัข Goldendoodle ที่สุด
  2. ภาพลูกสุนัขขนหยิกสีน้ำตาลในกรอบคือคำถาม ซึ่งเป็นภาพ ไม่ใช่ข้อความ
  3. ใต้หัวข้อ RESULTS มีผลลัพธ์สองภาพ คือ Goldendoodle และ Golden Retriever และข้อความบนหน้าบอกว่าลูกสุนัขคล้ายสองสายพันธุ์นี้ที่อยู่ในฐานข้อมูล
  4. ข้อความด้านล่างบอกว่าผู้ใช้โหลดภาพสุนัขตัวโปรดแล้วดูสายพันธุ์ที่เป็นเพื่อนบ้านที่ใกล้ที่สุดในฐานข้อมูลได้

ภาพนี้บอกว่า แอปภาพบนจอก็ใช้การหาเพื่อนบ้านที่ใกล้ที่สุด (nearest neighbor) เช่นกัน เพียงแต่คำถามเป็นภาพ (ผู้จัดทำ: ภาพก็ถูกแปลงเป็นเวกเตอร์ได้ ภาพสองภาพที่หน้าตาคล้ายกันจึงอยู่ใกล้กัน)

ในภาพนี้:

  1. กล่องแรกคือข้อมูลจำนวนมากในแอป ซึ่งเป็นสิ่งที่ผู้พูดบอกว่าแอปต้องรับมือให้ได้
  2. กล่องที่เน้นสีคือ ANN algorithm ซึ่งมีหลายแบบ และแต่ละแบบมีจุดแข็งกับข้อเสียต่างกัน
  3. กล่องที่สามคือผลลัพธ์ที่เร็วและเกี่ยวข้อง ซึ่งเป็นสิ่งที่ ANN ช่วยให้ได้
  4. ลูกศร "ส่งกลับ" พาผลลัพธ์ไปถึงผู้ใช้ ในงานสามแบบเดียวกับหัวข้อแรก

ภาพนี้บอกว่า เหตุผลที่ผู้พูดเรียก ANN ว่าสำคัญมาก คือมันเป็นทางผ่านที่ทำให้ข้อมูลจำนวนมากกลายเป็นผลลัพธ์ที่เร็วพอและตรงพอสำหรับผู้ใช้

เอาไปใช้ทำอะไร: คลิปบอกว่า ANN ทุกแบบมีจุดแข็งและข้อเสียของตัวเอง (ผู้จัดทำ: เวลาเลือกจึงควรดูว่างานต้องการความเร็วหรือความแม่นมากกว่ากัน)

Key Takeaways

1.ANN (Approximate Nearest Neighbor) ถูกระบบค้นหาใช้ดึงข้อมูลให้ search engine, ระบบแนะนำ และงานจดจำภาพ
2.kNN คำนวณระยะจริงระหว่างคำถามกับเอกสารทุกชิ้น ส่วน ANN ตั้งใจแลกความแม่นกับความเร็วในการดึงข้อมูล
3.ANN ไม่รับประกันว่าจะได้เพื่อนบ้านที่ใกล้ที่สุดจริง แต่ผู้ใช้ดึงเวกเตอร์ชุดบน ๆ ได้ภายในไม่กี่มิลลิวินาที แม้จาก object หนึ่งพันล้านชิ้น
4.ภาพบนจอแสดงการค้นบนกราฟ: เริ่มที่ entry point เก็บ 3 ตัวที่ใกล้คำถามที่สุด (ef = 3) แล้วย้ายศูนย์กลางไปตัวที่ดีที่สุดทีละขั้น
5.ANN มีมากมายหลายแบบ แต่ละแบบมีจุดแข็งและข้อเสีย และสำคัญมากต่อแอปที่ต้องรับข้อมูลจำนวนมากแล้วส่งผลที่เร็วและเกี่ยวข้องให้ผู้ใช้
