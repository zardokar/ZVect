What Are Word Embeddings? — Under The Hood

✍️ Under The Hood📅 เผยแพร่ 2025-02-21⏱ 19:32🎞 caption อังกฤษแบบ auto (ASR)📝 แปลแบบตีความ ครบทุกรายละเอียด 🔗 คลิปต้นฉบับ (YouTube)

📋 บทสรุปย่อ

บทสรุปย่อ: คลิปเล่าว่าทำไมการแปลงข้อความเป็นตัวเลขต้องมี embedding: เลข token ทำให้โมเดลเข้าใจผิดเรื่องความใกล้, one-hot แก้ปัญหานั้นแต่เวกเตอร์ยาวและไม่มีความหมาย, bag of words / n-gram เพิ่มบริบทได้มากขึ้นแต่ยังยาว sparse และไม่จับความหมายลึก จากนั้นอธิบาย word embedding (เวกเตอร์หนาแน่นที่คำคล้ายกันอยู่ใกล้กัน และบวกลบได้ เช่น king − man + woman ≈ queen), วิธีฝึกด้วย Word2Vec (CBOW และ skip-gram) ที่ weight matrix กลายเป็นตาราง lookup, embedding layer ใน decoder ของ Transformer ที่ฝึกไปพร้อมโมเดล และ positional encoding ที่บวกตำแหน่งเข้าไปก่อนเข้า attention

โหมดของเนื้อหา: แปลแบบตีความ ครบทุกรายละเอียด (license มาตรฐานของ YouTube, ตรวจ 2026-10-10) ทุกประเด็นอยู่ครบตามลำดับ 12 บทของคลิป เรียบเรียงด้วยคำของผู้จัดทำโดยไม่เปลี่ยนความหมาย caption เป็นแบบ auto จึงตรวจคำและตัวเลขกับภาพในคลิป ส่วนที่ผู้จัดทำเพิ่มเองอยู่ในส่วนที่ 11 และ 12

🧭 สรุปเชิงลึก

จุดตั้งต้น: โมเดลอย่างตัวกรอง spam หรือตัววิเคราะห์ความรู้สึกของรีวิวหนังต้องรับตัวเลข ตัวอย่างภาพขาวดำแปลงได้ตรง ๆ (สว่างสุด = 1 มืดสุด = 0 ระหว่างนั้นคือเทา) ส่วนข้อความ วิธีง่าย ๆ คือให้เลข token แต่ละคำ แต่เลขแบบนี้เหมาะกับข้อมูลที่มีลำดับจริงเท่านั้น (เช่น low, medium, high) ในตัวอย่าง good = 6, bad = 22, great = 21 โมเดลอาจคิดว่า bad ใกล้ great เพราะ 21 กับ 22 ใกล้กัน ทั้งที่ good กับ great ความหมายใกล้กันจริง

one-hot และ bag of words: one-hot ให้แต่ละคำเป็นเวกเตอร์ยาวเท่าคลังคำ มี 1 ตำแหน่งเดียว จึงไม่มีลำดับแฝงและทำง่าย แต่ถ้าคลังคำมี 50,000 คำ ทุกคำก็เป็นเวกเตอร์ 50,000 มิติที่เกือบทั้งหมดเป็นศูนย์ เปลืองหน่วยความจำและการคำนวณ และไม่รู้ว่า good ใกล้ great bag of words นับจำนวนครั้งที่คำปรากฏ (unigram) ขยายเป็น bigram หรือ n-gram เพื่อเพิ่มบริบท แต่ข้อมูลใหญ่จะได้ n-gram จำนวนมาก เวกเตอร์ใหญ่และ sparse เห็นบริบทได้แค่ไม่กี่คำ และยังไม่จับความหมายลึก จึงไม่พอสำหรับงานแปลภาษาหรือสร้างข้อความ

ต้องเข้าใจทั้งความหมายและบริบท: ประโยคตัวอย่างเรื่อง Sarah ในห้องสมุดเก่า ("…ซ่อนอยู่หลัง ___ ที่มีฝุ่น") ต้องรู้ว่า old ขยาย library ไม่ใช่ Sarah และเดาคำถัดไปได้เป็น table, wall หรือ bookshelf ผู้สอนบอกว่าตรงนี้ word embedding กับ attention มีบทบาทสำคัญ

word embedding: คำเป็นเวกเตอร์หนาแน่นใน vector space ต่อเนื่อง เวกเตอร์คล้ายกัน = คำคล้ายกัน และทิศในพื้นที่มีความหมาย ตัวอย่างไล่จาก 1 มิติ (อายุ) ไป 2 มิติ (อายุ, ความเป็นราชวงศ์) แล้วไปการคำนวณเวกเตอร์: king − man + woman ใกล้ queen และ Beijing + Japan − China ใกล้ Tokyo เรากำหนดเองไม่ได้ว่าแต่ละมิติคืออะไร เพราะขึ้นกับข้อมูลที่ใช้ฝึก embedding มีมิติ "ต่ำ" คือหลักร้อยถึงหลักพัน (one-hot ต้องหลักแสน) เริ่มจากค่าสุ่มแล้วเรียนความหมายระหว่างฝึก และดูได้ด้วยการฉายลงมิติต่ำ เช่น principal component analysis

Word2Vec: Google เสนอไว้ (paper ระบุในคำอธิบายคลิป) มีสองแบบ: CBOW ใช้คำรอบข้างทำนายคำกลาง (window 3 = context ข้างละ 1 คำ เช่น fox, over → jumps) และ skip-gram ใช้คำกลางทำนายคำรอบข้าง โครงข่ายมีชั้นซ่อนเท่ากับจำนวนมิติที่อยากได้ (ตัวอย่างใช้ 3, งานจริงหลักร้อยถึงพัน) และชั้น output เท่ากับขนาดคลังคำ หลังฝึก weight matrix (ตัวอย่าง 8 × 3) คือ embedding matrix: one-hot ของคำ คูณกับ matrix = แถวของคำนั้น

ใน Transformer: decoder ไม่ใช้ Word2Vec แต่มี embedding layer ตื้น ๆ ที่ weight ฝึกไปพร้อมทั้งโมเดลเพื่อทำนาย token ถัดไป ชั้น output เป็น linear ขนาดเท่าคลังคำ ส่วน positional encoding (ฝึกได้หรือคงที่) ถูกบวกเข้ากับ embedding ตั้งแต่ก่อนเข้า decoder block เพราะ Transformer ประมวลผลทุกคำพร้อมกัน รูปร่างของ matrix ไม่เปลี่ยน จากนั้นเข้า attention ซึ่งเป็นตัวสร้างความเข้าใจตามบริบท (คลิปถัดไป)

ตรวจทาน (เสริมจากผู้จัดทำ): ไม่พบข้อผิด และเมื่อผู้จัดทำลองคำนวณกับตัวอย่างในคลิป (คลิปไม่ได้คำนวณค่าเหล่านี้เอง): one-hot สองคำใด ๆ cos = 0 และระยะ = √2, bag of words ของ "This movie was good" กับ "This movie was bad" ได้ cosine 0.75 ทั้งที่ความรู้สึกตรงข้าม และ one-hot × matrix ได้แถวของคำนั้นจริง

1. กฎข้อแรก: แปลง input เป็นตัวเลข (ตัวอย่างภาพ)

~0:00–0:54 (บท Intro และ "Representing image into numbers")

ผู้สอนเปิดว่าเราอาจเคยเห็นโมเดล machine learning ที่อ่านข้อความแล้วทำนายว่าเป็น spam หรือไม่ หรือวิเคราะห์รีวิวหนังว่าความรู้สึกเป็นบวกหรือลบ สมมติว่าใช้ neural network ฝึกโมเดลแบบนี้ กฎข้อแรกของการฝึกโมเดล machine learning ทุกตัวคือต้องแปลง input เป็นตัวเลข

ตัวอย่างภาพ: ในภาพขาวดำ pixel ที่สว่างที่สุดมีค่า 1 ที่มืดที่สุดมีค่า 0 และเฉดเทามีค่าระหว่าง 0 ถึง 1 การแทนเป็นตัวเลขแบบนี้ทำให้ประมวลผลภาพได้ง่าย เมื่อแปลงภาพเป็นตัวเลขตามค่า pixel แล้วก็ใช้เป็น input ฝึกโมเดลได้ ให้ neural network เรียนจากค่า pixel แต่คลิปนี้ว่าด้วยข้อความ จึงต่อด้วยวิธีเตรียมข้อความ

2. ข้อความเป็นตัวเลข: เลข token และปัญหาเรื่องลำดับ

~0:54–2:20 (บท "Representing text into numbers")

วิธีง่าย ๆ ในการแปลงข้อความเป็นตัวเลขคือให้ทุกคำที่ไม่ซ้ำกันมีเลขของตัวเอง (ผู้สอนอ้างคลิปก่อนหน้าเรื่อง tokenization ว่าทุก token ได้เลขไม่ซ้ำกัน) ในเมื่อโมเดลต้องการตัวเลข ก็ลองใช้เลข token เป็น input ได้ แต่ วิธีนี้เหมาะกับ feature แบบ ordinal เท่านั้น คือกรณีที่ตัวเลขบอกลำดับจริง เช่น low, medium, high ที่ลำดับมีความหมาย

ตัวอย่างสามประโยค: ประโยคแรกความรู้สึกบวก ประโยคที่สองลบ ประโยคที่สามบวก ความต่างอยู่ที่คำ good, bad และ great ถ้าให้เลข token เป็น good = 6, bad = 22, great = 21 เลข 21 กับ 22 ใกล้กัน โมเดลอาจคิดว่า bad กับ great คล้ายกัน ขณะที่ good ดูต่างไปเลย ทั้งที่จริง good กับ great ความหมายใกล้กัน วิธีให้เลขแบบนี้จึงอาจทำให้โมเดลตีความความสัมพันธ์ผิด และทำนายผิดได้ เลข token เฉย ๆ จึงไม่เหมาะเป็น feature

3. one-hot encoding

~2:20–3:40 (บท "One Hot Encoding")

เทคนิคที่นิยมใช้แก้ปัญหานี้คือ one-hot encoding: แต่ละคำแทนด้วยเวกเตอร์ไม่ซ้ำกัน ขนาดเท่ากับจำนวนคำทั้งหมดในคลังคำ วิธีนี้ตัดปัญหาเรื่องลำดับของเลข token และทำให้ทุกคำถูกปฏิบัติเท่ากันโดยไม่มีความสัมพันธ์เชิงตัวเลขแฝง เวกเตอร์ของแต่ละคำมี 1 ในตำแหน่งเดียว บอกว่าคำนั้นอยู่ ตำแหน่งอื่นเป็น 0 ทั้งหมด จากนั้นแปลงข้อมูลฝึกเป็นตัวเลขด้วยเวกเตอร์เหล่านี้แล้วฝึกโมเดลได้

ข้อดีคือ one-hot ช่วยตัดความสัมพันธ์เชิงตัวเลขที่ไม่ได้ตั้งใจ และทำง่าย แต่มีข้อเสียใหญ่:

  • sparse: ถ้าคลังคำมี 50,000 คำ แต่ละคำจะเป็นเวกเตอร์ 50,000 มิติที่ sparse ซึ่งกินหน่วยความจำและคำนวณแพง
  • ไม่มีความหมายและบริบท: มองทุกคำเป็นสิ่งที่แยกจากกันอย่างสิ้นเชิง จึงไม่จับความสัมพันธ์ระหว่างคำ เช่น good กับ great ที่ความหมายคล้ายกัน

ข้อจำกัดเหล่านี้ทำให้ one-hot ไม่มีประสิทธิภาพสำหรับงาน NLP ขนาดใหญ่

4. bag of words: unigram, bigram, n-gram

~3:40–4:59 (บท "Bag of Words (Unigram, Bigram and N-Gram)")

อีกวิธีคือ bag of words: นับว่าคำแต่ละคำปรากฏในประโยคกี่ครั้ง แล้ววางจำนวนนั้นในตำแหน่งของคำนั้น เพราะนับทีละคำ จึงเรียกว่า unigram (แต่ละคำถูกคิดแยกกันตอนสร้าง feature vector)

แทนที่จะใช้แค่ unigram ก็ใช้บริบทสองคำ หรือ bigram ได้ คือนับทุกคู่คำที่เป็นไปได้มาสร้าง feature vector ซึ่งเพิ่มบริบทมากกว่า one-hot หรือ unigram และขยายเป็นบริบท n คำได้ เรียกว่า n-gram ที่โมเดลจับบริบทได้ถึง n คำ

แต่ n-gram ก็มีปัญหา:

  • ถ้าข้อมูลใหญ่ จะมีชุด n-gram ที่เป็นไปได้มาก ทำให้ feature vector ใหญ่และ sparse มาก
  • โมเดลมองได้แค่จำนวนคำจำกัดในครั้งเดียว เช่น trigram จับบริบทได้แค่จากสามคำรอบ ๆ
  • ไม่จับความหมายหรือความสัมพันธ์ที่ลึกระหว่างคำ จึงด้อยประสิทธิภาพในงาน NLP ขั้นสูงอย่างการแปลภาษาและการสร้างข้อความ ที่ต้องเข้าใจความหมายและบริบทของคำอย่างมาก

5. ต้องเข้าใจทั้งความหมายและบริบท

~4:59–6:28 (บท "Semantic and Contextual Understanding of text")

ตัวอย่างข้อความ: Sarah entered the old library, her heart was racing. She knew something was hidden behind the dusty ___ สมมติให้โมเดลทำนาย token ถัดไป โมเดลต้องเข้าใจ ความหมายของแต่ละคำ (semantic understanding) และ บริบทของประโยค ด้วย

  • มนุษย์ถามตัวเองได้ว่า Sarah ไปไหน และโยงคำตอบไปที่คำว่า library ได้ง่าย
  • คำว่า old ในประโยคหมายถึง Sarah หรือห้องสมุด เราเข้าใจจากประโยคว่า old ขยาย library ไม่ใช่ Sarah
  • ประโยคบอกว่ามีบางอย่างซ่อนอยู่หลังสิ่งที่มีฝุ่น เราอนุมานได้ว่าของที่ซ่อนอยู่หลังของที่มีฝุ่น ซึ่งช่วยเดาคำถัดไป

ผู้สอนอธิบายว่า "โมเดลควรเข้าใจความหมาย" หมายถึง ถ้าแทนบางคำด้วยคำที่ความหมายใกล้กัน ความหมายของประโยคต้องยังเหมือนเดิม และเห็นได้ว่าคำผูกกับบริบทในประโยค จากเรื่องนี้เดาได้ว่าคำถัดไปที่น่าจะเป็นที่สุดคือ table, wall หรือ bookshelf เพราะมักพบในห้องสมุดเก่าและอาจมีฝุ่น

ดังนั้นถ้าจะฝึกโมเดลให้เข้าใจทั้งความหมายและบริบท ต้องมีวิธีเข้ารหัสข้อมูลฝึกเป็น feature vector ที่จับได้ทั้งสองอย่าง และตรงนี้ word embedding กับ attention mechanism มีบทบาทสำคัญ คลิปนี้เจาะเรื่อง word embedding

6. word embedding

~6:28–9:44 (บท "Word Embeddings")

word embedding คือเทคนิคใน NLP ที่แทนคำด้วย เวกเตอร์ตัวเลขหนาแน่น (dense) ใน vector space ต่อเนื่อง ในตัวอย่างบนจอ คำสามคำแทนด้วยเวกเตอร์ 10 มิติที่หนาแน่น ไม่เหมือน one-hot ที่เกือบทุกค่าเป็นศูนย์ยกเว้น 1 ตัวที่บอกตำแหน่งของคำ แนวคิดของ embedding คือ เวกเตอร์สองตัวที่คล้ายกันตรงกับสองคำที่คล้ายกัน และ ทิศใน vector space มีความหมายบางอย่าง เช่น ในภาพ 2 มิติ king กับ queen อยู่ใกล้กันมากกว่าเทียบกับคำที่ไม่เกี่ยวอย่าง cat

ไล่จาก 1 มิติไป 2 มิติ

เริ่มจาก 1 มิติ: นึกถึงเส้นจำนวนที่แทนอายุ แล้วเข้ารหัสคน 10 คนด้วย feature vector ที่มี feature เดียวคืออายุ จะเห็นว่าคนอายุใกล้กันอยู่ใกล้กัน ผู้สอนย้ำว่านี่เป็นตัวอย่างพื้นฐาน feature จะเป็นอะไรก็ได้ที่เข้ารหัสข้อมูลได้ดีที่สุด

ขยายเป็น 2 มิติ: ให้แกน x คืออายุ แกน y คือความเป็นราชวงศ์ (royalty) กรณีนี้ king กับ queen คล้ายกันและอยู่ใกล้กัน ขณะที่อยู่ห่างจาก man กับ woman

บวกลบเวกเตอร์ได้

เมื่อ feature vector ถูกเข้ารหัสตามความหมายแล้ว ก็ทำการคำนวณเวกเตอร์ได้ เช่น เอา king ลบ man แล้วบวก woman ได้เวกเตอร์ที่ใกล้ queen แสดงว่าความต่างระหว่าง king กับ queen คล้ายกับความต่างระหว่าง man กับ woman เพื่อสาธิต ผู้สอนสมมติ embedding 5 มิติที่แต่ละมิติคือ gender, wealth, power, weight และ speech เข้ารหัส king, queen, man, woman และ cat แล้วเมื่อบวกลบเวกเตอร์ ผลลัพธ์ใกล้ queen มากกว่า cat

อีกตัวอย่าง: Beijing + Japan − China ได้คำที่ใกล้ที่สุดคือ Tokyo เพราะ Beijing เป็นเมืองหลวงของจีน เมื่อบวก Japan ก็เพิ่มคุณลักษณะของญี่ปุ่น เมื่อลบ China ก็เอาคุณลักษณะของจีนออก feature ที่เหลือยังแทนความเป็นเมืองหลวง จึงได้เวกเตอร์ที่ใกล้กับ Tokyo เมืองหลวงของญี่ปุ่น

มิติของ embedding

เรา กำหนดตรง ๆ ไม่ได้ ว่ามีคุณลักษณะอะไรอยู่ใน embedding space เพราะขึ้นกับข้อมูลที่ใช้ฝึกทั้งหมด แต่จากตัวอย่างข้างต้นเห็นได้ว่าโมเดลจับความหมายของข้อความได้บางส่วน และแทนไว้ใน vector space มิติต่ำ ซึ่ง "มิติต่ำ" ในที่นี้หมายถึงหลักร้อยหรือหลักพันมิติ ต่างจาก one-hot ที่อาจต้องหลายแสนมิติ เป้าหมายของ embedding คือใช้เวกเตอร์หนาแน่น เก็บความหมายของคำไว้ในพื้นที่ n มิติ ซึ่งเรียกว่า embedding space ตอนเริ่มต้น embedding แทนคำแบบสุ่ม แล้วโมเดลเรียนรู้ความหมายระหว่างการฝึก (caption ช่วงนี้กำกวมว่า embedding "ใช้ตรง ๆ แบบ one-hot ไม่ได้" รายงานนี้คงความหมายหลักไว้คือ embedding ต้องได้มาจากการฝึก)

7. ดู embedding เป็นภาพ

~9:44–10:30 (บท "Visualizing Word2Vec Embeddings")

เราดู embedding ที่มีหลายร้อยมิติตรง ๆ ไม่ได้ แต่ใช้เครื่องมือทางคณิตศาสตร์อย่าง principal component analysis ฉายลงมิติต่ำได้ สิ่งที่ผู้สอนเปิดให้ดูคือโมเดล embedding ที่ฝึกแล้ว แสดงคำว่า king กับคำที่ใกล้ที่สุด ทำนองเดียวกัน คำที่เกี่ยวกับ tennis อยู่ใกล้กัน คำที่เกี่ยวกับ cat รวมเป็นกลุ่ม และคำว่า one ที่หมายถึงตัวเลข ก็มีคำที่เกี่ยวกับเลขหนึ่งอยู่ใกล้กัน (คำอธิบายคลิปให้ลิงก์ TensorFlow Embedding Projector ไว้สำหรับดูเอง)

ผู้สอนสรุปช่วงนี้ว่า ตอนนี้เข้าใจแล้วว่า embedding สำคัญอย่างไรและแทนคำพร้อมความหมายได้อย่างไร ต่อไปจะดูว่าโมเดลแบบนี้ฝึกอย่างไร

ภาพช่วงนี้เป็นกลุ่มจุดเล็ก ๆ บนพื้นดำที่อ่านชื่อคำได้ยากเมื่อย่อ จึงไม่ได้ใส่ภาพ

8. ฝึกด้วย Word2Vec: CBOW และ skip-gram

~10:30–14:46 (บท "Word2Vec Training (CBOW and Skip-Gram)")

เทคนิคหนึ่งในการฝึก word embedding คือ Word2Vec ซึ่ง Google เสนอขึ้นเพื่อประมาณการแทนคำใน vector space อย่างมีประสิทธิภาพ ผู้สอนทวนว่า เลข token ไม่มีความหมายของความคล้ายในตัว และ n-gram ทำให้เวกเตอร์ใหญ่ โดยเฉพาะเมื่อฝึกกับข้อมูลหลายพันล้านคำ จึงขยายขนาดได้ไม่ดี ต้องการเทคนิคที่ให้เวกเตอร์ซึ่งคำคล้ายกันมักอยู่ใกล้กัน และจับความคล้ายได้หลายระดับ paper ของ Word2Vec แสดงเรื่องนี้ด้วยตัวอย่างดัง king, queen, man, woman ว่าความสัมพันธ์ของคำคงอยู่ใน vector space ได้ ตาม paper มีสองเทคนิคหลัก: continuous bag of words (CBOW) และ skip-gram

CBOW: เตรียมข้อมูล

ใช้ window ขนาด 3 คือ context ขนาด 1 คำกลางเป็นคำเป้าหมายที่โมเดลต้องทำนาย คำรอบข้างเป็น context ที่เป็น input แล้วเลื่อน window ไปทั่วเอกสาร ใช้ context ขนาด 2 ขึ้นไปก็ได้ แต่เพื่อความง่ายใช้ 1 ตัวอย่างหนึ่งชุดฝึก: input คือ fox และ over คำเป้าหมายคือ jumps ก่อนส่งเข้าโมเดล ต้องแทนแต่ละคำด้วย one-hot

CBOW: โครงข่าย

โมเดลเป็น neural network ง่าย ๆ: ชั้น input รับ one-hot ของคำ context, ชั้นซ่อน มี neuron เท่ากับจำนวนมิติของ embedding ที่อยากเรียน (ถ้าอยากได้เวกเตอร์ 3 มิติก็ใช้ 3 neuron; งานจริงอาจเป็นหลักร้อยหรือหลักพันแล้วแต่การฝึก) และ ชั้น output มี neuron เท่ากับขนาดคลังคำ ใช้คำ context สองคำเป็น input และคำเป้าหมายเป็น label คำนวณ error ระหว่างคำที่ทำนายกับคำจริง ทำ back propagation ปรับ weight แล้วเลื่อน window ไปชุดถัดไป

weight matrix คือ embedding matrix

หลังฝึก ใช้ weight matrix เป็น embedding matrix ได้ อยากได้ 3 มิติต่อคำ และฝึกกับคำแค่ 8 คำ จึงได้ matrix 8 × 3 ซึ่งเป็นตาราง lookup: แต่ละคำมีเวกเตอร์ 3 มิติประจำตัวที่คงที่ ค่า weight ที่ตรงกับ neuron ของคำแรกคือ feature vector ของคำแรก และในทำนองเดียวกัน คำว่า quick ได้ค่า B1, B2, B3 แต่ละคำในคลังคำจึงมีเวกเตอร์ของตัวเอง

การหา embedding ของคำ: แปลงคำเป็น one-hot ก่อน แล้ว คูณ (dot product) one-hot กับ embedding matrix ได้เวกเตอร์ของคำนั้น (ตัวอย่างในคลิปคือ fox) ดังนั้น embedding matrix จึงเป็นตาราง lookup ของทุกคำ จำนวนแถวเท่ากับจำนวนคำไม่ซ้ำ (ขนาดคลังคำ) จำนวนคอลัมน์เท่ากับมิติที่เลือก

skip-gram

เข้าใจ CBOW แล้ว skip-gram ก็ง่าย: แทนที่จะทำนายคำกลาง ใช้ คำกลางเป็น context แล้วทำนายคำรอบข้าง skip-gram จึงตรงข้ามกับ CBOW และผู้สอนบอกว่าทั้งสองแบบใช้ฝึก word embedding ได้ดี

9. embedding layer ใน Transformer

~14:46–17:16 (บท "Embedding Layer in Transformer Architecture")

นอกจากนี้ยังฝึก embedding แบบกำหนดเอง ตามงานที่ต้องการได้ ใน Transformer มี embedding layer ที่ออกแบบมาเพื่อหน้าที่ของมันเอง ผู้สอนอธิบาย embedding ในโมเดลสร้างข้อความ โดยเฉพาะส่วน decoder: หลังแปลงข้อความเป็น token ใช้ embedding layer สร้าง embedding ให้ทุก token เช่น 6 token ได้ embedding matrix ขนาด 6 × มิติของ embedding

  • decoder ไม่ได้ใช้โมเดลแบบ Word2Vec แต่ใช้ neural network ตื้น ๆ: ชั้น input รับ one-hot ของแต่ละคำ (neuron เท่าคลังคำ) ชั้นซ่อนมี neuron เท่ามิติที่อยากให้เรียน
  • weight ในชั้นนี้เป็น พารามิเตอร์ที่ฝึกได้ เรียนแทนคำในพื้นที่ n มิติ และเหมือน Word2Vec ตรงที่ weight ทำหน้าที่เป็นตาราง lookup ของ token
  • ถ้าฝึกดี embedding เหล่านี้จับความหมายของคำได้ แต่ต่างจาก Word2Vec ที่ฝึก embedding แยกไว้ต่างหาก ใน decoder embedding layer ถูกฝึกไปพร้อมทั้งโมเดล

เพราะต้องการให้ decoder ทำนาย token ถัดไป จึงใช้ embedding layer แบบกำหนดเองที่ให้เวกเตอร์ของข้อความ แล้วส่งต่อผ่าน decoder block ที่ซ้อนกันหลายชั้น ไปจนถึงชั้น output ที่ทำนาย token ถัดไป จากนั้นคำนวณ error และทำ back propagation ผ่านทุกชั้นด้วยชุดข้อมูลฝึก

ชั้น output เป็น linear layer อีกชั้นที่คล้าย embedding layer ตอนต้น แต่กลับด้าน: แทนที่ขนาด output จะเท่ามิติ embedding กลับมี neuron เท่ากับขนาดคลังคำ ทำให้โมเดลให้ความน่าจะเป็นกับ token ถัดไปที่เป็นไปได้ สรุปคือโมเดลแทน token ใน embedding space n มิติก่อน แล้วใช้การแทนนั้นทำนาย token ถัดไป ต่างจาก Word2Vec ที่ทำนายคำกลางจากคำ context ส่วน LLM มีเป้าหมายทำนายคำถัดไปจากคำก่อนหน้าทั้งหมด โดยมี decoder หลายชั้นประมวลผล embedding ต่อก่อนสร้าง token ถัดไป

10. positional encoding และสิ่งที่ตามมา

~17:16–19:32 (บท "Positional Encoding" และ Outro)

ผู้สอนบอกว่าเกือบครบเรื่อง embedding แล้ว เหลือรายละเอียดเล็ก ๆ อีกข้อ: ต่างจาก RNN ที่ประมวลผลทีละ token Transformer ประมวลผลทุกคำพร้อมกัน จึงต้องบอกโมเดลว่าแต่ละ token อยู่ตำแหน่งไหน คืออันไหนมาก่อนอันไหนตามมา

วิธีคือหลังทำ embedding แล้ว บวกเวกเตอร์ตำแหน่ง เข้ากับเวกเตอร์ embedding เพื่อใส่ข้อมูลตำแหน่งของแต่ละ token ข้อมูลตำแหน่งนี้จะเป็น ชั้นที่ฝึกได้อีกชั้น หรือ ตัวเลขคงที่ที่ไม่ซ้ำกันสำหรับแต่ละ token (ตามที่ผู้สอนพูด) ก็ได้ ผลรวมคือการแทนแบบใหม่ที่มีทั้งความหมายของคำและตำแหน่ง และที่สำคัญ รูปร่างของ embedding matrix ไม่เปลี่ยน มีแค่ค่าที่ปรับเล็กน้อยตามตำแหน่งของ token

จากนั้น matrix นี้พร้อมเข้า attention mechanism ซึ่งเป็นชั้นแรกของ decoder block ผู้สอนทวนว่า embedding layer ช่วยจับความหมายของคำ แต่ไม่ได้ให้ความเข้าใจตามบริบทของข้อความ ซึ่งเป็นหน้าที่ของ attention ที่ผู้สอนเรียกว่าเป็นหัวใจของ large language model ช่วยจับความสัมพันธ์ระหว่างคำที่เกินกว่าความหมายของคำเดี่ยว ๆ หลังผ่าน attention จะได้การแทน token ตามบริบท ซึ่งต่างจากการแทนตามความหมายตอนแรก

ปิดท้าย: ในซีรีส์นี้เตรียมข้อมูลและทำ tokenization มาแล้ว คลิปนี้ว่าด้วย embedding และ positional encoding เพื่อเข้าใจว่าทั้งสองช่วยแทนคำและตำแหน่งของคำในโมเดล Transformer อย่างไร ต่อไปจะเข้า decoder layer และส่วนที่สำคัญที่สุดคือ attention ซึ่งจะอธิบายละเอียดในคลิปหน้า (ช่วงชวนกด like, share, subscribe ตัดออก)

ข้อสังเกตเพิ่ม

  • ผลบวกลบอย่าง king − man + woman ≈ queen คือ "ใกล้ที่สุด" ไม่ใช่ "เท่ากันพอดี" ซึ่งคลิปก็พูดว่า "close to"
  • ในระบบจริง embedding layer ใช้ตาราง lookup โดยตรง ไม่ได้สร้างเวกเตอร์ one-hot จริง ๆ ผลเท่ากับที่คลิปอธิบาย เพราะคูณ one-hot = หยิบแถว
  • ประโยค "ตำแหน่งเปลี่ยนค่าเล็กน้อย" ขึ้นกับขนาดของเวกเตอร์ตำแหน่งเทียบกับ embedding ซึ่งแต่ละโมเดลต่างกัน

Key Takeaways

  1. เลข token ไม่เหมาะเป็น feature เพราะตัวเลขที่ใกล้กันหลอกให้โมเดลคิดว่าคำใกล้กัน (bad 22 กับ great 21)
  2. one-hot แก้เรื่องลำดับ แต่ sparse ยาวเท่าคลังคำ และไม่มีความหมาย; bag of words / n-gram เพิ่มบริบทได้จำกัด
  3. word embedding คือเวกเตอร์หนาแน่น ที่คำคล้ายกันอยู่ใกล้กันและบวกลบได้ เช่น king − man + woman ≈ queen
  4. Word2Vec (CBOW, skip-gram) ฝึกโครงข่ายตื้น แล้วใช้ weight matrix เป็นตาราง lookup
  5. ใน Transformer embedding layer ฝึกไปพร้อมโมเดล แล้วบวก positional encoding ก่อนเข้า attention ซึ่งให้ความเข้าใจตามบริบท
