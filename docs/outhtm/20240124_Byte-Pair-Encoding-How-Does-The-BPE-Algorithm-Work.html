📋 บทสรุปย่อ

บทสรุปย่อ: คลิปนี้อธิบาย Byte Pair Encoding (BPE) ซึ่งเป็นวิธีตัดข้อความเป็นชิ้นย่อยกว่าคำ (subword tokenization) ที่ผู้สอนบอกว่าโมเดลดังหลายตัวใช้ รวมถึง GPT เริ่มจากเหตุผลว่าทำไมต้องแปลงข้อความเป็นตัวเลข เทียบการตัดทีละตัวอักษร (คลังเล็ก แต่ลำดับยาว) กับการตัดทีละคำ (คลังใหญ่ แต่ลำดับสั้น) แล้วเสนอ subword เป็นทางกลาง จากนั้นเดินตัวอย่างจริงบนประโยค "fred fed ted bread, and ted fed fred bread" ทีละรอบ ได้กฎรวม 4 ข้อ คลังคำ 13 ตัว และใช้กฎเหล่านั้นแปลงประโยคใหม่ "ted and fred are friends" เป็นเลข 16 ตัว โดยตัว i กับ s กลายเป็น "?" เพราะไม่เคยเห็นตอนฝึก

โหมดของเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ (license มาตรฐานของ YouTube, ตรวจ 2026-10-11) ทุกประเด็นและตัวเลขอยู่ครบตามลำดับคลิป โดยไม่เปลี่ยนความหมาย แต่ไม่ได้ถอดคำพูดทีละประโยค ผู้จัดทำรันตัวอย่างในคลิปด้วยโค้ดแล้วพบว่า ตัวเลขรอบแรกถูกทั้งหมด แต่รอบที่สองมีสองค่าที่นับเกิน และสไลด์สุดท้ายใส่เลขของ "fred␣" ผิดหนึ่งตัว รายละเอียดอยู่ในส่วนที่ 12 (เนื้อหาในส่วนอื่นเขียนตามที่คลิปพูด)

🧭 สรุปเชิงลึก

ปัญหาตั้งต้น: เครื่องเข้าใจแต่ตัวเลข จึงต้องมีขั้นแปลงข้อความเป็นตัวเลขก่อน เรียกว่า tokenization แล้วโมเดลจึงเอาตัวเลขไปใช้ เช่น ทายอารมณ์ของข้อความ หรือสร้างข้อความต่อ

สองขั้วสุดทาง: แบบตัวอักษร ใช้คลังเล็ก (สไลด์มี 30 ตัว คือ a–z = 1–26 และ ! @ # $ = 27–30 ผู้สอนบอกว่าถ้าเติมตัวพิมพ์ใหญ่และสัญลักษณ์อื่นก็น่าจะไม่เกินราว 100) แต่ประโยคหนึ่งกลายเป็นเลขยาวมาก แบบคำ ได้เลขสั้น (สไลด์: hello = 86241, there = 129041) แต่คลังใหญ่มาก (คำสุดท้ายในสไลด์คือ zulu = 173248) ผู้สอนบอกว่าเราอยากได้คลังเล็กเพื่อประหยัดหน่วยความจำ แต่ลำดับยาวทำให้โมเดลประมวลผลนานขึ้น จึงอยากได้ทางที่สมดุล

subword: ชิ้นข้อความที่มักไม่ใช่ทั้งคำ แต่ก็ไม่ใช่ตัวอักษรเดียว เช่น ly, ence, tion วิธีที่นิยมมีสามแบบ: BPE (GPT), WordPiece (BERT) และ Unigram Language Modeling (T5) คลิปนี้เล่าเฉพาะ BPE

BPE สั้นที่สุด: เริ่มจากคลังที่มีทุกตัวอักษรในข้อความฝึก แล้วทำซ้ำ k ครั้ง: นับทุกคู่ที่ติดกัน เลือกคู่ที่เจอบ่อยที่สุด เพิ่มคู่นั้นเป็น token ใหม่ในคลัง และแทนคู่นั้นทุกจุดในข้อความด้วย token ใหม่ ตัวอย่างในคลิปได้กฎ 4 ข้อ: d+␣ → "d␣" (เจอ 7 ครั้ง), e+"d␣" → "ed␣" (6 ครั้ง), f+r → "fr" และ fr+"ed␣" → "fred␣" รวมคลังเป็น 13 ตัว ใส่เลข 1–13

ใช้กับข้อความใหม่: แตกเป็นตัวอักษร ใช้กฎทีละข้อตามลำดับที่ได้ตอนฝึก แล้วแปลงแต่ละ token เป็นเลขจากคลัง ประโยค "ted and fred are friends" ได้ 16 ตัว ส่วน i กับ s ไม่มีในคลังจึงเป็น "?" ผู้สอนบอกว่าเกิดเพราะข้อความฝึกเล็กมาก ในข้อความจริงน่าจะมีครบทุกตัวอักษร และอย่างน้อยกับ subword ก็ไม่ต้องกังวลเรื่องนี้ในงานจริง

สิ่งที่ผู้จัดทำตรวจพบ (ส่วนที่ 12): ตัวเลขรอบแรก (7, 6, 4, 3) ถูกทั้งหมด ผู้สอนเองพูดไว้ว่า "หวังว่าถูก" และชวนให้ลองนับเอง รอบที่สอง "d␣ ตามด้วย f" นับได้ 3 (สไลด์ 4) และ "fr" นับได้ 2 (สไลด์ 3) คู่ที่ชนะยังเป็น "ed␣" จึงไม่กระทบกฎข้อ 2 แต่ถ้านับคู่ตรง ๆ ทุกคู่ กฎข้อ 3–4 จะเป็น "ed␣f" กับ "ed␣b" ไม่ใช่ "fr" กับ "fred␣" ตามสไลด์ (ใช้เป็นตัวอย่างอธิบายวิธีได้ แต่ไม่ใช่ผลของการนับจริง) และในสไลด์สุดท้าย "fred␣" ควรได้เลข 13 ไม่ใช่ 7

1. tokenization คืออะไร และทำไมต้องแปลงข้อความเป็นตัวเลข

~0:01–0:58

ผู้สอนเปิดว่าจะเล่า byte pair encoding ซึ่งเป็นวิธีตัดข้อความเป็นชิ้นย่อยกว่าคำ (subword tokenization) ที่โมเดลประมวลผลภาษาธรรมชาติที่มีชื่อเสียงหลายตัวใช้ รวมถึง GPT

จากนั้นวางบริบท: การประมวลผลภาษาธรรมชาติ (NLP) เป็นสาขาย่อยของ machine learning ซึ่งเป็นสาขาย่อยของปัญญาประดิษฐ์อีกที เป้าหมายคือให้เครื่องเข้าใจข้อความได้ในระดับเดียวกับมนุษย์ แต่ติดปัญหาตรงที่เครื่องเข้าใจแต่ตัวเลข ไม่เข้าใจตัวหนังสือ

เราจึงต้องมีขั้นตอนแปลงข้อความเป็นตัวเลขก่อน เพื่อให้เครื่องนำไปประมวลผลต่อ เช่น ทายอารมณ์ของข้อความ (sentiment) หรือสร้างข้อความต่อแบบที่ language model ทำ ขั้นตอนแปลงข้อความเป็นตัวเลขนี้เรียกว่า tokenization

คำศัพท์ (เสริมจากผู้จัดทำ): token คือชิ้นข้อความหนึ่งชิ้นหลังตัดแล้ว (ตัวอักษร คำ หรือชิ้นย่อย) vocabulary หรือคลังคำ คือรายการ token ทั้งหมดที่ระบบรู้จัก แต่ละตัวมีเลขประจำตัวไม่ซ้ำกัน ในรายงานนี้ใช้ "␣" แทนช่องว่างเพื่อให้มองเห็น

2. ตัดทีละตัวอักษร (character tokenization)

~0:59–1:56

tokenization มีหลายแบบ แบบแรกคือ character tokenization สไลด์แสดงคลัง 30 ตัว: ตัวอักษร a ถึง z ได้เลข 1 ถึง 26 และสัญลักษณ์พิเศษ ! @ # $ ได้ 27 ถึง 30 แต่ละตัวอักษรจับคู่กับจำนวนเต็มที่ไม่ซ้ำกัน (a เป็น 1, b เป็น 2, $ เป็น 30) ผู้สอนบอกว่าจะเพิ่มตัวพิมพ์ใหญ่และสัญลักษณ์อื่นก็ได้ แต่ประเด็นคือคลังแบบนี้ค่อนข้างเล็ก น่าจะไม่เกินราว 100 ตัว

วิธีแปลงก็ง่าย: ไล่ทีละตัวอักษรในข้อความแล้วเปลี่ยนเป็นเลขของมัน เช่น h เป็น 8, e เป็น 5, l เป็น 12 ทำแบบนี้กับทุกตัวอักษร สไลด์แสดงประโยค "hello there you are amazing" มีลูกศรจากแต่ละตัวอักษรลงไปยังเลข ผู้สอนสรุปว่าเป็นวิธีที่ง่ายมาก ไม่มีอะไรซับซ้อน

เสริมจากผู้จัดทำ: ช่องว่างไม่ได้มีเลขในสไลด์นี้ ประโยคจึงได้เลข 23 ตัวตามจำนวนตัวอักษร (5 + 5 + 3 + 3 + 7) ตรงกับลำดับ 8,5,12,12,15 · 20,8,5,18,5 · 25,15,21 · 1,18,5 · 1,13,1,26,9,14,7 ในภาพ

3. ตัดทีละคำ (word tokenization) และคลังคำมาจากไหน

~2:00–3:28

แบบที่สองคือ word tokenization หลักการเดียวกัน แต่หน่วยเป็นคำ คลังในสไลด์เริ่มที่ a = 1, ab = 2, abbreviation = 3 มีคำ jungle = 92382 อยู่กลาง ๆ และจบที่ zulu = 173248 แต่ละคำได้จำนวนเต็มไม่ซ้ำกัน

เวลาแปลงข้อความใหม่ก็เปลี่ยนแต่ละคำเป็นเลขของมัน สไลด์ให้ hello = 86241, there = 129041, you = 164234, are = 1324 และ amazing = 914 (ผู้สอนอ่านออกเสียงแค่สองค่าแรก)

คำถามที่ตามมาคือคลังคำนี้มาจากไหน ผู้สอนบอกว่าเราจะไม่ยัดทุกคำในภาษาอังกฤษเข้าไป เพราะสิ้นเปลือง และอาจมีคำที่ไม่เคยถูกใช้เลย สิ่งที่ทำคือดูข้อความที่ใช้ฝึก (training corpus) ซึ่งอาจเป็นชุดข้อมูลข้อความ แล้วเก็บคำที่ไม่ซ้ำทั้งหมดมาสร้างคลัง เขาบอกด้วยว่ากระบวนการฝึกจริงซับซ้อนกว่านี้เล็กน้อย และจะเล่าเรื่องการฝึกทีหลัง ตอนนี้ขอเทียบสองแบบก่อน

เสริมจากผู้จัดทำ: เลขในคลังคำเรียงตามตัวอักษร (a, ab, abbreviation … zulu) เลขจึงบอกแค่ตำแหน่งในรายการ ไม่ได้บอกความหมาย ซึ่งเป็นเรื่องเดียวกับบท 3.3 Token ID ของ ZVect

4. สองขั้ว: คลังเล็ก แต่ลำดับยาว กับคลังใหญ่ แต่ลำดับสั้น

~3:10–4:28

ผู้สอนเทียบสองแบบตรง ๆ:

  • ตัวอักษร: คลังค่อนข้างเล็ก (น่าจะสูงสุดราว 100 ตัว) แต่ได้ลำดับเลขที่ยาว
  • คำ: คลังใหญ่มาก แต่ได้ลำดับเลขที่สั้น

นี่คือสองขั้วสุดทาง เราอยากได้คลังเล็กกว่าเพราะใช้หน่วยความจำน้อย แต่การตัดทีละตัวอักษรให้ลำดับที่ยาวมาก แปลว่าโมเดลที่รับเลขเหล่านี้ไปจะใช้เวลานานขึ้นมาก เพราะมีเลขให้ประมวลผลมากขึ้น ส่วนการตัดทีละคำให้ลำดับสั้น

ผู้สอนจึงบอกว่าถ้ามีวิธีที่หาจุดสมดุลระหว่างสองขั้วได้ คือได้คลังเล็กและได้ลำดับยาวพอประมาณ ก็จะดีมาก ซึ่งเป็นที่มาของหัวข้อถัดไป

5. subword และสามวิธีที่นิยม

~4:28–5:22

subword tokenization คือทางสมดุลระหว่างการตัดทีละคำกับทีละตัวอักษร ผู้สอนให้นึกถึง subword ว่าเป็นชิ้นข้อความเล็ก ๆ ที่มักไม่ใช่คำเต็ม แต่ก็ไม่ใช่ตัวอักษรเดี่ยว ตัวอย่างที่ยกคือชิ้นที่พบบ่อยอย่าง ly, ence และ tion

วิธี subword ที่มีชื่อและใช้กันแพร่หลายมีสามแบบ:

  • Byte-Pair Encoding (BPE) ใช้โดย GPT (เรื่องของคลิปนี้)
  • WordPiece ใช้โดย BERT
  • Unigram Language Modeling ใช้โดย T5 (caption ได้ยินเป็น "unagram")

คลิปนี้เล่าเฉพาะ BPE และในคำอธิบายใต้คลิป ผู้สอนบอกว่าคลิปถัดไปจะเขียน BPE ด้วย Python ตั้งแต่ศูนย์

เสริมจากผู้จัดทำ (ความรู้ทั่วไป): GPT-2 และรุ่นถัดมาใช้ BPE แบบ byte-level คือเริ่มคลังจาก 256 ค่าของไบต์แทนตัวอักษร ทุกข้อความจึงแตกเป็นไบต์ได้เสมอ ไม่มีตัวที่ "ไม่รู้จัก" แบบตัวอย่างในส่วนที่ 11 คลิปนี้อธิบาย BPE แบบตัวอักษรซึ่งเข้าใจง่ายกว่า หลักการรวมคู่เหมือนกัน

6. ขั้นตอนของ BPE

~5:23–6:43

ขั้นตอน BPE ตามสไลด์:

  1. เริ่มด้วยคลังที่มีทุกตัวอักษรที่ไม่ซ้ำในข้อความฝึก (ไล่ข้อความแล้วเก็บตัวอักษรลงเซตหรือรายการ)
  2. ทำซ้ำ:
    • เลือกสองสัญลักษณ์ที่อยู่ติดกันบ่อยที่สุดในข้อความฝึก สมมติว่าเป็น A กับ B วิธีหาคือไล่ทั้งข้อความแล้วนับทุก bigram (caption ได้ยินเป็น "biogram") คือชิ้นที่ประกอบด้วยสองตัวอักษรหรือสอง token
    • เพิ่มสัญลักษณ์ที่รวมแล้ว AB เข้าคลัง
    • แทนทุกจุดที่ A ตามด้วย B ในข้อความด้วย token เดียว AB (จากสอง token กลายเป็นหนึ่ง)
  3. หยุดเมื่อรวมครบ k ครั้ง

ผู้สอนยอมรับว่าฟังแบบนี้อาจงง จึงพาไปดูตัวอย่างจริงในส่วนถัดไป

7. ตัวอย่าง: ประโยคฝึกและคลังเริ่มต้น

~6:44–7:28

ข้อความฝึกในตัวอย่างมีประโยคเดียวแบบพูดเร็วลิ้นพันกัน: fred fed ted bread, and ted fed fred bread (ผู้สอนชวนให้ลองพูดเร็ว ๆ ห้าครั้ง) สไลด์ขีดเส้นใต้แยกทีละตัวอักษร และในตัวอย่างนี้ (รวมถึงตัวอย่างส่วนใหญ่) ช่องว่างและเครื่องหมายวรรคตอนจะนับเป็นตัวอักษรหนึ่งตัว

คลังเริ่มต้นคือทุกตัวอักษรที่ไม่ซ้ำในประโยค: a b d e f n r t ␣ รวมช่องว่างด้วย ผู้สอนบอกเองว่าลืมใส่ จุลภาค (,) ซึ่งควรอยู่ในคลังด้วย

เสริมจากผู้จัดทำ: ประโยคนี้ยาว 42 ตัวอักษร (นับช่องว่างและจุลภาค) มีตัวที่ไม่ซ้ำ 10 ตัว คือ 9 ตัวในสไลด์บวกจุลภาค สไลด์ใช้ตัวพิมพ์เล็กทั้งหมด ส่วน caption ขึ้นต้นชื่อด้วยตัวใหญ่ ผู้จัดทำนับตามสไลด์

8. รอบที่ 1: d + ช่องว่าง

~7:30–9:29

รอบที่ 1 ขั้นที่ 1 — เลือกคู่: สไลด์แสดงสี่คู่ที่เจอบ่อย: d␣ (d ตามด้วยช่องว่าง) 7 ครั้ง, ed 6 ครั้ง, re 4 ครั้ง และ ␣f 3 ครั้ง ผู้สอนชวนให้นับเองเพื่อยืนยัน และย้ำว่าแสดงแค่สี่อันดับแรก ของจริงต้องนับทุกคู่ที่เป็นไปได้ แล้วจึงหาคู่ที่บ่อยที่สุด (ช่วงนี้เป็นข้อความแทรกที่ผู้สอนอัดเพิ่มทีหลัง) เขาพูดด้วยว่า "หวังว่านับถูก" จากนั้นขีดเส้นใต้ d␣ ทั้ง 7 จุด

ขั้นที่ 2 — เพิ่มเข้าคลัง: d␣ ถูกเพิ่มเป็น token ใหม่ ซึ่งประกอบด้วยสองตัวอักษร

ขั้นที่ 3 — แทนในข้อความ: ทุกจุดที่มี d ตามด้วยช่องว่าง เดิมเป็นสอง token จะถูกรวมเป็น token เดียว d␣ (caption ได้ยิน corpus เป็น "chorus")

จบหนึ่งรอบ: คลังมี token เพิ่มหนึ่งตัว และได้ข้อความที่อัปเดตแล้ว ผู้สอนชี้ว่า d และช่องว่างยังอยู่ในคลังเหมือนเดิม เพียงแต่มี d␣ เพิ่มขึ้นมา

เสริมจากผู้จัดทำ: ผู้จัดทำนับด้วยโค้ดแล้ว ตัวเลขรอบแรกตรงกับสไลด์ทั้งสี่ค่า (7, 6, 4, 3) หลังรวม d␣ ประโยคเหลือ 35 token จาก 42

9. รอบที่ 2: e + d␣

~9:31–10:18

รอบที่สองทำซ้ำสามขั้นเดิม สไลด์แสดงคู่ที่บ่อยที่สุดสี่อันดับ: e ตามด้วย d␣ 6 ครั้ง, re 4 ครั้ง, d␣ ตามด้วย f 4 ครั้ง และ fr 3 ครั้ง คู่แรกจึงชนะ ผู้สอนไฮไลต์ทั้ง 6 จุด

จากนั้นเพิ่ม ed␣ (e, d, ช่องว่าง) เข้าคลัง แล้วไล่หาทุกจุดที่มี e ตามด้วย d␣ เพื่อรวมเป็น token เดียว ed␣ จบรอบที่สอง

ส่วนนี้คลิปพูดสั้น เพราะเป็นการทำซ้ำรอบแรก "เพื่อให้เห็นชัด" ตามที่ผู้สอนบอก หลังรอบนี้ประโยคเหลือ 29 token (ผู้จัดทำนับ)

10. หลังรวม 4 ครั้ง: กฎการรวมและเลขของคลัง

~10:22–11:01

ผู้สอนแนะนำอย่างมากให้ลองทำการรวมด้วยตัวเอง ถ้ารวมทั้งหมด 4 ครั้ง จะได้ชุดกฎการรวม (merge rules):

  1. d + ␣ → d␣
  2. e + d␣ → ed␣
  3. f + r → fr
  4. fr + ed␣ → fred␣

สมมติว่าเราต้องการรวมแค่ 4 ครั้ง ขั้นสุดท้ายของการฝึกคือเอาคลังใหม่ที่มี token เพิ่มแล้ว มาใส่เลขไม่ซ้ำกันให้ทุกตัว สไลด์ให้ a 1, b 2, d 3, e 4, f 5, n 6, r 7, t 8, ␣ 9, d␣ 10, ed␣ 11, fr 12 และ fred␣ 13

คลังและกฎชุดนี้คือ "ผลของการฝึก" ที่จะนำไปใช้กับข้อความใหม่ในส่วนถัดไป

11. แปลงประโยคใหม่เป็นตัวเลข

~11:05–12:51

เมื่อมีคลังและกฎแล้ว เราแปลงประโยคใหม่ได้ ตัวอย่างคือ ted and fred are friends เป้าหมายคือได้รายการจำนวนเต็ม

วิธีคือไล่กฎทีละข้อตามลำดับแล้วใช้กับประโยค:

  1. d + ␣ → d␣: เจอ 3 ครั้ง ในประโยค รวมให้หมด
  2. e + d␣ → ed␣: หาทุกจุดแล้วรวม
  3. f + r → fr: หาทุกจุดแล้วรวม
  4. fr + ed␣ → fred␣: หาทุกจุดแล้วรวม (caption ได้ยิน occurrences เป็น "currencies")

ได้ประโยคที่ตัดเป็น token แล้ว ขั้นสุดท้ายคือใช้คลังแปลงแต่ละ token เป็นเลข เช่น t เป็น 8, ed␣ เป็น 11, a เป็น 1 ไปเรื่อย ๆ จนครบทั้งประโยค

เสริมจากผู้จัดทำ: นับด้วยโค้ดแล้ว d␣ เจอ 3 ครั้ง (ted, and, fred) ed␣ 2 ครั้ง fr 2 ครั้ง (fred, friends) และ fred␣ 1 ครั้ง ประโยค 24 ตัวอักษรเหลือ 16 token ตรงกับจำนวนเลขในสไลด์

12. ตัวที่ไม่รู้จัก และข้อที่ควรเข้าใจให้ตรง

~12:53–14:20

ตัวที่ไม่รู้จัก (~12:53)

ถ้าสังเกตดี ๆ จะเห็นว่า i กับ s ได้ ? เพราะไม่มีในคลัง จึงใส่เลขให้ไม่ได้ และที่ไม่มีก็เพราะไม่เคยเห็นตัวอักษรเหล่านี้ตอนฝึก ประโยคฝึก (ผู้สอนจำประโยคไม่ได้แน่ชัดตอนพูด) ไม่มี i หรือ s เลย

ผู้สอนบอกว่ากรณีนี้เกิดได้ยากมาก ในข้อความฝึกจริงน่าจะมีตัวอักษรครบทุกตัว ที่เกิดในตัวอย่างนี้เพราะข้อความฝึกเล็กมาก และในงานจริงไม่ต้องกังวลเรื่องนี้ "อย่างน้อยกับ subword tokenization"

ช่วงท้ายคลิปเป็นการปิดและขอการสนับสนุนช่อง ซึ่งตัดออกตามกติกาของรายงาน เสียงคำสุดท้ายที่ 14:20 [ฟังไม่ชัด]

ข้อที่ควรเข้าใจให้ตรง (เสริมจากผู้จัดทำ)

ผู้จัดทำรันตัวอย่างของคลิปด้วยโค้ด Python (ไม่มี library เพิ่ม) บนประโยคฝึกตามสไลด์ ได้ผลดังนี้

from collections import Counter

def merge(tokens, a, b):
    """แทนทุกคู่ a,b ที่ติดกันด้วย token เดียว a+b (อ่านจากซ้ายไปขวา)"""
    out, i = [], 0
    while i < len(tokens):
        if i + 1 < len(tokens) and tokens[i] == a and tokens[i + 1] == b:
            out.append(a + b)
            i += 2
        else:
            out.append(tokens[i])
            i += 1
    return out

def train(corpus, k):
    """เริ่มจากตัวอักษร แล้วรวมคู่ที่ติดกันบ่อยที่สุด k ครั้ง"""
    tokens = list(corpus)
    vocab = sorted(set(tokens))
    rules = []
    for _ in range(k):
        pairs = Counter(zip(tokens, tokens[1:]))
        (a, b), n = pairs.most_common(1)[0]   # เสมอกัน = เลือกคู่ที่เจอก่อน
        rules.append((a, b))
        vocab.append(a + b)
        tokens = merge(tokens, a, b)
    return vocab, rules

def encode(text, vocab, rules):
    """ใช้กฎตามลำดับที่ได้ตอนฝึก แล้วแปลง token เป็นเลข (เริ่มที่ 1)"""
    tokens = list(text)
    for a, b in rules:
        tokens = merge(tokens, a, b)
    ids = {t: i + 1 for i, t in enumerate(vocab)}
    return tokens, [ids.get(t, "?") for t in tokens]

# คลังคำและกฎ 4 ข้อตามสไลด์ในคลิป
VOCAB = ["a", "b", "d", "e", "f", "n", "r", "t", " ", "d ", "ed ", "fr", "fred "]
RULES = [("d", " "), ("e", "d "), ("f", "r"), ("fr", "ed ")]
tokens, ids = encode("ted and fred are friends", VOCAB, RULES)
print(ids)

# ฝึกเองจากประโยคในคลิป นับคู่ตรง ๆ ทุกคู่
vocab, rules = train("fred fed ted bread, and ted fed fred bread", 4)
print(rules)

ผลที่พิมพ์ออกมา: [8, 11, 1, 6, 10, 13, 1, 7, 4, 9, 12, '?', 4, 6, 3, '?'] และ [('d', ' '), ('e', 'd '), ('ed ', 'f'), ('ed ', 'b')]

13. เชื่อมกับบทเรียนใน ZVect

อัปเดต 2026-10-11 หลังเจ้าของโปรเจกต์ขอ (15:11 และ 15:17)

เนื้อหาคลิปนี้อยู่ก่อน Token ID: Token ID ใช้คลังที่มีอยู่แล้ว ส่วนคลิปนี้ตอบว่าตัดข้อความเป็นชิ้นและสร้างคลังอย่างไร ZVect จึงเพิ่มสองหัวข้อแรกของบท 3

  • บท 3.1 Tokenization (ทำแล้ว): ตัดข้อความเป็นตัวอักษรหรือคำ แล้วเปิดคลังหาเลข มีภาพ "hello there you are amazing" แบบสไลด์ในส่วนที่ 2 (ภาพที่เจ้าของโปรเจกต์ส่งมา, WIP202610031) และช่องให้ลองพิมพ์ 4 ภาษาเหมือนบท 6.1 Bi-Encoder
  • บท 3.2 BPE (ทำแล้ว): เลื่อนจำนวนรอบ k ดูตารางนับคู่ กฎที่ได้ และประโยคใหม่ที่แปลงเป็นเลข ตัวเลขทุกตัวคำนวณสดด้วยโค้ด ไม่ลอกจากสไลด์ (เพราะรอบ 2 ในสไลด์นับเกิน)
  • Token ID เลื่อนเป็นบท 3.3 และหัวข้ออื่นในบท 3 เลื่อนตาม
  • บท 7.1 LLM input (ยังเป็นข้อเสนอ): ขั้น tokenization ที่อยู่ก่อน embedding อ้างคลิปนี้ได้ว่า GPT ใช้ BPE, BERT ใช้ WordPiece, T5 ใช้ Unigram

Key Takeaways

  1. tokenization แปลงข้อความเป็นตัวเลข เพราะเครื่องเข้าใจแต่ตัวเลข
  2. ตัวอักษร = คลังเล็ก ลำดับยาว · คำ = คลังใหญ่ ลำดับสั้น subword คือทางกลาง
  3. BPE ฝึกด้วยการรวมคู่ที่ติดกันบ่อยที่สุดซ้ำ k ครั้ง ผลคือคลังคำและกฎการรวมที่เรียงตามลำดับ
  4. ข้อความใหม่ต้องใช้กฎตามลำดับเดิม แล้วจึงแปลง token เป็นเลข ตัวที่ไม่เคยเห็นตอนฝึกได้ ?
  5. นับเองทุกครั้ง (ผู้จัดทำ): ตัวอย่างในคลิปรอบ 2 นับเกินสองค่า และกฎข้อ 3–4 ไม่ใช่ผลของการนับตรง ๆ
