What is Sentiment Analysis? — Martin Keen, IBM Technology

✍️ IBM Technology (ผู้บรรยาย Martin Keen)📅 เผยแพร่ 2024-06-19⏱ 10:04🧩 โหมด iwd 🔗 คลิปต้นฉบับ (YouTube)

บทสรุปย่อ

คลิปนี้เป็นบทเรียนสั้นของ IBM Technology ที่ Martin Keen อธิบายว่า sentiment analysis คือการให้ซอฟต์แวร์อ่านข้อความจำนวนมากแล้วบอกว่าผู้เขียนรู้สึกบวก ลบ หรือกลาง ๆ อยู่ตรงไหน โดยเล่าสองแนวทางหลัก คือแบบ rule-based ที่ใช้ lexicon (กลุ่มคำที่มีทิศทางความรู้สึกกำกับ) กับแบบ machine learning ที่เรียนจากข้อมูล พร้อมชี้จุดที่ rule-based พลาดง่าย (ประชด การปฏิเสธ สำนวน) แล้วปิดด้วยสามชนิดของงาน คือ fine-grained, aspect-based (ABSA) และ emotion detection รายงานนี้เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ส่วนที่ผู้จัดทำเสริม (ผลตรวจข้อเท็จจริง การเชื่อมกับบทเรียนของ ZVect) แยกไว้ในกล่อง "เสริมจากผู้จัดทำ" ทุกแห่ง

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ แบบวิเคราะห์เชิงลึก (license มาตรฐานของ YouTube) ตรวจข้อเท็จจริงแล้ว 9 ข้อ ส่วนที่ผู้จัดทำเสริมมีป้าย "เสริมจากผู้จัดทำ" ทุกแห่ง

สรุปเชิงลึก

โจทย์ของคลิป บริษัทอ่านใจลูกค้าไม่ได้ แต่อ่านสิ่งที่ลูกค้าเขียนออนไลน์ได้ (ทวีต อีเมล รีวิว และอื่น ๆ) sentiment analysis คือการวิเคราะห์ข้อความปริมาณมากเพื่อดูว่าความรู้สึกที่แสดงออกเป็นบวก ลบ หรืออยู่ระหว่างกลางอย่าง neutral เป้าหมายคือให้บริษัทเข้าใจลูกค้าดีขึ้น ทำประสบการณ์ลูกค้าให้ดีขึ้น และดูแลชื่อเสียงแบรนด์ แต่ผู้บรรยายเตือนทันทีว่างานนี้ก็มีกับดักอยู่ด้วย งานนี้ตั้งอยู่บน NLP (natural language processing) คือการฝึกซอฟต์แวร์ให้วิเคราะห์และตีความข้อความในแบบที่เลียนการเข้าใจของมนุษย์

สองแนวทางหลัก และอาจผสมกัน (hybrid) แนวทางแรก rule-based ใช้ lexicon คือกลุ่มคำที่บอกเจตนาของผู้เขียน ตัวอย่างในคลิป: affordable, well-made, fast อยู่ในกลุ่มบวก ส่วน expensive, poorly made, slow อยู่ในกลุ่มลบ ซอฟต์แวร์สแกนข้อความหาคำเหล่านี้ แล้วคำนวณคะแนนความรู้สึกจากความถี่และบริบทของคำ รีวิว "รองเท้าราคาจับต้องได้ (affordable) และส่งเร็ว" ได้คะแนนบวกสูง จึงจัดเป็นบวกโดยรวม

จุดที่ rule-based พลาด ผู้บรรยายเล่นมุกล้อว่าภาษามนุษย์คงไม่มาขวางการให้คะแนนแน่ แล้วชี้ว่านั่นคือการประชด (sarcasm) ซึ่งทำให้ระบบสะดุดได้ โดยเฉพาะแบบ rule-based เช่น รีวิวประชดว่ารองเท้า "ดีเยี่ยม" ใช้ได้แค่สัปดาห์เดียว ระบบแบบกฎอาจเห็น wonderful กับ well-made แล้วตัดสินว่าบวก จึงพลาดน้ำเสียงประชดไป ปัญหาที่สองคือการปฏิเสธ (negation) เช่น "I wouldn't say the shoes were inexpensive" ซึ่งสื่อว่ารองเท้าค่อนข้างแพง ทั้งที่ inexpensive ปกติอยู่ฝั่งบวก ปัญหาที่สามคือสำนวน (idiom) เช่น รีวิวที่บอกว่าราคานี้รองเท้าเป็น a steal ซึ่งแปลว่าถูกมาก ไม่ได้หมายถึงการขโมย

Machine learning ช่วยแก้บางส่วนของปัญหาเหล่านี้ด้วยการฝึกอัลกอริทึมบนชุดข้อมูลขนาดใหญ่ให้จับรูปแบบรวมถึงความซับซ้อนของภาษา โดยทั่วไปใช้อัลกอริทึมจำแนกประเภท (classification) คลิปยกสามตัว: linear regression (ทำนายคะแนนความรู้สึกจาก feature เช่น ความถี่ของคำบวกและลบ ความยาวรีวิว วลีที่แสดงอารมณ์), Naive Bayes (ใช้ทฤษฎีบทของ Bayes คำนวณความน่าจะเป็นของความรู้สึกจากคำที่ปรากฏ โดยเรียนจากรีวิวที่ติดป้ายบวก/ลบไว้แล้ว) และ SVM (หาเส้นแบ่งที่ดีที่สุดระหว่างสองกลุ่ม ให้ margin ระหว่างรีวิวบวกกับลบกว้างที่สุด) ผู้บรรยายสรุปว่าวิธีเหล่านี้ช่วยกรองประชด การปฏิเสธ และสำนวนในข้อความที่คนเขียน

Polarity และสามชนิดของงาน ทุกชนิดอาศัยการวัด polarity คือความรู้สึกโดยรวมของข้อความบนสเกลจากบวกผ่านกลางไปลบ และบางโมเดลแบ่งละเอียดถึง "บวกมาก" กับ "ลบมาก" (1) fine-grained หรือ graded: บอกระดับของอารมณ์ ผู้บรรยายอธิบายว่ามักแสดงเป็นคะแนน 0–100 โดย 0 คือ neutral และ 100 คือรุนแรงสุด (2) aspect-based (ABSA): โฟกัสด้านใดด้านหนึ่งของสินค้า บริการ หรือประสบการณ์ เช่น แอปท่องเที่ยวราคาประหยัดดูเฉพาะฟีดแบ็กเรื่อง chatbot ตัวใหม่ (3) emotion detection: ดูสภาพจิตใจและเจตนาของผู้เขียน ซับซ้อนกว่าสองชนิดแรกตามที่ผู้บรรยายว่า เช่น ตั๋วซัพพอร์ตที่เขียนว่า "ฉันหงุดหงิดมากกับปัญหาที่เกิดซ้ำ" บอกทั้งความรู้สึกลบและอารมณ์เฉพาะคือ frustration

ใช้ทำอะไร ผู้บรรยายยกตัวอย่างว่าองค์กรใช้ตัดสินใจว่าเรื่องไหนควรยกระดับในฟอรัมซัพพอร์ต ทำ market research เรื่องคู่แข่ง จับแนวโน้ม และหาโอกาสใหม่ และปิดว่า ถ้าทำได้ถูกต้อง แม้รีวิวที่ยากสุดอย่างรีวิวประชดก็แปลงเป็นข้อมูลที่ชัดเจนได้

สิ่งที่ผู้จัดทำตรวจ ตรวจ 9 ข้อ: ยืนยัน 4, ยืนยันบางส่วน 5, ขัดแย้ง 0 ข้อที่ควรอ่านอย่างระวังมีสามข้อ ข้อแรก linear regression ถูกเรียกว่าอัลกอริทึม classification ซึ่งไม่ตรงตามตำรา (linear regression ทำนายค่าต่อเนื่อง ส่วนตัวที่ใช้จำแนกประเภทคือ logistic regression) ข้อสอง สเกล 0–100 ของ fine-grained ตรงกับถ้อยคำในหน้าเว็บของ IBM เอง แต่ผู้จัดทำไม่พบว่าเป็นรูปแบบมาตรฐานในงานวิจัย ข้อสาม rule-based รุ่นที่พัฒนาแล้วอย่าง VADER มีกฎเรื่อง negation อยู่แล้ว จึงไม่ใช่ว่า rule-based ทุกตัวพลาดเรื่องนี้ สิ่งที่คลิปไม่มี: วิธีวัดความแม่นยำ ภาษาที่ไม่ใช่อังกฤษ (รวมถึงภาษาไทย) และโมเดลที่เป็น embedding หรือ LLM

ตรวจข้อเท็จจริง

ข้ออ้างในคลิปผลตรวจรายละเอียดอ่านจาก
แนวทางมีสามแบบ: rule-based, machine learning, hybridยืนยันหน้าของ IBM เองแบ่งไว้เหมือนกัน และอธิบาย hybrid ว่าผสมสองแบบหน้า IBM "What is sentiment analysis"
rule-based ใช้ lexicon นับคำบวก/ลบ แล้วคำนวณคะแนนยืนยันบางส่วนหน้า IBM อธิบายว่านับคำจากรายการคำบวกและลบ ส่วนรุ่นที่พัฒนาแล้วอย่าง VADER (lexicon ประมาณ 7,500 คำ คะแนน -4 ถึง +4) เพิ่มกฎเรื่อง negation, ตัวเน้นระดับ, ตัวพิมพ์ใหญ่ และคำว่า "but"หน้า IBM; เอกสารบรรยายมหาวิทยาลัย UMass; บทคัดย่อ VADER
คำว่า "ฝึก" (trained) ซอฟต์แวร์ให้จัดกลุ่มคำใน lexiconยืนยันบางส่วนวิธีแบบ lexicon ไม่ได้เรียนจากข้อมูลที่ติดป้าย กลุ่มคำถูกสร้างไว้ก่อน (VADER สร้างจากคะแนนที่คนช่วยกันให้) นี่เป็นเรื่องถ้อยคำ ไม่กระทบภาพรวมเอกสารบรรยาย UMass
ประชด การปฏิเสธ สำนวน ทำให้ rule-based พลาดยืนยันบางส่วนตรงกับความเข้าใจทั่วไปของวิธีนับคำแบบง่าย แต่ VADER มีกฎ negation (ดู 3 คำก่อนคำที่มีความรู้สึก) จึงไม่ใช่ rule-based ทุกตัวพลาดเรื่องนี้ ส่วนประชดไม่พบในแหล่งที่อ่านเอกสารบรรยาย UMass
ML ใช้อัลกอริทึมจำแนกประเภท เช่น Naive Bayes และ SVMยืนยันงานคลาสสิกของ Pang, Lee และ Vaithyanathan (2002) เทียบ Naive Bayes, maximum entropy และ SVM บนรีวิวหนัง และพบว่าชนะ baseline ที่คนเขียนกฎเองarXiv cs/0205070
linear regression เป็นอัลกอริทึม classification ที่ทำนายคะแนนความรู้สึกยืนยันบางส่วนทำนายคะแนนต่อเนื่องได้จริง แต่เป็น regression ไม่ใช่ classification ตัวที่ใช้จำแนกประเภทคือ logistic regression (scikit-learn เรียกว่า "classifier") หน้า IBM ก็อธิบาย linear regression ว่าทำนายค่าหน้า IBM; เอกสาร scikit-learn LogisticRegression
SVM หาเส้นแบ่งที่ให้ margin สูงสุดระหว่างสองกลุ่มยืนยันตรงกับนิยามของ SVM: ระนาบที่ห่างจากจุดฝึกที่ใกล้สุดมากที่สุดเอกสาร scikit-learn SVM
fine-grained แสดงเป็นคะแนน 0–100 โดย 0 คือ neutralยืนยันบางส่วนตรงกับถ้อยคำในหน้า IBM เอง (ซึ่งเองก็ไม่คงเส้นคงวาว่าเริ่มที่ 0 หรือ 1) แต่ผู้จัดทำไม่พบมาตรฐานเดียวที่ตรงกับนิยามนี้ในแหล่งที่อ่าน (หน้า Stanford Sentiment Treebank พูดถึงป้ายละเอียดระดับวลีและการจำแนกบวก/ลบ ไม่ได้ระบุสเกล 0–100)หน้า IBM; หน้า Stanford Sentiment Treebank
ABSA โฟกัสด้านเฉพาะของสินค้าหรือบริการยืนยันตรงกับงานมาตรฐาน SemEval-2014 Task 4: ดึง aspect term/หมวด แล้วจำแนก polarity ของแต่ละอัน บนข้อมูลแล็ปท็อปและร้านอาหารเว็บ ACL ของ SemEval-2014 Task 4

1. sentiment analysis คืออะไร และใช้ทำอะไร (~0:00–0:37)

คลิปเปิดด้วยคำถามว่าบริษัทรู้ได้อย่างไรว่าเราคิดอะไรกับเขา คำตอบคือเขาอ่านใจไม่ได้ แต่อ่านทวีต อีเมล รีวิว และเกือบทุกอย่างที่เราเขียนออนไลน์ได้ นี่คือจุดที่ sentiment analysis เข้ามา Sentiment analysis หมายถึงการวิเคราะห์ข้อความปริมาณมากเพื่อตัดสินว่าความรู้สึกที่แสดงออกเป็นบวกหรือลบ หรืออยู่ระหว่างกลางอย่าง neutral จุดประสงค์ตามที่ผู้บรรยายบอกคือช่วยให้บริษัทเข้าใจลูกค้าดีขึ้น เพื่อมอบประสบการณ์ที่ดีขึ้นให้ลูกค้าและปรับปรุงชื่อเสียงของแบรนด์ ปิดท้ายส่วนนี้ด้วยการเตือนสั้น ๆ ว่างานนี้มี "pitfall" อยู่ด้วย ซึ่งคลิปจะกลับมาเล่าทีหลัง

เสริมจากผู้จัดทำ

ข้อสังเกตเรื่องนิยาม คลิปพูดถึงสามระดับในประโยคเดียวคือ บวก ลบ และ "กลางหรือระหว่างนั้น" ผู้จัดทำจึงใช้คำว่า polarity เรียกแกนนี้ตามที่คลิปเรียกในนาที ~6:47 ตลอดทั้งรายงาน

2. พื้นฐาน NLP และสองแนวทางหลัก (~0:37–1:00)

ผู้บรรยายบอกว่า sentiment analysis สร้างอยู่บน NLP หรือ natural language processing ซึ่งฝึกซอฟต์แวร์ให้วิเคราะห์และตีความข้อความในแบบที่เลียนการเข้าใจของมนุษย์ แนวทางหลักมีสองแบบ แบบแรกอิงกฎ (rule-based) แบบที่สองอิง machine learning และบางครั้งจะเห็นการผสมสองแบบเรียกว่า hybrid คลิปเริ่มอธิบายจาก rule-based ก่อน ส่วน hybrid ไม่มีรายละเอียดเพิ่ม (ผู้จัดทำ) ผู้ชมที่อยากรู้ว่าผสมกันอย่างไรต้องหาจากแหล่งอื่น

3. Rule-based และ lexicon (~1:00–2:38)

ในแนวทางนี้ ผู้บรรยายอธิบายว่าซอฟต์แวร์ถูก "ฝึก" ให้จัดกลุ่มคำสำคัญในข้อความตามกลุ่มคำที่เรียกว่า lexicon ซึ่งก็คือการรวมคำที่บอกเจตนาของผู้เขียนไว้ด้วยกัน ตัวอย่างที่เขียนบนกระดาน: affordable, well-made และ fast อยู่กลุ่มเดียวกันคือ positive lexicon (วาดหน้ายิ้ม) ส่วน expensive, poorly made และ slow อยู่กลุ่มลบ (วาดหน้าเศร้า) จากนั้นซอฟต์แวร์สแกนข้อความหาคำเหล่านี้ แล้วคำนวณคะแนนความรู้สึกจากความถี่และบริบทของคำ ตัวอย่างรีวิว "these shoes are affordable and shipping was fast" ได้คะแนนสูงในกลุ่มบวก จึงนับเป็นบวกโดยรวม ผู้บรรยายสรุปด้วยน้ำเสียงล้อว่า "ง่ายจัง" แล้วเชื่อมไปสู่หัวข้อถัดไป

ข้อที่ควรเข้าใจให้ตรง

ผู้จัดทำ: คลิปใช้คำว่า "ฝึก" (trained) กับ rule-based แต่วิธีแบบ lexicon ไม่ได้เรียนจากข้อมูลที่ติดป้าย กลุ่มคำถูกกำหนดไว้ก่อนแล้ว

4. ทำไม rule-based พลาด: ประชด การปฏิเสธ สำนวน (~2:38–4:22)

ประชด (sarcasm) ผู้บรรยายพูดเองว่ามุกล้อของตัวเองที่ว่าไม่มีทางที่ความซับซ้อนของภาษามนุษย์จะมาขวางการให้คะแนนนั้นเป็นตัวอย่างของการประชด และประชดทำให้ระบบ sentiment analysis สะดุดได้ โดยเฉพาะแบบ rule-based ตัวอย่างรีวิวคือรีวิวที่ร้องว่า "วิเศษจริง" รองเท้าทำดีจนใช้ได้ครบหนึ่งสัปดาห์เต็ม ระบบแบบกฎอาจเห็น wonderful กับ well-made ในกลุ่มบวก แล้วตัดสินเป็นบวกโดยรวม จึงพลาดน้ำเสียงประชดทั้งหมด การปฏิเสธ (negation) ประโยค "I wouldn't say the shoes were inexpensive" คำว่า inexpensive ปกติสื่อบวกใน lexicon แต่ที่นี่ถูกใช้ในรูปปฏิเสธเพื่อบอกว่ารองเท้าค่อนข้างแพงอยู่บ้าง ถ้าไม่เข้าใจบริบท ระบบแบบกฎอาจตีความผิด สำนวน (idiomatic language) วลีอย่าง break a leg หรือ it's a piece of cake ไม่ได้หมายตามตัวอักษร ถ้าผู้ใช้เขียนว่าราคานี้รองเท้าเป็น a steal ระบบแบบกฎอาจเข้าใจว่าเป็นความลบเรื่องการขโมย แทนที่จะเข้าใจว่าหมายถึงรองเท้าเป็นข้อตกลงที่คุ้มมาก (a great bargain)

เสริมจากผู้จัดทำ

ข้อแก้ ASR คำบรรยายอัตโนมัติเขียน "steal" เป็น "steel" และ "Bayes" เป็น "base" รายงานนี้ใช้ตามบริบทของประโยค ไม่แก้ไฟล์ transcript [!author] ข้อควรระวัง ที่คลิปว่า rule-based พลาดเรื่อง negation เป็นจริงกับวิธีนับคำแบบง่าย แต่วิธีที่พัฒนาแล้วอย่าง VADER มีกฎจัดการ negation (ดูสามคำก่อนคำที่มีความรู้สึก) ดูตารางตรวจข้อเท็จจริง

5. Machine learning: linear regression, Naive Bayes, SVM (~4:22–6:27)

ผู้บรรยายเริ่มว่าแนวทาง machine learning ช่วยแก้บางส่วนของปัญหาข้างต้นได้ด้วยการฝึกอัลกอริทึมบนชุดข้อมูลขนาดใหญ่ ให้จับรูปแบบรวมถึงความซับซ้อนของภาษามนุษย์ นักพัฒนาใช้อัลกอริทึม sentiment analysis สอนซอฟต์แวร์ให้ระบุอารมณ์ในข้อความ ในแบบที่ผู้บรรยายว่าเหมือนที่มนุษย์ทำ ซึ่งโดยทั่วไปทำด้วยอัลกอริทึมจำแนกประเภท (classification) คลิปยกสามตัวอย่าง Linear regression ผู้บรรยายเรียกว่าอัลกอริทึม classification ที่ค่อนข้างพบบ่อย ในกรณีนี้ทำนายคะแนนความรู้สึกจาก feature ในข้อความ เช่น ความถี่ของคำบวกและลบ ความยาวรีวิว และวลีที่แสดงอารมณ์เฉพาะ Naive Bayes ใช้ทฤษฎีบทของ Bayes จำแนกข้อความโดยคำนวณความน่าจะเป็นของความรู้สึกจากคำที่ปรากฏ เช่น ถ้ามีชุดรีวิวร้านอาหารที่ติดป้ายบวก/ลบไว้แล้ว อัลกอริทึมจะคำนวณโอกาสที่รีวิวใหม่เป็นบวกหรือลบจากคำที่มี SVM (support vector machine) ผู้บรรยายว่าเป็นอัลกอริทึมจำแนกประเภทที่เร็วและได้ผล ใช้กับปัญหาสองกลุ่ม จำแนกรีวิวเป็นบวกหรือลบโดยหาเส้นแบ่งที่ดีที่สุดระหว่างสองกลุ่ม จากการวิเคราะห์ feature อย่างความถี่ของคำและวลี ให้ margin ระหว่างรีวิวบวกกับลบกว้างที่สุด ผู้บรรยายสรุปว่าเมื่อใช้ร่วมกัน วิธีเหล่านี้ช่วยกรองประชด การปฏิเสธ และสำนวนในข้อความที่มนุษย์เขียนได้

ข้อที่ควรเข้าใจให้ตรง

ผู้จัดทำ: linear regression เป็นเทคนิค regression (ทำนายค่าต่อเนื่อง) ไม่ใช่ classification ตัวที่ใช้จำแนกประเภทเป็นหลักคือ logistic regression ที่คลิปพูดว่า "ทำนายคะแนนความรู้สึก" ตรงกับธรรมชาติของ linear regression แต่คำว่า classification ไม่ตรง [!author] สิ่งที่คลิปไม่ได้บอก คลิปไม่ได้บอกว่าข้อความถูกแปลงเป็นตัวเลขอย่างไรก่อนเข้าอัลกอริทึมทั้งสามตัว (ที่คลิปเรียก "word frequencies" คือ bag of words นั่นเอง) และไม่ได้บอกว่าวิธีเหล่านี้จัดการประชดหรือสำนวนได้ดีแค่ไหนจริง คำกล่าวว่า "ช่วยกรอง" เป็นของผู้บรรยาย

6. Polarity: สเกลจากบวกถึงลบ (~6:27–7:21)

ผู้บรรยายบอกว่าองค์กรเลือกใช้ sentiment analysis ได้หลายชนิดตามความต้องการ เพื่อให้เห็นภาพความรู้สึกลูกค้าชัดขึ้น และทุกชนิดอาศัยความสามารถของซอฟต์แวร์ในการวัดสิ่งที่เรียกว่า polarity Polarity คือความรู้สึกโดยรวมที่ข้อความสื่อ โดยทั่วไปอธิบายเป็นสเกล: บวกอยู่ปลายด้านหนึ่ง กลางอยู่ตรงกลาง และลบอยู่ปลายอีกด้าน บางโมเดลไปไกลกว่านั้นด้วยการแบ่งข้อความเป็นหมวดย่อย เช่น "บวกมาก" (extremely positive) และ "ลบมาก" (extremely negative)

เสริมจากผู้จัดทำ

ในงานจริง สเกลนี้คือ label ที่ต้องเลือกตอนสร้างชุดข้อมูล (เช่น สามระดับ บวก/กลาง/ลบ) คลิปไม่ได้ลงรายละเอียดตรงนี้

7. สามชนิด: fine-grained, ABSA, emotion detection (~7:21–9:21)

Fine-grained (graded) ชนิดนี้จัดข้อความตามอารมณ์และระดับของอารมณ์ที่แสดงออก ผู้บรรยายว่า polarity ในชนิดนี้มักแสดงเป็นคะแนน 0–100 โดย 0 คือ neutral และ 100 คือความรู้สึกรุนแรงที่สุด Aspect-based (ABSA) จำกัดโฟกัสไว้ที่ด้านใดด้านหนึ่งของสินค้า บริการ หรือประสบการณ์ลูกค้า ตัวอย่างในคลิป: แอปท่องเที่ยวราคาประหยัดอาจใช้ ABSA วิเคราะห์ฟีดแบ็กเฉพาะเรื่อง chatbot ตัวใหม่ ซึ่งช่วยให้ธุรกิจรู้ชัดว่าลูกค้าชอบหรือไม่ชอบฟีเจอร์ใด และแก้เฉพาะจุดนั้นได้ Emotion detection พยายามเข้าใจสภาพจิตใจของคนที่อยู่เบื้องหลังข้อความ รวมถึงกรอบความคิดตอนเขียนและเจตนา ผู้บรรยายว่าซับซ้อนกว่าสองชนิดแรก และมักใช้เพื่อเข้าใจแรงจูงใจหรือสภาวะอารมณ์ของคนนั้นลึกขึ้น ตัวอย่าง: ตั๋วซัพพอร์ตที่เขียนว่า "I'm extremely frustrated by the repeated issues" บอกทั้งความรู้สึกลบและอารมณ์เฉพาะคือความหงุดหงิด (frustration) จึงต่างจากการใช้ polarity แค่บวก ลบ กลาง ที่ emotion detection ระบุอารมณ์เฉพาะในข้อความได้

ข้อที่ควรเข้าใจให้ตรง

สเกล 0–100 ที่ 0 = neutral เป็นคำอธิบายของคลิป (ซึ่งตรงกับหน้าเว็บของ IBM) ผู้จัดทำไม่พบมาตรฐานเดียวที่ตรงกับนิยามนี้ จึงไม่ควรถือว่าเป็นรูปแบบที่ใช้กันทั่วไป

8. สรุปและการนำไปใช้ (~9:12–9:52)

แนวคิดหลักของคลิปคือ เมื่อสร้างความเข้าใจต่อความรู้สึกที่เกี่ยวกับประสบการณ์โดยรวมของลูกค้า ฟีเจอร์เฉพาะ และอารมณ์ที่อยู่เบื้องหลัง องค์กรจะมีศักยภาพในการเปลี่ยนแปลงที่มีความหมาย ตัวอย่างที่ผู้บรรยายให้: รู้ว่าปัญหาไหนควรยกระดับในฟอรัมซัพพอร์ต ทำ market research เรื่องคู่แข่ง (คำบรรยายอัตโนมัติตัดประโยคตรงนี้ ผู้จัดทำจึงสรุปตามที่ฟังได้) จับแนวโน้ม และหาโอกาสใหม่ ผู้บรรยายสรุปว่า sentiment analysis คือเครื่องมือสกัดการวิเคราะห์ที่มีความหมายเพื่อนำทางการตัดสินใจทางธุรกิจ และถ้าทำได้ถูกต้อง มันเดินบนเส้นของความละเอียดอ่อนของมนุษย์ได้ จนแม้รีวิวที่ยากที่สุด รวมถึงรีวิวประชด ก็กลายเป็นข้อมูลที่ชัดเจนได้ ท้ายคลิปเป็นคำเชิญให้ถามคำถามและ subscribe ซึ่งผู้จัดทำไม่ได้นำมาไว้

9. เสริมจากผู้จัดทำ: ใช้กับ ZVect อย่างไร (นอกคลิป)

เสริมจากผู้จัดทำ

ทั้งหัวข้อนี้ไม่ได้มาจากคลิป คลิปไม่พูดถึง embedding, LLM หรือภาษาไทย ข้อเสนอด้านล่างเป็นความเห็นของผู้จัดทำเพื่อเชื่อมกับบทเรียนของ ZVect

สามระดับของวิธีวัดความรู้สึก (1) lexicon / bag of words: นับคำบวกลบ ตรงกับบท 4.2 (bag of words) เข้าใจง่ายที่สุด และอธิบายคะแนนย้อนกลับได้ (2) embedding: แทนข้อความด้วยเวกเตอร์ แล้วจำแนกด้วยตัวอย่างที่รู้ป้ายแล้ว ตรงกับบท 4.3–4.5 และ classify(x, centroids) ใน ZVect ซึ่งหา centroid ที่ใกล้ที่สุด (บท 8.4) (3) LLM: ให้โมเดลอ่านทั้งประโยคแล้วตัดสิน ซึ่งจัดการประชดและสำนวนได้ดีกว่าสองข้อแรก แต่คลิปนี้ไม่ได้วัดข้อนี้ ผู้จัดทำจึงไม่ยืนยัน ตัวอย่างการปฏิเสธที่คลิปยกมา คือโจทย์ตรง ๆ ของบท 8.3 บท 8.3 สอนกฎ negation แยกตามภาษา (not / ไม่ / 不 วางหน้าคำ, ない วางหลังคำ) ประโยค "I wouldn't say the shoes were inexpensive" เป็นกรณี negation ที่ซับซ้อนกว่า "not + คำ" เพราะคำปฏิเสธไม่ติดกับ inexpensive และ inexpensive เองมีคำนำหน้า in- ซึ่งเป็นการปฏิเสธในตัวมันเอง จึงเป็นตัวอย่างต่อยอดที่ดีของบทนั้น ภาษาไทย คลิปไม่ได้พูดถึงภาษาไทย ปัญหาที่ผู้จัดทำเห็นมี (ก) ไม่มีช่องว่างระหว่างคำ ทำให้การทำ lexicon ต้องตัดคำก่อน (ตรงกับบท 3.1 และ 8.1) (ข) ชุดข้อมูลภาษาไทยที่ติดป้ายความรู้สึกแบบสาธารณะมีไม่มาก ตัวที่ผู้จัดทำพบคือ Wisesight Sentiment Corpus มีข้อความโซเชียลภาษาไทย 26,737 ข้อความ ป้าย pos / neu / neg / q (คำถาม) ใบอนุญาต CC0 ตามหน้า GitHub ของ PyThaiNLP ผู้จัดทำไม่ได้ตรวจเนื้อหาข้างใน ใช้เป็นจุดเริ่มค้นต่อเท่านั้น (ค) โมเดลภาษาไทยอย่าง WangchanBERTa (RoBERTa-base ฝึกบนข้อความไทยประมาณ 78 GB ตามบทคัดย่อ) ซึ่งเป็นคนละเรื่องกับ lexicon

Key Takeaways

1.Sentiment analysis คือการให้ซอฟต์แวร์ดูข้อความปริมาณมากแล้วบอกว่าเป็นบวก ลบ หรือกลาง เป้าหมายคือให้องค์กรเข้าใจลูกค้าและตัดสินใจดีขึ้น
2.Rule-based ใช้ lexicon ของกลุ่มคำบวก/ลบ แล้วคำนวณคะแนนจากความถี่และบริบท พลาดง่ายเมื่อเจอประชด การปฏิเสธ และสำนวน (ตามคลิป)
3.Machine learning ฝึกอัลกอริทึมบนชุดข้อมูลขนาดใหญ่ คลิปยกตัวอย่าง linear regression, Naive Bayes และ SVM ผู้จัดทำเตือนว่า linear regression เป็น regression ไม่ใช่ classification
4.ทุกชนิดอาศัย polarity (บวก–กลาง–ลบ) และงานแตกเป็น fine-grained (ระดับความรุนแรง) ABSA (รายด้านของสินค้า) และ emotion detection (อารมณ์เฉพาะ)
5.(ผู้จัดทำ) ในงานจริงควรตรวจว่าวิธีที่เลือกจัดการ negation ได้หรือไม่ rule-based ที่พัฒนาแล้วอย่าง VADER มีกฎนี้ แต่ตัวนับคำแบบง่ายไม่มี
