📋 บทสรุปย่อ

บทสรุปย่อ: ผู้สอนอธิบายเป็นภาษาฮินดีตั้งแต่ศูนย์ว่า LLM เห็นข้อความอย่างไร: ข้อความถูกตัดเป็น token ("อะตอมของภาษา") ด้วย BPE แต่ละ token ได้ token ID แล้วเปิดแถวใน embedding matrix ได้เวกเตอร์ขนาดเช่น 1,536 ตัวเลข ที่ตำแหน่งถูกจัดจากการฝึกจนคำที่ใช้คล้ายกันอยู่ใกล้กัน จากนั้น self-attention ให้ทุกคำดูทุกคำ ทำให้ "bank" มีเวกเตอร์ต่างกันตามประโยค และสุดท้ายเวกเตอร์ถูกให้คะแนนกับทุกคำในคลัง ผ่าน softmax + temperature เพื่อเลือก token ถัดไป ตัวอย่างหลักคือตารางคุณสมบัติของ cat / dog / tiger / lion บนกระดานไวท์บอร์ด

โหมดของเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ (license มาตรฐานของ YouTube, ตรวจ 2026-10-11) อ่านจาก caption ภาษาฮินดีอัตโนมัติ โดยใช้คำแปลอังกฤษอัตโนมัติช่วย และเทียบตัวเลขกับกระดาน · คำบรรยายมีหลายจุดที่คลาดเคลื่อน รวมไว้ในส่วนที่ 8 · ตรวจข้อเท็จจริง 5 ข้อด้วยการค้นเว็บ (ส่วนที่ 9)

🧭 สรุปเชิงลึก

Token: ตัวอย่าง "I love AI Agents" ได้ ID 2, 891, 15, 4402 ผู้สอนเรียก token ว่า "language atoms" ในเครื่องมือตัด token ประโยคตัวอย่าง 57 ตัวอักษรได้ 11 token คำอย่าง Open, AI, 's แยกเป็น token และช่องว่างติดไปกับคำถัดไป คำยาวอย่าง internationalization แตกเป็นชิ้น เหตุผลที่ไม่เก็บคำทั้งคำ: run / running / runner และทุกภาษา จะทำให้คลังคำใหญ่มหาศาล วิธีแตกคือ BPE (ผู้สอนเรียก "byte pair coding"): เริ่มจากตัวอักษร นับคู่ที่ติดกันบ่อย รวมเป็น token ใหม่ ทำซ้ำ กฎหัวแม่มือ: 1 token ≈ 4 ตัวอักษร 1 ล้าน token ≈ 4 ล้านตัวอักษร อย่าเทียบ token กับคำ ทำไมสำคัญ: ผู้ให้บริการ (OpenAI, Claude, Gemini, DeepSeek) คิดเงินตาม token องค์กรที่มีผู้ใช้หลักล้านจึงต้องลด token ในทุกส่วนของ prompt

Embedding: ถ้าให้เลข 1–4 กับ cat, dog, tiger, lion เครื่องจะคิดว่า 1 ใกล้ 2 ซึ่งไม่มีความหมาย ผู้สอนจึงทำตารางคุณสมบัติ (ขา, ขน, หาง, ขนาด, เป็นสัตว์เลี้ยง, ดุร้าย) แล้วเห็นว่าเลขของ cat กับ dog คล้ายกัน คุณสมบัติ 6 อย่าง = 6 มิติ ขยายเป็น 1,536 มิติก็คือ embedding ของ text-embedding-3-small (รุ่นใหญ่ 3,072) แต่ในของจริงไม่มีใครกำหนดคุณสมบัติเอง โมเดลกำหนดเอง: เริ่มสุ่ม แล้วคำที่ปรากฏในประโยคคล้ายกัน (cat drinks / dog drinks, cute cat / cute dog) ถูกขยับเข้าหากันด้วย backpropagation หลายพันล้านครั้ง (distributional semantics)

เวกเตอร์และ embedding matrix: token ID คือที่อยู่ในพจนานุกรม เวกเตอร์คือรายการตัวเลขที่เก็บที่ที่อยู่นั้น ผู้สอนบอกว่าความหมายมาจากการรวมกันทั้งหมด ไม่ใช่ของคำเดี่ยว ๆ ตารางทั้งแผ่น (แถว = token ID, คอลัมน์ = D1…D1536) คือ embedding matrix หรือ lookup table embedding ไปเก็บในฐานข้อมูลเวกเตอร์ (Pinecone, Qdrant) และผู้สอนย้ำว่า Pinecone แค่เก็บและหาความคล้าย (cosine / dot) ไม่ได้สร้าง embedding เอง

Self-attention และ token ถัดไป: บนหน้าเดโม คลิกคำใน "I love AI Agents" เห็นว่าแต่ละคำให้ความสนใจคำไหน (AI ↔ Agents) ผู้สอนอธิบายเป็น dot product ของเวกเตอร์คำ ตัวอย่าง bank: "ฝากเงินในธนาคาร" กับ "ถึงฝั่งแม่น้ำยมุนา" ก่อน attention bank มีเวกเตอร์เดียว หลัง attention เวกเตอร์เปลี่ยนตามประโยค (contextual embedding) สุดท้ายเวกเตอร์ถูกให้คะแนนกับทุกคำในคลัง ผ่าน softmax + temperature: หลัง "cat drinks" milk มีโอกาสสูงสุด temperature 0 เลือกตัวสูงสุดเสมอ สูงขึ้นจะ "สร้างสรรค์" ขึ้น

ข้อควรรู้ (ผู้จัดทำ): มีจุดคลาดเคลื่อนสำคัญ เช่น เอา "1.5 แสน token ที่ ChatGPT รับได้" มาเป็นจำนวนแถวของตาราง (นั่นคือ context window ไม่ใช่ขนาดคลังคำ ~100k / ~200k), บอกว่า "ใช้สูตร BPE แก้ตัวเลข" (BPE แค่ตัด token ตัวเลขมาจากการฝึก) และอธิบาย attention โดยไม่มี Q / K / V ทั้งหมดอยู่ในส่วนที่ 8 โยงกับ ZVect: คลิปนี้เดินตามบท 3.1–3.8 และ 7.1–7.2 เกือบทั้งเส้น

1. Token คืออะไร และทำไมไม่เก็บทั้งคำ (~0:00–3:11)

ผู้สอนเปิดว่าทำเนื้อหาเป็นภาษาฮินดีเพื่อถ่ายทอดสิ่งที่เรียนจากลูกค้าต่างประเทศ แล้ววางแผนคลิป: token คืออะไร, embedding สร้างอย่างไรและหมายถึงอะไร, เวกเตอร์ และฐานข้อมูลเวกเตอร์

ประโยค "I love AI Agents" ถูกแบ่งและแต่ละชิ้นได้ token ID: I = 2, love = 891, AI = 15, agents = 4402 ผู้สอนให้นิยามว่า token คือ "language atoms" ในเครื่องมือตัด token ประโยคตัวอย่างเกี่ยวกับ OpenAI (ยาว 57 ตัวอักษร ได้ 11 token): Open เป็นหนึ่ง token, AI หนึ่ง token, 's หนึ่ง token, large หนึ่ง token ทุกชิ้นได้ ID ของตัวเอง เครื่องมือยังบอกว่าโดยเฉลี่ย 4 ตัวอักษรเป็น 1 token

ทำไมไม่เก็บทั้งคำ: คำเดียวมีหลายรูป เช่น run, running, runner และ LLM ตอบได้หลายภาษา ถ้าต้องเก็บทุกรูปของทุกคำในทุกภาษา คลังคำจะใหญ่เป็นพันล้านคำ การใส่คำตรง ๆ เข้า LLM จึงทำได้ยาก ตัวอย่างคำยาว internationalization ถูกแตกเป็น inter, nation, al และ ization ซึ่งเป็นไปตามวิธี BPE

2. BPE ตัด token อย่างไร และกฎ 4 ตัวอักษร (~3:12–8:56)

ผู้สอนเรียก BPE ว่า "byte pair coding" แล้วอธิบายด้วยคำว่า "the": เริ่มจาก T, H, E ทีละตัว แล้วลองจับคู่ ดูว่าคู่ไหนปรากฏบ่อยในข้อความทั้งหมด ถ้า "the" เจอบ่อยมาก ก็ถือ the เป็นหนึ่ง token ในทำนองเดียวกัน "Open" ใน OpenAI เจอบ่อยจึงเป็น token และ "AI" เป็นอีก token เพราะ "open" กับ "AI" ที่มีช่องว่างคั่นเจอบ่อยไม่เท่ากัน 's เป็น token แยกเพราะเจอบ่อยกับหลายคำ และช่องว่างหน้าคำ (เช่น " language") ติดไปกับคำนั้นเป็นหนึ่ง token ผู้สอนอ่านจากหน้าเดโม: เริ่มจากตัวอักษรดิบ นับคู่เพื่อนบ้านที่เจอบ่อยสุด รวมเป็น token ใหม่ แล้วทำซ้ำ "หลายล้านครั้ง" ไม่ใช่ผ่านข้อความรอบเดียวแล้วจบ

กฎหัวแม่มือ: คำ 4 ตัวอักษรส่วนใหญ่เป็น 1 token ถ้าพูดถึง 1 ล้าน token ก็คือราว 4 ล้านตัวอักษร (ผู้สอนคิดแบบอินเดีย: 1 ล้าน = 10 lakh × 4 ตัวอักษร = 40 lakh คือราว 4 ล้านตัวอักษร) อย่าคิดว่า 400 token = 400 ตัวอักษร หรือ 400 คำ ให้คิดว่าเป็น token ที่เกิดจากการรวมคำในประโยคและย่อหน้า

ทำไม token สำคัญ: ราคา — ไม่ว่าจะใช้ OpenAI, Claude, Gemini, DeepSeek หรือโฮสต์โมเดลเอง ทุกอย่างก็วิ่งเป็น token และบริษัท LLM ก็คิดค่าใช้จ่ายตาม token นี้ จึงต้องลด token ทุกที่ ทั้งส่วน system, user และ skill ที่สร้าง องค์กรที่มีผู้ใช้หลักล้านคนพร้อมกันต้องสู้เรื่องนี้ รวมถึงงบของ RAG ผู้สอนบอกว่าจะพูดเรื่อง latency และ context window ทีหลัง

ผลตรวจ E2: เอกสาร OpenAI: 1 token ≈ 4 ตัวอักษรภาษาอังกฤษ ≈ ¾ คำ (ภาษาไทยไม่เข้ากฎนี้ — ดูบท 3.1 ของ ZVect)

3. จากเลข ID สู่ตารางคุณสมบัติ (~10:20–17:01)

ตัวอย่างพื้นฐาน: มีคำ 4 คำ cat, dog, tiger, lion จะส่งให้ LLM สมมติว่ายังไม่มี AI หรือ LLM เลย ชิปข้างในซึ่งมี ALU (หน่วยคำนวณเชิงตรรกะ) เข้าใจแค่ 0 กับ 1 ไม่เข้าใจคำ จึงต้องแปลงเป็นตัวเลข ถ้าให้ cat = 1, dog = 2, tiger = 3, lion = 4 แล้วถามว่าใครใกล้ใคร ความเข้าใจแบบมือใหม่จะตอบว่า 1 กับ 2 ใกล้กัน (cat–dog) และ tiger กับ lion ใกล้กัน แต่คลุมเครือมาก เพราะไม่ได้ใช้คุณสมบัติหลักของสัตว์เลย มนุษย์รู้ว่าหมาแมวอยู่ใกล้คน มีสี่ขา เสือก็สี่ขาแต่ไม่อยู่กับเรา ขนาดก็ต่างกัน

ผู้สอนจึงทำตาราง: คอลัมน์ animal, index, ขา, ขน, หาง, ขนาด, เป็นสัตว์เลี้ยง (pet), ดุร้าย (wild) cat: ขา 4, มีขน, มีหาง, ขนาด 1 (เล็กสุด), เป็นสัตว์เลี้ยง, ไม่ดุร้าย · dog: ใหญ่กว่า cat ขนาด 2, เป็นสัตว์เลี้ยง · tiger: ขนาด 3, ไม่ใช่สัตว์เลี้ยง, ดุร้าย · lion: ใหญ่สุด 4, ดุร้าย ตอนนี้ตัวเลขของ cat กับ dog "ค่อนข้างคล้ายกัน" ต่างจากตอนให้เลข 1, 2, 3, 4 ที่เครื่องตอบอย่างไม่มีความหมาย คุณสมบัติ 6 อย่าง = 6 มิติ ผู้สอนบอกว่าค่าขนาดจะให้ 10 ก็ได้ ตัวเลขเหล่านี้ทำให้คอมพิวเตอร์ "มีเหตุผล" ที่จะวางสองคำไว้ด้วยกัน

ข้อสังเกต (ผู้จัดทำ): เวกเตอร์บนกระดานรวมเลข index ไว้หน้า (cat → [1, 4, 1, 1, 1, 1, 0]) ซึ่งเอาเลข ID ที่ไม่มีความหมายกลับเข้าไปปน และค่าของ tiger / lion ที่พูดออกเสียงสับสน (ผู้สอนแก้เองที่ ~16:39 ว่า "เลข 3 ตรงนี้เขียนผิด" ควรเป็นขา 4, ขน 1, หาง 1, ขนาด 4 หรือจะให้ขนาด 10 ก็ได้) ตารางด้านบนจึงใช้เฉพาะ 6 คุณสมบัติตามที่ผู้สอนนับ ("6 มิติ")

4. จาก 6 มิติเป็น 1,536 มิติ และใครเป็นคนกำหนดตัวเลข (~17:02–24:40)

ถ้าขยาย 6 มิติเป็น 1,536 มิติ ก็คือ embedding ที่ OpenAI ให้ใน text-embedding-3-small และรุ่นใหญ่ให้ 3,072 (ASR ได้ยินเป็น "372") ความหมายของคำถูกนิยามด้วยตัวเลข 1,536 ตัว เช่นส่งประโยค "I love NitMonk videos" ก็ได้ embedding ที่บอกว่าคำเหล่านี้เชื่อมกันอย่างไร

ผู้สอนวาดตารางแบบ Excel: ถ้า ChatGPT บอกว่ารับ input ได้ 1.5 แสน token ให้นึกถึงแถว 0 ถึง 150,000 คอลัมน์คือ D1, D2 … D1536 ถ้าแถวหนึ่งคือ cat ก็เก็บตัวเลข 1,536 ตัวของ cat ได้อาร์เรย์ที่แทน cat และเรียกตารางนี้ว่า "พจนานุกรม" (ส่วนที่ 8 อธิบายว่าจำนวนแถวที่ถูกคือขนาดคลังคำ ไม่ใช่จำนวน token ที่รับได้)

ทวนเส้นทาง: token ID → BPE เลือกว่าอะไรเป็น token (cat เป็น token เพราะ c หรือ ca ไม่มีความหมาย และ cat เจอบ่อย) → มิติที่มีตัวเลข แต่ในของจริงไม่มีใครนั่งกำหนดคุณสมบัติเอง บอกไม่ได้ว่า D1 คือขา D2 คือขน มิติอย่าง 1,536, "372" (น่าจะหมายถึง 3,072) หรือ "น่าจะ 436" ตามที่ผู้สอนพูด โมเดลกำหนดเอง: ก่อนฝึกกระจายแบบสุ่ม หลังฝึกคำที่ใช้ในบริบทคล้ายกัน "ลอย" เข้าหากัน ประโยคอย่าง "the cat drinks" / "the dog drinks", "cute cat" / "cute dog", "pet cat" / "pet dog" สร้างคุณสมบัติเหล่านี้ แล้ว backpropagation: ทุกครั้งที่โมเดลทายผิดก็ขยับตัวเลขทีละนิด หลายพันล้านครั้ง เรียกว่า distributional semantics คำที่เชื่อมกันในหลายประโยคถูกย้ายมาอยู่ที่เดียวกัน

ตัวอย่าง 2 มิติของผู้สอน (~24:00): ก่อนฝึก tiger (10, 20), dog (100, 120), cat (10, 30) หลังเจอประโยค dog ราว (101, 110) และ cat ราว (105, 108) — พิกัดของหมาแมวเข้ามาใกล้กัน (ตัวเลขประกอบภาพ ไม่ใช่ผลฝึกจริง)
โยงกับ ZVect: บท 3.7 "ตารางมาจากการฝึก" สาธิตแนวคิดนี้ด้วยกฎขยับทีละนิด และบท 3.8 Latent space

5. เวกเตอร์, embedding matrix และทำไมไม่ใช้ 1 ล้านมิติ (~24:41–29:25)

สามคำที่ต้องแยก: token = ชิ้นของข้อความ ("language atom") · token ID = ที่อยู่ในพจนานุกรม · เวกเตอร์ = รายการตัวเลขที่เก็บอยู่ที่ที่อยู่นั้น ใน 2 มิติเวกเตอร์มี 2 ตัวเลข 3 มิติมี 3 ตัว ไปจนถึง 1,536 ตัว ผู้สอนพูดว่ามิติแต่ละตัวมีความหมาย แต่ "ไม่ใช่ความหมายของคำเดี่ยว ๆ การรวมกันทั้งหมดต่างหากที่ให้ความหมาย" และนั่นทำให้คำเข้ามาใกล้กัน (ถ้อยคำกำกวม ผู้จัดทำเข้าใจว่าหมายถึงการรวมกันของตัวเลขทุกมิติ) เราจึงหาความคล้ายของ cat กับ dog และความไม่คล้ายของ cat กับ banana ได้ ตัวเลขเริ่มต้นสุ่ม เช่น 0.14, … แล้วถูกจัดใหม่ระหว่างฝึก

Embedding matrix: แผ่นงานทั้งแผ่น แถวคือ token ID (0, 1, … ไปถึงราว 1.5 แสน) คอลัมน์ D1 ถึง D1536 หนึ่งแถว = หนึ่งเวกเตอร์ ทั้งชุด = embedding matrix หรือ lookup table เช่นแถว ID 40213 เก็บตัวเลขของคำนั้น เริ่มจากสุ่มแล้วจัดระเบียบตามการฝึก

ทำไมไม่ใช้ 1 ล้านมิติ: ผู้สอนตอบว่าต้องนิยาม D1 ถึง D1,000,000 และถ้าคิดเป็นตาราง 1 ล้าน × 1 ล้าน (ID 1 ล้าน × มิติ 1 ล้าน) ทุกครั้งที่หยิบคำก็ต้องหยิบแถวยาว 1 ล้านตัวเลข → ช้ามาก จึงใช้ 1,536 มิติซึ่ง transformer ปัจจุบันเข้าใจความหมายของคำที่มนุษย์สร้างได้ และ 3,072 ก็เข้าใจได้

ฐานข้อมูลเวกเตอร์: embedding เหล่านี้ไปเก็บใน Pinecone หรือ Qdrant แต่Pinecone ไม่ได้สร้าง embedding มันแค่เก็บค่า และหา cosine similarity หรือ dot product ว่าแถวไหนใกล้กัน embedding มาจากโมเดลอย่าง text-embedding-3-small ของ OpenAI ด้วยมิติที่เราเลือก

ผลตรวจ E5: หน้าที่หลักของฐานข้อมูลเวกเตอร์คือเก็บและค้นจริง แต่ปัจจุบัน Pinecone, Weaviate, Milvus และ Qdrant ต่างมีตัวเลือกสร้าง embedding ในตัว (integrated inference / vectorizer) แล้ว

6. Self-attention: ทุกคำมองทุกคำ และ bank สองความหมาย (~31:13–35:23)

บนหน้าเดโมมีประโยค "I love AI Agents" คลิกที่ I → ใกล้ love ที่สุด · คลิก love → ไปที่ I และ agents · คลิก AI → ไปที่ agents · คลิก agents → ไปที่ AI ผู้สอนอธิบาย: ให้ I เป็นเวกเตอร์ a, love = b, AI = c, agents = d หา dot product ของ a กับ b ได้ความคล้าย สมมติว่าได้ 93% "แบบนี้ก็เหมือน attention" ทุกคำแสดง "ความสนใจ" ว่าควรอยู่ใกล้ใคร นี่คือที่มาของ self-attention: transformer หาความสัมพันธ์ของทุกคำกับทุกคำจากความคล้ายของเวกเตอร์ เหมือนที่ cat กับ dog คล้ายกัน

ตัวอย่าง bank: "I deposited money in the bank" — bank คือสถาบันการเงินที่ฝากเงิน · "I reached Yamuna river bank" — bank คือฝั่งแม่น้ำที่นั่งเรือมาถึง เวกเตอร์ของ bank ขึ้นกับประโยค ทุกคำมีเวกเตอร์ของตัวเอง แต่มี contextual embedding ที่ผูกกับประโยคที่คำนั้นอยู่ ก่อน attention Apple (หรือ bank) มี embedding ตายตัวหนึ่งเดียว หลัง attention อ่านประโยครอบข้างแล้ว เวกเตอร์เปลี่ยน — bank ถูกดึงไปทางสถาบันการเงินหรือฝั่งแม่น้ำ, apple ถูกดึงไปทางผลไม้หรือบริษัท token เดียวกัน ความหมายต่างกัน เพราะบริบทเปลี่ยนตัวเลข บนหน้าเดโม แถวของ "I ate an apple" กับ "Apple released a phone" มีตัวเลขต่างกันทั้งแถว

โยงกับ ZVect: บท 7.2 Attention: query · key และบท 6.2 (late interaction ใช้เวกเตอร์ตามบริบทของทุก token)

7. เลือก token ถัดไป: softmax และ temperature และสรุปทั้งเส้น (~35:24–38:44)

ผู้สอนอ่านจากหน้าเดโม: หลังผ่านทุกชั้น เวกเตอร์สุดท้ายถูกให้คะแนนกับทุกคำในคลังคำ คะแนนดิบกลายเป็นความน่าจะเป็นด้วย softmax และ temperature ตัวอย่างหลัง cat มีตัวเลือก milk, water, the, coffee, juice ผู้สอนถามว่าคำไหนน่าจะมาที่สุด — milk เพราะในประโยคทั้งหมดที่ใช้สร้างเวกเตอร์ cat กับ milk มาด้วยกันบ่อย เวกเตอร์ของ cat และ milk จึง "คล้ายกันมาก" ถ้าคุยเรื่อง cat กับ pet ก็จะมี contextual embedding ที่ถูกอัปเดตตามประโยคเหมือนกรณี apple และ bank GPT เลือก token ถัดไปจากความคล้ายของเวกเตอร์ร่วมกับ self-attention ส่วน softmax และพารามิเตอร์กำหนดว่าจะเลือกกี่ token

temperature: ตั้งเป็น 0 → เลือก token ที่ใกล้ที่สุดเสมอ (milk ที่ 93%) ถ้าตั้งเป็น 3 → "สร้างสรรค์ขึ้นอีกหน่อย" ถ้าแมวดื่มนมก็คงดื่มน้ำ milk และ water จึงมีโอกาสทั้งคู่

สรุปทั้งเส้นของผู้สอน: "I love AI agents" → ตัดเป็น token (I, love, AI, agents) → ให้ token ID เก็บในตาราง → ทำมิติ D1 ถึง D1536 ให้ตัวเลขสุ่มก่อน → "ใช้สูตร BPE แก้ตัวเลข" (ดูส่วนที่ 8) → ได้ embedding matrix → เวกเตอร์ → self-attention หา dot product ได้ความคล้าย → เมื่อ self-attention ทำงาน ก็สร้าง token ถัดไปได้

8. จุดที่คำบรรยายคลาดเคลื่อน (เสริมจากผู้จัดทำ)

  • จำนวนแถวของ embedding matrix ≠ จำนวน token ที่รับได้: ผู้สอนเอา "ChatGPT รับ input 1.5 แสน token" มาเป็นแถว 0–150,000 ของตาราง จำนวนแถวที่ถูกคือขนาดคลังคำ (tokenizer o200k_base ของ GPT-4o ≈ 200,000 · cl100k_base ≈ 100,000 — ผลตรวจ E3) ส่วนจำนวน token ที่รับได้ในครั้งเดียวคือ context window เป็นคนละเรื่อง หน้าเดโมเองเขียนว่าตารางมี "ราว 150,000 แถว" (150,000 × 1536 ≈ 230 ล้านตัวเลข) ซึ่งใช้เป็นตัวเลขกลม ๆ ของคลังคำได้ ที่ผิดคือเหตุผลว่า 150,000 มาจากจำนวน token ที่ ChatGPT รับได้
  • BPE ไม่ได้ "แก้ตัวเลข": ในสรุปท้าย (~38:12) ผู้สอนพูดว่าใช้สูตร BPE แก้ตัวเลขในตาราง BPE ทำแค่ขั้นตัด token ตัวเลขในตารางมาจากการฝึกด้วย backpropagation ซึ่งผู้สอนเองอธิบายถูกที่ ~22:48
  • ข้อชี้แจงเรื่อง 1 ล้านมิติ: ขนาดตาราง = คลังคำ × มิติ (ผู้สอนสมมติให้ทั้งสองเป็น 1 ล้าน) การเพิ่มมิติทำให้แต่ละแถวยาวขึ้นเท่านั้น และเหตุผลที่ไม่ใช้มิติสูงมากไม่ได้มีแค่ความเร็ว แต่รวมถึงหน่วยความจำและข้อมูลที่ต้องใช้ฝึกด้วย (ผู้จัดทำ; ดูบท 5.2 มิติสูง)
  • self-attention ไม่ใช่ dot product ของเวกเตอร์คำตรง ๆ: ของจริงแปลงแต่ละคำเป็น query / key / value ด้วยเมทริกซ์ที่ฝึกมา แล้วใช้ softmax(q · k) ถ่วงน้ำหนัก value (คำอธิบายคลิปมีหัวข้อ QKV แต่ในเนื้อคลิปไม่ได้อธิบาย) ตัวเลข "93%" เป็นภาพประกอบ — ZVect บท 7.2 ใช้ query · key
  • เลือก token ถัดไปไม่ได้มาจาก "cat คล้าย milk" โดยตรง: เวกเตอร์สุดท้ายของตำแหน่งนั้นถูกคูณกับเมทริกซ์ผลลัพธ์เพื่อให้คะแนนทุกคำ (ตามที่หน้าเดโมเขียน) ความคล้ายของ embedding cat กับ milk เป็นการเปรียบเทียบแบบง่าย
  • softmax ไม่ได้กำหนดว่าจะเลือกกี่ token: ผู้สอนพูดว่า softmax และพารามิเตอร์กำหนดว่าจะเลือกกี่ token แต่ softmax แค่แปลงคะแนนดิบเป็นความน่าจะเป็น โมเดลเลือกทีละ 1 token ต่อรอบ ส่วน temperature, top-k, top-p กำหนดว่าจะสุ่มจากตัวเลือกกว้างแค่ไหน (ความรู้ทั่วไป)
  • temperature 3: API ของ OpenAI รับ 0 ถึง 2 (ผลตรวจ E4) แนวคิด "สูงขึ้น = หลากหลายขึ้น" ถูก
  • การนับมิติ: ผู้สอนบอก 6 คุณสมบัติ = 6 มิติ แต่เวกเตอร์บนกระดานมี 7 ตัวเลขเพราะรวม index ไว้ด้วย
  • คำแปลอัตโนมัติ: คำฮินดี "पेट" ในตารางคือคำอังกฤษ pet (สัตว์เลี้ยง) ไม่ใช่ "ท้อง" ตามที่ YouTube แปลอัตโนมัติ (ยืนยันจากกระดานที่เขียน Pet)

9. ผลตรวจข้อเท็จจริง (เสริมจากผู้จัดทำ, 2026-10-11)

คลิปเผยแพร่หลังความรู้ของผู้จัดทำ จึงให้ผู้ตรวจแยกค้นเว็บจากแหล่งต้นทาง 5 ข้อ: ยืนยัน 4 · บางส่วน 1 · ไม่พบ 0 · ขัดแย้ง 0

Key Takeaways

  1. token = ชิ้นข้อความจาก BPE · token ID = ที่อยู่ · เวกเตอร์ = ตัวเลขที่เก็บที่ที่อยู่นั้น · embedding matrix = ตาราง lookup ทั้งแผ่น
  2. เลข ID เปล่า ๆ ทำให้เครื่องตอบอย่างไม่มีความหมาย (1 ใกล้ 2 จึงบอกว่า cat ใกล้ dog โดยไม่มีเหตุผล) ตัวเลขที่มีความหมายต้องมาจากคุณสมบัติ — ในของจริงโมเดลเรียนเองจากบริบท
  3. 1 token ≈ 4 ตัวอักษร (ภาษาอังกฤษ) และผู้ให้บริการคิดเงินตาม token
  4. self-attention ทำให้คำเดียวกัน (bank, apple) ได้เวกเตอร์ต่างกันตามประโยค
  5. token ถัดไป = คะแนนกับทุกคำในคลัง → softmax + temperature · ระวังจุดคลาดเคลื่อนของคลิป (คลังคำ ≠ context window, BPE ไม่ได้แก้ตัวเลข, ไม่มี QKV)
