บทสรุปย่อ

คลิปสอนพื้นฐาน text embedding สำหรับมือใหม่ เริ่มจากวิธีแปลงข้อความเป็นตัวเลขแบบนับคำ (one-hot, bag of words, n-gram, TF-IDF) แล้วชี้จุดอ่อนของวิธีเหล่านี้ จากนั้นอธิบายว่า embedding คือเวกเตอร์แบบ dense ที่ทำให้คำความหมายใกล้กันอยู่ใกล้กันใน embedding space ได้มาจากการฝึก model (word2vec แบบ CBOW / skip-gram) และปัจจุบันนิยม contextual embedding จาก transformer ปิดท้ายด้วยการเรียกใช้ model สำเร็จรูปของ OpenAI เพื่อวัดระยะระหว่างข้อความ

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ครบทุกประเด็นและตัวเลข พร้อมตรวจข้อเท็จจริง (license มาตรฐานของ YouTube)

สรุปเชิงลึก

ปัญหาตั้งต้น: คอมพิวเตอร์ต้องการตัวเลข ผู้สอนแบ่ง embedding เป็นสองแบบ คือ token (หรือ word) embedding แทนคำเดียว และ document embedding แทนทั้งประโยคหรือย่อหน้า ทั้งสองแบบสร้างได้ด้วยหลักการคล้ายกัน

รุ่นแรก นับคำ (frequency-based): one-hot ใช้เวกเตอร์ยาวเท่าจำนวนคำในคลังคำ (vocabulary) มีเลข 1 ช่องเดียว · bag of words นับว่าแต่ละคำอยู่ในประโยคกี่ครั้ง · n-gram นับเป็นกลุ่มคำ เช่น สองหรือสามคำ · TF-IDF ดูทั้งความถี่ในเอกสารนั้นและความถี่ในเอกสารอื่น เพื่อแยกคำทั่วไปอย่าง the ออกจากคำที่สำคัญจริง ผู้สอนบอกว่าวิธีเหล่านี้เข้าใจง่ายและช่วยงาน NLP มาหลายปี แต่มีจุดอ่อนสี่ข้อ ได้แก่ ไม่สนลำดับคำ (dog bit owner สองแบบได้เวกเตอร์เดียวกัน) ไม่ดูบริบท (fine สองความหมายได้ค่าเดียวกัน) เวกเตอร์ยาวและมีแต่ศูนย์ (คลังคำ 100,000 คำ ก็ต้องใช้ 100,000 ช่อง) และจับความหมายไม่ได้ ("Meal was bad" กับ "Food is awful" ได้เวกเตอร์ต่างกันทั้งที่ความหมายแทบเหมือนกัน)

รุ่นที่สอง embedding: แนวคิดย้อนไปถึงนักภาษาศาสตร์ยุค 1950s ว่า คำที่อยู่ในบริบทคล้ายกันมีความหมายคล้ายกัน (ตัวอย่าง ong choy ซึ่งผู้จัดทำตรวจพบว่าเป็นตัวอย่างในตำรา Jurafsky & Martin) เป้าหมายคือเวกเตอร์ dense ที่สั้นกว่าจำนวนคำ ผู้สอนบอกว่าขนาดมักอยู่ราว 50 ถึงไม่กี่พันมิติ เช่น text-embedding-ada-002 ของ OpenAI ให้ 1,536 ตัวเลข ค่าแต่ละตัวในเวกเตอร์ไม่มีความหมายในตัวเอง สิ่งที่สำคัญคือความสัมพันธ์ระหว่างเวกเตอร์ ใช้ cosine หรือ Euclidean วัดระยะ และใช้การลดมิติเพื่อวาดภาพสองมิติได้

สร้างอย่างไร: ข้อความ → token → token ID → one-hot (ยังไม่มีความหมาย) → embedding ซึ่งได้เป็นผลพลอยได้จากการฝึก neural network word2vec มีสองแบบ คือ CBOW (เดาคำกลางจากคำรอบข้าง) กับ skip-gram (เดาคำรอบข้างจากคำกลาง) ฝึกแบบ self-supervised ด้วยตัวอย่างบวกและลบ แล้วเก็บ weight ของ hidden layer มาเป็น embedding ข้อเสียคือได้ static embedding (คำว่า bank มีเวกเตอร์เดียว) ปัจจุบันจึงมักใช้ contextual embedding (ELMo, BERT, GPT) ที่ทำให้คำเดียวกันได้เวกเตอร์ต่างกันตามบริบท ส่วน model ที่ใช้ transformer ปรับ embedding ด้วย self-attention

ใช้งาน: ฝึก model เองได้ แต่น่าจะต้องใช้ข้อมูลมากและน่าจะใช้เวลานาน คุ้มเมื่อต้องการ model เฉพาะงาน ผู้สอนบอกว่าโดยทั่วไปใช้ model สำเร็จรูปง่ายกว่ามาก ทั้งแบบ open source และแบบเสียเงินผ่าน API (OpenAI, Mistral มี ส่วน Anthropic ไม่มี) คุณภาพขึ้นกับ model และงาน leaderboard (บนจอคือ MTEB) ใช้เป็นข้อมูลอ้างอิงตอนเลือก model ได้ เดโมใน notebook: ผู้สอนบอกว่าคู่ Paris กับ coffee shop ได้ระยะมากกว่าคู่ Amsterdam ค่าบนจอ (cosine distance) คือ Amsterdam–coffeeshop ≈ 0.175 · Paris–coffeeshop ≈ 0.224

ผลตรวจของผู้จัดทำ: ตรวจ 10 ข้อ ยืนยัน 7 ข้อ ยืนยันบางส่วน 3 ข้อ ไม่พบข้อที่ขัดแย้ง สิ่งที่ควรรู้เพิ่มคือ ada-002 ยังใช้ได้แต่มีรุ่นใหม่กว่าแล้ว (text-embedding-3-small 1,536 มิติ และ -3-large 3,072 มิติ) และบนสไลด์ bag of words ที่ ~1:58 มีเลข 1 ผิดช่องหนึ่งช่อง

เอาไปใช้ (ผู้จัดทำ): เมื่อทำระบบค้นด้วยความหมาย ให้เลือก model จากผลบนงานแบบเดียวกับของเรา และอ่านค่าที่ได้ให้ถูกชนิด (distance ยิ่งน้อยยิ่งใกล้ ส่วน similarity ยิ่งมากยิ่งใกล้)

1. Text embedding คืออะไร (~0:00–0:55)

ผู้สอนเปิดว่าเวลาทำงานกับ language model มักได้ยินคำว่า text embedding และเป็นแนวคิดที่ควรเข้าใจ คลิปนี้จึงจะอธิบายว่ามันคืออะไร สร้างอย่างไร และเริ่มใช้อย่างไร นิยามที่ให้คือ วิธีแทนคำหรือเอกสารด้วยเวกเตอร์ตัวเลขที่จับความหมายไว้ ทำให้ข้อความอยู่ในรูปที่คอมพิวเตอร์เข้าใจและทำงานต่อได้ embedding แบ่งกว้าง ๆ ได้สองกลุ่ม คือ token หรือ word embedding ซึ่งแทนคำหรือ token เดียว และ document embedding ซึ่งพยายามแทนทั้งเอกสาร อาจเป็นประโยคหรือย่อหน้า ผู้สอนบอกว่าทั้งสองแบบใช้ได้หลายงาน และสร้างจากหลักการกับเทคนิคที่คล้ายกัน

2. วิธีนับความถี่: one-hot, bag of words, n-gram, TF-IDF (~0:55–2:56)

ผู้สอนบอกว่ามีหลายวิธีมากในการแทนคำด้วยตัวเลข และไม่จำเป็นต้องซับซ้อน

  • One-hot encoding: รวบรวมคำไม่ซ้ำจากทุกประโยคเป็นคลังคำ แล้วสร้างเวกเตอร์ยาวเท่าจำนวนคำในคลัง ใส่ศูนย์ทุกช่อง ยกเว้นช่องของคำที่ต้องการแทน ผู้สอนเรียกว่าวิธีง่ายและซื่อ ๆ ได้เวกเตอร์ยาวมากต่อคำหนึ่งคำ จึงใช้พื้นที่ได้ไม่คุ้มที่สุด
  • Bag of words: ถ้าจะแทนทั้งประโยคด้วยเวกเตอร์เดียว ให้นับว่าแต่ละคำอยู่ในประโยคกี่ครั้ง
  • วิธีข้างต้นอยู่ในกลุ่ม frequency-based และมีรุ่นปรับปรุง เช่น n-gram ที่นับเป็นกลุ่มคำ เช่น สองหรือสามคำแทนการนับทีละคำ
  • TF-IDF (term frequency–inverse document frequency) ดูทั้งความถี่ของคำในเอกสารหรือประโยคนั้น และความถี่ที่คำเดียวกันไปปรากฏในเอกสารอื่นของข้อมูลฝึก เพื่อแยกคำที่ใช้ทั่วไปในภาษาอังกฤษ (the, like, you, me) ออกจากคำที่สำคัญและมีความหมายกับเอกสารนั้นจริง
ข้อที่ควรเข้าใจให้ตรง

บนสไลด์ที่ ~1:58 คลังคำคือ [this, movie, is, very, slow, and, long, spooky] และประโยค "Long and spooky movie" ควรได้ 0 1 0 0 0 1 1 1 (ช่อง movie, and, long, spooky) แต่สไลด์แสดง 0 1 0 0 1 0 1 1 คือเลข 1 ไปอยู่ช่อง slow แทน and · คำที่สไลด์ระบายสีถูกต้อง เฉพาะตัวเลขที่ผิด (ผู้จัดทำนับใหม่)

3. จุดอ่อนของวิธีนับ (~2:56–4:25)

ผู้สอนยอมรับว่าวิธีนับเข้าใจง่ายและทำได้ง่าย และช่วยงาน NLP มาหลายปี แต่มีข้อบกพร่องร้ายแรงหลายข้อ

  1. ไม่สนลำดับคำ: "Her dog bit the owner" กับ "The dog bit her owner" ได้ bag of words เหมือนกันทุกช่อง แต่ความหมายต่างกันมาก
  2. ไม่ดูบริบท: คำสะกดเหมือนกันแต่ความหมายต่าง เช่น fine ใน "I'm fine" กับ fine ใน "I got a fine" ได้ค่าเดียวกันทุกประการ
  3. เวกเตอร์ sparse: ส่วนใหญ่เป็นศูนย์ จึงไม่ใช่วิธีที่ประหยัด ถ้าคลังคำมี 100,000 คำ ก็ต้องใช้เวกเตอร์ 100,000 ช่องเพื่อแทนคำหรือประโยคเดียว
  4. อ่านแค่ตัวคำ จับความหมายข้างใต้ไม่ได้: "Meal was bad." กับ "Food is awful." ได้เวกเตอร์ต่างกันโดยสิ้นเชิง ทั้งที่ความหมายแทบจะเหมือนกัน

4. Embedding ใช้ทำอะไร และแนวคิดเบื้องหลัง (~4:26–7:30)

ผู้สอนบอกว่า text embedding สำคัญมาก และอยู่เบื้องหลังงาน NLP จำนวนมากในปัจจุบัน ตัวอย่างที่ยก:

  • Google ใช้ text embedding ช่วยระบบค้นหา โดยวางคำค้นและเอกสารไว้ในพื้นที่เดียวกัน ทำให้จับคู่คำที่ความหมายใกล้กันได้แม้ไม่มีคำตรงตัว
  • บริการแปลภาษาอย่าง Google Translate อาศัย embedding ในการแปล
  • วิเคราะห์ข้อมูลและทำ machine learning กับข้อความ เช่น clustering เพื่อหารูปแบบในข้อความจำนวนมาก
  • chatbot ที่ใช้ retrieval-augmented generation (RAG) ใช้ embedding ตีความสิ่งที่ผู้ใช้พิมพ์ ค้นข้อมูลที่เกี่ยวข้อง แล้วสร้างคำตอบ

เพื่อปูแนวคิด ผู้สอนยกคำพูดของจวงจื่อ (Zhuangzi) ใจความว่า แหมีไว้จับปลา ได้ปลาแล้วก็ลืมแหได้ คำพูดมีไว้สื่อความหมาย ได้ความหมายแล้วก็ลืมคำได้ คำจึงเป็นเพียงสื่อของความหมาย คำถามคือจะช่วยให้คอมพิวเตอร์ได้ความหมายจนลืมตัวคำได้อย่างไร

แนวคิดนี้มีประวัติยาวใน NLP ย้อนไปถึงยุค 1950s ที่นักภาษาศาสตร์เสนอว่า คำสองคำที่ปรากฏในการกระจายตัวคล้ายกัน คือมีคำข้างเคียงคล้ายกัน มีความหมายคล้ายกัน หรือคำที่ใช้ในบริบทเดียวกันมักมีความหมายใกล้กัน ตัวอย่าง: ถ้าไม่รู้จักคำว่า ong choy (คำยืมจากภาษากวางตุ้งที่เพิ่งเข้ามาไม่นาน) แต่เห็นในประโยคว่าอร่อยเมื่อผัดกับกระเทียม ดีมากเมื่อราดบนข้าว และใบเข้ากับซอสเค็ม แล้วเคยเห็นคำแวดล้อมแบบเดียวกันกับ spinach, chard และ collard greens ก็อาจเดาได้ว่า ong choy เป็นผักใบเขียวคล้ายผักเหล่านั้น ผู้สอนบอกว่าเราจึงนับได้ง่าย ๆ ว่าคำหนึ่งอยู่กับคำอื่นในบริบทเดียวกันบ่อยแค่ไหน แต่การนับเป็นเพียงจุดเริ่ม เป้าหมายคือทำให้มีประสิทธิภาพที่สุด และแทนแต่ละคำด้วยเวกเตอร์ dense โดยให้คำที่คล้ายกันอยู่ใกล้กันใน embedding space

ข้อที่ควรเข้าใจให้ตรง

ตัวอย่าง ong choy เป็นตัวอย่างในตำรา Speech and Language Processing ของ Jurafsky & Martin (บทที่ 6 ในฉบับร่าง ม.ค. 2025 สะกด ongchoi) คลิปไม่ได้ระบุที่มา · คำกล่าวว่า Google ใช้ embedding ในการค้นหาเป็นจริงบางส่วน: Google เองอธิบายว่าใช้ neural matching และ BERT แทน "แนวคิด" ในคำค้นและหน้าเว็บ แต่ไม่ได้ใช้คำว่า embedding หรือ common space (ผลตรวจของผู้จัดทำ)

5. เวกเตอร์ dense และ embedding space (~7:30–10:55)

Dense vector แปลว่าเวกเตอร์ของคำไม่ได้เป็นศูนย์เกือบทั้งหมด โดยทั่วไป embedding ของคำมีจำนวนมิติน้อยกว่าจำนวนคำในคลังคำ เวกเตอร์จึงสั้น "สั้น" แค่ไหนขึ้นกับ model ผู้สอนบอกว่ามักอยู่ระหว่าง 50 ถึงไม่กี่พัน เช่น text-embedding-ada-002 ของ OpenAI แปลงข้อความเป็นเวกเตอร์ 1,536 ตัวเลข

embedding จับความหมาย: tea กับ coffee คล้ายกันเพราะเจอในบริบทเดียวกันเสมอ (เครื่องดื่ม อาหารเช้า) จึงอยู่ใกล้กันในพื้นที่มากกว่า tea กับ pasta ข้อความที่ความหมายใกล้กันอยู่ใกล้กัน ข้อความที่ไม่ค่อยเกี่ยวกันอยู่ห่างกันในพื้นที่หลายมิติ ผู้สอนย้ำว่า ค่าแต่ละตัวในเวกเตอร์ไม่มีความหมายในตัวเอง แต่ความสัมพันธ์ระหว่างเวกเตอร์สำคัญ

Embedding space คือการแทนทางคณิตศาสตร์ของที่อยู่ของ embedding ผู้สอนไล่ตัวอย่าง: คำ 10 คำที่แต่ละคำมีตัวเลขเดียวคือ embedding หนึ่งมิติ ระยะระหว่างจุดสองจุดบอกความคล้ายของคำ ถ้าแทนด้วยสองค่าก็วางในพื้นที่สองมิติและเห็นความสัมพันธ์มากขึ้น แล้วขึ้นเป็นสามมิติ หลังมิติที่สามจะวาดภาพไม่ได้ แต่คิดด้วยตรรกะเดิม เวกเตอร์ยาว 32 คือจุดในพื้นที่ 32 มิติ วาดไม่ได้แต่ยังคำนวณระยะได้ ด้วย cosine distance, cosine similarity หรือ Euclidean distance ซึ่งมีฟังก์ชันและ package ให้ใช้อยู่แล้ว ถ้าอยากเห็นภาพ ใช้ algorithm ลดมิติแปลงข้อมูล 32 มิติเป็นสองมิติ จะเห็นคำที่คล้ายกันอยู่ใกล้กัน เช่น king, queen, sovereign, kingdom หรืออีกกลุ่ม cat, dog, pet, bird, animal

เสริมจากผู้จัดทำ: ข้อสังเกตเรื่องค่าบนสไลด์

ระยะ 0.2 และ 0.5 บนสไลด์ coffee/tea/pasta และเวกเตอร์ใต้ภาพเป็นตัวเลขประกอบภาพ ผู้สอนไม่ได้บอกว่ามาจาก model ใด จึงไม่ควรนำไปใช้เป็นค่าจริง (ผู้จัดทำ)

6. สร้าง embedding อย่างไร: วงจรชีวิตและ word2vec (~10:55–15:13)

ผู้สอนบอกว่า word embedding ได้จากการฝึก machine learning model หรือ deep learning model บน corpus ขนาดใหญ่ ซึ่งก็คือชุดข้อความจำนวนมาก วงจรชีวิต: ข้อความถูกตัดเป็นชิ้นเล็กเรียกว่า token (คำ ตัวอักษร ตัวเลข หรือเครื่องหมาย) ขั้นนี้เรียกว่า tokenization แต่ละ token ได้เลขประจำตัวเรียกว่า token ID เช่น คลังคำ 16 token ได้ ID 0 ถึง 15 ID เหล่านี้แทนข้อความแบบง่ายได้ เช่น ผ่าน one-hot แต่ทั้ง ID และ one-hot ไม่มีความหมายเกี่ยวกับตัว token เป็นแค่ตัวเลขสุ่มหรือรูปแบบ 0/1 ขั้นที่สำคัญที่สุดจึงเป็นขั้นถัดไป คือสร้าง embedding ที่จับความหมายและความสัมพันธ์ระหว่าง token

โดยทั่วไป text embedding เป็นผลพลอยได้จากการฝึก neural network หรือ machine learning model หนึ่งในวิธีดั้งเดิมที่นิยมที่สุดคือ word2vec ซึ่งรับคำแบบ one-hot แล้วสร้าง embedding โดยใช้บริบทของประโยคด้วย มีสองแบบ:

  • Continuous bag of words (CBOW): แบ่งข้อความเป็นกลุ่ม n คำ (ตัวอย่างใช้ 3 คำ) เอาสองคำรอบข้างใส่ neural network แล้วฝึกให้เดาคำกลาง
  • Skip-gram: ทำกลับกัน ใช้คำกลางเดาสองคำรอบข้าง

ผู้สอนอธิบาย skip-gram ละเอียดขึ้น และบอกว่าเข้าใจตัวนี้แล้วจะเข้าใจ model ที่คล้ายกันได้:

  • สร้าง classification model แบบ shallow neural network มี hidden layer ชั้นเดียว จำนวน neuron ใน hidden layer คือขนาดของ embedding และจำนวน neuron ใน output layer คือขนาดคลังคำ
  • model พยายามทำนายความน่าจะเป็นที่สองคำจะเป็นคำข้างเคียงกันใน corpus เช่น คำว่า car มีแนวโน้มอยู่ใกล้ apricot หรือไม่
  • ฝึกแบบ self-supervised คือเอาทั้ง input และ output จากตัวข้อความเอง สร้างตัวอย่างบวก (คำที่อยู่ข้าง apricot จริง) และตัวอย่างลบ (คำ noise ในคลังคำที่ไม่เกี่ยวกับ apricot) แล้วฝึก ผลลัพธ์คือรายการความน่าจะเป็นว่าแต่ละคำจะอยู่ใกล้ apricot แค่ไหน
  • ผู้สอนบอกว่าตลกตรงที่เราไม่ได้สนงานทำนายนี้เลย สิ่งที่เก็บคือ weight ที่เรียนได้ใน hidden layer ซึ่งก็คือ word embedding
ข้อที่ควรเข้าใจให้ตรง

คลิปเล่า skip-gram สองแบบปนกัน: output layer ขนาดเท่าคลังคำคือแบบดั้งเดิม (Mikolov 2013 ฝึกด้วย hierarchical softmax) ส่วนการฝึกด้วยตัวอย่างบวก/ลบเป็นตัวจำแนกสองคลาส คือ negative sampling ที่เสนอในงานถัดมา ทั้งสองแบบมีจริง แต่เป็นคนละวิธีฝึก (ผลตรวจของผู้จัดทำ)

7. Static กับ contextual embedding (~15:13–16:37)

word2vec และวิธีที่ใช้ shallow neural network แบบเดียวกันให้ static embedding คือแต่ละคำมี embedding เดียว เช่น bank ที่มีหลายความหมายก็ได้เวกเตอร์เดียว ผู้สอนบอกว่าเป็นปัญหาใหญ่เพราะภาษาขึ้นกับบริบท ปัจจุบันจึงมักใช้ contextual embedding ซึ่งทรงพลังกว่า วิธีสมัยใหม่ที่นิยมได้แก่ ELMo, BERT และ GPT คำเดียวกันในบริบทต่างกันจะได้เวกเตอร์ต่างกัน ผู้สอนเรียกว่าก้าวใหญ่ของงานวิจัย NLP เพราะทำให้ model เข้าใจภาษาลึกและยืดหยุ่นขึ้น จับความหมายที่เปลี่ยนเล็กน้อยตามบริบทได้ embedding model ที่ใช้สถาปัตยกรรม transformer ไม่ได้แปลงแค่ตัวคำ แต่ประมวลทั้งลำดับข้อความ แล้วปรับ embedding โดยพิจารณาบริบทของทุกคำ ผ่านกลไก self-attention ที่ให้น้ำหนักความสำคัญของทุกคำในประโยค

8. ใช้ embedding ในงานจริง (~16:37–19:56)

มีสองทาง คือสร้าง word embedding เองตั้งแต่ศูนย์ หรือใช้ model ที่ฝึกไว้แล้ว (pre-trained)

  • สร้างเอง: ผู้สอนบอกว่าไม่ยากนัก เพราะทุก algorithm ที่พูดมามี library ที่ให้ model และโค้ดสำเร็จรูป แค่ส่งข้อมูลเข้าไป แต่ปัญหาคือน่าจะต้องใช้ข้อมูลฝึกมาก และน่าจะใช้เวลานานกว่าจะได้ผลดี จึงควรทำเฉพาะเมื่อต้องการ model เฉพาะงานของตัวเอง
  • ใช้ model สำเร็จรูป: ผู้สอนบอกว่าโดยทั่วไปง่ายกว่ามาก มี library open source หลายตัว และกลุ่มวิจัยมักปล่อย model ให้ใช้ฟรี นอกจากนี้มีผู้ให้บริการเชิงพาณิชย์ผ่าน API แบบเสียเงิน ซึ่งมักคุณภาพสูงกว่ามากและเหมาะกับหลายงาน เช่น OpenAI และ Mistral ส่วน Anthropic ผู้สอนบอกว่าน่าเสียดายที่ไม่มี
  • คุณภาพของ embedding ขึ้นกับ model ที่ใช้อย่างมาก และ model ต่างกันทำงานต่างประเภทได้ไม่เท่ากัน ผู้สอนเปิด leaderboard ให้ดูเป็นข้อมูลอ้างอิงเวลาเลือก model

เดโม: ผู้สอนบอกว่าใช้ API แบบเสียเงิน จึงเป็นแค่การสาธิต ใช้ model text-embedding-ada-002 ของ OpenAI แปลงคำว่า cat เป็นเวกเตอร์ ได้ list ขนาด 1,536 ตัวเลข แล้ววัดว่าข้อความสองชิ้นใกล้กันแค่ไหน ผู้สอนคิดว่า Amsterdam กับ coffee shop เกี่ยวข้องกัน เพราะ Amsterdam ขึ้นชื่อเรื่อง coffee shop ได้ระยะค่าหนึ่ง แล้วเปลี่ยนเป็น Paris ได้ระยะมากกว่า จึงสรุปว่า Paris กับ coffee shop คล้ายกันน้อยกว่า

ผู้สอนปิดว่านี่คือบทนำสั้น ๆ ว่า embedding ทำงานอย่างไร และใช้ประเมินว่าข้อความสองชิ้นเกี่ยวข้องกันหรือไม่

เสริมจากผู้จัดทำ: วิเคราะห์เพิ่มจากผู้จัดทำ
  • ในโค้ดเรียกค่าที่ได้ว่า cosine distance (ยิ่งน้อยยิ่งใกล้) ถ้าเปลี่ยนไปใช้ cosine similarity ทิศการอ่านจะกลับกัน ควรดูให้ชัดว่าฟังก์ชันคืนค่าแบบใด
  • ส่วนต่าง 0.175 กับ 0.224 ไม่มาก และเป็นผลจาก model เดียวในเวลาเดียว ใช้แสดงแนวคิดได้ แต่ยังไม่พอจะสรุปเป็นกฎ
  • คลิปใช้ ada-002 ซึ่ง OpenAI มีรุ่นใหม่กว่าแล้ว (text-embedding-3-small 1,536 มิติ และ -3-large 3,072 มิติ ตามประกาศของ OpenAI)

Key Takeaways

1.วิธีนับความถี่ (one-hot, bag of words, n-gram, TF-IDF) เข้าใจง่าย แต่ไม่ดูลำดับคำ ไม่ดูบริบท เวกเตอร์ยาวและ sparse และจับความหมายไม่ได้
2.embedding คือเวกเตอร์ dense ที่สั้นกว่าคลังคำ (ผู้สอนบอกว่าราว 50 ถึงไม่กี่พันมิติ) ค่าแต่ละตัวไม่มีความหมายในตัวเอง ความสัมพันธ์ระหว่างเวกเตอร์คือสิ่งที่สำคัญ
3.แนวคิดหลักมาจากยุค 1950s: คำที่อยู่ในบริบทคล้ายกันมีความหมายคล้ายกัน
4.word2vec (CBOW / skip-gram) ได้ embedding เป็นผลพลอยได้จาก weight ของ hidden layer แต่เป็น static ส่วน ELMo, BERT, GPT ให้ contextual embedding และ model แบบ transformer ใช้ self-attention
5.ผู้สอนบอกว่าโดยทั่วไปใช้ model สำเร็จรูปง่ายกว่ามาก คุณภาพขึ้นกับ model และประเภทงาน และ leaderboard ใช้เป็นข้อมูลอ้างอิงตอนเลือกได้
