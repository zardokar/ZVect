สรุปเชิงลึก

แนวคิดหลัก: embedding คือข้อมูล (เช่นคำหรือข้อความ) ที่ถูกแปลงเป็นชุดตัวเลขเรียกว่าเวกเตอร์ ตัวเลขชุดนี้ทำหน้าที่เหมือนแผนที่หลายมิติ ข้อมูลที่ความหมายใกล้กัน เช่น dog กับ puppy จะได้เวกเตอร์ที่อยู่ใกล้กัน ผู้สอนบอกว่าของจริงมี "หลายร้อยมิติ" แต่โมเดลที่ใช้ในคลิป (text-embedding-ada-002) ให้ 1536 ตัวเลขต่อข้อความ ซึ่งเห็นได้บนจอเอง (ตาราง docs ที่ 6:53 และเลขบรรทัด 8–1543 ของผลลัพธ์ใน Postman ~11:28 รวม 1536 ตัว) ฐานข้อมูลที่เก็บ embedding เรียกว่า vector database ใช้ได้สี่งาน คือค้นหา จัดกลุ่ม แนะนำ และจัดประเภท คลิปทำเฉพาะงานค้นหา

ขั้นตอนในคลิป:

  1. ส่ง POST ไปที่ https://api.openai.com/v1/embeddings พร้อม Bearer token และ body ที่มีแค่ model กับ input ได้เวกเตอร์กลับมา
  2. ข้อความยาวก็ส่งได้ ผู้สอนบอกว่าขีดจำกัดประมาณ 8000 token ราว 30000 ตัวอักษร หรือน่าจะประมาณ 10 หน้าเอกสาร (docs บนจอเขียน 8191; reference ปัจจุบันเขียน 8,192)
  3. สร้างตาราง myvectortable สองคอลัมน์ text TEXT กับ vector BLOB ใน SingleStore แล้ว INSERT สามแถว โดยห่อเวกเตอร์ด้วย JSON_ARRAY_PACK
  4. ค้นหา: แปลงคำค้นเป็นเวกเตอร์ด้วยโมเดลเดียวกัน แล้วสั่ง dot_product(vector, JSON_ARRAY_PACK("[…]")) as score … order by score desc limit 5
  5. ผลจริงบนจอ: คำค้น "open AI" ได้ "OpenAI Vectors and Embeddings are Easy!" อันดับ 1 (0.840060293674469); คำค้น "hello Earth" ได้ "Hello World" อันดับ 1 (0.8969387412071228) สูงกว่าอันดับ 2 (0.7428184747695923) ชัดเจน
  6. ปิดท้ายด้วยฟังก์ชัน createEmbedding ใน Node.js ที่ใช้ fetch และแผนต่อยอด: อ่าน PDF → แบ่งเป็นย่อหน้า → เก็บเป็นเวกเตอร์ → ค้นหา

ทำไม DOT_PRODUCT ใช้ได้ (ผู้จัดทำอธิบายเพิ่ม ไม่มีในคลิป): embedding ของ OpenAI มีความยาว 1 (ถ้าวาดเวกเตอร์เป็นลูกศร ลูกศรยาว 1 หน่วยพอดี) ผลคูณจุด (dot product) จึงเท่ากับ cosine similarity พอดี แต่การค้นแบบในคลิปให้คะแนนทุกแถว (brute force) ตารางใหญ่ต้องใช้ดัชนี ANN (approximate nearest neighbor: การหาแถวที่ใกล้ที่สุดแบบประมาณ โดยใช้ดัชนีช่วยให้ไม่ต้องเทียบทุกแถว)

เอาไปใช้ (ความเห็นของผู้จัดทำ): ใช้เป็นแบบฝึกครบวงจรแรก (ฝัง → เก็บ → ค้น) ได้ แต่ควรใช้โมเดลรุ่นใหม่ เก็บคีย์ใน environment variable (ค่าที่ตั้งไว้ในระบบนอกตัวโค้ด) และแก้ฟังก์ชันให้ return await response.json()

ผังภาพรวม

ในภาพนี้:

  1. แถวบน: ข้อความ → OpenAI API → เวกเตอร์ → SingleStore — ขั้นเก็บ ข้อความในคลิปมีสามชิ้น ("Hello World", ประโยคหนึ่งประโยค และเอกสาร NDA หนึ่งหน้า) แต่ละชิ้นได้เวกเตอร์ 1536 ตัวเลข แล้ว INSERT ลงตาราง (หัวข้อ 5–10)
  2. แถวล่างจากซ้าย: คำค้น → OpenAI API → เวกเตอร์คำค้น — ขั้นค้น คำค้นต้องผ่านโมเดลเดียวกันก่อน จึงเทียบกับของที่เก็บไว้ได้
  3. DOT_PRODUCT (ขวาล่าง) — รับสองทาง: แถวทั้งหมดจาก SingleStore (ลูกศรลงมาจากด้านบน) และเวกเตอร์คำค้น ให้คะแนนความคล้ายทุกแถว แล้วเรียงจากมากไปน้อย (หัวข้อ 11)

  • ทฤษฎี — อธิบายสองคำที่ทำงานคู่กัน: embedding (ข้อมูลที่แปลงเป็นชุดตัวเลข) กับ vector database (ฐานข้อมูลที่เก็บชุดตัวเลขเหล่านั้น)
  • การใช้งาน — สร้าง embedding จริง เก็บ และค้น
  • การเชื่อมเข้าโค้ด — เขียนฟังก์ชันเรียก API เอง
ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (ผู้จัดทำยกขึ้นเอง ไม่มีในคลิป)

สมมติมีสัญญาเป็น PDF หลายร้อยฉบับ อยากถาม AI ว่า "ฉบับไหนพูดเรื่องข้อมูลลับ" โดยไม่ต้องเปิดอ่านทุกฉบับ สามช่วงของคลิปคือสามขั้นที่ต้องผ่านเพื่อทำแบบนี้ได้

ในภาพนี้:

  1. ทฤษฎี — embedding คืออะไร และ vector database ใช้ทำอะไร (หัวข้อ 2–3)
  2. การใช้งาน — ขอ embedding จาก OpenAI แล้วเก็บและค้นใน SingleStore (หัวข้อ 4–11)
  3. เชื่อมเข้าโค้ด — ฟังก์ชัน Node.js ที่ขอ embedding เอง (หัวข้อ 12)
  4. เป้าหมาย (ค้นตามความหมาย) — ผู้สอนบอกว่าดูจบแล้วจะสร้าง "ความจำระยะยาว" (long-term memory) ให้ ChatGPT ได้ (คลิปไม่ได้อธิบายวิธีทำ ผู้จัดทำ: หมายถึงเก็บข้อความเก่าเป็นเวกเตอร์ แล้วค้นข้อความที่เกี่ยวข้องมาใส่ในคำถามรอบใหม่) หรือค้นตามความหมาย (semantic search) ในฐานข้อมูล PDF ขนาดใหญ่ที่ต่อกับ AI ได้

เอาไปใช้ทำอะไร: ใช้เป็นแผนที่ของหน้านี้ หัวข้อ 2–12 เรียงตามสามช่วงนี้

2. Embedding คืออะไร: ข้อมูลที่กลายเป็นชุดตัวเลข (~0:31–1:28)

หัวข้อนี้จะพาดูอะไร: ความหมายของ embedding และเวกเตอร์ ภาพตัวอย่างคำที่อยู่ใกล้กัน และการแปลงภาพถ่ายเป็นตัวเลข

ใจความ: เวกเตอร์ (vector) คือรายการตัวเลขเรียงกัน embedding คือข้อมูล เช่นคำ ที่ถูกแปลงเป็นเวกเตอร์ที่เก็บ "รูปแบบความสัมพันธ์" ไว้ ตัวเลขทั้งชุดทำหน้าที่เหมือนแผนที่หลายมิติไว้วัดว่าของสองอย่างคล้ายกันแค่ไหน คำที่มักใช้ในสถานการณ์คล้ายกัน เช่น dog กับ puppy จึงได้เวกเตอร์ที่อยู่ใกล้กัน ผู้สอนเรียกภาพ 2 มิติที่ใช้ว่าตัวอย่างอย่างง่าย ของจริงมี "หลายร้อยมิติ" (1:04) ภาพถ่ายก็แปลงเป็นเวกเตอร์ได้ ผู้สอนบอกว่านี่คือวิธีที่ Google ค้นภาพที่คล้ายกัน

คำว่า dog กับ puppy: บนกราฟ 2 มิติอยู่ติดกัน และบนจอมีตัวเลข 5 ตัวแรกของแต่ละคำให้ดู (ผู้จัดทำ: ตัวเลขชุดนี้น่าจะเป็นตัวอย่างประกอบ ไม่ใช่ผลจากโมเดลจริง)

ในภาพนี้:

  1. DATA — ข้อมูลตั้งต้น ในภาพเป็นข้อความตัวอย่าง lorem ipsum
  2. กล่อง embedding model — โมเดลที่แปลงข้อมูลเป็นตัวเลข
  3. กล่องตัวเลขทางขวา — เวกเตอร์ผลลัพธ์ "…" แทนตัวเลขที่ละไว้
ข้อที่ควรเข้าใจให้ตรง: ผู้จัดทำตรวจ: ตัวเลข -248.6 ในภาพนี้จะไม่เกิดกับ embedding ของ OpenAI

ภาพนี้เป็นภาพประกอบทั่วไป ไม่ได้อ้างว่าเป็นโมเดลของ OpenAI แต่โมเดลที่คลิปใช้ให้ embedding ยาว 1 เสมอ (factcheck ข้อ 18) "ยาว" ของเวกเตอร์คือความยาวของลูกศรเมื่อวาดเป็นภาพ คิดจากรากที่สองของผลบวกกำลังสองของตัวเลขทุกตัว (สูตรในหัวข้อ 11) ถ้าลูกศรยาว 1 ตัวเลขแต่ละตัวจึงอยู่ระหว่าง −1 กับ 1 ค่าจริงที่เห็นในหัวข้อ 6 เช่น -0.00709195 เล็กมาก ภาพถัดไป (~0:46) ก็มีค่าเกิน 1 อย่าง 1.3 และ -1.8 ซึ่งเป็นภาพประกอบเช่นกัน

ในภาพนี้ (อ่านจากซ้ายไปขวา ทีละแถว):

  1. คอลัมน์ Object — ชนิดข้อมูลตั้งต้น: ภาพ (IMAGE), ข้อความ (TEXT, ตัวอย่าง "Happy Birthday") และเสียง (AUDIO)
  2. ไอคอนโครงข่ายกลางภาพ — โมเดลที่เหมาะกับข้อมูลชนิดนั้น: IMAGE TRANSFORMER, NLP TRANSFORMER, AUDIO TRANSFORMER (ผู้จัดทำ: transformer คือแบบโครงสร้างของโครงข่ายประสาทเทียมที่โมเดล AI สมัยใหม่ส่วนใหญ่ใช้; NLP คือการประมวลผลภาษา)
  3. คอลัมน์ Vector — เวกเตอร์ผลลัพธ์ เช่น [0.3, -0.4, 1.2, 0.3, ...] ของข้อความ
  4. คอลัมน์ Task — งานที่ทำต่อจากเวกเตอร์: แถวภาพ: จำวัตถุ (Object recognition), หาภาพซ้ำ (deduplication), แยกฉาก (scene detection), ค้นสินค้า (product search); แถวข้อความ: แปลภาษา (Translation), เข้าใจข้อความ (understanding), วิเคราะห์ความรู้สึก (Sentiment), ตอบคำถาม (Question Answering), ค้นตามความหมาย (Semantic Search); แถวเสียง: หาความผิดปกติ (Anomaly detection), แปลงเสียงเป็นข้อความ (speech-to-text), ถอดโน้ตเพลง (music transcription), ตรวจเครื่องจักรขัดข้อง (machinery malfunction)
  5. ภาพนี้ขึ้นจอระหว่างที่ผู้สอนพูดเรื่องรูปแบบความสัมพันธ์ — ผู้สอนไม่ได้อ่านข้อความในตาราง

ในภาพนี้:

  1. วงกลมรอบ dog กับ puppy — สองคำที่ผู้สอนยกเป็นตัวอย่าง อยู่ติดกัน
  2. wolf — อยู่ใกล้กลุ่มนั้นแต่ไม่อยู่ในวง
  3. tea, coffee, milk — เครื่องดื่ม รวมกลุ่มอยู่อีกมุม
  4. congress — คำที่ไม่เกี่ยวกับทั้งสองกลุ่ม อยู่ห่างออกไป
  5. แกนทั้งสอง — ไม่มีชื่อ ผู้สอนพูดถึงกราฟนี้ว่าเป็นตัวอย่าง 2 มิติอย่างง่าย และไม่ได้บอกว่าแกนหมายถึงอะไร (ผู้จัดทำ: ในเวกเตอร์จริง ตัวเลขแต่ละตำแหน่งไม่มีความหมายที่คนอ่านออกได้ทีละตัว ความหมายอยู่ที่ตำแหน่งเทียบกับคำอื่น)

ในภาพนี้:

  1. จุดทั้งเจ็ด — คำเดียวกับในภาพของคลิป วางตามตำแหน่งที่ผู้จัดทำวัดจากภาพ
  2. ลูกศร dog (เส้นทึบ) และ puppy (เส้นประ) — ผู้จัดทำเติม: เวกเตอร์คือลูกศรจากจุดเริ่มต้น สองลูกศรนี้ชี้ไปทางเกือบเดียวกัน
  3. ความใกล้ — ระยะห่างของปลายลูกศรและมุมระหว่างลูกศรเล็ก แปลว่าคล้ายกัน หัวข้อ 11 ใช้แนวคิดเรื่องมุมนี้ในการค้นหา
  4. มุมราว 6.5° — มุมระหว่างสองลูกศรในภาพนี้ (ผู้จัดทำคิดจากพิกัดที่วัด: dog ทำมุม 45° กับแกนนอน puppy ราว 38.5°) มุมนี้เป็นของภาพ 2 มิติเท่านั้น ส่วนตัวเลข 5 ตัวของ dog กับ puppy ในตารางถัดไปให้มุมราว 35.3° (หัวข้อ 11) เพราะเป็นภาพประกอบคนละชุด ไม่ได้มาจากเวกเตอร์เดียวกัน

ในภาพนี้:

  2. ลูกศรลงไปที่ตัวเลข — แต่ละส่วนกลายเป็นตัวเลขในแถว
  3. ป้าย green, flower, background — ผู้สอนติดป้ายบอกคร่าว ๆ ว่าตัวเลขช่วงไหนมาจากส่วนไหนของภาพ ภาพไม่ได้จับคู่ตัวเลขกับป้ายทีละตัว และผู้สอนไม่ได้บอกว่าแปลงภาพเป็นตัวเลขด้วยวิธีใด บอกเพียงว่าภาพถูกแบ่งเป็นส่วน ๆ แล้วกลายเป็นชุดตัวเลข

3. Vector database และสี่งานที่ใช้ (~1:28–2:08)

หัวข้อนี้จะพาดูอะไร: ฐานข้อมูลที่เก็บ embedding เรียกว่าอะไร ใช้ทำอะไรได้บ้าง และคลิปนี้เลือกทำงานไหน

ใจความ: เมื่อสร้าง embedding แล้วก็เก็บลงฐานข้อมูลได้ ฐานข้อมูลที่เต็มไปด้วย embedding เรียกว่า vector database ผู้สอนยกสี่งาน:

  • ค้นหา (searching) — เรียงผลตามความเกี่ยวข้องกับข้อความที่ค้น
  • จัดกลุ่ม (clustering) — รวมข้อความที่คล้ายกันเป็นกลุ่ม
  • แนะนำ (recommendations) — แนะนำของที่มีข้อความเกี่ยวข้องกัน
  • จัดประเภท (classification) — ติดป้ายให้ข้อความตามป้ายที่คล้ายที่สุด

คลิปทำแค่งานค้นหา เพราะผู้สอนบอกว่าใช้บ่อยที่สุด OpenAI มีโมเดลสำหรับสร้าง embedding โดยเฉพาะ แต่ไม่มีที่เก็บให้ (2:03) คลิปจึงใช้ฐานข้อมูลบนคลาวด์ในหัวข้อ 8

ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (ผู้จัดทำยกขึ้นเอง ไม่มีในคลิป)

ร้านหนังสือออนไลน์ที่เก็บ embedding ของคำโปรยหนังสือทุกเล่ม: ค้นหา = พิมพ์ "นิยายสืบสวนในเกียวโต" แล้วได้เล่มที่ใกล้ที่สุด; จัดกลุ่ม = รวมเล่มแนวเดียวกัน; แนะนำ = "คนที่ซื้อเล่มนี้อาจชอบ"; จัดประเภท = ติดป้ายหมวดให้เล่มใหม่

ในภาพนี้:

  1. vector database (กลางภาพ) — ที่เก็บ embedding
  2. clustering (ซ้ายบน) — วงกลมซ้อนกันแทนกลุ่มที่ทับกันบางส่วน
  3. recommendations (ขวาบน) — นิ้วโป้งแทนการแนะนำ
  4. searching (ซ้ายล่าง) — แว่นขยายแทนการค้นหา งานเดียวที่คลิปทำ
  5. classifications (ขวาล่าง) — ดาวสามดวงแทนการจัดประเภท

ในภาพนี้:

  1. กล่องบนสุด — vector database ที่เก็บ embedding
  2. กล่อง "ค้นหา" (เน้นสี) — งานเดียวที่คลิปทำต่อจากนี้
  3. อีกสามกล่อง — งานที่ผู้สอนเอ่ยถึงแต่ไม่ได้สาธิต
ข้อที่ควรเข้าใจให้ตรง: ผู้จัดทำตรวจ: "OpenAI ไม่มีที่เก็บให้" ถูกในปี 2023

ตั้งแต่ 2024-04-17 OpenAI มี vector_store ที่รับไฟล์ไปแบ่งชิ้น ฝัง และค้นด้วยเครื่องมือ file_search ให้เอง แต่เป็นที่เก็บไฟล์ ไม่ใช่ฐานข้อมูลที่เราเขียนเวกเตอร์ของตัวเองลงไป งานแบบในคลิปจึงยังต้องใช้ฐานข้อมูลภายนอก (factcheck ข้อ 4)

เอาไปใช้ทำอะไร: รู้ว่า embedding ชุดเดียวใช้ได้หลายงาน คลิปนี้สอนงานค้นหาซึ่งเป็นพื้นฐานของงานอื่น

4. เข้า OpenAI: บัญชี เอกสาร และ API reference (~2:08–3:05)

หัวข้อนี้จะพาดูอะไร: ไปหาเอกสารและรายละเอียดของ API สร้าง embedding ได้จากที่ไหน

ใจความ: API คือช่องทางให้โปรแกรมส่งคำขอไปให้บริการอื่นทำงานแล้วส่งผลกลับ ผู้สอนเข้าเว็บ OpenAI สมัครหรือล็อกอิน (เขาบอกว่าสมัครฟรี และใช้บัญชี Google) จากนั้น:

  1. เลือกส่วน API จากตัวเลือก ChatGPT, DALL·E และ API อื่น ๆ แล้วเข้า dashboard
  2. เปิดเอกสาร (documentation) เรื่อง embeddings ซึ่งเขาใส่ลิงก์ไว้ในคำอธิบายคลิป
  3. เปิดหน้า API reference หัวข้อ embeddings ที่บอกทุกอย่างที่ต้องใช้

ผู้สอนสรุปว่าการสร้าง embedding ง่ายมาก คือส่งคำขอแบบ POST ครั้งเดียวพร้อมข้อมูลเข้า แล้วได้คำตอบกลับ ทำได้ทั้งเขียนโค้ด ใช้ terminal หรือใช้โปรแกรมที่มีหน้าจอ เขาเลือกแบบหลังเพราะง่ายที่สุด

5. เตรียมคำขอใน Postman: URL, เมธอด และ API key (~3:05–5:00)

ใจความ: Postman เป็นโปรแกรมสำหรับส่งคำขอไปยัง API โดยไม่ต้องเขียนโค้ด ผู้สอนติดตั้งรุ่น Windows แล้วทำตามลำดับ:

  1. สร้าง workspace ชื่อ "OpenAI Vector Database" มีแบบ personal และ private ด้วย แต่เลือกแบบ team เพราะเปิดทางให้แชร์ workspace ให้คนอื่นได้ภายหลังถ้าต้องการ
  2. เปิดแท็บใหม่ เลือกชนิดคำขอเป็น POST (การส่งข้อมูลไปให้เซิร์ฟเวอร์ประมวลผล)
  3. วาง URL https://api.openai.com/v1/embeddings
  4. Postman เตือนว่า endpoint (ที่อยู่ปลายทางของบริการหนึ่งใน API) นี้ต้องมีการยืนยันตัวตน จึงไปที่หน้า API keys ของ OpenAI สร้าง secret key ตั้งชื่อว่า embeddings
  5. วาง key ในช่อง API key ของ Postman ผู้สอนบอกว่า Postman รองรับการยืนยันตัวตนได้หลายแบบ ในที่นี้ใช้แบบ Bearer token ซึ่งเป็นวิธีที่ OpenAI ใช้ยืนยันตัวตน (ผู้จัดทำ: bearer แปลว่า "ผู้ถือ" ใครถือรหัสนี้แนบไปกับคำขอก็ใช้ API ในนามบัญชีนั้นได้ จึงต้องเก็บเป็นความลับ)

ในภาพนี้:

  1. แถว Postman — สามขั้นที่ทำในโปรแกรม: สร้าง workspace, ตั้ง POST กับ URL, และวาง key
  2. แถวเว็บ OpenAI — ขั้นเดียวที่ต้องออกไปทำนอก Postman คือสร้าง secret key
  3. กล่อง Bearer token (เน้นสี) — ขั้นสุดท้ายก่อนส่งคำขอได้ บนจอ Postman แสดงหัวข้อ "Get your API Key for OpenAI API" พร้อมช่อง "Enter the Bearer Token here"

ตั้งแต่มีนาคม 2026 แผน Free ของ Postman ใช้ได้คนเดียวและสร้าง team ไม่ได้ ผู้เรียนที่ใช้แผนฟรีวันนี้จะแชร์ workspace แบบในคลิปไม่ได้ (factcheck ข้อ 5)

เอาไปใช้ทำอะไร: URL + POST + Bearer token คือสามอย่างที่ทุกคำขอ embedding ต้องมี โค้ดในหัวข้อ 12 ใช้ค่าชุดเดียวกัน

7. ข้อมูลเข้าแบบต่าง ๆ และขีดจำกัดความยาว (~6:05–7:35)

ใจความ: ผู้สอนแยก embedding ตามขนาดข้อความที่ส่ง:

  • คำเดียว เช่น dog หรือ cat — ใช้ในงานค้นหาบางแบบ
  • หลายคำ เช่นประโยค "open AI vectors and embeddings are easy" — ผู้สอนบอกว่าได้ embedding ที่ละเอียดกว่า (คลิปไม่ได้อธิบายว่าละเอียดอย่างไร) แต่สำหรับคนดู ผลก็หน้าตาเหมือนกัน
  • ข้อความก้อนใหญ่ เช่นย่อหน้าหรือทั้งส่วนของเอกสาร — ผู้สอนบอกว่านี่คือจุดแข็งของ embedding: รวมข้อมูลก้อนใหญ่เป็นก้อนเดียว (chunk) แล้วสร้าง embedding หนึ่งตัวไว้ดึงมาใช้ตอนค้นฐานข้อมูล

เอาไปใช้ทำอะไร: ใช้กะขนาดชิ้นข้อความก่อนส่ง: หนึ่งคำขอรับได้หลายหน้า แต่ทุกชิ้นได้เวกเตอร์ยาวเท่ากันเสมอ

8. SingleStore: สร้าง workspace และฐานข้อมูล (~7:35–9:25)

หัวข้อนี้จะพาดูอะไร: เตรียมที่เก็บ embedding บนคลาวด์ตั้งแต่สมัครจนได้ฐานข้อมูลว่างหนึ่งก้อน

ใจความ: OpenAI ไม่มีฐานข้อมูลให้ ต้องสร้างเอง ผู้สอนใช้ SingleStore ซึ่งเขาอธิบายว่าเป็น SQL database แบบ real-time, unified และกระจายหลายเครื่อง (distributed) ซึ่งเขาบอกว่าใช้ง่ายเพราะอยู่บนคลาวด์ และรองรับ vector database ในตัว เขาบอกว่าสมัครฟรี ได้เครดิตเพิ่มและตั้งฐานข้อมูลได้ไม่จำกัด ขั้นตอน:

  1. ล็อกอิน (เขาใช้บัญชี Google) แล้วสร้าง workspace (ชุดเครื่องที่ใช้ประมวลผล) ตั้งชื่อ "OpenAI Vector Database"
  2. เลือก cloud เป็น AWS (เลือก Google หรือ Microsoft Azure ก็ได้) region ผู้สอนแนะนำให้เลือกที่ใกล้ตัว แต่เขาใช้ค่าเริ่มต้น US West
  3. ขนาดเครื่อง (CPU, RAM) ผู้สอนเลือกเล็กที่สุด บนจอคือ S-00: 2 vCPUs (หน่วยประมวลผลเสมือน), RAM 16 GB, 0.25 CR (credits หน่วยเครดิตที่ SingleStore คิดค่าใช้งาน) ต่อชั่วโมง; ตั้งค่าขั้นสูงใช้ค่าเริ่มต้น
  4. รอ workspace ตั้งตัวเสร็จ แล้วกด create a database ตั้งชื่อ "OpenAI database"

ชื่อที่พูดกับชื่อบนจอไม่ตรงกันทั้งหมด: บนจอภายหลังเห็น "OpenAI Vector Database Workspace Gr…" เป็นชื่อกลุ่มของ workspace ตัว workspace ชื่อ openai-workspace และ database เขียนติดกันเป็น openaidatabase คลิปไม่ได้อธิบายว่าทำไมต่างกัน หน้านี้ใช้ชื่อตามจอ

ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (มาจากคลิป)

ฐานข้อมูล openaidatabase ใน workspace openai-workspace บน AWS region US West ขนาด S-00 ซึ่งยังว่างเปล่า ไม่มีตารางหรือข้อมูล

ในภาพนี้:

  1. ชั้นบัญชี — บัญชี SingleStore
  2. ชั้น workspace (เน้นสี) — ส่วนที่กำหนดเครื่องและค่าใช้จ่าย: ผู้ให้บริการคลาวด์ ตำแหน่ง และขนาด
  3. ชั้น database — ฐานข้อมูลที่สร้างใน workspace
  4. ชั้น table — ตารางที่จะสร้างในหัวข้อ 9
ข้อที่ควรเข้าใจให้ตรง: ผู้จัดทำตรวจ: "ฟรีและไม่จำกัด"

ปัจจุบัน SingleStore มีรุ่น Shared ฟรีหนึ่ง workspace (สำหรับทดลองและพัฒนา) และรุ่น Standard ที่ทดลองด้วยเครดิต $500 ไม่พบหลักฐานเรื่อง "ฐานข้อมูลไม่จำกัด" ทั้งตอนนั้นและตอนนี้ (factcheck ข้อ 15) คำว่า "real-time unified" เป็นคำโฆษณาของบริษัท (factcheck ข้อ 14)

เอาไปใช้ทำอะไร: ได้ฐานข้อมูลเปล่าไว้รับตารางเวกเตอร์ในหัวข้อถัดไป

9. สร้างตาราง: คอลัมน์ข้อความกับคอลัมน์เวกเตอร์ (~9:25–10:40)

หัวข้อนี้จะพาดูอะไร: คำสั่ง SQL ที่สร้างตารางเก็บ embedding และชนิดข้อมูลของแต่ละคอลัมน์

ใจความ: ผู้สอนเปิด SQL editor (หน้าพิมพ์คำสั่งฐานข้อมูล) เลือกฐานข้อมูลที่ใช้อยู่ด้านบน แล้วพิมพ์คำสั่งสร้างตาราง myvectortable ถ้ายังไม่มี ตารางมีสองคอลัมน์:

  • text — เก็บข้อความต้นฉบับ ชนิด TEXT
  • vector — เก็บเวกเตอร์ ชนิด BLOB (ก้อนข้อมูลไบนารี)

ผู้สอนบอกว่าคอลัมน์มีชนิดอื่นได้ เช่นจำนวนเต็ม ตัวเลข และทศนิยม และจะเพิ่มคอลัมน์อย่าง ID หรือ URL ก็ได้ แต่ทำให้ง่ายไว้สำหรับการสาธิต

ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (มาจากคลิป)

ตาราง myvectortable ใน openaidatabase ซึ่งในหัวข้อถัดไปจะเก็บสามแถว แถวแรกคือ "Hello World" กับเวกเตอร์ของมัน

CREATE TABLE IF NOT EXISTS myvectortable (

);

คำสั่งใน SQL editor (~10:40) รันแล้วได้ Insert ID 0, Affected Rows 0, Changed Rows 0 ใน 609 ms (ผู้จัดทำ: ตัวนับเหล่านี้บอกจำนวนแถวที่คำสั่งเพิ่มหรือแก้ การสร้างตารางไม่ได้แตะแถวใดจึงเป็น 0 ทั้งหมด) คำพูดเรียกชื่อตารางว่า "my Vector table" ส่วนบนจอเขียนติดกันเป็น myvectortable

ในภาพนี้:

  1. ฝั่งซ้าย text — เก็บข้อความไว้ให้คนอ่าน ผลค้นหาในหัวข้อ 11 แสดงคอลัมน์นี้
  2. ฝั่งขวา vector (เน้นสี) — เก็บตัวเลขไว้ให้เครื่องคำนวณ ต้องแปลงก่อนเก็บ (หัวข้อ 10)
  3. หมายเหตุด้านล่าง — ทางเลือกปัจจุบันที่ผู้จัดทำเติม (กล่องถัดไป)

หลังรันคำสั่ง ผู้สอนเปิดดูตารางในฐานข้อมูล: แท็บ Columns บอกชื่อและชนิดของคอลัมน์ ส่วนแท็บ Sample Data ยังขึ้นว่า "This table has no rows"

ข้อที่ควรเข้าใจให้ตรง: ผู้จัดทำตรวจ: BLOB ถูกในปี 2023 ตอนนี้มีชนิด VECTOR

SingleStore 8.5 (2024-01-19) เพิ่มชนิดข้อมูล VECTOR และการค้นแบบ ANN ที่มีดัชนี (หาแถวที่ใกล้ที่สุดแบบประมาณโดยไม่ต้องเทียบทุกแถว) เอกสาร DOT_PRODUCT ปัจจุบันแนะนำให้ใช้ VECTOR เมื่อทำได้ (factcheck ข้อ 17)

เอาไปใช้ทำอะไร: ได้โครงตาราง "ข้อความคู่เวกเตอร์" ซึ่งเป็นรูปแบบพื้นฐานของ vector database ทุกตัว

10. ใส่ข้อมูล: INSERT กับ JSON_ARRAY_PACK (~10:40–12:55)

หัวข้อนี้จะพาดูอะไร: นำเวกเตอร์จาก Postman ไปเก็บลงตาราง และทำไมต้องห่อด้วยฟังก์ชันพิเศษ

ใจความ: ผู้สอนพิมพ์คำสั่ง INSERT ใส่ค่าสองคอลัมน์: text คือ "Hello World" ที่คัดลอกจาก input ใน Postman และ vector คือตัวเลขก้อนใหญ่จากผลลัพธ์ใน Postman ซึ่งต้องห่อด้วยฟังก์ชัน JSON_ARRAY_PACK (ฟังก์ชันของ SingleStore ที่แปลงรายการตัวเลขแบบ JSON เป็นข้อมูลไบนารี) ผู้สอนบอกว่าจำเป็นเพื่อให้เป็นโครงสร้าง BLOB รันแล้วได้ผล "1 row added" และเห็นแถวใหม่ในแท็บ Sample Data จากนั้นทำซ้ำอีกสองแถวจากประวัติคำขอใน Postman: ประโยค "OpenAI Vectors and Embeddings are Easy!" และเอกสาร NDA (Non-Disclosure Agreement สัญญารักษาความลับ หน้าเดียวกับที่วางเป็น input ในหัวข้อ 7 ขึ้นต้นว่า "Document includes: …") รวมเป็นสามแถว ผู้สอนบอกว่าเรียบง่ายแต่พอเริ่มค้นได้

11. ค้นหาด้วย DOT_PRODUCT (~12:55–15:10)

หัวข้อนี้จะพาดูอะไร: สามขั้นของการค้น คำสั่ง SQL ที่ให้คะแนน และผลจริงจากสองคำค้น

ใจความ: ผู้สอนบอกว่าการค้นใน vector database ง่ายมาก และอธิบายเป็นสามขั้น (ดูผังและรายการด้านล่าง) คำสั่ง SQL ใช้ฟังก์ชัน dot_product (ผลคูณจุด: คูณตัวเลขตำแหน่งเดียวกันของสองเวกเตอร์แล้วบวกกันทั้งหมด) ระหว่างเวกเตอร์ที่เก็บไว้กับเวกเตอร์ของคำค้น ได้ค่าหนึ่งตัวที่ตั้งชื่อว่า score แล้วเรียงจากมากไปน้อย จำกัดห้าผล ผู้สอนเรียก score ว่าการจัดอันดับว่าคล้ายกับเนื้อหาในฐานข้อมูลแค่ไหน ปิดท้ายว่านี่คือหลักการพื้นฐานของการค้นด้วยเวกเตอร์ (15:02)

คำค้นแรกคือ "open AI" และคำค้นที่สองคือ "hello Earth" ค้นในตารางสามแถวจากหัวข้อ 10 ส่วนตัวเลขในตารางสัญลักษณ์ใช้ dog กับ puppy จากหัวข้อ 2 ซึ่งผู้จัดทำคำนวณเอง

เอาไปใช้ทำอะไร: ฟังก์ชันนี้ (หลังแก้ return) คือชิ้นแรกของระบบตามแผน PDF → ชิ้นข้อความ → เวกเตอร์ → ค้นหา ซึ่งเป็นแกนของระบบถามตอบจากเอกสาร

Key Takeaways

1.embedding คือข้อมูลที่แปลงเป็นเวกเตอร์ ของที่ความหมายใกล้กันได้เวกเตอร์ใกล้กัน โมเดลในคลิป (text-embedding-ada-002) ให้ 1536 ตัวเลขต่อข้อความ ไม่ใช่ "หลายร้อย"
2.คำขอ embedding มีแค่ POST https://api.openai.com/v1/embeddings + Bearer token + body model กับ input และคำตอบอยู่ที่ data[0].embedding
3.ใน SingleStore ปี 2023 เก็บเวกเตอร์เป็น BLOB ผ่าน JSON_ARRAY_PACK และค้นด้วย dot_product(...) as score order by score desc ปัจจุบันใช้ชนิด VECTOR และดัชนี ANN ได้
4.dot_product เท่ากับ cosine similarity เพราะ embedding ของ OpenAI ยาว 1 (ผู้จัดทำตั้งข้อสังเกต: คะแนนของแถวที่ไม่เกี่ยวก็ยังสูงราว 0.7 จึงต้องดูที่อันดับ)
5.ฟังก์ชัน Node.js ในคลิปพิมพ์ผลได้แต่ไม่คืนค่า ต้องแก้เป็น return await response.json() และอ่าน key จาก environment variable
