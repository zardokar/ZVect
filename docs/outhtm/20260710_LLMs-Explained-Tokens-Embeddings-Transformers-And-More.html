บทสรุปย่อ

CJ จากช่อง Syntax เล่าว่าเกิดอะไรขึ้นตั้งแต่พิมพ์คำถามใน LLM จนได้คำตอบ โดยสร้าง LLM ตัวเล็กเองและแสดงโค้ดทุกขั้น ได้แก่ chatbot แบบกฎ, neural network แก้ XOR, tokenizer แบบ BPE, การฝึก embedding แบบ word2vec, transformer ที่แต่งนิทานเด็ก และการเลือก token ถัดไปด้วย temperature และ top-p แต่ละขั้นมีประวัติศาสตร์ประกอบ ตั้งแต่เกมทายตัวอักษรของ Shannon จนถึง "Attention Is All You Need" แล้วปิดด้วย fine-tuning, RLHF, tool calling และความเห็นของผู้พูดว่า LLM เป็นเครื่องเติมข้อความที่ซับซ้อนมาก มากกว่าจะเข้าใจจริง

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ครบทุกประเด็นและตัวเลข พร้อมตรวจข้อเท็จจริงและเทียบกับโค้ดของผู้สอน (license มาตรฐานของ YouTube)

สรุปเชิงลึก

แก่นของคลิป: LLM คือ model สถิติของภาษาที่ทาย token ถัดไป ผู้พูดเริ่มจากเกมของ Claude Shannon ที่ให้ภรรยาทายตัวอักษรถัดไป และพบว่าถ้ามีบริบทพอ ตัวถัดไปมักแทบจะแน่นอน แล้วบอกว่าสิ่งที่ LLM ทำในวันนี้ก็แทบจะเป็นแบบนั้น แต่มีเครื่องจักรอีกมากก่อนจะถึงขั้นทาย ลำดับที่เล่า: chatbot ยุคแรก (ELIZA 1966, PARRY 1972, ALICE 1995, SmarterChild 2001) ล้วนเป็นกฎที่คนเขียนไว้ล่วงหน้า ผู้พูดสร้าง chatbot แบบ if ให้ดู แล้วมองระบบเป็น "กล่องดำ" ที่มีเข้าและออก ซึ่งค่อย ๆ เปลี่ยนไส้ในให้ฉลาดขึ้นได้ จากนั้นอธิบาย neural network ว่าเป็นชั้นของ neuron ที่มี weight บนเส้นเชื่อม เล่าตั้งแต่ McCulloch–Pitts 1943, perceptron 1958, หนังสือ Perceptrons 1969 (ชั้นเดียวทำ XOR ไม่ได้) และ backpropagation 1986 ในโค้ด XOR ชั้นเดียวไม่ถึงคำตอบแม้ผ่าน 5,000 รอบ ส่วนแบบหลายชั้นทำได้ และ model คือไฟล์ weight: ชั้นเดียวมี 3 ตัวเลข แบบมีชั้นซ่อน 4 neuron มี 17 ตัวเลข Token: ข้อความถูกตัดเป็น token ด้วย BPE (Gage 1994 เพื่อบีบอัดข้อมูล, Sennrich และคณะ 2015 ใช้สร้างคลังคำ) จำนวน token กำหนดราคาและสิ่งที่ใส่ใน context window ได้ ในตัวอย่าง "the cat sat on the mat" ได้ 6 token (บนจอแสดงการรวม 7 ครั้ง) และบทพูดจากภาพยนตร์ Bee Movie ได้ 2,088 token Embedding: ID ของ token ไม่มีความหมาย จึงต้องแปลงเป็นเวกเตอร์ ตามแนวคิดของ Frege (1884) และ Firth (1957) "รู้จักคำจากคำที่อยู่ด้วย" word2vec (2013) ทำให้ king − man + woman ใกล้ queen ผู้พูดฝึก skip-gram เองด้วย 107 ประโยคและเวกเตอร์ 32 มิติ ผลบนจอมี queen ↔ king 0.92 และ king − man + woman = queen (0.84) Transformer: แก้ความช้าของ LSTM ด้วย attention ล้วน (2017) แต่ละ block มี self-attention ที่สร้าง query, key, value แล้วผสมข้อมูลจากคำอื่น (คำว่า bank ได้เวกเตอร์ต่างกันตามประโยค) ตามด้วย feed forward แล้วซ้อนหลายชั้น ผลลัพธ์คือความน่าจะเป็นของทุก token แล้วเลือกด้วย temperature และ top-p เติม token กลับเข้าไปแล้วทำซ้ำ (autoregressive) ภายใน context window ที่ต้องแก้ (จากการตรวจของผู้จัดทำ): ตรวจ 33 ข้อ ยืนยัน 17 · บางส่วน 10 · ไม่พบ 2 · ขัดแย้ง 4

  • top-p 0.2 ไม่ได้แปลว่า "token บนสุด 20%" แต่คือชุด token ที่เล็กที่สุดซึ่งความน่าจะเป็นรวมถึง 0.2
  • transformer บนจอตั้งไว้ 6 ชั้น ซึ่งนับตามโค้ดได้ 102,792 พารามิเตอร์ ตัวเลข 52,000 ที่พูดตรงกับแบบ 2 ชั้น (51,976)
  • โค้ดใน repo ตอนที่ตรวจตั้งรวม BPE สูงสุด 1,000 ครั้ง (ไม่ใช่ 10,000) และหน้าต่าง word2vec ค่าเริ่มต้น 2 สูงสุด 5 (ไม่ใช่ "ห้าหรือหก")
  • cosine 0 แปลว่าตั้งฉาก ค่าต่ำสุดคือ −1 · temperature 0 ไม่ได้ให้ผลเหมือนเดิมทุกครั้งในระบบจริง

เอาไปใช้: คลิปนี้ไล่ครบทั้งเส้นทางในระดับเริ่มต้น เหมาะเป็นแผนที่รวม ส่วนตัวเลขที่ใช้สอนควรอ้างจากโค้ดหรือบทความต้นฉบับ (ผู้จัดทำ)

1. คำถามตั้งต้นและเกมของ Shannon (~0:00–1:54)

ผู้พูดตั้งคำถามว่าเมื่อพิมพ์คำถามใน LLM อย่าง ChatGPT, Claude หรือ Gemini แล้วกด enter เกิดอะไรขึ้น คำตอบเกี่ยวกับงานวิจัยกว่า 80 ปี เงินหลายพันล้านดอลลาร์ และคณิตศาสตร์ที่เขาเรียกว่างดงามที่สุดชิ้นหนึ่ง เขาจึงสร้าง LLM ขึ้นเองตั้งแต่ศูนย์ และจะพาดูตั้งแต่กดแป้นจนได้คำตอบที่ทยอยออกมา พร้อมโค้ดทุกขั้น เรื่องเริ่มในปี 1950: Claude Shannon บิดาแห่งทฤษฎีสารสนเทศ เล่นเกมกับ Betty ภรรยา ให้ดูข้อความที่ซ่อนตัวอักษรถัดไป แล้วให้ทายทีละตัว เขาวัดว่าเธอทายถูกบ่อยแค่ไหน สิ่งที่วัดจริง ๆ คือภาษาเขียนคาดเดาได้แค่ไหน ผลคือ ถ้ามีบริบทพอ ตัวอักษรถัดไปมักแทบจะแน่นอน แปลว่าภาษามีโครงสร้างทางสถิติลึก และผู้พูดบอกว่ากว่า 70 ปีต่อมา สิ่งที่ LLM ทำก็แทบจะเป็นแบบนั้น คือทายสิ่งที่มาถัดไป LLM เป็น model สถิติของภาษา ดึงรูปแบบและความสัมพันธ์จากข้อความจำนวนมหาศาล แล้วสร้างตัวแทนทางคณิตศาสตร์ว่าคำสัมพันธ์กันอย่างไร คนมักเรียกว่า "เครื่องทาย token ถัดไป" ซึ่งถูก แต่ผู้พูดบอกว่ามีเครื่องจักรอีกมากก่อนถึงขั้นนั้น และเขาอยากเข้าใจส่วนนั้น เพราะเราใช้บริการ AI มากขึ้นทุกวันทั้งที่บ้านและที่ทำงาน แต่รายละเอียดถูกซ่อนไว้ และคนส่วนใหญ่ก็แค่บอกผ่าน ๆ ว่า "มันทาย token ถัดไป"

2. ประวัติ chatbot แบบกฎ (~1:54–4:21)

ก่อนมี LLM มี chatbot มาแล้วกว่า 60 ปี จุดเริ่มคือปี 1950 เมื่อ Alan Turing ตีพิมพ์ "Computing Machinery and Intelligence" เสนอ Turing test ว่าถ้าเครื่องคุยได้จนแยกจากคนไม่ออก เครื่องคิดได้หรือไม่ ผู้พูดบอกว่านี่ตั้งเป้าให้ 70 ปีต่อมา

  • ELIZA (1966) โดย Joseph Weizenbaum ที่ MIT เป็นโปรแกรมจับรูปแบบที่เลียนแบบนักบำบัดแนว Rogerian ไม่มีความเข้าใจเลย ข้อความที่ผู้ใช้พิมพ์ผ่าน if ต่อกันเพื่อเลือกคำตอบ แบบนี้เรียกว่า rule-based system คือโปรแกรมเมอร์ต้องเขียนทุกเงื่อนไขเอง เลขานุการของ Weizenbaum เคยขอให้เขาออกจากห้องเพื่อคุยกับ ELIZA เป็นส่วนตัว และเขาเขียนภายหลังว่าไม่คิดว่าการคุยกับโปรแกรมง่าย ๆ เพียงสั้น ๆ จะทำให้คนปกติเกิดความคิดหลงผิดได้ขนาดนี้ ผู้พูดบอกว่าเราเห็นแบบนี้ในวันนี้ คนพึ่งการคุยกับ ChatGPT เหมือนเพื่อนหรือนักบำบัด
  • PARRY (1972) โดย Kenneth Colby ที่ Stanford จำลองผู้ป่วยจิตเภทชนิดหวาดระแวง มีสถานะภายในเรื่องความโกรธ ความกลัว ความไม่ไว้ใจ แล้วเปลี่ยนคำตอบตามนั้น จิตแพทย์ที่คุยด้วยแยกไม่ออกจากผู้ป่วยจริง ต่อมาในปีเดียวกัน ELIZA กับ PARRY ถูกต่อเข้าหากัน กลายเป็นนักบำบัดบอทคุยกับผู้ป่วยบอท
  • ALICE (1995) มีรูปแบบที่เขียนด้วยมือ 41,000 รูปแบบ และ SmarterChild (2001) บน AOL Instant Messenger ซึ่งเป็น chatbot ยุคแรกที่คนหลายล้านใช้ทุกวัน ผู้พูดมองว่าอาจถือเป็นต้นแบบของ ChatGPT

ทุกตัวจนถึงตอนนั้นใช้กฎ สคริปต์ template หรือ decision tree คนต้องเขียนทุกคำตอบไว้ล่วงหน้า ผู้พูดจึงบอกว่าจาก ELIZA ถึง ChatGPT ไม่ใช่แค่ chatbot ที่ดีขึ้น แต่เป็นกลไกคนละแบบเลย

ข้อที่ควรเข้าใจให้ตรง

ผลตรวจของผู้จัดทำ: จิตแพทย์ในการทดสอบ PARRY ทายถูก 48% ซึ่งเท่ากับการเดา (ตรงกับที่ผู้พูดบอกว่า "แยกไม่ออก") · ELIZA กับ PARRY คุยกันครั้งแรก 18 ก.ย. 1972 ส่วนเอกสาร RFC 439 ลงวันที่ ม.ค. 1973 · ตัวเลข 41,000 ของ ALICE เป็นจำนวน category ในภายหลัง ไม่ใช่ตอนเปิดตัวปี 1995 · SmarterChild มีผู้ใช้รวมกว่า 17 ล้าน แต่ไม่พบตัวเลขผู้ใช้รายวัน

3. Chatbot ด้วย if และความคิดแบบกล่องดำ (~4:21–7:41)

ผู้พูดสร้าง chatbot แบบ ELIZA ให้ดู พิมพ์ hello หรือ hi ก็ตอบ "Hello, how can I help you today?" เหมือน LLM โค้ดทุกส่วนในคลิปอยู่ในลิงก์ใต้คลิป ในโค้ด: มีรายการคำทักทายทั้งหมด ฟังก์ชันเดียวรับข้อความของผู้ใช้ ลบอักขระพิเศษและช่องว่างที่ไม่จำเป็น ได้เป็นรายการคำ แล้วตรวจทีละเงื่อนไข

  • มีคำทักทายในข้อความ → ตอบคำทักทาย
  • ขึ้นต้นด้วย "I feel" → ดึงส่วนที่ตามมา เปลี่ยน I เป็น you แล้วตอบ "Why do you feel …" เช่น "I feel happy today" → "Why do you feel happy today?"
  • มีคำว่า "my" → ดึงสิ่งที่ตามมาเป็นหัวข้อ แล้วตอบ "Tell me more about your …" เช่น "My boss gave me good remarks" → "Tell me more about your boss."
  • ไม่ตรงอะไรเลย → สุ่มคำตอบกลาง ๆ เช่น "Please go on." "How does that make you feel?" (ตัวอย่าง "He is cool and is a breakdancer" ได้ "Please go on.")

ด้วย if ไม่กี่ตัวก็ทำให้ผู้ใช้รู้สึกว่ามีอะไรฉลาดอยู่อีกฝั่ง และหน้าจอที่ผู้ใช้เห็นแทบเหมือน ChatGPT หรือ Claude คือมีช่องพิมพ์และได้คำตอบกลับ กล่องดำ: ผู้พูดชอบมองระบบเป็นกล่องที่มีข้อมูลเข้า กระบวนการ และข้อมูลออก ในที่นี้กระบวนการคือ if ชุดหนึ่ง แต่เปลี่ยนกล่องเป็น LLM ได้ คำถามเข้า LLM ทำอะไรบางอย่าง คำตอบออก ทั้งคลิปจะค่อย ๆ เปลี่ยนชิ้นส่วนให้ฉลาดขึ้น เขามองโลกเทคโนโลยีแบบนี้ ทุกอย่างเริ่มเป็นกล่องดำแล้วค่อยเปิดดูว่าทำงานอย่างไร และถ้ามองเป็นเข้าและออก ก็เปลี่ยนไส้ในเป็นของที่ฉลาดกว่าได้ภายหลัง

4. Neural network และประวัติ (~7:41–10:27)

ก่อนจะถาม LLM ได้ ต้องสร้าง LLM ก่อน คำถามที่พิมพ์ใน ChatGPT ถูกส่งไปยัง model ที่ฝึกไว้แล้ว การฝึกเกิดล่วงหน้าและได้ ไฟล์ model ที่อยู่บนเซิร์ฟเวอร์ ซึ่งคือสิ่งที่เราคุยด้วยจริง ๆ LLM ย่อมาจาก large language model และ model คือ neural network ระบบของ node ที่เรียกว่า neuron จัดเป็นชั้น ข้อมูลเข้าที่ชั้น input ผ่านชั้นซ่อนหนึ่งชั้นหรือมากกว่า แล้วออกที่ชั้น output แต่ละเส้นเชื่อมมี weight คือตัวเลขที่กำหนดว่า neuron หนึ่งมีผลต่อตัวถัดไปมากแค่ไหน

  • 1943 Warren McCulloch (นักประสาทสรีรวิทยา) กับ Walter Pitts (นักตรรกศาสตร์ที่เรียนเอง) เสนอว่า neuron ในสมองจำลองเป็นประตูตรรกะเปิด-ปิดได้ ต่อกันมากพอในรูปแบบที่ถูกต้องก็คำนวณอะไรก็ได้ในทางทฤษฎี ตอนนั้นเป็นแค่การทดลองทางความคิด ยังไม่มีใครสร้างได้
  • 1958 นักจิตวิทยา Frank Rosenblatt สร้าง perceptron เป็นเครื่องจริงขนาดห้อง มีสายไฟ มอเตอร์ และเซลล์รับแสง ดูภาพบนบัตรแล้วเรียนรู้จำแนกได้ กองทัพเรือสหรัฐแถลงข่าว และ New York Times รายงานว่าเป็นตัวอ่อนของคอมพิวเตอร์ที่จะรู้ตัวว่ามีตัวตน
  • 1969 Marvin Minsky กับ Seymour Papert ตีพิมพ์หนังสือ Perceptrons พิสูจน์ว่า perceptron ชั้นเดียวแก้ปัญหาพื้นฐานบางอย่างไม่ได้ ที่ดังที่สุดคือ exclusive or (XOR) ได้ input สองตัวแบบ 0/1 ให้ตอบ 1 เมื่อมีตัวเดียวเป็น 1 ง่ายมากสำหรับคน แต่เป็นไปไม่ได้ทางคณิตศาสตร์สำหรับชั้นเดียว แบบหลายชั้นทำได้ แต่ไม่มีใครรู้วิธีฝึกให้ได้ผลดี
  • 1986 David Rumelhart, Geoffrey Hinton และ Ronald Williams ตีพิมพ์ใน Nature เรื่อง backpropagation วิธีฝึกหลายชั้น: ทาย วัดว่าผิดเท่าไร ส่งสัญญาณความผิดย้อนกลับทุกชั้น ปรับทุก weight ให้ผิดน้อยลงนิดหนึ่ง แล้วทำซ้ำเป็นพันล้านครั้ง ผู้พูดบอกว่า neural network ทุกตัวที่เราใช้วันนี้ รวมถึง Claude, ChatGPT, Gemini ฝึกด้วย backpropagation รูปแบบใดรูปแบบหนึ่ง

ผลตรวจของผู้จัดทำ: งาน perceptron ปี 1958 ที่แถลงข่าวรันบนคอมพิวเตอร์ IBM 704 ซึ่งมีขนาดเท่าห้อง ส่วนเครื่อง Mark I Perceptron ที่มีเซลล์รับแสงสร้างเสร็จภายหลัง · คำพาดหัวของ New York Times ถูกต้อง

5. โค้ด XOR: model คือไฟล์ weight (~10:27–15:35)

ผู้พูดใช้ปัญหาเดียวกับที่ทำให้ perceptron ตกอับ ฝึกสด ๆ ให้ดู

  • ชั้นเดียว: แม้ผ่าน 5,000 รอบก็ยังไม่ได้ output ที่ต้องการ
  • หลายชั้น: ทำได้ ราว 800 รอบ loss ก็ต่ำมาก แล้วต่ำลงเรื่อย ๆ จนถึง 5,000 รอบแทบไม่ลดอีก ค่าที่ได้ไม่เป๊ะ แต่ปัดแล้วตรง (ปัดลงเป็น 0, ขึ้นเป็น 1, ขึ้นเป็น 1, ลงเป็น 0) สำหรับ input false/false, false/true, true/false, true/true

สิ่งที่ผู้พูดอยากให้เห็นคือ หลังฝึกเสร็จ โค้ดสร้างไฟล์ในโฟลเดอร์ .data ที่เก็บ weight ไว้ model ก็คือไฟล์ที่มีค่า weight อยู่ข้างใน

ผู้พูดบอกว่าแม้ตัวอย่างนี้ง่ายมาก แต่ neural network ทุกตัวทำงานแบบเดียวกัน คือมีไฟล์ weight (ไฟล์ model) ที่ได้จากการฝึกด้วย backpropagation ในโค้ด: มี input (false/false … true/true) และ output ที่ต้องการ (false, true, true, false) ทุก network ต้องรู้ว่า input คืออะไรและ output ที่คาดหวังคืออะไร ฟังก์ชันฝึกชั้นเดียวรับจำนวน epoch (ค่าเริ่มต้น 5,000) แต่ละรอบ: คำนวณ output ด้วย weight, input และ bias → ดูว่าห่างจากเป้าหมายเท่าไร → ใช้อนุพันธ์หา delta → ปรับ weight และ bias → ทำซ้ำ (จะตั้งให้หยุดเมื่อ loss ต่ำกว่าเกณฑ์ก็ได้ แต่ตัวนี้ทำครบ 5,000 รอบเสมอ) weight เริ่มเป็นค่าสุ่ม แบบหลายชั้นคล้ายกัน ต่างที่ต้องสุ่ม weight ทุกเส้น และคำนวณผ่านสองชั้น (input → ชั้นซ่อน → output) จึงมีสอง delta คือ delta ของ output และ delta ของชั้นซ่อน แล้วปรับทุก weight มีชั้นซ่อนกี่ชั้นก็ได้ โค้ดคล้ายเดิม สรุปคือ ตั้ง input, output, ชั้นซ่อน แล้ววนปรับ weight จนให้ output ที่ต้องการ

6. Tokenization และ BPE (~15:35–17:55)

คำถามที่พิมพ์เป็น input ของ neural network แต่ network ไม่รับข้อความทั้งก้อน ต้องตัดเป็นชิ้นที่ใช้เป็น input ได้ ขั้นแรกคือ tokenization model ตัดคำถามเป็นชิ้นที่ไม่ใช่คำและไม่ใช่ตัวอักษร แต่อยู่ระหว่างนั้น token คือหน่วยข้อความที่เล็กที่สุดที่ model ใช้ เช่น "the" เป็นหนึ่ง token · "tokenization" อาจถูกตัดเป็น "token" กับ "ization" · ช่องว่างมักเป็นส่วนหนึ่งของ token · ขึ้นบรรทัดใหม่เป็น token · emoji อาจเป็นหลาย token model ไม่ได้เห็นคำแบบที่เราเห็น แต่เห็น token BPE (byte pair encoding): Philip Gage คิดในปี 1994 เพื่อบีบอัดข้อมูล ไม่เกี่ยวกับ language model เลย หลักคือดูลำดับไบต์ หาคู่ที่เจอบ่อยที่สุด แทนด้วยสัญลักษณ์ใหม่ แล้วทำซ้ำ 21 ปีต่อมา (2015) Rico Sennrich, Barry Haddow และ Alexandra Birch ที่ University of Edinburgh เห็นว่าเหมาะกับการสร้างคลังคำสำหรับ neural machine translation: แทนที่จะกำหนดคลังคำล่วงหน้า ให้ BPE เรียนคลังคำเองโดยรวมคู่ตัวอักษรที่พบบ่อยในข้อมูลฝึกไปเรื่อย ๆ คำที่พบบ่อยอย่าง "the" ยังเป็นคำเต็ม คำหายากถูกตัดเป็นชิ้นย่อย ข้อดีคืออัลกอริทึมเดียวใช้ได้กับอังกฤษ ญี่ปุ่น โค้ด Python, TypeScript และ emoji โดยไม่ต้องมีกฎเฉพาะภาษา

tokenization มีผลจริง: จำนวน token กำหนดราคา (API คิดเงินต่อ token) และ กำหนดว่าอะไรใส่ใน context ได้ ทุก model มี context window สูงสุดนับเป็น token ถ้าเกิน บางอย่างจะถูกตัดทิ้ง

7. โค้ด tokenizer (~17:55–21:37)

demo "basic tokenizer" ใส่ข้อความฝึกแล้วแสดงคู่ที่รวมในแต่ละขั้นและคลังคำสุดท้าย "the cat sat on the mat" ได้ 6 token ที่ไม่ซ้ำ หลักของ BPE คือรวมคู่ที่พบบ่อยที่สุด เพราะข้อความฝึกมีประโยคเดียว จึงได้แต่ละคำเป็น token บนจอ การรวม 7 ขั้นคือ a+t → at (×3), t+h → th (×2), th+e → the (×2), c+at → cat, s+at → sat, o+n → on, m+at → mat ถ้าจำกัดการรวมสูงสุดเป็น 3 ครั้ง จะได้ "at" เป็น token เพราะ at โผล่หลายครั้ง (cat, sat, mat) และ "the" ได้ token ของตัวเองเพราะโผล่สองครั้ง ที่เหลือเป็นตัวอักษรเดี่ยว ขั้นตอนในโค้ด:

  1. regular expression: ข้อความฝึกผ่าน regex ก่อนเสมอ เพราะ BPE ไม่รวมข้ามขอบเขตคำ ต้องกำหนดกลุ่มไว้ก่อน ตัวนี้ตัดตามช่องว่างเป็นคำ ส่วน GPT-2 / GPT-4 มี regex ที่ซับซ้อนกว่ามากเพราะกำหนดกฎไว้ล่วงหน้า
  2. นับความถี่ของคำ เป็นการเร่งความเร็ว จำนวนครั้งเป็นน้ำหนักว่าคำนั้นสำคัญแค่ไหน เช่น "the" โผล่สองครั้งจึงหนักกว่าคำอื่น
  3. วนรวม สูงสุดตามจำนวนที่ตั้ง (ผู้พูดบอกว่าตั้งไว้ 10,000) จำนวนนี้กำหนดขนาดคลังคำ ยิ่งมากยิ่งน่าจะได้ token ครบ แต่ละรอบดูทุกคู่ตัวอักษร หาคู่ที่พบบ่อยที่สุดโดยคิดน้ำหนักของคำ แล้วรวมคู่นั้นในทุกคำ แล้วหาคู่ถัดไป

Bee Movie: ใส่บทภาพยนตร์ Bee Movie ได้ 2,088 token ซึ่งแทบเป็นคำทั้งหมดในบท ถ้าลดการรวมสูงสุดเหลือราว 1,000 จะเห็นคำถูกแตก เช่น "according" เป็น 4 token เพราะงบ token มีจำกัดและคำนี้ไม่ค่อยโผล่ในบท สุดท้ายทุก token ในคลังคำมี ID เป็นตัวเลข คือตำแหน่งในคลังคำ ID เป็นเลขที่ไม่มีความหมาย ไม่บอกว่า token สัมพันธ์กันอย่างไร

8. Embedding และเวกเตอร์ (~21:37–24:39)

ID ของ token ไม่มีความหมาย จึงต้องแปลง token เป็นสิ่งที่ model ใช้คิดได้

  • 1884 Gottlob Frege เสนอ context principle ว่า อย่าถามความหมายของคำโดยลำพัง ให้ถามในบริบทของประโยคเท่านั้น
  • 1957 J.R. Firth นักภาษาศาสตร์อังกฤษ เขียนไว้ว่า "You shall know a word by the company it keeps" วันนี้เรียกแนวคิดนี้ว่า distributional semantics ผู้พูดบอกว่าประโยคนี้คือแก่นของ embedding model ทุกตัวที่เคยสร้าง

model ภาษาสมัยใหม่ทุกตัวเริ่มจากวางคำลงในพื้นที่ตัวเลขขนาดใหญ่ที่คำข้างเคียงมีความหมายใกล้กัน แผนที่นี้เรียกว่า embedding

  • 2013 Tomas Mikolov และทีมที่ Google เขียน word2vec ฝึก network ให้ทายคำจากคำข้างเคียงในข้อความจำนวนมาก เมื่อดูเวกเตอร์ที่ได้ พบโครงสร้างที่ไม่มีใครสอน: เวกเตอร์ king − man + woman ใกล้ queen ที่สุด ไม่มีใครบอก model เรื่องเพศหรือราชวงศ์ ความคิดเหล่านี้เกิดจากสถิติว่าคำไหนอยู่ใกล้คำไหนล้วน ๆ ผู้พูดบอกว่านี่คือครั้งแรกที่แนวคิด "รู้จักคำจากคำที่อยู่ด้วย" ถูกทำเป็นคณิตศาสตร์

เวกเตอร์ คือรายการตัวเลขที่ระบุจุดในพื้นที่หลายมิติ ง่ายที่สุดคือ 3 มิติ (x, y, z) แต่ embedding ใหญ่กว่ามาก ผู้พูดบอกว่า word2vec ใช้ 300 มิติ และ GPT-3 ตัวใหญ่สุดใช้ 12,288 มิติ แต่ละตัวเลขจับลักษณะบางอย่างที่ model เรียนเอง ไม่ใช่สิ่งที่คนตั้งชื่อ รวมกันแล้วเข้ารหัสความหมายเป็นตำแหน่ง คำความหมายใกล้กันอยู่ใกล้กัน เช่น happy กับ joyful ใกล้กัน happy กับ refrigerator ห่างกัน วัดความใกล้ด้วย cosine similarity ซึ่งดูมุมระหว่างสองเวกเตอร์ ผู้พูดบอกว่า 1 คือเหมือนกัน และ 0 คือไม่เกี่ยวกันเลย embedding ใน LLM ปัจจุบันสืบทอดจาก word2vec โดยตรง แค่ขยายจากคำเดี่ยวเป็นบริบททั้งหมด

ข้อที่ควรเข้าใจให้ตรง

ผลตรวจของผู้จัดทำ: cosine 1 แปลว่าทิศเดียวกัน (ความยาวต่างกันได้) 0 แปลว่าตั้งฉาก และค่าต่ำสุดคือ −1 (ทิศตรงข้าม) · บทความ word2vec ทดลองหลายขนาดตั้งแต่ 20 ถึง 1,000 มิติ 300 เป็นหนึ่งในนั้น

9. โค้ดฝึก embedding แบบ word2vec (~24:39–30:48)

demo "train embeddings" รับคำไม่กี่คำ ฝึก embedding model สด แล้วแสดงเวกเตอร์ของแต่ละคำและการเทียบกัน บนจอ queen ↔ king 0.92, cat ↔ dog 0.73, king ↔ cat 0.47, queen ↔ cat 0.42, king ↔ dog 0.34, queen ↔ dog 0.33 คำนวณคำ: king − man + woman = queen และกลับทางได้ queen − woman + man = king (บนจอ 0.84 และ 0.86) ยังมี prince − boy + girl = princess และ kitten − cat + dog = puppy ผู้พูดบอกว่าแม้ชุดข้อมูลเล็กก็ได้ผลที่คนเข้าใจภาษาเห็นว่าสมเหตุสมผล

corpus: สิ่งที่ต้องมีคือข้อความฝึกทั้งหมด ที่นี่เป็นประโยคบอกเล่าราว 100 กว่าประโยค (107) เช่น "the cat sat on the mat", "the kitten is a baby cat" และหมวดราชวงศ์ "king is a man who rules" / "queen is a woman who rules" / "a prince is a young man of royal blood" / "a princess is a young woman of royal blood" การวางคำในบริบทเดียวกันแล้วสลับคำ ทำให้ model เรียนว่า princess เกี่ยวกับ woman และ young ส่วน prince เกี่ยวกับ young และ man การฝึก: บทความ word2vec มีสองแบบ skip-gram กับ CBOW (continuous bag of words) ผู้พูดทำแบบ skip-gram

  1. สร้างคู่คำ ตาม window size (ผู้พูดบอกว่าตั้งราวห้าหรือหก) คำหนึ่งจับคู่กับทุกคำที่อยู่ภายในระยะนั้น เช่น king–is, king–of, king–man, king–who, king–rules และ man–a, man–is, man–king … model จะเห็นว่า king มักมากับ man, queen มักมากับ woman, ทั้งคู่มักมากับ kingdom ได้ 107 ประโยค → 3,970 คู่
  2. ไฟล์ weight: word2vec เป็น neural network ที่ง่ายที่สุดแบบหนึ่ง ไฟล์ weight จึงเป็นแค่คลังคำทั้งหมด และแต่ละคำมีเวกเตอร์หนึ่งชุด (tokenize ก่อน แล้วสร้างเวกเตอร์ให้ทุก token) เริ่มเป็นค่าสุ่ม ขนาดคลังคำ × มิติ ที่นี่ 32 มิติ ผู้พูดบอกว่ามิติยิ่งมากยิ่งเก็บข้อมูลได้มาก
  3. วนฝึก: ทุก epoch ดึงเวกเตอร์ของคู่ที่อยู่ใกล้กันให้ใกล้กันมากขึ้น และผลักคำที่ไม่เคยอยู่ใกล้กันให้ห่างออกไป ดึงและผลักไปเรื่อย ๆ
  4. ใช้งาน: หลังฝึก เวกเตอร์ทั้งหมดอยู่ในไฟล์ weight จะคำนวณคำก็เปิดเวกเตอร์ของสามคำ ลบ บวก ได้เวกเตอร์ผลลัพธ์ที่ไม่ตรงคำใดเป๊ะ แล้วเทียบกับทุกคำในคลัง เลือกตัวที่ใกล้ที่สุด เช่น queen

ผู้พูดสรุปว่าตัวนี้ง่ายมาก ชุดข้อมูลเล็ก และสร้างเวกเตอร์แค่ของคำเดี่ยว embedding model สมัยใหม่ใช้ข้อมูลมหาศาล (เขาพูดว่า "ทุกข้อความที่มนุษย์เคยเขียนตลอดประวัติศาสตร์") และ embed ทั้งประโยคหรือย่อหน้า ไม่ใช่แค่คำในคลังคำ แต่เป็นแนวคิดเดียวกันที่ขยายขนาด

10. ทำไมต้องมี transformer (~30:48–32:33)

มี token และ embedding แล้ว แต่อะไรประมวลผล คำตอบคือ transformer LLM หลักทุกตัวในวันนี้ ทั้ง GPT, Claude, Gemini เป็น transformer รูปแบบหนึ่ง ปี 2016 ระบบแปลภาษาของ Google ใช้ LSTM (long short-term memory) อ่านข้อความทีละคำพร้อมความจำที่สะสมไว้ ใช้ได้แต่ช้า แต่ละคำต้องรอคำก่อนหน้าทำเสร็จ เพื่อช่วยประโยคยาว นักวิจัยเสริม attention เข้าไป attention มาจากบทความปี 2014 ของ Dzmitry Bahdanau, Kyunghyun Cho และ Yoshua Bengio: model แปลภาษาเดิมบีบทั้งประโยคเป็นเวกเตอร์ขนาดคงที่ตัวเดียวก่อนแปล ประโยคสั้นไม่มีปัญหา ประโยคยาวพัง แนวคิดของ Bahdanau คือให้ model มองย้อนไปที่ input ในแต่ละขั้นและเน้นคำที่สำคัญตอนนั้น ได้ผล แต่ยังติดอยู่กับ LSTM จึงยังช้า ปี 2017 Jakob Uszkoreit ที่ Google เสนอให้ทิ้งส่วนที่ทำทีละลำดับ ใช้ attention อย่างเดียว นักวิจัยแปดคนซึ่งระบุว่ามีส่วนเท่ากันสร้างขึ้นและตั้งชื่อบทความว่า "Attention Is All You Need" ผู้พูดบอกว่าบทความถูกอ้างอิงเกิน 100,000 ครั้ง ผู้เขียนทั้งแปดออกจาก Google แล้ว หลายคนตั้งบริษัทมูลค่าพันล้าน และบทความยาวแค่ 15 หน้า อ่านฟรีได้ แบบแปลนของเทคโนโลยีที่ขับเคลื่อนอุตสาหกรรมล้านล้านดอลลาร์จึงเป็นแค่ PDF ที่ใครก็นั่งอ่านได้

11. ข้างใน transformer block (~32:33–35:14)

ข้างล่างสุด transformer คือ neural network ชนิดเฉพาะ ระดับฮาร์ดแวร์แทบทั้งหมดเป็น การคูณเมทริกซ์ ผู้พูดบอกว่าความฉลาดไม่ได้อยู่ที่ตรรกะฉลาด ๆ แต่อยู่ในตัวเลขนับพันล้านในเมทริกซ์ ซึ่งเริ่มจากสุ่มแล้วถูกปรับระหว่างฝึก แต่ละ block มีสองงาน คือ attention ที่ token แลกข้อมูลกัน และ feed forward ที่แต่ละ token ถูกประมวลผลแยกกัน ทั้งสองมี weight ของตัวเอง และฝึกแบบเดียวกัน คือทาย วัดความผิด ปรับทุก weight ไปทางที่ลดความผิด

Self-attention: สำหรับแต่ละ token model สร้างสามเวกเตอร์จาก embedding คือ query (token นี้กำลังมองหาอะไร) key (แต่ละ token มีอะไรให้) และ value (สิ่งที่ส่งต่อเมื่อจับคู่ได้) model เทียบทุก query กับทุก key ให้คะแนน แล้วผสม value ตามคะแนน ผลคือเวกเตอร์ใหม่ต่อ token รูปร่างเดิม แต่มีข้อมูลจากคำอื่นในประโยค ตัวอย่าง bank: ใน "Bank of the river was muddy" เวกเตอร์ของ bank ถูกกำหนดโดย river และ muddy เป็นหลัก ส่วนใน "I went to the bank to deposit money" ถูกกำหนดโดย deposit และ money คำเดียวกันเข้า เวกเตอร์ต่างกันออก ความหมายถูกตัดสินด้วยบริบท Multi-head attention: ทำแบบนี้หลายครั้งพร้อมกัน แต่ละครั้งมี weight ของ query, key, value ต่างกัน เรียกว่า head ไม่มีใครบอกว่าแต่ละ head ต้องสนใจอะไร เริ่มสุ่มแล้วระหว่างฝึกจะเชี่ยวชาญเอง เช่น head หนึ่งอาจตามว่าสรรพนามหมายถึงคำนามไหน อีก head อาจตาม tense ของกริยา อีก head อาจตามตำแหน่ง ผู้พูดบอกว่าเกิดขึ้นเองไม่ได้ออกแบบ แล้วผลของทุก head รวมกลับเป็นเวกเตอร์เดียวต่อ token Feed forward: เวกเตอร์ของแต่ละ token ที่มีบริบทแล้ว ผ่าน network สองชั้นเล็ก ๆ ทีละ token เพื่อขัดเกลาก่อนไปต่อ ซ้อนชั้น: attention + feed forward = หนึ่ง block หรือหนึ่งชั้น LLM สมัยใหม่ซ้อนหลายสิบถึงหลายร้อยชั้น ทุกชั้นรับและส่งรูปร่างเดิม (หนึ่งเวกเตอร์ต่อ token) แต่ละชั้นต่อยอดจากชั้นก่อน ผู้พูดบอกว่าชั้นต้นมักจับไวยากรณ์ ชั้นกลางจับความหมาย ชั้นท้ายจับการให้เหตุผล และนี่คือความหมายของ deep learning คือชั้นที่ซ้อนกันมาก สรุปสถาปัตยกรรม: token เข้า → embed → ผ่าน attention และ feed forward หลายชั้น → ได้คำทำนาย ทุกอย่าง ทั้ง GPT, Claude, Gemini เป็นสูตรเดียวกันที่ขยายขนาด

12. Transformer ที่ผู้พูดฝึกเอง (~35:14–41:37)

demo "train transformer" รับจำนวน epoch, temperature, top-p, จำนวนชั้น และจำนวน token ที่จะทำนาย transformer ทำนายทีละ token เท่านั้น (การทำนายหลาย token อยู่ในหัวข้อถัดไป) ผู้พูดสร้าง transformer ที่แต่งนิทานเด็กง่าย ๆ และใช้ model ที่ฝึกไว้แล้ว เพราะฝึกบน MacBook ราว 14 คอร์ใช้เวลามากกว่าชั่วโมงครึ่ง โดยใช้ CPU ล้วน ไม่ใช้ GPU เริ่มจาก "once upon a time" ขอ token ถัดไปได้ "a" ขออีกได้ "small" พอปรับ temperature และ top-p ได้ token ต่างออกไป เช่น "a young" เพราะในข้อมูลฝึกมี once upon a time หลายแบบและตัวละครหลายตัว ข้อมูลฝึกคือนิทานเด็กสั้น ๆ กว่า 30 เรื่อง เรื่องละราวสี่ถึงห้าประโยค เช่น "once upon a time there was a king", "a young prince lived in a castle", "there was once a wicked old man" model จึงเรียนความสัมพันธ์ของตัวละคร สถานที่ และฉาก output ไม่ใช่ token แต่เป็นการกระจายความน่าจะเป็น ทุก token ในคลังคำได้ค่าว่ามีโอกาสเป็น token ถัดไปเท่าไร แล้วใช้ temperature และ top-p เลือก

ไฟล์ weight: มีขนาดคลังคำ (ที่ได้จากข้อมูลฝึก) และ context length ซึ่งเล็กมากเทียบกับ model ที่ใช้ทุกวัน model นี้ดูลำดับ 32 token แล้วทาย token ถัดไป ในไฟล์มีคลังคำและ merges เพื่อ tokenize ข้อความใหม่ได้ และมี embedding model แยกของ transformer นี้ที่มี weight ของ embedding และ weight ของตำแหน่ง (positional) ผู้พูดอธิบายว่า input และ output ของ transformer คือรายการ token ทั้งหมด แต่คำถามมีแค่ไม่กี่คำ positional embedding จึงช่วยให้ model รู้ว่า input คือ token เหล่านี้ในลำดับนี้ แล้วมี weight ของทุก block คือ query, key, value และ feed forward ทุกอย่างเริ่มสุ่มแล้วปรับระหว่างฝึก ผู้พูดบอกว่า embedding 32 มิติ 6 ชั้น ได้ 52,000 พารามิเตอร์ แล้วเทียบกับ gpt-oss-120b ที่มี 120 พันล้านพารามิเตอร์ตามชื่อ 52,000 จึงเล็กมากแม้เทียบกับ model ที่รันในเครื่อง และ model ในเครื่องเหล่านั้นก็ยังเล็กมากเทียบกับ model บนเซิร์ฟเวอร์ของ OpenAI และ Anthropic ในโค้ดของแต่ละ block: คูณเมทริกซ์ได้ query, key, value → dot product ของ query กับ key ได้คะแนน attention ของทุก token ต่อทุก token → คะแนนกลายเป็นน้ำหนัก → คูณกับ value ได้เมทริกซ์ attention ผู้พูดยอมรับว่าไม่ได้เข้าใจรายละเอียดทั้งหมด แต่ให้ดูเพราะมัน "ไม่ใช่เวทมนตร์ แค่คณิตศาสตร์" จากนั้นเอา input (คำถาม + ข้อมูลตำแหน่ง) บวกกับเมทริกซ์ attention แล้วผ่าน feed forward ด้วยการคูณเมทริกซ์ได้ output ของ block แล้วส่งต่อ block ถัดไป ขนาด input และ output เท่าเดิมเสมอ สุดท้ายได้ความน่าจะเป็นของทุก token ในคลังคำ

เสริมจากผู้จัดทำ
  • คำอธิบาย positional embedding ของผู้พูด ("เปลี่ยนคำถามเป็นรายการ token ทั้งหมด") ไม่ตรงกับแบบทั่วไป: ใน transformer ทั่วไป input คือ ID ของ token ในคำถาม แต่ละ ID เปิดแถวในตาราง embedding แล้วบวกเวกเตอร์ตำแหน่ง ส่วน output คือคะแนนของทุก token ในคลังคำ (ความรู้ทั่วไป)
  • ประโยค "dot product ของ query กับ key ได้ value" น่าจะพูดพลาด เพราะผู้พูดอธิบายต่อทันทีว่าได้คะแนน แล้วคะแนนเป็นน้ำหนักที่ใช้ผสม value

13. Softmax, temperature และ top-p (~41:37–42:54)

output ของ transformer เป็นคะแนนของทุก token ในคลังคำ เรียกว่า logits ใช้ softmax แปลงเป็นความน่าจะเป็นที่รวมกันได้ 1 แล้ว model ไม่ได้เลือก token ที่น่าจะเป็นสูงสุด แต่สุ่มเลือก

  • temperature ต่ำ → การกระจายคาดเดาได้ · สูง → สร้างสรรค์และคาดเดายาก ผู้พูดบอกว่า temperature 0 ได้ token เดิมทุกครั้ง ส่วนค่าสูงอย่าง 1.5 จะสุ่มมากและบางครั้งไม่สมเหตุสมผล
  • top-p เป็นการตัด ให้สุ่มเฉพาะ token ที่ครอบคลุมสัดส่วนหนึ่งของการกระจาย ค่า 1 คือทุก token มีโอกาส ผู้พูดบอกว่า 0.2 คือดูแค่ token บนสุด 20% ทำให้รายการ token ที่เป็นไปได้หดลง

14. วนทีละ token และ context window (~42:54–44:45)

ทุกขั้นที่ผ่านมา ทั้ง tokenization, embedding, transformer, softmax และการสุ่ม ได้แค่ token เดียว จะได้ token ถัดไปต้องเติม token นั้นท้าย input แล้วรันทั้งหมดใหม่ ได้ attention ใหม่ การกระจายใหม่ token ใหม่ เติม ทำซ้ำ เรียกว่า autoregressive generation ผู้พูดบอกว่า model ไม่มีแผน ไม่รู้ว่าประโยคจะจบอย่างไรตอนเริ่ม ย่อหน้าที่อ่านรู้เรื่องจาก LLM จึงเกิดทีละก้าวแบบมองไม่เห็นทางข้างหน้า สิ่งที่ model เห็นจริง: เมื่อส่งคำถามไปยัง LLM ที่ใช้งานจริง model ไม่ได้เห็นแค่คำถาม แต่เห็นชุดข้อมูลที่จัดโครงสร้าง ประกอบด้วย system prompt (คำสั่งซ่อนที่ผู้ให้บริการเขียน เช่น "you're a useful chatbot") ประวัติการสนทนาทั้งหมด และข้อความล่าสุดท้ายสุด model ไม่มีความจำระหว่างคำขอ ประวัติการสนทนาคือความจำ และป้อนเข้าวงวนนี้ ทั้งหมดต้องอยู่ใน context window ตัวอย่างของผู้พูดมี 32 token ส่วน model ปัจจุบันมีตั้งแต่ 100,000 ถึงหลายล้าน token context window คือทุกอย่างที่ transformer เห็นตอนทำนาย token ถัดไป ผู้พูดบอกว่านี่คือเหตุที่บทสนทนายาว ๆ คำตอบอาจเริ่มแย่ลงหรือเริ่มเห็นการแต่งเรื่อง (hallucination) เพราะมีเรื่องให้ดูมากขึ้น อาจไม่ทำตามคำสั่งก่อนหน้า เพราะข้อความหลัง ๆ อาจมีน้ำหนักใน attention มากกว่า

15. ภาพรวม และขั้นการฝึก (~44:45–47:24)

ภาพรวม: คำถามถูกตัดเป็น token ตามคลังคำที่กำหนดไว้ล่วงหน้าจากข้อมูลฝึก → token กลายเป็น embedding ที่ให้ความหมาย → ผ่าน transformer ที่ attention รวบรวมบริบทจากทุก token ผ่านหลาย block → ได้ความน่าจะเป็นของทุก token ในคลังคำ → สุ่มด้วย temperature และ top-p → เติม token กลับไปแล้ววนใหม่ (ดูผังภาพรวม) Pre-training: ทุกอย่างในคลิปเป็นแค่ขั้น pre-training คือฝึก transformer ด้วยข้อมูลก้อนใหญ่จากอินเทอร์เน็ต ชุดข้อมูลที่ใหญ่ที่สุดชุดหนึ่งคือ Common Crawl องค์กรไม่แสวงกำไรที่เก็บเว็บมาตั้งแต่ 2008 มีข้อความดิบหลาย petabyte นอกจากนั้นมี Wikipedia, Reddit, GitHub, หนังสือดิจิทัล บทความวิชาการ คลังข่าว และผู้พูดบอกว่ามีงานติดลิขสิทธิ์จำนวนมากที่บริษัท AI ไม่ค่อยยอมรับว่าใช้ ผลของขั้นนี้ ผู้พูดเรียกว่าเครื่องเติมข้อความชั้นดี ซึ่งก็คือสิ่งที่สร้างในคลิปนี้ Fine-tuning: เอา model ที่มีอยู่มาฝึกต่อด้วยข้อมูลชุดใหม่ คือคู่ถาม-ตอบจำนวนมากที่คัดแล้วในสไตล์ที่อยากให้ chatbot ตอบ ปรับ weight ทีละน้อยให้ตอบแบบ chatbot แทนการเติมข้อความ RLHF (reinforcement learning from human feedback): จ้างคนจริงให้คะแนนคำตอบ คำตอบแบบ chatbot ที่ดีได้อันดับสูง ที่แย่ได้ต่ำ ผู้พูดบอกว่าอะไรดีหรือแย่ขึ้นกับบริษัทที่ฝึกและวิจารณญาณของผู้ให้คะแนน

16. Tool calling (~47:24–48:36)

ผลของทั้งหมดคือ model ที่ทำตัวเหมือน chatbot ตอบคำถาม คุยโต้ตอบได้ แต่ยังเป็น model เดี่ยว คือไฟล์ weight บนเซิร์ฟเวอร์ ไม่รู้มากกว่าที่ถูกฝึก และเอื้อมออกไปนอกตัวไม่ได้ ทำได้แค่สร้าง token ถัดไป Tools: ใส่รายการเครื่องมือที่ใช้ได้และวิธีเรียกไว้ใน context เช่น ดูสภาพอากาศ ค้นเว็บ รันไฟล์โค้ด ค้นไฟล์ในเครื่อง คำอธิบายเครื่องมือบอก model ว่าทำอะไรได้ และ model ถูก fine-tune เพิ่มให้ส่ง tool call แทนคำตอบ คือส่งโค้ดที่มีโครงสร้างว่า "ช่วยเรียกเครื่องมือนี้" model ไม่ได้ออกไปบนเว็บเอง แต่สร้าง JSON object ว่าให้เรียกเครื่องมือ Harness: โปรแกรมที่ครอบ model เช่น code editor หรือ desktop app เห็นว่า output เป็น tool call ก็ทำตามจริง เช่น รันโค้ดหรือค้นเว็บ แล้วเติมผลลัพธ์เข้าไปในประวัติการสนทนา การเรียก model ครั้งถัดไปจึงมีข้อมูลนั้นใน context และตอบได้แม่นขึ้น ผู้พูดบอกว่ายังมีเทคนิคอื่นอีกมากใน LLM สมัยใหม่ เช่น mixture of experts และ thinking mode แต่คลิปนี้พูดแค่ระดับภาพรวม

17. Dartmouth และความเห็นท้ายคลิป (~48:36–51:48)

ย้อนกลับไปฤดูร้อนปี 1956 นักวิจัยสี่คน John McCarthy, Marvin Minsky, Nathaniel Rochester และ Claude Shannon รวบรวมคนราว 10 คนที่ชั้นบนสุดของภาควิชาคณิตศาสตร์ Dartmouth ใน Hanover, New Hampshire มีทุนจาก Rockefeller Foundation $7,500 และแผนงานแปดสัปดาห์ ตั้งชื่อว่า Dartmouth Summer Research Project on Artificial Intelligence ผู้พูดบอกว่าเป็นครั้งแรกที่ใช้คำว่า artificial intelligence ข้อเสนอเขียนว่าจะศึกษาสองเดือนโดยคนสิบคน บนสมมติฐานว่าทุกแง่ของการเรียนรู้หรือลักษณะอื่นของความฉลาด โดยหลักการแล้วอธิบายได้แม่นยำพอที่จะให้เครื่องจำลองได้ และพวกเขาคิดว่าฤดูร้อนเดียวพอ 70 ปีต่อมาเรายังทำอยู่ สถาปัตยกรรมเดียวจากบทความเดียวขับเคลื่อนผลิตภัณฑ์ที่คนนับพันล้านใช้ และผู้พูดบอกว่าเราอาจห่างจากการเปลี่ยนครั้งใหญ่อีกแค่บทความเดียว transformer อาจไม่ใช่สถาปัตยกรรมสุดท้าย เป็นแค่ของช่วงนี้ที่มีเงินวิจัยหลายพันล้านหนุน นักวิจัยกำลังสำรวจทางเลือก และสิ่งต่อไปอาจไม่เหมือนสิ่งที่พูดวันนี้เลย ทุกอย่างในคลิปมาจากงานวิจัยสาธารณะ บทความเปิดอ่านได้ มี open weight model ที่ดาวน์โหลดมารันเองได้ และโค้ดของผู้พูดอยู่ในคำอธิบายคลิป ความเห็นส่วนตัวของผู้พูด:

  • ยิ่งค้นคว้า ยิ่งรู้สึกว่า LLM คือเครื่องจับรูปแบบและเติมข้อความที่ซับซ้อนที่สุดที่เคยสร้าง เขาไม่คิดว่ามันเข้าใจจริง
  • ยิ่งเวทมนตร์น้อยลง ยิ่งเข้าใจเทคโนโลยีจริง ยิ่งใกล้วิธีทำงานกับ LLM ที่ดีขึ้นหรือเข้าใจสถิติของภาษาดีขึ้น
  • LLM ฝึกจากข้อความเขียนเท่านั้น แต่ความฉลาดของคนมากกว่าข้อความ ข้อความเป็นแค่การสื่อสารออกภายนอกแบบหนึ่ง ไม่ใช่วิธีที่สมองทำงาน สำหรับเขานี่ยืนยันว่า LLM ทำนาย token ถัดไปจากสถิติของภาษา ไม่จำเป็นว่าจะเป็นการจำลองความฉลาดของมนุษย์หรือสิ่งที่เกิดขึ้นในสมองจริง ๆ
  • ในความเห็นของเขา AI น่าจะเรียกว่า alien intelligence มากกว่า artificial intelligence เพราะมันฉลาด แต่ไม่จำเป็นว่าจะเป็นความฉลาดของคนแบบปลอม เป็นอะไรที่ต่างไปเลย

เสริมจากผู้จัดทำ: วิเคราะห์เพิ่ม
  • คลิปไล่ครบทั้งเส้นทาง ตั้งแต่ข้อความ → token → เวกเตอร์ → transformer → ความน่าจะเป็น → token ถัดไป จุดแข็งคือโค้ดเล็ก ๆ ที่รันได้จริงทุกขั้น
  • จุดที่ควรระวังเวลาเอาไปสอน: นิยาม top-p, จำนวนพารามิเตอร์, ค่าตั้งใน repo (window, max merges) และคำอธิบาย positional embedding ตามกล่องแก้ด้านบน
  • คำอธิบายใต้คลิป (ไม่ได้พูดในคลิป) อ้างทางเลือกอย่าง Mamba, xLSTM, Jamba และ JEPA
  • ความเห็นเรื่อง "ไม่เข้าใจจริง" และ "alien intelligence" เป็นความเห็นส่วนตัวของผู้พูด ไม่ได้มาจากการทดลองในคลิป

Key Takeaways

1.LLM คือ model สถิติของภาษาที่ทาย token ถัดไปทีละตัว แล้วเติมกลับเข้าไปวนใหม่ (autoregressive)
2.model คือไฟล์ weight ที่เริ่มจากค่าสุ่มและถูกปรับด้วย backpropagation ตั้งแต่ XOR 17 ตัวเลขจนถึง LLM หลายพันล้านพารามิเตอร์
3.BPE สร้างคลังคำจากคู่ตัวอักษรที่พบบ่อย จำนวน token กำหนดราคาและสิ่งที่ใส่ใน context window ได้
4.embedding วางคำที่ความหมายใกล้กันไว้ใกล้กัน (word2vec: king − man + woman ≈ queen) ส่วน self-attention ทำให้คำเดียวกันได้เวกเตอร์ต่างกันตามประโยค
5.(ผลตรวจของผู้จัดทำ) top-p คือชุด token ที่เล็กที่สุดซึ่งความน่าจะเป็นรวมถึง p ไม่ใช่ "token บนสุด 20%" อย่างที่ผู้พูดอธิบาย
6.chatbot ที่ใช้จริงผ่าน pre-training → fine-tuning → RLHF และเรียกเครื่องมือผ่าน JSON ที่ harness นำไปทำ
