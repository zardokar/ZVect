สรุปเชิงลึก

เส้นเรื่อง: ChatGPT คือโมเดลภาษา (language model) ที่เดาข้อความต่อไปทีละชิ้น และแกนข้างในคือ Transformer จากเปเปอร์ "Attention Is All You Need" ปี 2017 ผู้สอนไม่สร้าง ChatGPT แต่ฝึก Transformer ระดับตัวอักษร (character-level) บนชุดข้อมูล tiny Shakespeare ไฟล์ประมาณ 1 MB หรือราว 1 ล้านตัวอักษร ซึ่งมีตัวอักษรไม่ซ้ำ 65 ตัว ข้อความ 90% แรกใช้ฝึก อีก 10% เก็บไว้วัด

ขั้นที่ 1 ข้อมูล: แต่ละก้อนยาว block_size + 1 ตัว ซ่อนตัวอย่างไว้ block_size ข้อ (บริบทยาว 1 ถึง 8) และวางหลายก้อนซ้อนเป็น batch ขนาด 4×8 ได้ 32 ตัวอย่างที่ไม่คุยกัน โมเดลแรกคือ bigram: ตารางขนาด 65×65 ที่อ่าน "คะแนนตัวถัดไป" จากตัวอักษรตัวเดียว ก่อนฝึก loss ควรประมาณ 4.17 (= −ln(1/65)) แต่ได้ 4.87 พอฝึกด้วย AdamW 10,000 รอบ loss ลงไปราว 2.5

ขั้นที่ 2 ทริกคณิต: การเฉลี่ยตัวก่อนหน้าทำได้ด้วยการคูณเมทริกซ์สามเหลี่ยมล่าง (torch.tril) ที่แต่ละแถวรวมเป็น 1 และเขียนแบบ softmax ได้: ใส่ −∞ ในช่องอนาคตแล้ว softmax จะได้เมทริกซ์เดิม ช่องที่ยังเป็น 0 คือ "ความสนใจ" (affinity) ซึ่ง self-attention จะคำนวณจากข้อมูลจริง

ขั้นที่ 3 self-attention: ทุกตำแหน่งปล่อย query (ฉันหาอะไร) และ key (ฉันมีอะไร) ค่า wei = q·kᵀ ผ่าน mask และ softmax แล้วคูณกับ value เพื่อรวมข้อมูล เปเปอร์หารด้วย √d_k เพื่อให้ความแปรปรวนไม่โตตามขนาดหัว ไม่อย่างนั้น softmax จะแหลมจนแทบเป็น one-hot

ขั้นที่ 4 ประกอบเป็น Transformer: val loss ลดตามลำดับดังนี้

  • หัวเดียว: 2.4
  • 4 หัวขนาด 8: 2.28
  • เพิ่ม feed-forward: 2.24
  • เพิ่ม residual + projection + ชั้นในกว้าง ×4: 2.08
  • LayerNorm แบบ pre-norm: 2.06
  • ขยายเป็น batch 64, block 256, n_embd 384, 6 หัว, 6 ชั้น, dropout 0.2: 1.48 ใช้เวลาประมาณ 15 นาทีบน A100

สิ่งที่ต้องระวัง (จากการตรวจ): ผู้สอนแก้ตัวเองในคำอธิบายคลิปสองจุด: ที่ 57:00 ต้องเป็น "อนาคตคุยกับอดีตไม่ได้" และที่ 1:20:05 ต้องหารด้วย head_size ไม่ใช่ C แต่โค้ดบนจอยังหารด้วย C อยู่ การตรวจข้อเท็จจริง 20 ข้อได้ผล ยืนยัน 18 · ยืนยันบางส่วน 1 · ขัดแย้ง 1 ข้อที่ขัดแย้งคือ GPT-2 ออกปี 2019 ไม่ใช่ 2017 ข้อที่ยืนยันบางส่วนคือ tiny Shakespeare เป็นเพียงส่วนหนึ่งของบทละคร ไม่ใช่ผลงานทั้งหมด

เอาไปใช้ (ความเห็นผู้จัดทำ): โค้ดชุดนี้เหมาะเป็นแบบฝึกสำหรับบทเรียน "ข้อความ → เลข → เวกเตอร์ → attention" ใน ZVect เพราะทุกขั้นมีตัวเลขบนจอให้ตรวจซ้ำได้ ส่วนตามคำผู้สอน GPT-3 ใช้สถาปัตยกรรมเกือบเหมือนกัน แต่ใหญ่กว่าระหว่าง 10,000 ถึง 1 ล้านเท่าแล้วแต่วิธีนับ และ ChatGPT ยังต้องผ่านขั้น fine-tuning อีกราวสามขั้น (SFT, reward model, PPO)

ผังภาพรวม

ในภาพนี้ (ตามลูกศร: แถวบนจากซ้ายไปขวา แถวกลางย้อนจากขวาไปซ้าย แล้วลงแถวล่าง):

  1. ข้อความ → encode — แปลงตัวอักษรแต่ละตัวเป็นเลขประจำตัว 0 ถึง 64 (หัวข้อ 3)
  2. get_batch — สุ่มหยิบก้อนยาว T ตัวมา B ก้อนพร้อมกัน (หัวข้อ 4)
  3. embedding — แต่ละเลขได้เวกเตอร์ของตัวอักษร บวกเวกเตอร์ของตำแหน่ง (หัวข้อ 11)
  4. Block × n_layer (สีเน้น) — ช่วง "คุยกัน" ด้วย attention แล้ว "คิดเอง" ด้วย feed-forward ซ้ำหลายชั้น พร้อม residual และ LayerNorm (หัวข้อ 12–20)
  5. ln_f + lm_head → softmax → สุ่ม — แปลงเป็นคะแนนของตัวอักษรทั้ง 65 ตัว ทำเป็นความน่าจะเป็น แล้วสุ่มตัวถัดไป (หัวข้อ 5)

1. ChatGPT, Transformer และแผนของคลิป (~0:00–7:52)

หัวข้อนี้จะพาดูอะไร: ChatGPT ทำงานแบบไหน ชิ้นส่วนข้างในมาจากไหน และทำไมคลิปนี้จึงเลือกสร้างของที่เล็กกว่ามาก

ใจความ: ผู้สอนให้ ChatGPT แต่งกลอนไฮกุจากคำสั่งเดียวกันสองครั้ง แล้วได้กลอนไม่เหมือนกัน แปลว่าระบบนี้ "สุ่มตามความน่าจะเป็น" (probabilistic) สิ่งที่มันทำจริง ๆ คือเติมลำดับข้อความต่อจากที่เราให้ไว้ ระบบที่ทำแบบนี้เรียกว่า โมเดลภาษา (language model)

ผู้สอนเล่าว่ามีเว็บไซต์รวมตัวอย่างการใช้ ChatGPT ที่หลายอันตลก เช่น ให้อธิบาย HTML เหมือนพูดกับสุนัข เขียน release notes ของ chess 2 หรือเขียนเรื่อง Elon Musk ซื้อ Twitter (~1:03) ตัวอย่างที่เขาเปิดให้ดูคือคำสั่งให้เขียนข่าวด่วนเรื่องใบไม้ร่วงจากต้นไม้ ได้ข่าวว่าใบไม้ที่เคยติดกิ่งหลุดลงสู่พื้น ซึ่งเขาแซวว่า "ดราม่ามาก" (~1:20–1:33)

โครงข่ายที่ทำงานหนักข้างในชื่อ Transformer มาจากเปเปอร์ "Attention Is All You Need" ปี 2017 ซึ่งเขียนเพื่องานแปลภาษา ผู้สอนคิดว่าผู้เขียนคงไม่ได้คาดเต็มที่ว่ามันจะครองวงการ AI ในราว 5 ปีถัดมา โดยถูกคัดลอกไปใช้แทบไม่เปลี่ยน GPT ย่อมาจาก Generatively Pretrained Transformer

  • สิ่งที่คลิปจะไม่ทำ: ทำซ้ำ ChatGPT ซึ่งฝึกจากข้อมูลอินเทอร์เน็ตก้อนใหญ่และผ่านทั้งขั้น pre-training และ fine-tuning
  • สิ่งที่คลิปจะทำ: ฝึก Transformer ระดับตัวอักษรบน tiny Shakespeare (ไฟล์เดียว ประมาณ 1 MB) ให้เดาตัวอักษรถัดไป แล้วสร้าง "Shakespeare ไม่รู้จบ" ทีละตัวอักษร ตัวอย่างผลที่ผู้สอนเปิดให้ดูล่วงหน้า เช่น "verily my Lord, the sites have left the again…" (~5:09) เป็นภาษาคล้าย Shakespeare แต่ไม่มีความหมาย (~4:55 ผู้สอนขอโทษว่าการแสดงผลยังมีจุดติดขัดที่เขาแก้ไม่ได้) ส่วน ChatGPT สร้างทีละ token ซึ่งเป็นชิ้นคำย่อย (subword) ไม่ใช่ทั้งคำ
  • โค้ดเต็มที่ทำไว้แล้ว: repo ชื่อ nanoGPT มีสองไฟล์ ไฟล์ละ 300 บรรทัด (นิยามโมเดล / ฝึกโมเดล) ฝึกบน OpenWebText แล้วได้ผลเท่า GPT-2 ตัวเล็กสุด 124 ล้านพารามิเตอร์ แต่คลิปนี้จะเขียนใหม่จากไฟล์เปล่า
  • พื้นฐานที่ควรมี: Python, แคลคูลัสและสถิติเบื้องต้น และควรดูชุด makemore ของผู้สอนมาก่อน

  2. กล่องขวา — ChatGPT: เดาทีละชิ้นคำ ข้อมูลใหญ่มาก ฝึกสองช่วง
  3. ลูกศรกลาง — ทั้งสองใช้ Transformer เป็นแกน ต่างกันที่ขนาดและขั้นการฝึก (รายละเอียดในหัวข้อ 23)

2. อ่านและสำรวจข้อมูล (~7:52–9:28)

หัวข้อนี้จะพาดูอะไร: ข้อมูลที่ใช้ฝึกหน้าตาเป็นอย่างไร และ "คำศัพท์" (vocabulary) ของโมเดลระดับตัวอักษรมีกี่ตัว

ใจความ: ผู้สอนเปิด Google Colab (notebook ที่แชร์ไว้ในคำอธิบายคลิป) ดาวน์โหลด tiny Shakespeare ไฟล์ประมาณ 1 MB อ่านเป็นข้อความยาวประมาณ 1 ล้านตัวอักษร แล้วพิมพ์ 1,000 ตัวแรกดู

จากนั้นหา ตัวอักษรไม่ซ้ำทั้งหมด: set เก็บแต่ละตัวครั้งเดียว list ทำให้มีลำดับ และ sorted เรียงลำดับ จำนวนที่ได้คือ vocab_size หรือจำนวนสิ่งที่โมเดล "เห็นหรือพูดออกมาได้" ในชุดนี้ได้ 65 ตัว ได้แก่ช่องว่าง เครื่องหมายพิเศษ ตัวพิมพ์ใหญ่ และตัวพิมพ์เล็ก

3. Tokenization และการแบ่ง train / val (~9:28–14:27)

หัวข้อนี้จะพาดูอะไร: วิธีเปลี่ยนข้อความเป็นเลข (tokenize) แบบง่ายที่สุด เทียบกับแบบที่ใช้จริงใน GPT แล้วแบ่งข้อมูลเป็นส่วนฝึกและส่วนวัด

ใจความ: tokenize คือการแปลงข้อความดิบเป็นลำดับเลขจำนวนเต็มตาม "สมุดรหัส" (vocabulary) ในคลิปนี้หนึ่งตัวอักษรคือหนึ่งเลข: สร้างตารางจากตัวอักษรเป็นเลข (stoi) และจากเลขกลับเป็นตัวอักษร (itos) ฟังก์ชัน encode แปลงข้อความเป็นรายการเลข ส่วน decode แปลงกลับเป็นข้อความเดิมเป๊ะ

  • ระบบที่ใช้จริง: Google ใช้ SentencePiece ซึ่งตัดเป็น "ชิ้นคำย่อย" (subword) ไม่ใช่ทั้งคำและไม่ใช่ตัวอักษรเดี่ยว ส่วน OpenAI มีไลบรารี tiktoken ที่ใช้ byte pair encoding (BPE) และ GPT ใช้แบบนี้
  • การได้อย่างเสียอย่าง: สมุดรหัสเล็กทำให้ลำดับเลขยาว สมุดรหัสใหญ่ทำให้ลำดับสั้น ผู้สอนบอกว่าในทางปฏิบัติมักใช้แบบชิ้นคำย่อย แต่คลิปนี้เลือกระดับตัวอักษรเพราะง่ายที่สุด
  • แปลงทั้งไฟล์: ทั้งไฟล์ถูก encode แล้วห่อเป็น torch.tensor ชื่อ data ผู้สอนคาดว่า 0 น่าจะเป็นตัวขึ้นบรรทัดใหม่ และ 1 น่าจะเป็นช่องว่าง โดยบอกว่า "ไม่แน่ใจ 100%"
  • แบ่งข้อมูล: 90% แรกใช้ฝึก (train) อีก 10% ท้ายไฟล์ซ่อนไว้วัด (validation) เพื่อดูว่าโมเดลจำข้อความเป๊ะ ๆ (overfitting) มากแค่ไหน เพราะต้องการข้อความที่ "เหมือน Shakespeare" ไม่ใช่การท่องจำ
ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (จากจอ ~10:26 และ ~12:01)

ข้อความ "hii there" ที่ผู้สอนใช้ทดสอบทั้งสองระบบ ระบบตัวอักษรได้ 9 เลข ส่วน tiktoken ของ GPT-2 ได้ 3 เลข

# create a mapping from characters to integers
stoi = { ch:i for i,ch in enumerate(chars) }
itos = { i:ch for i,ch in enumerate(chars) }
encode = lambda s: [stoi[c] for c in s] # encoder: take a string, output a list of integers
decode = lambda l: ''.join([itos[i] for i in l]) # decoder: take a list of integers, output a string

print(encode("hii there"))
print(decode(encode("hii there")))

ผลบนจอ: [46, 47, 47, 1, 58, 46, 43, 56, 43] และ hii there

>>> import tiktoken
>>> enc = tiktoken.get_encoding('gpt2')
>>> enc.n_vocab
50257
>>> enc.encode("hii there")
[71, 4178, 612]
>>> enc.decode([71, 4178, 612])
'hii there'

ในภาพนี้:

  1. ซ้าย (แถวแรกเป็นสีเน้น) — tokenizer ของคลิป: 1 ตัวอักษร = 1 เลข "hii there" จึงได้ 9 เลข (ช่องว่างคือเลข 1)
  2. ขวา — tokenizer ของ GPT-2: สมุดรหัส 50257 ตัว ข้อความเดียวกันเหลือ 3 เลข
  3. ลูกศร — การได้อย่างเสียอย่างที่ผู้สอนเน้น: ขยายสมุดรหัสแลกกับลำดับที่สั้นลง
# let's now encode the entire text dataset and store it into a torch.Tensor
import torch # we use PyTorch: https://pytorch.org
data = torch.tensor(encode(text), dtype=torch.long)
print(data.shape, data.dtype)
print(data[:1000]) # the 1000 characters we looked at earier will to the GPT look like this
# Let's now split up the data into train and validation sets
n = int(0.9*len(data)) # first 90% will be train, rest val
train_data = data[:n]
val_data = data[n:]
เสริมจากผู้จัดทำ: เรื่องตัวเลขบนจอ

คำว่า "earier" ในคอมเมนต์ของโค้ดบนจอสะกดผิดอยู่แล้วในต้นฉบับ (ผู้จัดทำคงไว้ตามจอ) ส่วนผู้สอนพูดว่า tiktoken มี "50,000 token" ขณะที่จอพิมพ์ 50257 คือ 50,257 ตัว (ตรวจแล้วตรงกับเอกสารของ GPT-2) ผู้สอนชี้ด้วยว่าเลขของ tiktoken ไม่ได้อยู่ในช่วง 0–64 แต่อยู่ในช่วง 0 ถึง 50,256 (~11:54–12:01)

เอาไปใช้ทำอะไร: ตั้งแต่ตรงนี้ไป ข้อความทั้งไฟล์กลายเป็นลำดับเลขยาวหนึ่งเส้น และเป็นจุดเชื่อมกับบทที่ 3.1 ของ ZVect (character tokenizer)

4. Data loader: ตัดข้อมูลเป็นก้อนและวางเป็น batch (~14:27–22:11)

หัวข้อนี้จะพาดูอะไร: ทำไมไม่ป้อนข้อความทั้งไฟล์ในครั้งเดียว และก้อนข้อมูลหนึ่งก้อนซ่อนตัวอย่างฝึกไว้กี่ข้อ

ใจความ: การป้อนข้อความทั้งหมดในครั้งเดียวแพงเกินไป จึงสุ่มหยิบ ก้อน (chunk) สั้น ๆ มาฝึกทีละชุด

ความยาวสูงสุดของก้อนเรียกว่า block_size (บางที่เรียก context length) เริ่มที่ 8 แล้วหยิบมา 9 ตัว (block_size + 1) เพราะ 9 ตัวที่เรียงกันซ่อนตัวอย่างไว้ 8 ข้อ: เห็น 1 ตัวเดาตัวที่ 2, เห็น 2 ตัวเดาตัวที่ 3, … จนเห็น 8 ตัวเดาตัวที่ 9

  • x และ y: x คือ block_size ตัวแรก y คือชุดเดียวกันที่เลื่อนไป 1 ตัว y จึงเป็น "คำตอบ" ของทุกตำแหน่งใน x
  • ทำไมฝึกทุกความยาว: ไม่ได้ทำเพื่อประหยัดอย่างเดียว แต่ทำให้ Transformer คุ้นกับบริบทตั้งแต่ 1 ตัวจนถึง block_size ตอนสร้างข้อความจึงเริ่มจากตัวอักษรเดียวได้ และถ้ายาวเกิน block_size ต้องตัดทิ้ง เพราะโมเดลไม่เคยรับเกินนั้น
  • มิติ batch: วางหลายก้อนซ้อนกันเป็นเทนเซอร์เดียวเพื่อให้ GPU ทำงานขนานกันเต็มที่ ก้อนเหล่านี้ประมวลผลแยกกันโดยสิ้นเชิง "ไม่คุยกัน"

import torch
import torch.nn as nn
from torch.nn import functional as F
torch.manual_seed(1337)

class BigramLanguageModel(nn.Module):

    def __init__(self, vocab_size):
        super().__init__()
        # each token directly reads off the logits for the next token from a lookup table
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):

        # idx and targets are both (B,T) tensor of integers
        logits = self.token_embedding_table(idx) # (B,T,C)

        B, T, C = logits.shape
        logits = logits.view(B*T, C)
        targets = targets.view(B*T)
        loss = F.cross_entropy(logits, targets)

        return logits, loss

    def generate(self, idx, max_new_tokens):
        # idx is (B, T) array of indices in the current context
        for _ in range(max_new_tokens):
            # get the predictions
            logits, loss = self(idx)
            # focus only on the last time step
            logits = logits[:, -1, :] # becomes (B, C)
            # apply softmax to get probabilities
            probs = F.softmax(logits, dim=-1) # (B, C)
            # sample from the distribution
            idx_next = torch.multinomial(probs, num_samples=1) # (B, 1)
            # append sampled index to the running sequence
            idx = torch.cat((idx, idx_next), dim=1) # (B, T+1)
        return idx

ใจความ: ผู้สอนเรียกนี่ว่า "ทริกทางคณิตศาสตร์" ที่อยู่หัวใจของ self-attention แบบมีประสิทธิภาพ คูณเมทริกซ์ a (3×3) กับ b (3×2) ได้ c (3×2) แต่ละช่องของ c คือแถวของ a คูณกับคอลัมน์ของ b แบบ dot product

  • a เป็นเลข 1 ทั้งหมด: ทุกช่องของ c คือผลรวมของคอลัมน์ของ b เช่น 2 + 6 + 6 = 14 และ 7 + 4 + 5 = 16
  • a เป็นสามเหลี่ยมล่าง (torch.tril): แถวแรก [1, 0, 0] ดึงแถวแรกของ b ออกมาตรง ๆ (2, 7) แถวสอง [1, 1, 0] รวมสองแถวแรก (8, 11) แถวสาม [1, 1, 1] รวมทั้งหมด (14, 16)
  • หารแต่ละแถวของ a ด้วยผลรวมของแถว: แถวรวมเป็น 1 ผลจึงกลายเป็นค่าเฉลี่ยสะสม เช่นแถวสองได้ค่าเฉลี่ยของ 2 กับ 6 คือ 4 และของ 7 กับ 4 คือ 5.5

ใจความ: ผู้สอนแก้สคริปต์ 3 จุด:

  • ไม่ส่ง vocab_size เข้าตัวสร้าง เพราะเป็นตัวแปรส่วนกลางอยู่แล้ว
  • ชั้นกลาง n_embd: ตาราง embedding ไม่ให้ logits ตรง ๆ อีกต่อไป แต่ให้ "token embedding" ยาว n_embd = 32 (ค่าที่ GitHub Copilot เสนอ ผู้สอนบอกว่าเป็นเลขที่ดี) แล้วใช้ชั้นเชิงเส้น lm_head (language modeling head) แปลงจาก 32 เป็น 65 คะแนน ผู้สอนเตือนว่า C ของสองที่นี้ไม่เท่ากัน: ตัวหนึ่งคือ n_embd อีกตัวคือ vocab_size
  • position embedding: ตารางที่สองขนาด block_size × n_embd ให้แต่ละตำแหน่ง 0 ถึง block_size − 1 มีเวกเตอร์ของตัวเอง แล้ว x = token embedding + position embedding

การบวก (B, T, C) กับ (T, C) ใช้ broadcasting: PyTorch เติมมิติ batch ให้ตัวหลังแล้วบวกทุก batch ตอนนี้ตำแหน่งยังไม่มีประโยชน์ เพราะ bigram ดูแค่ตัวเดียว "อยู่ตำแหน่งไหนก็เหมือนกัน" แต่จะสำคัญเมื่อมี self-attention

# super simple bigram model
class BigramLanguageModel(nn.Module):

    def __init__(self):
        super().__init__()
        # each token directly reads off the logits for the next token from a lookup table
        self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
        self.position_embedding_table = nn.Embedding(block_size, n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape

        # idx and targets are both (B,T) tensor of integers
        tok_emb = self.token_embedding_table(idx) # (B,T,C)
        pos_emb = self.position_embedding_table(torch.arange(T, device=device)) # (T,C)
        x = tok_emb + pos_emb # (B,T,C)
        logits = self.lm_head(x) # (B,T,vocab_size)

        if targets is None:
            loss = None
        else:
            B, T, C = logits.shape
            logits = logits.view(B*T, C)
            targets = targets.view(B*T)
            loss = F.cross_entropy(logits, targets)

12. Version 4: self-attention หัวใจของคลิป (~1:02:00–1:11:38)

หัวข้อนี้จะพาดูอะไร: ส่วนที่ผู้สอนบอกว่าสำคัญที่สุดของคลิป: แต่ละตำแหน่งคำนวณน้ำหนักความสนใจจากข้อมูลจริงอย่างไร

ใจความ: น้ำหนักในหัวข้อ 10 เท่ากันทุกช่อง แต่ตัวอักษรแต่ละตัวสนใจตัวอื่นไม่เท่ากัน ผู้สอนยกตัวอย่างว่าถ้าฉันเป็นสระ ฉันอาจอยากรู้ว่าพยัญชนะก่อนหน้าคืออะไร self-attention แก้ปัญหานี้: ทุกตำแหน่งปล่อยเวกเตอร์สองตัว

  • query — คร่าว ๆ คือ "ฉันกำลังหาอะไร"
  • key — คร่าว ๆ คือ "ฉันมีอะไร"

ความสนใจระหว่างสองตำแหน่งคือ dot product ของ query ของตำแหน่งหนึ่งกับ key ของอีกตำแหน่ง ถ้าสองเวกเตอร์ไปทางเดียวกันค่าจะสูง และตำแหน่งนั้นจะได้เรียนรู้จากอีกตำแหน่งมาก ทั้งหมดนี้ทำใน head หนึ่งหัว ขนาด head_size = 16

  • ขั้น 1: key และ query เป็นชั้นเชิงเส้นไม่มี bias ทุกตำแหน่งสร้าง k, q ขนาด (B, T, 16) พร้อมกันโดยยังไม่คุยกัน
  • ขั้น 2: wei = q @ k.transpose(-2, -1) สลับสองมิติท้ายของ k ได้ (B, T, 16) @ (B, 16, T) = (B, T, T) ตอนนี้แต่ละ batch มีน้ำหนักของตัวเอง ไม่ใช่ค่าคงที่
  • ขั้น 3: ค่าดิบอยู่ราว −2 ถึง 2 ผ่าน mask สามเหลี่ยมแล้ว softmax ได้การกระจายที่รวมเป็น 1 ("ไม่อยากรวม −0.11 ของตำแหน่งนั้น มันไร้สาระ")
  • ขั้น 4: ไม่ได้รวม x ตรง ๆ แต่สร้าง value อีกชุด แล้วส่งออก wei @ v ขนาด 16 ช่อง ผู้สอนเปรียบ x ว่าเป็น "ข้อมูลส่วนตัว" ของตำแหน่งนั้น ส่วน v คือ "ถ้าเธอสนใจฉัน นี่คือสิ่งที่ฉันจะบอก"
ตัวอย่างที่ใช้ตลอดหัวข้อนี้ (จากจอ ~1:10:50)

แถวที่ 8 ของ wei[0] (ตำแหน่งสุดท้ายของลำดับแรก): น้ำหนักไม่เท่ากันแล้ว เช่นให้ตำแหน่งที่ 7 = 0.2423 ตำแหน่งที่ 8 (ตัวเอง) = 0.2391 และตำแหน่งที่ 4 = 0.2297 แต่ให้ตำแหน่งที่ 1 เพียง 0.0210 ผู้สอนเล่าว่าตำแหน่งที่ 8 รู้ว่าตัวเองเป็นอะไรและอยู่ตรงไหน จึงสร้าง query ประมาณว่า "ฉันเป็นสระที่ตำแหน่ง 8 กำลังหาพยัญชนะในตำแหน่งไม่เกิน 4"

14. Scaled attention: หารด้วย √head_size (~1:16:56–1:19:11)

ใจความ: เมื่อเทียบกับสูตรในเปเปอร์ สิ่งเดียวที่ยังขาดคือการหารด้วย √d_k โดย d_k คือ head_size เปเปอร์เรียกว่า "scaled attention" ผู้สอนอธิบายว่า

  • ปัญหาความแปรปรวน: ถ้า q และ k เป็นค่าสุ่มที่มีค่าเฉลี่ย 0 ความแปรปรวน 1 ผลคูณ q·k จะมีความแปรปรวน "ในระดับของ" head_size ซึ่งในกรณีนี้คือ 16 แต่ถ้าคูณด้วย 1/√head_size ความแปรปรวนจะกลับเป็นประมาณ 1
  • ทำไมสำคัญ: wei เข้า softmax ต่อ และโดยเฉพาะตอนเริ่มฝึก wei ควร "กระจาย" ถ้ามีค่าบวกหรือลบมาก ๆ softmax จะลู่เข้าหา one-hot (แหลมไปที่ค่าสูงสุดตัวเดียว) แต่ละจุดจะรับข้อมูลจากจุดเดียว ซึ่งไม่ใช่สิ่งที่ต้องการตอนเริ่มต้น

class Head(nn.Module):
    """ one head of self-attention """

    def __init__(self, head_size):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B,T,C = x.shape
        k = self.key(x)   # (B,T,C)
        q = self.query(x) # (B,T,C)
        # compute attention scores ("affinities")
        wei = q @ k.transpose(-2,-1) * C**-0.5 # (B, T, C) @ (B, C, T) -> (B, T, T)
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float('-inf')) # (B, T, T)
        wei = F.softmax(wei, dim=-1) # (B, T, T)
        # perform the weighted aggregation of the values
        v = self.value(x) # (B,T,C)
        out = wei @ v # (B, T, T) @ (B, T, C) -> (B, T, C)
        return out

class BigramLanguageModel(nn.Module):

    def __init__(self):
        super().__init__()
        # each token directly reads off the logits for the next token from a lookup table
        self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
        self.position_embedding_table = nn.Embedding(block_size, n_embd)
        self.sa_head = Head(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape

        # idx and targets are both (B,T) tensor of integers
        tok_emb = self.token_embedding_table(idx) # (B,T,C)
        pos_emb = self.position_embedding_table(torch.arange(T, device=device)) # (T,C)
        x = tok_emb + pos_emb # (B,T,C)
        x = self.sa_head(x) # apply one head of self-attention. (B,T,C)
        logits = self.lm_head(x) # (B,T,vocab_size)

        if targets is None:
            loss = None
        else:
            B, T, C = logits.shape
            logits = logits.view(B*T, C)
            targets = targets.view(B*T)
            loss = F.cross_entropy(logits, targets)

        return logits, loss

    def generate(self, idx, max_new_tokens):
        # idx is (B, T) array of indices in the current context
        for _ in range(max_new_tokens):
            # crop idx to the last block_size tokens
            idx_cond = idx[:, -block_size:]
            # get the predictions
            logits, loss = self(idx_cond)
            # focus only on the last time step
            logits = logits[:, -1, :] # becomes (B, C)
            # apply softmax to get probabilities
            probs = F.softmax(logits, dim=-1) # (B, C)
            # sample from the distribution
            idx_next = torch.multinomial(probs, num_samples=1) # (B, 1)
            # append sampled index to the running sequence
            idx = torch.cat((idx, idx_next), dim=1) # (B, T+1)
        return idx

class MultiHeadAttention(nn.Module):
    """ multiple heads of self-attention in parallel """

    def __init__(self, num_heads, head_size):
        super().__init__()
        self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])

    def forward(self, x):
        return torch.cat([h(x) for h in self.heads], dim=-1)

class FeedFoward(nn.Module):
    """ a simple linear layer followed by a non-linearity """

    def __init__(self, n_embd):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd),
            nn.ReLU(),
            nn.Linear(4 * n_embd, n_embd),
        )

    def forward(self, x):
        return self.net(x)

class Block(nn.Module):
    """ Transformer block: communication followed by computation """

    def __init__(self, n_embd, n_head):
        # n_embd: embedding dimension, n_head: the number of heads we'd like
        super().__init__()
        head_size = n_embd // n_head
        self.sa = MultiHeadAttention(n_head, head_size)
        self.ffwd = FeedFoward(n_embd)

    def forward(self, x):
        x = x + self.sa(x)
        x = x + self.ffwd(x)

ใจความ: "Norm" ใน Add & Norm คือ LayerNorm ซึ่งคล้าย BatchNorm ที่ทำในชุด makemore มาก

BatchNorm ทำให้ "แต่ละคอลัมน์" (นิวรอนหนึ่งตัวข้าม batch) มีค่าเฉลี่ย 0 และส่วนเบี่ยงเบนมาตรฐาน 1 ผู้สอนคัดลอก BatchNorm1d มาแล้วเปลี่ยนมิติที่หาค่าเฉลี่ยและความแปรปรวนจาก 0 เป็น 1 ก็กลายเป็นการ normalize แต่ละแถว คือเวกเตอร์ของตัวอย่างหนึ่ง

  • สิ่งที่ตัดทิ้งได้: เพราะไม่ได้คำนวณข้ามตัวอย่างแล้ว จึงไม่ต้องมี running buffers ไม่ต้องมี momentum และไม่ต้องแยกโหมดฝึกกับโหมดทดสอบ แต่ยังเก็บ gamma และ beta ไว้
  • pre-norm: ผู้สอนบอกว่ารายละเอียดของ Transformer แทบไม่เปลี่ยนเลยในช่วง 5 ปี แต่จุดนี้เป็นส่วนที่เบี่ยงจากเปเปอร์เดิมเล็กน้อย (~1:35:25): ในเปเปอร์ Add & Norm อยู่หลังการแปลง แต่ปัจจุบัน "นิยมกว่าเล็กน้อย" ที่จะวาง LayerNorm ก่อนการแปลง และเขาเลือกทำแบบนี้: x = x + self.sa(self.ln1(x)) และ x = x + self.ffwd(self.ln2(x))
  • ขนาด: LayerNorm ขนาด n_embd = 32 ค่าเฉลี่ยและความแปรปรวนคิดจาก 32 ตัวเลขของแต่ละตำแหน่ง ส่วน batch และ time ทำหน้าที่เป็นมิติ batch ทั้งคู่ gamma และ beta ที่ฝึกได้ทำให้ผลอาจไม่เป็น unit Gaussian ก็ได้ตามที่การฝึกเลือก

class BatchNorm1d:

  def __init__(self, dim, eps=1e-5, momentum=0.1):
    self.eps = eps
    self.gamma = torch.ones(dim)
    self.beta = torch.zeros(dim)

  def __call__(self, x):
    # calculate the forward pass
    xmean = x.mean(1, keepdim=True) # batch mean
    xvar = x.var(1, keepdim=True) # batch variance
    xhat = (x - xmean) / torch.sqrt(xvar + self.eps) # normalize to unit variance
    self.out = self.gamma * xhat + self.beta
    return self.out

  def parameters(self):
    return [self.gamma, self.beta]

class Head(nn.Module):
    """ one head of self-attention """

    def __init__(self, head_size):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer('tril', torch.tril(torch.ones(block_size, block_size)))

        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        B,T,C = x.shape
        k = self.key(x)   # (B,T,C)
        q = self.query(x) # (B,T,C)
        # compute attention scores ("affinities")
        wei = q @ k.transpose(-2,-1) * C**-0.5 # (B, T, C) @ (B, C, T) -> (B, T, T)
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float('-inf')) # (B, T, T)
        wei = F.softmax(wei, dim=-1) # (B, T, T)
        wei = self.dropout(wei)
        # perform the weighted aggregation of the values
        v = self.value(x) # (B,T,C)
        out = wei @ v # (B, T, T) @ (B, T, C) -> (B, T, C)
        return out

    def __init__(self, config):
        super().__init__()
        assert config.n_embd % config.n_head == 0
        # key, query, value projections for all heads, but in a batch
        self.c_attn = nn.Linear(config.n_embd, 3 * config.n_embd)
        # output projection
        self.c_proj = nn.Linear(config.n_embd, config.n_embd)
        # regularization
        self.attn_dropout = nn.Dropout(config.dropout)
        self.resid_dropout = nn.Dropout(config.dropout)
        # causal mask to ensure that attention is only applied to the left in the input sequence
        self.register_buffer("bias", torch.tril(torch.ones(config.block_size, config.block_size))
                                    .view(1, 1, config.block_size, config.block_size))
        self.n_head = config.n_head
        self.n_embd = config.n_embd

    def forward(self, x):
        B, T, C = x.size() # batch size, sequence length, embedding dimensionality (n_embd)

        # calculate query, key, values for all heads in batch and move head forward to be the batch dim
        q, k ,v  = self.c_attn(x).split(self.n_embd, dim=2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)

        # causal self-attention; Self-attend: (B, nh, T, hs) x (B, nh, hs, T) -> (B, nh, T, T)
        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
        att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
        att = F.softmax(att, dim=-1)
        att = self.attn_dropout(att)
        y = att @ v # (B, nh, T, T) x (B, nh, T, hs) -> (B, nh, T, hs)
        y = y.transpose(1, 2).contiguous().view(B, T, C) # re-assemble all head outputs side by side

        # output projection
        y = self.resid_dropout(self.c_proj(y))
        return y

  • pre-training: ฝึก Transformer แบบ decoder อย่างเดียวบนอินเทอร์เน็ตก้อนใหญ่ให้ "พูดต่อ" ซึ่งก็คือสิ่งที่คลิปทำในขนาดจิ๋ว โมเดลของเรามีประมาณ 10 ล้านพารามิเตอร์ ข้อมูลประมาณ 1 ล้านตัวอักษร ถ้าใช้คำศัพท์ของ OpenAI (ประมาณ 50,000 ชิ้นคำ) น่าจะเป็นราว 300,000 token ส่วน GPT-3 ตัวใหญ่สุดมี 175 พันล้านพารามิเตอร์ ฝึกบน 300 พันล้าน token หรือราวล้านเท่า และผู้สอนบอกว่าตามมาตรฐานตอนนั้นก็ขึ้นไปถึง 1 ล้านล้าน token ขึ้นไปแล้ว การฝึกระดับนี้ต้องใช้ GPU หลายพันตัว ผลของช่วงนี้คือ document completer: ถามคำถามไปอาจได้คำถามเพิ่ม หรือได้ข่าวที่แต่งต่อ จึงได้พฤติกรรมที่คาดเดาไม่ได้ (undefined behavior) ผู้สอนบอกว่ามัน "ยังไม่ถูกจัดแนว (unaligned) เลย" (~1:52:17 คำบรรยายอัตโนมัติเขียนเพี้ยนเป็น "unineed" ผู้จัดทำอ่านเป็น unaligned จากประโยคถัดไปที่พูดเรื่องการ align)
  • fine-tuning (การปรับให้เป็นผู้ช่วย): บล็อก ChatGPT ของ OpenAI อธิบาย "ราวสามขั้น" (ภาพและผังด้านล่าง) ข้อมูลของช่วงนี้จำนวนมากไม่เปิดเผย เป็นของภายใน OpenAI จึงทำซ้ำได้ยากกว่ามาก และ nanoGPT เน้นแค่ pre-training

บทสรุปของคลิป: เราฝึก Transformer แบบ decoder อย่างเดียวตามเปเปอร์ปี 2017 บน tiny Shakespeare ได้ผลที่สมเหตุสมผล โค้ดฝึกทั้งหมดประมาณ 200 บรรทัด ผู้สอนจะเผยแพร่พร้อมประวัติ git และ notebook ส่วน GPT-3 มีสถาปัตยกรรมแทบเหมือนกัน แต่ใหญ่กว่าราว 10,000 ถึง 1 ล้านเท่า "แล้วแต่วิธีนับ" ถ้าต้องการให้ทำงานเฉพาะ จัดแนวตามที่ต้องการ หรือตรวจ sentiment ต้องทำ fine-tuning ต่อ ไม่ว่าจะแบบ supervised ธรรมดาหรือแบบ reward model + PPO

ตาราง 2.1 ของเปเปอร์ GPT-3 ที่ผู้สอนเปิด (~1:51:10) คัดลอกครบ 8 แถว คำบรรยายใต้ตารางบอกว่า batch size นับเป็น token และทุกโมเดลฝึกรวม 300 พันล้าน token ผู้สอนชี้คอลัมน์ n_layers, d_model, n_heads, d_head และ batch size แล้วบอกว่าของเรา "คือ 65" ซึ่งน่าจะหมายถึง batch size 64 ในสคริปต์สุดท้าย (ผู้จัดทำ) และบอกว่า learning rate "ใกล้เคียงกัน"

เสริมจากผู้จัดทำ: อ่านตาราง GPT-3 ให้ตรง
  • แถว 13B เขียน d_model = 5140 แต่ 40 หัว × 128 = 5120 ตัวเลขนี้เป็นของเปเปอร์เอง ผู้จัดทำคงไว้ตามจอ
  • batch size ของ GPT-3 นับเป็น token (0.5M ถึง 3.2M) ส่วนของคลิปนับเป็นลำดับ: 64 × 256 = 16,384 token และ learning rate 3e-4 ของคลิปอยู่ในช่วงของรุ่นเล็ก "ใกล้เคียง" จึงจริงแบบหลวม ๆ
  • "1 ล้านล้าน token ขึ้นไป" เป็นมาตรฐานของต้นปี 2023 ต่อมา Llama 3 (เม.ย. 2024) ฝึกด้วย 15 ล้านล้าน token

ในภาพนี้:

  1. Step 1 (ซ้าย) — คนเขียนคำตอบตัวอย่างให้ prompt แล้วใช้ fine-tune โมเดลแบบ supervised (SFT) ผู้สอนบอกว่าข้อมูลแบบนี้น่าจะ "หลักพันตัวอย่าง" และโมเดลใหญ่มาก "ใช้ตัวอย่างอย่างคุ้มค่า"
  2. Step 2 (กลาง) — ให้โมเดลตอบหลายแบบ คนเรียงอันดับว่าแบบไหนดีกว่า แล้วใช้ฝึก reward model ที่ทำนายว่าคำตอบหนึ่ง "น่าพอใจแค่ไหน"
  3. Step 3 (ขวา) — ใช้ PPO (อัลกอริทึม reinforcement learning แบบ policy gradient) ปรับโมเดลให้คำตอบได้คะแนนสูงจาก reward model ลูกศรวนทางขวาคือทำซ้ำ คำว่า policy ในผังหมายถึงตัวโมเดลภาษาที่เลือกคำตอบและกำลังถูกปรับ ผู้สอนเรียกว่า "sampling policy" (~1:53:53) ส่วน "supervised policy" คือโมเดลที่ได้จาก Step 1 (ผู้จัดทำอธิบายคำนี้ คลิปไม่ได้นิยาม)
  4. ข้อความใต้ภาพบนหน้าเว็บ — ระบุว่า fine-tune จากโมเดลตระกูล GPT-3.5

ในภาพนี้:

  1. pre-training — ช่วงที่คลิปทำ ได้โมเดลที่แค่ "เติมเอกสาร"
  2. SFT → reward model — ขั้น 1 และ 2 ของผัง: สอนรูปแบบคำถามคำตอบ แล้วสร้างตัวให้คะแนน
  3. PPO (สีเน้น) — ขั้น 3: ปรับโมเดลตามคะแนน
  4. ลูกศร "ทำซ้ำ" — บล็อกของ OpenAI บอกว่าทำหลายรอบ

ขั้นตอนเดียวกันเป็นข้อ ๆ:

  1. pre-train Transformer แบบ decoder อย่างเดียวบนข้อมูลขนาดใหญ่ ได้ document completer
  2. เก็บเอกสารแบบ "คำถามด้านบน คำตอบด้านล่าง" แล้ว fine-tune แบบ supervised
  3. ให้โมเดลตอบหลายแบบ ให้คนเรียงอันดับ แล้วฝึก reward model
  4. ใช้ PPO ปรับโมเดลให้ได้คะแนนสูงจาก reward model และทำซ้ำได้หลายรอบ
ข้อที่ควรเข้าใจให้ตรง: ผู้จัดทำ ตรวจจากบล็อกของ OpenAI

ผู้สอนเล่าเรื่องนี้ต่อจาก GPT-3 แต่บล็อก ChatGPT (30 พ.ย. 2022) ระบุว่า ChatGPT fine-tune จากโมเดลตระกูล GPT-3.5 ไม่ใช่ GPT-3 ตัวในตาราง (OpenAI)

เอาไปใช้ทำอะไร: สิ่งที่สร้างในคลิปคือขั้นแรกของ LLM ทุกตัว: เดาตัวถัดไปจากบริบท ส่วนพฤติกรรม "ผู้ช่วย" มาจากขั้นที่เพิ่มทีหลัง (ZVect บทที่ 9 เรื่อง LLM)

Key Takeaways

1.โมเดลภาษาเดาตัวถัดไปจากบริบท: ข้อความ → เลข → เวกเตอร์ (ตัวอักษร + ตำแหน่ง) → Block × n → คะแนน → softmax → สุ่ม
2.attention คือการเฉลี่ยถ่วงน้ำหนักด้วยการคูณเมทริกซ์: น้ำหนักมาจาก q·k หารด้วย √head_size ปิดอนาคตด้วย −∞ แล้ว softmax แล้วรวม v
3.Transformer Block = สื่อสาร (multi-head attention) + คำนวณ (feed-forward) โดยมี residual และ LayerNorm (pre-norm) ทำให้ซ้อนลึกได้
4.val loss ลดจากราว 2.5 (bigram) เป็น 1.48 (6 ชั้น, 6 หัว, n_embd 384, block 256, dropout 0.2) ในเวลาประมาณ 15 นาทีบน A100
5.โค้ดบนจอหารด้วย √C ซึ่งผู้สอนแก้เองว่าต้องเป็น √head_size; GPT-2 ออกปี 2019 ไม่ใช่ 2017
6.ChatGPT = pre-training แบบนี้ในขนาดใหญ่กว่ามาก + fine-tuning ราวสามขั้น (SFT, reward model, PPO)
