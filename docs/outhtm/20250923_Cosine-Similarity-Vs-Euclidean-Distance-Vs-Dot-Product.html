1. ทำไมการเลือก metric สำคัญ และ similarity metric คืออะไร

~0:00–1:18

ยินดีต้อนรับกลับมาที่ช่องครับ วันนี้เราจะเจาะลึกการตัดสินใจที่สำคัญที่สุดเรื่องหนึ่งใน AI และ machine learning นั่นคือ การเลือก similarity metric ให้เหมาะกับงาน vector search ไม่ว่าคุณกำลังสร้าง recommendation system ทำ RAG ให้ LLM หรือทำ image search, metric ที่เลือกจะตัดสินได้เลยว่าผลลัพธ์ออกมาดีหรือพัง และปัญหาคือ developer ส่วนใหญ่แค่หยิบมาสักตัว โดยไม่เข้าใจ trade-off ของมัน

ในคลิปนี้เราจะดู metric พื้นฐานสามตัว คือ cosine similarity, Euclidean distance และ dot product จะเข้าใจว่าแต่ละตัวควรใช้เมื่อไร ดูการทำงานจริงผ่านตัวอย่างโค้ด และพอจบคลิป คุณจะรู้ชัดว่าควรเลือก metric ไหนสำหรับ use case ของคุณ

ก่อนลงรายละเอียด มาทำความเข้าใจก่อนว่าเรากำลังวัดอะไร ใน AI เราแทนทุกอย่างด้วย vector ทั้งคำ ประโยค รูปภาพ และความชอบของผู้ใช้ vector เหล่านี้อยู่ใน high-dimensional space (space ที่มีหลายมิติ) similarity metric บอกว่า vector สองตัวใกล้หรือคล้ายกันแค่ไหน

แต่ตรงนี้น่าสนใจ คำว่า "คล้าย" มีความหมายต่างกันได้ตาม use case ประเด็นสำคัญคือ metric แต่ละตัวจับคนละด้านของความคล้าย บางตัวดูทิศทาง (direction) บางตัวดูขนาด (magnitude) และบางตัวดูทั้งสองอย่าง

สไลด์ในช่วงนี้มีโค้ดตัวอย่าง word embedding สองคำ (ถอดจากภาพ):

โค้ดในสไลด์ (Python)
import numpy as np

# Word embeddings example
king = np.array([0.2, 0.8, -0.1, 0.4])
queen = np.array([0.1, 0.7, -0.2, 0.5])

print(f"King: {king}")
print(f"Queen: {queen}")
# How similar are they?
สไลด์ทิ้งคำถาม "How similar are they?" ไว้โดยไม่เฉลย ผู้จัดทำคำนวณให้: cosine = 0.976, dot product = 0.80, Euclidean distance = 0.20

2. Cosine similarity

~1:18–2:15

เริ่มจาก cosine similarity ซึ่งน่าจะเป็น metric ที่นิยมที่สุดในงาน NLP และ recommendation system

Cosine similarity วัดมุมระหว่าง vector สองตัว ค่าอยู่ระหว่าง −1 ถึง 1 โดย 1 แปลว่าทิศเดียวกันเป๊ะ, 0 แปลว่าตั้งฉาก และ −1 แปลว่าสวนทางกัน

ประเด็นสำคัญ: cosine similarity ไม่สนขนาดเลย vector สองตัวที่ชี้ทิศเดียวกันจะได้ similarity = 1 ไม่ว่าจะยาวแค่ไหน

ใช้ cosine similarity เมื่อทิศทางสำคัญกว่าขนาด เหมาะกับ

  • ความคล้ายของเอกสารด้วย TF vector (นับความถี่คำ)
  • การเปรียบเทียบ word embedding
  • การจับคู่ความชอบของผู้ใช้
  • ทุกกรณีที่ขนาดของ vector ไม่ได้บอกความสำคัญ

สังเกตว่าเอกสารสองชิ้นในตัวอย่างพูดเรื่องเดียวกัน แต่จำนวนคำต่างกัน cosine similarity บอกได้ถูกว่าทั้งสองชี้ทิศเดียวกันเป๊ะ

โค้ดในสไลด์ ฝั่งซ้าย (Python)
def cosine_similarity(a, b):
    dot_product = np.dot(a, b)
    norms = np.linalg.norm(a) * np.linalg.norm(b)
    return dot_product / norms

# Same direction, different magnitude
vec_a = np.array([1, 2, 3])
vec_b = np.array([2, 4, 6])
print(cosine_similarity(vec_a, vec_b))  # 1.0
โค้ดในสไลด์ ฝั่งขวา (Python)
# Document vectors (TF-IDF)
doc1 = np.array([2, 1, 0, 1]) # "AI machine learning"
doc2 = np.array([4, 2, 0, 2]) # "AI AI machine machine learning learning"

# Same topics, different word frequencies
print(f"Cosine similarity: {cosine_similarity(doc1, doc2):.3f}") # 1.000

การ์ดในสไลด์บอกว่าเหมาะกับ: Text Similarity (เทียบเอกสาร, word embedding), Search Ranking (ความเกี่ยวข้องระหว่าง query กับเอกสาร), Recommendations (จับคู่ความชอบผู้ใช้) และ NLP Tasks (semantic similarity)

ตรวจแล้ว
ตัวเลขในโค้ดทั้งสองชุดถูกต้อง: vec_a กับ vec_b ได้ 1.0 และ doc1 กับ doc2 ได้ 1.000 (คำนวณซ้ำแล้ว)

3. Euclidean distance

~2:15–3:08

Euclidean distance คือระยะเส้นตรงระหว่างสองจุดใน space ให้นึกถึงทฤษฎีบทพีทาโกรัสแบบหลายมิติ

metric กลุ่ม similarity ให้ค่ายิ่งสูงเมื่อยิ่งคล้าย แต่ distance metric ทำงานกลับกัน ระยะยิ่งน้อยแปลว่ายิ่งคล้าย

Euclidean distance คิดทั้งทิศทางและขนาด vector สองตัวอาจทำมุมใกล้กัน แต่อยู่ห่างกันมากได้ ถ้าขนาดต่างกันมาก

สังเกตตรงนี้: vec C อยู่ใกล้ vec A มากกว่า vec B ในแง่ Euclidean distance ทั้งที่ vec B ชี้ทิศเดียวกับ vec A เป๊ะ

ใช้ Euclidean distance เมื่อทั้งทิศทางและขนาดสำคัญ เช่น feature vector ของรูปภาพ, การเทียบข้อมูล sensor, พิกัดทางภูมิศาสตร์ และการวัดค่าจริงใด ๆ ที่ขนาด (scale) มีความหมาย

โค้ดในสไลด์ (Python)
def euclidean_distance(a, b):
    return np.linalg.norm(a - b)

# Customer data: [age, income, spending]
customer1 = np.array([25, 40, 60])
customer2 = np.array([27, 42, 65])
customer3 = np.array([50, 80, 30])

print(f"Distance 1-2: {euclidean_distance(customer1, customer2):.2f}")
print(f"Distance 1-3: {euclidean_distance(customer1, customer3):.2f}")
สไลด์ไม่ได้แสดงผลลัพธ์ ผู้จัดทำคำนวณให้: Distance 1-2 = 5.74, Distance 1-3 = 55.90 ลูกค้า 1 กับ 2 จึงคล้ายกันมากกว่า

ตัวอย่าง vec A, B, C ที่ผู้พูดอ้างถึงไม่ปรากฏบนสไลด์ที่จับได้ ผู้จัดทำจึงสร้างตัวอย่างที่ให้ผลแบบเดียวกันขึ้นมาใหม่ด้านล่าง ข้อมูลชุดเดียวกันแต่สาม metric ตอบไม่เหมือนกัน:

4. Dot product

~3:08–3:47

Dot product เป็น metric ที่คำนวณเร็วที่สุด และกำลังกลับมาได้รับความนิยมในงาน AI สมัยใหม่

dot product วัดความสัมพันธ์ทั้งด้านมุมและขนาด ต่างจาก cosine similarity ตรงที่ไม่ normalize ความยาวของ vector

เหตุผลที่ dot product ได้รับความนิยมมากขึ้นคือมันเร็วมาก ไม่มีรากที่สอง ไม่มีการหาร มีแค่คูณแล้วบวก ใน transformer architecture และ attention mechanism สมัยใหม่ dot product มีอยู่ทุกที่ ด้วยเหตุผลสามข้อ

  1. คำนวณได้มีประสิทธิภาพ
  2. ทำงานได้ดีกับ embedding ที่ normalize แล้ว
  3. รักษาลำดับ (ranking) เชิงเปรียบเทียบไว้ได้
โค้ดในสไลด์ (Python)
# Attention mechanism example
query = np.array([0.1, 0.8, 0.3])
key1 = np.array([0.2, 0.7, 0.4])
key2 = np.array([0.9, 0.1, 0.2])

attention1 = np.dot(query, key1)  # 0.69
attention2 = np.dot(query, key2)  # 0.15

print(f"Attention to key1: {attention1:.2f}")
print(f"Attention to key2: {attention2:.2f}")
ตัวเลขในสไลด์ผิด
คอมเมนต์ # 0.69 และ # 0.15 ไม่ตรงกับผลจริง คำนวณได้ attention1 = 0.1×0.2 + 0.8×0.7 + 0.3×0.4 = 0.70 และ attention2 = 0.1×0.9 + 0.8×0.1 + 0.3×0.2 = 0.23 ข้อสรุปว่า query สนใจ key1 มากกว่ายังถูกเหมือนเดิม

การ์ดในสไลด์: High Performance (งาน real-time), Transformers (attention), Normalized Data (vector ยาว 1), Rankings (สนใจลำดับเชิงเปรียบเทียบ) ช่วงค่าคือ −∞ ถึง ∞

5. ดูภาพเปรียบเทียบ (Visualization)

~3:47–4:09

มาสร้างความเข้าใจด้วยภาพ ผู้พูดทำ visualization แบบ interactive ที่แสดงว่าแต่ละ metric ทำงานอย่างไรกับ vector ชุดเดียวกัน

สังเกตว่า cosine similarity ขึ้นกับมุมอย่างเดียว, Euclidean distance คิดจากตำแหน่งใน space และ dot product รวมผลของทั้งมุมและขนาด

7. กับดักและแนวปฏิบัติ (Edge cases & best practices)

~4:52–5:21

ผู้พูดเล่า gotcha ที่เจอในระบบ production

Pro tip
ถ้า vector ทั้งหมด normalize ให้ยาว 1 แล้ว cosine similarity จะเท่ากับ dot product นี่คือเหตุผลที่ embedding model สมัยใหม่หลายตัว output vector ที่ normalize แล้ว
Curse of dimensionality
ใน space ที่มีมิติสูงมาก Euclidean distance เจอปัญหา curse of dimensionality: ทุกจุดจะอยู่ห่างกันพอ ๆ กัน ผู้พูดบอกว่า cosine similarity ทนทานกว่าในกรณีนี้ (ดูข้อสังเกตเพิ่มในส่วนที่ 9.3)
Common Pitfalls (โค้ดในสไลด์)

zero_vec = np.array([0, 0, 0])

# ✅ Safe implementation
def safe_cosine_similarity(a, b, epsilon=1e-8):
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a < epsilon or norm_b < epsilon:
        return 0.0
    return np.dot(a, b) / (norm_a * norm_b)
Pro Tips (โค้ดในสไลด์)
# 🚀 Vectorized operations
def batch_cosine_similarity(matrix_a, matrix_b):
    # Normalize rows
    norm_a = matrix_a / np.linalg.norm(matrix_a, axis=1, keepdims=True)
    norm_b = matrix_b / np.linalg.norm(matrix_b, axis=1, keepdims=True)

    # Batch dot product
    return np.sum(norm_a * norm_b, axis=1)

# Always vectorize for performance!

สิ่งที่ต้องระวัง (Watch Out For): vector ศูนย์ (หารด้วยศูนย์), vector ที่ขนาดเล็กมาก, curse of dimensionality และ outlier ใน Euclidean distance

แนวปฏิบัติ (Best Practices): normalize ข้อมูลเมื่อเหมาะสม, ใช้การคำนวณแบบ vectorized, คิดถึงต้นทุนของการเตรียมข้อมูล, ทดสอบกับข้อมูลจริงของคุณ และคอยเฝ้าดู edge case

คำว่า "This crashes!" ในสไลด์เกินจริงเล็กน้อย กับ NumPy การหาร 0 ด้วย 0.0 ไม่ทำให้โปรแกรมหยุด แต่ได้ nan พร้อม RuntimeWarning ซึ่งอันตรายกว่าเพราะไหลต่อไปเงียบ ๆ ส่วน batch_cosine_similarity ก็ยังเจอปัญหา vector ศูนย์ (แถวที่ norm = 0) แบบเดียวกัน

9.2 ทำไม normalize แล้วทั้งสามเรียงลำดับเหมือนกัน

ถ้า â และ b̂ ยาว 1 ทั้งคู่ จะได้ â·b̂ = cos θ และ ‖â − b̂‖² = ‖â‖² + ‖b̂‖² − 2â·b̂ = 2 − 2cos θ ดังนั้นยิ่ง cos มาก ระยะยิ่งน้อย ลำดับของผลค้นหาจึงเหมือนกันทั้งสามแบบ ทดสอบด้วยตัวเลขแล้ว: ‖â − b̂‖² = 2.063661 และ 2 − 2cos θ = 2.063661
