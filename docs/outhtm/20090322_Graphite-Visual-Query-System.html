บทสรุปย่อ

คลิปสาธิตของ Graphite ระบบที่ให้ผู้ใช้ วาดรูปแบบ (pattern) ที่อยากหาเป็นกราฟเล็ก ๆ ระบุ attribute ของแต่ละโหนด แล้วค้นหาส่วนของกราฟขนาดใหญ่ที่ตรงกับ pattern นั้น ทั้งแบบตรงเป๊ะ (exact) และแบบใกล้เคียง (approximate) จากนั้นแสดงผลที่พบในหน้าจอเดียวกัน ผู้พูดเปิดด้วยโจทย์สี่ข้อ (สร้างคิวรีง่าย ๆ, หาทั้ง match ตรงและใกล้เคียง, เร็ว, ดูผลให้เข้าใจ) แล้วสาธิตกับกราฟ DBLP ผู้เขียน–งานตีพิมพ์ที่มีผู้เขียนกว่า 350,000 คน ด้วยคิวรีรูปดาว (star) ที่มีผู้เขียนใน PODS ตรงกลาง ผลจับคู่แสดงเป็นแท็บ จัดเรียงให้ผลต้น ๆ น่าจะสำคัญต่อผู้ใช้มากกว่า (ตามคำพูดที่ว่า empirically) และเมื่อไม่มี match ตรง ระบบเสนอ match ใกล้เคียงที่ยอมให้มีเส้นทางอ้อมระหว่างโหนด คลิปยาว 3 นาทีเศษ เสียงพูดมีเฉพาะช่วงต้นและท้าย ช่วงกลางเป็นการวาดบนจอที่แทบไม่มีคำพูด

โหมดเนื้อหา: เรียบเรียงใหม่ด้วยคำของผู้จัดทำ ครบทุกประเด็น (license มาตรฐานของ YouTube) ต้นทางคือ caption อัตโนมัติ (ASR) ที่มีคำผิด จึงยึดข้อความบนจอเป็นหลักเมื่อขัดกัน

1. โจทย์: หา pattern ในกราฟ และอุปสรรคสี่ข้อ (~0:03–0:49)

คลิปเปิดด้วยสไลด์ชื่องาน "GRAPHITE: A Visual Query System for Large Graphs" ผู้เขียนคือ Duen Horng Chau, Christos Faloutsos, Hanghang Tong, Jason I. Hong (Carnegie Mellon University) และ Brian Gallagher, Tina Eliassi-Rad (Lawrence Livermore National Laboratory) (~0:06)

ผู้พูดเริ่มจากความต้องการทั่วไปว่า คนมักอยากหา pattern ในกราฟเพื่อเข้าใจพลวัตของกราฟนั้น ตัวอย่างที่ยกคือ social network ที่ occupation ของคนเป็น attribute แล้วอยากหา วงจรฟอกเงิน (money laundering ring) ที่ประกอบด้วยนักธุรกิจและนายธนาคารที่ประสานงานกัน ภาพบนจอเป็นกลุ่มคนจางจำนวนมากที่มีสี่คนซึ่งต่อกันเป็นรูปทรงหนึ่งเด่นขึ้นมา สีน้ำเงินกับส้มสลับกัน

จากนั้นผู้พูดไล่ อุปสรรคสี่ข้อ ข้อแรก ต้องมีวิธีสะดวก ๆ ในการระบุ pattern ที่เป็นคิวรี ข้อสอง ต้องหา match ที่เป็นไปได้ทั้งหมด และต้องการ match ใกล้เคียงด้วย เช่น ยอมให้มีอีกคนหนึ่งคั่นระหว่างนักธุรกิจกับนายธนาคาร เพราะเราอาจไม่รู้ว่าวงจรฟอกเงินจริงหน้าตาเป็นอย่างไร ข้อสาม ต้องการให้กระบวนการจับคู่กราฟเร็ว ข้อสี่ ต้องการแสดง match ทั้งหมดเพื่อให้เข้าใจและตีความได้ดีขึ้น บนจอช่วงนี้ปรากฏเฉพาะข้อความสองบรรทัดคือ "How to specify query?" กับ "How to get exact and close matches?" (ในเฟรมที่เก็บ ~0:40 ไม่เห็นข้อสามและสี่เป็นข้อความ)

2. Graphite คืออะไร (~0:49–1:09)

ผู้พูดแนะนำ Graphite ว่าออกแบบมาแก้อุปสรรคข้างต้น ระบบให้ผู้ใช้ สร้างคิวรีแบบมองเห็น (visually construct a query pattern) ค้นหาทั้ง match ตรงและใกล้เคียง และแสดงผลทั้งหมด ใน user interface เดียวกัน ฉากที่ประกอบคำพูดช่วงนี้คือหน้าจอ Graphite ที่มีผลลัพธ์อยู่แล้ว (ผู้พูดบอกว่าจะสาธิตวิธีใช้ต่อ จึงควรอ่านเป็นภาพรวมของหน้าต่าง) หน้าต่างแบ่งเป็นสองส่วนติดกัน: ด้านซ้ายมีป้ายจางว่า Query ด้านขวามีป้าย Match มี legend สีของ attribute มุมขวาบนของส่วน Query และแถบล่างสำหรับตั้งจำนวน match

3. ข้อมูลที่ใช้สาธิต: DBLP (~1:07–1:25)

ผู้พูดบอกว่าจะสาธิตผ่านตัวอย่าง โดยสมมติว่าทำงานกับ กราฟ DBLP author–publication ซึ่งมีผู้เขียนมากกว่า 350,000 คน และมีกรณี co-authorship 1.9 ล้านครั้ง ตัวเลขในคำอธิบายคลิประบุว่าเป็น 356K โหนดกับ 1.9M เส้น คำอธิบายคลิปยังกล่าวว่า Graphite ใช้อัลกอริทึม G-Ray ในการรันคิวรีกับกราฟที่ผู้ใช้เลือก ซึ่งให้ข้อดีคือเร็ว ขยายได้ และหาได้ทั้ง match ตรงและใกล้เคียง และใช้อัลกอริทึมเร็วประมาณ node proximity เพื่อให้ scale ตามขนาดฐานข้อมูลกราฟได้ ในส่วนนี้ G-Ray และการประมาณ node proximity มาจากคำอธิบายคลิปเท่านั้น ส่วนการหา match ทั้งแบบตรงและใกล้เคียง (ผู้พูดพูดที่ ~1:00) และการยอมให้มีเส้นทางอ้อมที่ยาวกว่า (~2:25) ผู้พูดพูดไว้ในเสียงด้วย

ข้อความจากคำอธิบายคลิปเท่านั้น

G-Ray และการประมาณ node proximity มาจากคำอธิบายคลิปเท่านั้น ผู้พูดไม่ได้พูดถึงในเสียงของคลิป ตัวเลข 356K โหนด / 1.9M เส้นก็มาจากคำอธิบายเช่นกัน

4. สร้างคิวรีรูปดาว (~1:23–2:10)

ผู้พูดบอกว่าอยากหา star pattern ที่ถามหาผู้เขียนที่เคยตีพิมพ์ใน PODS และเคยเขียนร่วมกับผู้เขียนอีกสามคน คนหนึ่งมาจาก PODS คนหนึ่งมาจาก ISBMS และคนหนึ่งมาจาก IAT ตามที่ ASR ได้ยิน (ตรงกับป้ายบนจอ) ช่วงนี้แทบไม่มีคำพูด ผู้ชมเห็นการวาดบนจอแทน

ลำดับที่เห็น: วางโหนดว่างสีขาวบนพื้นที่ Query จากนั้นเปิดกล่อง Specify Vertex Attribute มีช่อง Search ที่พิมพ์ "pods" เพื่อกรองรายการ และมีตาราง Attributes ที่เลื่อนได้ (รายการแรก PODS ตามด้วย PODS ที่ต่อท้ายด้วยปี) แล้วกด Okay (เห็นเคอร์เซอร์อยู่ที่ปุ่ม Okay) legend มุมขวาบนของ Query ลิสต์สีของ attribute ที่ใช้อยู่ โดยแถวบนสุดสีขาวไม่มีป้ายคือโหนดที่ยังไม่ได้กำหนด attribute (ข้อสังเกตจากภาพ ผู้พูดไม่ได้อธิบาย)

ผู้ชมเห็นโหนดถูกเพิ่มทีละโหนดและเชื่อมด้วยเส้นโค้ง จนได้โหนด PODS กลางที่เชื่อมกับ PODS, ISBMS และ IAT คำพูดช่วง ~1:56–2:10 ถูก ASR ถอดเพี้ยนมาก อ่านได้คร่าว ๆ ว่าเป็นการกำหนด attribute ที่เป็นชื่อ conference ให้โหนดผู้เขียนและเพิ่มเส้นที่แทน co-authorship [ฟังไม่ชัด] จึงอธิบายตามภาพบนจอเป็นหลัก สีของ attribute ในคลิปไม่ตรงกันทุกฉาก เช่น ฉากภาพรวม (~0:58) ใช้ส้มเข้มสำหรับ IAT และเหลืองสำหรับ ISBMS แต่ฉากสร้างคิวรี (~1:48) ใช้ส้มสำหรับ ISBMS และเหลืองสำหรับ IAT จึงควรอ่านสีจาก legend ของฉากนั้น ๆ (ข้อสังเกตจากภาพ ผู้พูดไม่ได้พูดถึง)

5. ผลลัพธ์: แท็บ การจัดอันดับ และ match ใกล้เคียง (~2:10–2:31)

ผู้พูดบอกว่า match ถูกแสดงเป็นแท็บ และ จัดเรียงให้ match ลำดับต้น ๆ น่าจะสำคัญต่อผู้ใช้มากกว่า (ASR ที่ ~2:13 อ่านว่า "empirically more important to the user" คำว่า empirically อาจเพี้ยนจากเสียงจริง จึงไม่ขยายความต่อว่าเกณฑ์จัดอันดับคืออะไร) Graphite จะ หา exact match ก่อนเสมอเท่าที่เป็นไปได้ แต่ถ้าไม่มี เช่นในตัวอย่างนี้ ก็จะแสดง close match ที่ยอมให้มี เส้นทางอ้อมที่ยาวกว่า ระหว่างโหนดของกราฟคิวรี

6. ตัวอย่างผลลัพธ์อันดับต้น (~2:31–2:51)

ผู้พูดเปิดดูผลอันดับต้นหนึ่งผลบนจอ Philip Yu ผู้เขียนที่มีผลงานมากและอยู่ใน PODS อยู่ตรงกลาง เชื่อมกับผู้เขียนที่มีผลงานมากอีกคนคือ Hector Garcia-Molina โดยมีโหนดคั่น (ASR ช่วง ~2:42 ฟังไม่ชัด บนจอโหนดคั่นคือ Sudarshan S. Chawathe) ส่วน Mark (Zhongfei Zhang บนจอ) ถูกบรรยายว่าเป็นนักวิจัยด้าน computer vision ที่เพิ่งสนใจ data mining จึงเชื่อมกับ Philip Yu ได้ ในผลนี้แขน PODS และแขน ISBMS มีโหนดสีขาวคั่น ส่วนแขน IAT ต่อกับ Philip Yu โดยตรง (ข้อสังเกตจากภาพ) บนจอโหนดที่ผู้ใช้กำหนด attribute แสดงชื่อ attribute กับชื่อผู้เขียนซ้อนกัน ส่วนโหนดที่คั่นตรงกลางเป็นสีขาวและแสดงแค่ชื่อ

7. ปิดท้าย: ใช้กับกราฟของตัวเอง (~2:51–3:04)

ผู้พูดสรุปว่าตัวอย่างนี้แสดงให้เห็นว่า ใช้ Graphite ทำ graph query ได้ง่าย และผู้ใช้ ไม่จำเป็นต้องใช้กราฟ DBLP แต่ใช้ attributed graph ของตัวเอง และวาดกราฟคิวรี โครงสร้างใดก็ได้ (arbitrary structures) ได้ ที่ ~3:02 บนจอยังเป็นหน้าต่างผลลัพธ์เดิม (เฟรมที่ ~2:52 และ ~3:02 ดูเหมือนกัน)

เสริมจากผู้จัดทำ

1.Graphite ให้ผู้ใช้ วาดคิวรีเป็นกราฟ แล้วกำหนด attribute ของโหนดจากรายการที่มีช่อง Search ให้กรอง
2.หน้าจอแบ่งสองส่วนติดกัน คือ Query (ซ้าย) กับ Match (ขวา) ทำให้เทียบคิวรีกับผลได้ในที่เดียว
3.ผลอยู่ในแท็บตัวเลข เรียงให้อันดับต้นสำคัญกว่า และระบบหา exact match ก่อนเสมอเท่าที่ทำได้
4.เมื่อไม่มี exact match ระบบแสดง close match ที่มีโหนดหรือเส้นทางอ้อมคั่น และในผลที่ยกมาโหนดคั่นเป็นสีขาว
