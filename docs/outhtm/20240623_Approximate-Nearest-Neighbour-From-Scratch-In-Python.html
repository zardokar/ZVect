📋 บทสรุปย่อ

บทสรุปย่อ: ผู้สอนอธิบายและเขียน approximate nearest neighbor (ANN) เองตั้งแต่ศูนย์ใน Python (Jupyter notebook) โดยใช้เวกเตอร์สุ่ม 2 มิติ 1,000 ตัวเพื่อให้วาดดูได้ แล้วหาเพื่อนบ้านใกล้สุดของเวกเตอร์เป้าหมาย (50, 50) ไอเดียคือ สุ่มเลือกสองจุด หา hyperplane ที่อยู่ห่างจากสองจุดเท่ากัน แล้วแบ่งเวกเตอร์ทั้งหมดเป็นฝั่งซ้ายกับขวา ทำซ้ำแบบ recursive จนแต่ละกลุ่มเหลือไม่เกิน 5 ตัว ได้เป็นต้นไม้ตัดสินใจ (binary tree) ตอนค้นหาก็เดินจากรากลงไปตามฝั่งที่เวกเตอร์เป้าหมายอยู่ ในคลิปใช้ 9 ขั้น แทนการเทียบกับเวกเตอร์ทั้ง 1,000 ตัวแบบ k-NN ผู้สอนจึงบอกว่าเร็วกว่าราว 111 เท่าถ้าสร้างต้นไม้ไว้ก่อน และวิธีเดียวกันใช้กับเวกเตอร์หลายมิติได้ (เป็นแนวคิดเบื้องหลัง Spotify Annoy)

โหมดของเนื้อหา: แปลแบบตีความ ครบทุกรายละเอียด (license มาตรฐานของ YouTube, ตรวจ 2026-10-10) ทุกประเด็นและทุกขั้นของโค้ดอยู่ครบตามลำดับ เรียบเรียงด้วยคำของผู้จัดทำโดยไม่เปลี่ยนความหมาย caption เป็นแบบอัตโนมัติ คำที่ฟังผิดแก้ตามภาพบนจอ (เช่น "from Secret" = from scratch) ส่วนที่ผู้จัดทำเพิ่มเองอยู่ในส่วนที่ 8 และ 9

🧭 สรุปเชิงลึก

ANN คืออะไร ทำไมสำคัญ: ผู้สอนบอกว่า approximate nearest neighbor เป็นแกนหลักของ vector database และ vector index หลายตัวในปัจจุบัน เช่น Spotify Annoy ใช้อัลกอริทึมนี้ทำ index ของ vector embeddings ทำให้หาเวกเตอร์ที่ใกล้ที่สุดจากหลักล้านหรือหลักพันล้านตัวได้ในเวลาเพียงมิลลิวินาที และไอเดียเบื้องหลังเรียบง่ายมาก ใช้แค่คณิตศาสตร์ระดับมัธยม

ข้อมูลทดลอง: สร้างเวกเตอร์สุ่ม 1,000 ตัว แต่ละตัวมี 2 มิติ (ค่า 0–100 ปัดทศนิยม) เพื่อให้วาดดูได้ ในงานจริงเวกเตอร์มีหลายมิติ เช่น FaceNet ให้เวกเตอร์ 128 มิติ แต่ละจุดอาจแทนเพลงใน Spotify หรือรูปภาพที่ Google ทำ index ก็ได้ เป้าหมายคือหาเวกเตอร์ที่ใกล้ (50, 50) ที่สุด ซึ่งดูจากกราฟก็รู้ แต่ในงานจริงมีหลายมิติจนวาดไม่ได้ จึงต้องมีวิธีอื่น

อัลกอริทึม: สุ่มเลือกสองจุด หาเส้น (ใน 2 มิติ) หรือ hyperplane (ในมิติที่สูงกว่า) ที่ห่างจากสองจุดเท่ากัน เก็บสมการนี้ไว้ใน node ของต้นไม้ แล้วจัดทุกเวกเตอร์ลงกิ่งซ้ายหรือขวาตามฝั่งของ hyperplane ทำซ้ำในแต่ละกิ่งจนได้ต้นไม้ใหญ่ ฟังก์ชันที่เขียนมีสามตัว: hyperplane_equation (normal vector = ผลต่างของสองเวกเตอร์, จุดกึ่งกลาง, ค่าคงที่ = dot ของ normal กับจุดกึ่งกลาง), check_vector_side (ถ้า dot ของ normal กับเวกเตอร์มากกว่าค่าคงที่คือขวา น้อยกว่าคือซ้าย กรณีเท่ากันนับเป็นซ้าย) และ build_tree (แบบ recursive หยุดเมื่อกลุ่มไม่เกิน subset size = 5)

ผล: ค้นหาด้วยการเดินจากรากตามฝั่งของเป้าหมาย ได้ใน 9 ขั้น (กลุ่มลดจาก 1,000 → 582 → 264 → 196 → 113 → 45 → 34 → 26 → 9) และได้เวกเตอร์ใกล้เป้าหมาย 3 ตัว ผู้สอนเทียบว่า k-NN ต้องเทียบทั้ง 1,000 ตัว (O(1000)) ส่วนวิธีนี้ใช้ 9 ขั้น จึงเร็วกว่าราว 111 เท่า (1000 / 9) ถ้าสร้างต้นไม้ไว้ก่อน ภาพสุดท้ายแสดงว่าเวกเตอร์ที่ได้อยู่ใกล้เป้าหมายจริง และวิธีเดียวกันยังใช้ได้กับเวกเตอร์หลายมิติแม้จะวาดดูไม่ได้

ตรวจทาน (เสริมจากผู้จัดทำ): ผู้จัดทำเขียนโค้ดเทียบเท่าแล้วรันจริงกับข้อมูลสุ่ม 1,000 จุดเหมือนในคลิป ได้จำนวนขั้นเฉลี่ยราว 9.6 (5–15) แต่ต้นไม้ต้นเดียวมีใบที่มีเพื่อนบ้านใกล้สุดจริงอยู่ด้วยแค่ราว 70–75% ของครั้ง พอใช้ 10 ต้นรวมกัน (ผู้จัดทำเข้าใจว่า Annoy ใช้หลายต้นแบบนี้ แต่ยังไม่ได้ตรวจกับเอกสาร) ได้ครบ 100% จาก 300 คำถาม และ "111 เท่า" นับเป็นจำนวนขั้น ไม่ได้รวมต้นทุนสร้างต้นไม้และการเทียบระยะในใบ

ผู้สอน (Sefik) บอกว่าคลิปนี้จะโฟกัสที่อัลกอริทึม approximate nearest neighbor และเขียนมันเองตั้งแต่ศูนย์ (from scratch) ใน Python (ช่วงขอให้กดไลก์ ติดตามช่อง และแสดงความเห็น ตัดออก)

2. สร้างเวกเตอร์สุ่ม 1,000 ตัว และวาดกราฟ

~1:04–4:25

งานแรกคือสร้าง vector embeddings แบบสุ่ม จึง import โมดูล random ก่อน การทดลองนี้มี 1,000 instances สร้าง for loop จาก 0 ถึงจำนวน instances และใช้ vector embeddings 2 มิติ

ผู้สอนย้ำว่าในความเป็นจริงเราใช้เวกเตอร์หลายมิติ เช่น ถ้าใช้โมเดลจดจำใบหน้า FaceNet จะได้ vector embeddings 128 มิติ (คำอธิบายคลิปยกตัวอย่าง VGG-Face ด้วย) แต่การทดลองนี้ใช้แค่ 2 มิติเพื่อให้วาดภาพดูได้

  • ค่า x มาจาก random.random() ซึ่งให้ทศนิยมระหว่าง 0 ถึง 1 คูณ 100 จึงได้ค่าระหว่าง 0 ถึง 100 แล้วปัดทศนิยมให้ค่าดูสวยขึ้น ทำแบบเดียวกันกับมิติที่สอง
  • เก็บคู่ x, y ไว้ในลิสต์ชื่อ vectors ด้วยการ append (อีกทางคือ import NumPy แล้วเก็บเป็น NumPy array แทน tuple)
  • ได้เวกเตอร์ 2 มิติที่ต่างกัน 1,000 ตัวในลิสต์ vectors

จากนั้นวาดภาพด้วย import matplotlib.pyplot as plt สร้าง for loop เรียก plt.scatter ทุกรอบ ส่งค่า x (index 0) และ y (index 1) ของแต่ละเวกเตอร์ สีดำ marker เป็น x แล้วเรียก plt.show() หลัง loop ภาพเล็กไป จึงสร้าง plt.figure(figsize=(10, 10)) ก่อน loop ได้ภาพที่ดีขึ้นมาก

ตอนนี้มี vector embeddings ที่ต่างกัน 1,000 ตัว และสมมติว่าคำนวณไว้แล้วล่วงหน้า แต่ละจุดอาจแทนเพลงใน Spotify หรือรูปภาพที่ Google ทำ index หรืออะไรก็ได้ที่แทนด้วย vector embeddings ได้ การทดลองใช้ 2 มิติเพื่อวาดดู แต่ในงานจริงใช้วิธีเดียวกันกับเวกเตอร์หลายมิติได้

3. เวกเตอร์เป้าหมาย และไอเดีย hyperplane + ต้นไม้ตัดสินใจ

~4:26–6:44

ตั้งเวกเตอร์เป้าหมาย แล้วหาเวกเตอร์ที่ใกล้ที่สุดของมัน เช่น (50, 50) วาดไว้ด้วยสีแดงหลัง loop งานของการทดลองคือหาเวกเตอร์ที่ใกล้ที่สุดของเวกเตอร์นี้ ดูจากกราฟก็บอกได้ง่าย ๆ ว่าตัวไหนใกล้ที่สุด เพราะเราวาดภาพได้ แต่ในโลกจริงใช้เวกเตอร์หลายมิติซึ่งวาดภาพไม่ได้ จึงต้องทำอย่างอื่น

ไอเดีย (บนจอเปิดบทความใน sefiks.com ของผู้สอนประกอบ):

  1. สุ่มเลือกสองจุด (ไฮไลต์ด้วย marker สีแดง)
  2. หาเส้นที่ห่างจากสองจุดเท่ากัน (equidistant) และหาสมการของเส้นนี้ เป็นเส้นเพราะเวกเตอร์เป็น 2 มิติ ถ้าเป็น 3 มิติจะเป็นระนาบ 2 มิติ ผู้สอนบอกว่ามันเป็น hyperplane เสมอ จึงเรียกว่า hyperplane แทนเส้น
  3. เก็บสมการนี้ไว้ในต้นไม้ตัดสินใจ (decision tree) แล้วจัดเวกเตอร์ทั้งหมดตามฝั่งของ hyperplane: อยู่ซ้ายไปกิ่งซ้าย อยู่ขวาไปกิ่งขวา
  4. ตอนนี้มี decision node ที่เก็บสมการ และมีเวกเตอร์ในกิ่งซ้ายและขวา ขั้นที่สองก็สุ่มสองจุดอีก หา hyperplane ที่ห่างเท่ากัน แล้วแบ่งกลุ่มอีก
  5. ทำแบบนี้ซ้ำแบบ recursive จนได้ต้นไม้ตัดสินใจขนาดใหญ่

4. class Node, hyperplane_equation และ check_vector_side

~6:44–10:34

class Node

เพื่อเก็บต้นไม้ สร้าง class ชื่อ Node มีเมธอด initialization รับ hyperplane (เก็บสมการของ hyperplane) และ value (เก็บลิสต์ของเวกเตอร์) ค่าเริ่มต้นเป็น None ทั้งคู่ แล้วเก็บค่าที่รับเข้ามาไว้ในตัวแปรของ class และมีกิ่ง left กับ right ที่เริ่มเป็น None

จากนั้นต้องเขียนสองงาน: (1) หา hyperplane ที่ห่างจากสองเวกเตอร์เท่ากัน และ (2) บอกว่าเวกเตอร์อยู่ซ้ายหรือขวาของ hyperplane

hyperplane_equation(vector1, vector2)

ผู้สอนบอกว่าการหา hyperplane ที่ห่างเท่ากันใช้แค่คณิตศาสตร์ระดับมัธยม ฟังก์ชันรับสองเวกเตอร์ (เป็น NumPy array)

  1. normal vector = ผลต่างของสองเวกเตอร์
  2. จุดกึ่งกลาง (midpoint) = ผลบวกของสองเวกเตอร์หารสอง
  3. ค่าคงที่ (constant term) = np.dot(normal_vector, midpoint) (ผู้สอนเรียก np.dot ว่าการคูณเมทริกซ์)
  4. คืนค่า normal vector และค่าคงที่

ทดสอบกับสองตัวแรกของลิสต์ (ผู้สอนเขียนค่าของสองเวกเตอร์ไว้ก่อนรัน): ได้ normal vector และค่าคงที่ ซึ่งเขียนเป็นสมการได้ว่า 0.99·x − 0.64·y = 17.035

check_vector_side(normal_vector, constant_term, target_vector)

หา dot ของ normal vector กับเวกเตอร์เป้าหมาย ถ้ามากกว่าค่าคงที่แปลว่าอยู่ขวา ถ้าน้อยกว่าอยู่ซ้าย ถ้าเท่ากันแปลว่าอยู่บน hyperplane พอดี แต่ผู้สอนไม่แยกกรณีเท่ากัน และนับเป็นซ้าย

5. build_tree แบบ recursive

~10:34–15:21

ฟังก์ชันย่อยพร้อมแล้ว จึงสร้างฟังก์ชันหลักชื่อ build_tree(vectors)

  1. สุ่มสองจุด: ใช้ random.randint(0, len(vectors) - 1) หา index ของจุดแรกและจุดที่สอง แต่ในทางทฤษฎีสองค่าอาจซ้ำกัน จึงตั้งค่าเริ่มเป็น 0 ทั้งคู่ แล้วสุ่มใน while loop ตราบที่ index เท่ากัน พอต่างกัน loop ก็จบ
  2. ดึงเวกเตอร์ตาม index ทั้งสอง แล้วเรียก hyperplane_equation ได้ hyperplane ของสองเวกเตอร์นี้
  3. จัดทุกเวกเตอร์เป็นซ้ายหรือขวา: สร้าง left_nodes และ right_nodes เป็นลิสต์ว่าง วน for loop ทุกเวกเตอร์ เรียก check_vector_side โดยส่ง hyperplane[0] (normal vector) และ hyperplane[1] (ค่าคงที่) ถ้าได้ left ใส่ left_nodes ไม่เช่นนั้นใส่ right_nodes
  4. สร้าง current_node = Node(hyperplane=hyperplane, value=vectors) และฟังก์ชันจะคืน current_node แต่ต้องตั้งกิ่งซ้ายขวาก่อนคืน

เงื่อนไขหยุด: ผู้สอนอยากแบ่งต่อไปจนแต่ละกลุ่มมีเวกเตอร์จำนวนคงที่ เช่น ถ้าแบ่งแล้วเหลือ 5 ตัวก็หยุดได้ จึงตั้ง subset_size = 5 (ปรับทีหลังได้)

  • ถ้า len(left_nodes) > subset_size ให้แบ่งต่อ โดยเรียก build_tree(left_nodes) แบบ recursive ซึ่งคืน node มา ตั้งให้เป็น current_node.left
  • ไม่เช่นนั้น current_node.left = Node(value=left_nodes) ผู้สอนชี้ว่า build_tree คืน node ที่มี hyperplane แต่กรณีนี้ไม่มี hyperplane
  • ทำแบบเดียวกันกับกิ่งขวา

build_tree จึงเป็นฟังก์ชัน recursive เรียกกับเวกเตอร์ทั้งหมดแล้วเก็บไว้ในตัวแปร tree ซึ่งสร้างเสร็จเร็วมาก

6. ค้นหาใน 9 ขั้น และเทียบกับ k-NN

~15:21–17:41

กลับมาที่เวกเตอร์เป้าหมาย v สร้าง while loop: ตราบที่ len(tree.value) (เวกเตอร์ทั้งหมดของชั้นนั้น) มากกว่า subset size และ tree.hyperplane ไม่ใช่ None ให้เรียก check_vector_side กับ v โดยใช้ tree.hyperplane[0] เป็น normal vector และ tree.hyperplane[1] เป็นค่าคงที่ ถ้าได้ left ให้ tree = tree.left ไม่เช่นนั้น tree = tree.right และพิมพ์ log "go to left" / "go to right" พร้อมจำนวนเวกเตอร์ len(tree.value)

ผลคือหาเจอใน 9 ขั้น และเพื่อนบ้านใกล้สุดของ v อยู่ใน tree.value ซึ่งคือเวกเตอร์ที่อยู่ใกล้ v ที่สุด

ผู้สอนเทียบ: ขั้นแรกมีเวกเตอร์ที่ต่างกัน 1,000 ตัว ถ้าใช้อัลกอริทึม k-NN แทน ANN ต้องเทียบ v กับทั้ง 1,000 ตัว ความซับซ้อนจึงเป็น O(1000) แต่เราสร้าง binary tree เก็บเวกเตอร์ทั้งหมดไว้ จึงหาเพื่อนบ้านใกล้สุดของ v ได้ใน 9 ขั้น หรือพูดอีกอย่างคือ แทนที่จะเป็น 1,000 ได้ผลใน 9 ขั้น ผู้สอนสรุปว่าอัลกอริทึมนี้เร็วกว่า k-NN ราว 111 เท่า ถ้าสร้างต้นไม้ไว้ล่วงหน้า

7. ภาพผลลัพธ์และข้อสรุป

~17:44–19:06

สุดท้ายวาดเวกเตอร์ที่ใกล้ที่สุดเหล่านี้: for loop บน tree.value แล้ว plt.scatter แต่ละตัวด้วยสีน้ำเงิน จุดสีแดงคือเวกเตอร์เป้าหมาย และสีน้ำเงินคือเพื่อนบ้านใกล้สุด ซึ่งอยู่ใกล้เป้าหมายมากจริง แสดงว่าวิธีนี้ทำงานได้ดี

ถ้าขยายการทดลองไปเป็นหลายมิติ (n มิติ) วิธีนี้ยังใช้ได้ แม้จะวาดภาพดูไม่ได้ ก็ยังหาเวกเตอร์ที่ใกล้ที่สุดได้ด้วยอัลกอริทึมนี้ ผู้สอนสรุปว่าคลิปนี้โฟกัสที่ approximate nearest neighbor แทน k-NN และเขียนเองใน Python ตั้งแต่ศูนย์ (ช่วงท้ายขอไลก์ ติดตาม และขอบคุณผู้ชม ตัดออก)

8. ตรวจทาน ลองรันจริง และข้อมูลเสริม (จากผู้จัดทำ)

เสริมจากผู้จัดทำ ทั้งส่วนนี้ไม่ได้อยู่ในคลิป

ลองรันจริง (ผู้จัดทำเขียนโค้ดเทียบเท่าเอง)

ผู้จัดทำเขียนอัลกอริทึมเดียวกันใน Python ล้วน (ไม่ใช้ NumPy) สุ่มเวกเตอร์ 2 มิติ 1,000 ตัวค่า 0–100 (seed 42) เป้าหมาย (50, 50) และ subset size 5 แล้วรันในเครื่อง:

การทดลองผล
ต้นไม้ 1 ต้น (seed 7)เดิน 9 ขั้น ใบมี 4 เวกเตอร์ และมีเพื่อนบ้านใกล้สุดจริง (51.47, 49.88) ระยะ 1.47 อยู่ด้วย
ต้นไม้ 500 ต้น เป้าหมาย (50, 50)จำนวนขั้นเฉลี่ย 9.6 (ต่ำสุด 5 สูงสุด 15) ใบเฉลี่ย 3.6 เวกเตอร์ ใบมีเพื่อนบ้านใกล้สุดจริงอยู่ 74.6% ของครั้ง
ต้นไม้ 1 ต้นต่อคำถามสุ่ม 300 คำถามใบมีเพื่อนบ้านใกล้สุดจริง 70.3%
ป่า 10 ต้น (รวมใบของทุกต้น) 300 คำถามมีเพื่อนบ้านใกล้สุดจริง 100% โดยมีผู้สมัครเฉลี่ย 13.7 เวกเตอร์ แล้วค่อยเทียบระยะกับผู้สมัครเหล่านี้

ข้อสรุป: ต้นไม้ต้นเดียวเร็วแต่พลาดได้ เพราะเพื่อนบ้านที่ใกล้จริงอาจอยู่อีกฝั่งของ hyperplane (นี่คือความหมายของคำว่า approximate) การใช้หลายต้นช่วยแก้ปัญหานี้ (ผู้จัดทำเข้าใจว่า Annoy สร้างต้นไม้หลายต้นแบบนี้ แต่ไม่ได้ตรวจกับเอกสารของ Annoy ในงานนี้)

Python (ผู้จัดทำเขียนเอง และรันแล้ว)
import random, math
def hyperplane(v1, v2):
    n = [a - b for a, b in zip(v1, v2)]; mid = [(a + b) / 2 for a, b in zip(v1, v2)]
    return n, sum(a * b for a, b in zip(n, mid))    # n · x = c
def side(n, c, v): return "right" if sum(a * b for a, b in zip(n, v)) > c else "left"
class Node:
    def __init__(self, hp=None, value=None): self.hp, self.value, self.left, self.right = hp, value, None, None
def build(vs, leaf=5):
    i = j = 0
    while i == j: i, j = random.randint(0, len(vs) - 1), random.randint(0, len(vs) - 1)
    hp = hyperplane(vs[i], vs[j])
    L = [v for v in vs if side(*hp, v) == "left"]; R = [v for v in vs if side(*hp, v) == "right"]
    node = Node(hp, vs)
    node.left = build(L, leaf) if len(L) > leaf else Node(value=L)
    node.right = build(R, leaf) if len(R) > leaf else Node(value=R)
    return node
def search(t, q, leaf=5):
    while len(t.value) > leaf and t.hp is not None: t = t.left if side(*t.hp, q) == "left" else t.right
    return t.value

เสริมจากผู้จัดทำ ส่วนนี้เป็นข้อเสนอของผู้จัดทำ ไม่ได้อยู่ในคลิป
บทใน ZVectเนื้อหาจากคลิปที่ใช้ได้

Key Takeaways

  1. ANN เป็นแกนของ vector database และ vector index หลายตัว เช่น Spotify Annoy ใช้อัลกอริทึมนี้ทำ index และอาศัยแค่คณิตศาสตร์ระดับมัธยม
  2. แบ่งพื้นที่ด้วย hyperplane ที่ห่างจากสองจุดสุ่มเท่ากัน normal = ผลต่าง, ค่าคงที่ = normal · จุดกึ่งกลาง, ฝั่ง = n · v เทียบกับค่าคงที่
  3. ทำซ้ำแบบ recursive จนได้ต้นไม้ หยุดเมื่อกลุ่มไม่เกิน subset size (5 ในคลิป)
  4. ค้นหาด้วยการเดินลงกิ่ง ในคลิปใช้ 9 ขั้นแทนการเทียบ 1,000 ตัว ผู้สอนจึงบอกว่าเร็วกว่า k-NN ราว 111 เท่าถ้าสร้างต้นไม้ไว้ก่อน
  5. ใช้กับหลายมิติได้ แม้จะวาดภาพดูไม่ได้ (ผู้จัดทำลองรันแล้วพบว่าต้นไม้ต้นเดียวพลาดได้ จึงควรใช้หลายต้น)
